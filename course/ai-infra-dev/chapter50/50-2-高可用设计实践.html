🏗️ 高可用架构

  • 主节点提供服务
  • 备节点处于待机
  • 故障时自动切换
  • 成本较低

主主架构

  • 多个节点同时服务
  • 负载均衡分发
  • 故障时摘除节点
  • 资源利用率高

  • 多节点集群部署
  • 数据自动复制
  • 自动故障转移
  • 扩展性好

  • 多个数据中心

  • 成本最高

    • 🔄 故障转移设计

    # 故障转移配置

# 1. Kubernetes高可用部署
apiVersion: apps/v1
kind: Deployment
metadata:
  name: inference-service
spec:
  replicas: 3  # 多副本
  strategy:
    type: RollingUpdate
    rollingUpdate:
      maxUnavailable: 1
      maxSurge: 1
  template:
    spec:
      # Pod反亲和性
      affinity:
        podAntiAffinity:
          requiredDuringSchedulingIgnoredDuringExecution:
          - labelSelector:
              matchExpressions:
              - key: app
                operator: In
                values:
                - inference
            topologyKey: "kubernetes.io/hostname"

---

# 2. 服务健康检查
apiVersion: v1
kind: Service

  name: inference-service

  selector:
    app: inference
  ports:
  - port: 8080
    targetPort: 8080
  type: LoadBalancer

    💾 数据备份策略

    # 备份策略配置

# 1. 增量备份
#!/bin/bash
BACKUP_DIR="/backup/incremental"
DATA_DIR="/data"
LAST_BACKUP=$(cat /tmp/last_backup)

# 创建增量备份
rsync -av --link-dest="$LAST_BACKUP" \
  "$DATA_DIR/" "$BACKUP_DIR/$(date +%Y%m%d_%H%M%S)/"

# 更新最后备份时间
echo "$BACKUP_DIR/$(date +%Y%m%d_%H%M%S)" > /tmp/last_backup

# 2. 数据库备份
# 每日全备
0 2 * * * mysqldump -u root -p database_name > /backup/db/daily_$(date +\%Y\%m\%d).sql

# 每小时增量
0 * * * * mysqldump -u root -p --single-transaction --flush-logs database_name > /backup/db/incremental_$(date +\%Y\%m\%d_\%H).sql

# 3. Checkpoint管理
#!/bin/bash
# 保留最近10个checkpoint
find /checkpoints -name "checkpoint_*.pt" -type f | \
  sort -r | tail -n +11 | xargs rm

    高可用设计原则

    消除单点：确保每个组件都有冗余。快速检测：及时发现故障并告警。自动恢复：尽可能实现自动故障转移。定期演练：定期进行故障演练验证。
