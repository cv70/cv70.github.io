CI/CD for ML概述

CI/CD for ML（持续集成/持续部署）是自动化的机器学习开发、 测试和部署流程。它将传统的DevOps实践扩展到ML领域，实现模型的快速迭代和可靠部署。

图：ML CI/CD完整流程

  • 模型训练

持续交付（CD）

  • 模型评估

持续监控

🛠️ GitHub Actions for ML

CI流水线

name: ML CI Pipeline on: push: branches: [main, develop] pull_request: branches: [main] workflow_dispatch: jobs: test: runs-on: ubuntu-latest steps: - uses: actions/checkout@v3 - name: Set up Python uses: actions/setup-python@v4 with: python-version: '3.9' - name: Install dependencies run: | pip install -r requirements.txt pip install pytest black mypy - name: Code quality checks run: | black --check . mypy . - name: Unit tests run: | pytest tests/ -v - name: Data validation run: | python scripts/validate_data.py train: needs: test runs-on: gpu-node steps: - uses: actions/checkout@v3 - name: Train model run: | python train.py \ --data-path ./data \ --output-dir ./model - name: Evaluate model run: | python evaluate.py \ --model-path ./model \ --test-data ./data/test - name: Save metrics run: | echo "accuracy=0.95" >> $GITHUB_OUTPUT - name: Upload model uses: actions/upload-artifact@v3 with: name: model-artifact path: ./model

CD流水线

name: ML CD Pipeline on: workflow_run: workflows: ["ML CI Pipeline"] types: [completed] branches: [main] jobs: register-model: runs-on: ubuntu-latest if: ${{ github.event.workflow_run.conclusion == 'success' }} steps: - uses: actions/checkout@v3 - name: Download model artifact uses: actions/download-artifact@v3 with: name: model-artifact path: ./model - name: Register model run: | python register_model.py \ --model-path ./model \ --model-name my-model - name: Update model version run: | # 更新模型版本标签 git tag -a v$(date +%Y%m%d-%H%M%S) -m "Model deployment" git push origin v$(date +%Y%m%d-%H%M%S) deploy-staging: needs: register-model runs-on: ubuntu-latest steps: - name: Deploy to staging run: | kubectl apply -f k8s/staging/ - name: Wait for deployment run: | kubectl rollout status deployment/my-model -n staging - name: Run smoke tests run: | python tests/smoke.py --env staging deploy-production: needs: deploy-staging runs-on: ubuntu-latest environment: name: production url: https://model.example.com steps: - name: Deploy to production run: | kubectl apply -f k8s/production/ - name: Wait for deployment run: | kubectl rollout status deployment/my-model -n production - name: Monitor deployment run: | python scripts/monitor_deployment.py --env production

GitLab CI配置

# .gitlab-ci.yml stages: - test - train - register - deploy-staging - deploy-production variables: PYTHON_VERSION: "3.9" DOCKER_IMAGE: "registry.example.com/ml-pipeline:latest" # 代码测试 test: stage: test image: python:${PYTHON_VERSION} script: - pip install -r requirements.txt - pip install pytest black mypy - black --check . - mypy . - pytest tests/ -v only: - branches # 模型训练 train: stage: train image: ${DOCKER_IMAGE} script: - python train.py --data-path ./data --output-dir ./model - python evaluate.py --model-path ./model --test-data ./data/test artifacts: paths: - model/ expire_in: 1 week dependencies: - test only: - main # 模型注册 register: stage: register image: ${DOCKER_IMAGE} script: - python register_model.py --model-path ./model --model-name my-model dependencies: - train only: - main # 部署到Staging deploy-staging: stage: deploy-staging image: bitnami/kubectl:latest script: - kubectl apply -f k8s/staging/ - kubectl rollout status deployment/my-model -n staging - python tests/smoke.py --env staging environment: name: staging url: https://staging.model.example.com dependencies: - register only: - main when: manual # 部署到Production deploy-production: stage: deploy-production image: bitnami/kubectl:latest script: - kubectl apply -f k8s/production/ - kubectl rollout status deployment/my-model -n production environment: name: production url: https://model.example.com dependencies: - deploy-staging only: - main when: manual

蓝绿部署

# blue-green-deploy.sh #!/bin/bash NEW_VERSION=$1 DEPLOYMENT="my-model" NAMESPACE="production" # 部署Green版本 kubectl set image deployment/${DEPLOYMENT} \ model=registry.example.com/my-model:${NEW_VERSION} \ -n ${NAMESPACE} # 等待Green版本就绪 kubectl rollout status deployment/${DEPLOYMENT} -n ${NAMESPACE} # 运行集成测试 python tests/integration.py --env production # 验证通过后切换流量 echo "Deployment successful, switching traffic..." # 7天后删除旧版本 kubectl delete deployment/${DEPLOYMENT}-blue \ --ignore-not-found \ -n ${NAMESPACE}

🔍 质量控制

数据质量检查

# scripts/validate_data.py import pandas as pd import great_expectations as ge # 加载数据 df = pd.read_csv("data/train.csv") # 使用Great Expectations验证 context = ge.DataContext() batch = context.get_batch(data=df) # 定义期望 expectation_suite = context.get_expectation_suite("data_expectations") # 运行验证 validation_result = context.run_validation( batch=batch, expectation_suite=expectation_suite ) # 检查验证结果 if not validation_result.success: print("Data validation failed!") print(validation_result.statistics) exit(1) print("Data validation passed!")

模型性能检查

# scripts/check_model.py import mlflow import yaml # 加载配置 with open("config/thresholds.yaml") as f: thresholds = yaml.safe_load(f) # 从MLflow获取模型指标 model_uri = "models:/my-model/Production" model = mlflow.pyfunc.load_model(model_uri) # 评估模型 metrics = evaluate_model(model) # 检查阈值 if metrics["accuracy"] < thresholds["accuracy"]: print(f"Accuracy {metrics['accuracy']} below threshold {thresholds['accuracy']}") exit(1) if metrics["f1_score"] < thresholds["f1_score"]: print(f"F1 score {metrics['f1_score']} below threshold {thresholds['f1_score']}") exit(1) print("Model performance check passed!")

🔄 持续监控与重训

监控流水线

# 定期监控任务 name: Model Monitoring on: schedule: # 每天凌晨2点运行 - cron: '0 2 * * *' workflow_dispatch: jobs: monitor: runs-on: ubuntu-latest steps: - uses: actions/checkout@v3 - name: Check data drift run: | python scripts/check_drift.py - name: Check model performance run: | python scripts/check_performance.py - name: Trigger retrain if needed if: steps.check-model-performance.outputs.needs-retrain == 'true' run: | curl -X POST \ -H "Authorization: token ${{ secrets.GITHUB_TOKEN }}" \ -H "Accept: application/vnd.github.v3+json" \ https://api.github.com/repos/${{ github.repository }}/actions/workflows/train.yml/dispatches \ -d '{"ref":"main"}'
