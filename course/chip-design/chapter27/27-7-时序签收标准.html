27.7 时序签收标准

时序验证的通过标准

🎯 学习目标

  • 理解时序签收的概念和重要性
  • 掌握时序签收的标准和指标
  • 学会进行时序签收验证
  • 了解签收报告的内容和格式

什么是时序签收

时序签收（Timing Signoff）是指在芯片设计的最后阶段， 对设计进行全面的静态时序分析，确保所有时序要求都满足规范， 可以进入制造阶段的关键验证过程。时序签收是芯片流片前的必要条件。

✅ 时序签收标准

基本标准

指标 标准 说明
Setup WNS > 0 最差路径必须为正裕量
Setup TNS = 0 总负Slack必须为零
Hold WNS > 0 Hold路径必须有正裕量
Hold TNS = 0 Hold总负Slack必须为零
Recovery/Removal > 0 异步信号时序必须满足

📋 签收检查清单

完整性检查

  • 所有时钟都已正确定义和约束
  • 所有IO端口都有适当的延迟约束
  • 所有时序例外都已合理设置
  • 没有未约束的时序路径

多角多模检查

  • 所有工艺角（SS/TT/FF）都已分析
  • 所有工作模式（功能/测试）都已验证
  • 跨时钟域路径已正确处理
  • OCV分析已包含

时序违例检查

  • Setup违例：WNS > 0, TNS = 0
  • Hold违例：WNS > 0, TNS = 0
  • Transition违例：无违例
  • Capacitance违例：无违例

📊 签收报告内容

必需的报告

#!/bin/tcl # ============================================================================ # 时序签收报告生成 # ============================================================================ file mkdir signoff_reports # 1. Setup时序报告 # ============================================ report_timing -max_paths 100 -delay_type max \ -input_pins -nets -transition_time -capacitance \ > signoff_reports/setup_100paths.rpt report_timing -slack_lesser_than 0.1 -delay_type max \ > signoff_reports/setup_violations.rpt # 2. Hold时序报告 # ============================================ report_timing -max_paths 100 -delay_type min \ -input_pins -nets -transition_time -capacitance \ > signoff_reports/hold_100paths.rpt report_timing -slack_lesser_than 0.1 -delay_type min \ > signoff_reports/hold_violations.rpt # 3. 时序摘要 # ============================================ report_timing_summary > signoff_reports/timing_summary.rpt # 4. 时钟报告 # ============================================ report_clock -attributes > signoff_reports/clocks.rpt report_clock_interaction > signoff_reports/clock_interaction.rpt # 5. 约束报告 # ============================================ report_constraint -all_violators > signoff_reports/constraint_violations.rpt report_exceptions > signoff_reports/exceptions.rpt # 6. 设计规则报告 # ============================================ check_design > signoff_reports/design_check.rpt check_timing -verbose > signoff_reports/timing_check.rpt # 7. 单元使用报告 # ============================================ report_cell > signoff_reports/cell_usage.rpt report_reference > signoff_reports/reference.rpt # 8. OCV报告（如果适用） # ============================================ report_timing_derate > signoff_reports/derating.rpt

⚠️ 签收常见问题

问题 原因 解决方法
Setup负Slack 时序不满足 优化设计或调整约束
Hold负Slack 时钟偏斜过大 优化时钟树或插入延迟
未约束路径 约束不完整 补充缺失的约束
跨角违例 OCV考虑不足 增加OCV分析
⚠️
签收注意事项

1）签收必须在网表级进行，不能只做RTL级验证； 2）必须包含所有工艺角和工作模式；3）OCV分析是签收的必需项； 4）签收报告需要详细存档；5）任何违例都必须在流片前解决。

📝 本节小结

✅
  • • 时序签收是流片前的关键步骤
  • • 所有时序指标必须满足标准
  • • 需要生成完整的签收报告
  • • 多角多模分析是必需的
