42.1 模块概念

理解 NestJS 模块化设计的核心

🎯 学习目标

  • 理解模块的作用和意义
  • 掌握模块的基本结构
  • 了解模块的元数据属性
  • 理解模块与依赖注入的关系

📚 什么是模块？

模块是 NestJS 中组织代码的基本单元。每个 NestJS 应用至少有一个模块（根模块），随着应用增长，可以创建多个功能模块来组织相关功能。

// 基本模块结构 import { Module } from '@nestjs/common'; import { UsersController } from './users.controller'; import { UsersService } from './users.service'; @Module({ controllers: [UsersController], // 控制器 providers: [UsersService], // 提供者（服务） imports: [], // 导入其他模块 exports: [], // 导出给其他模块使用 }) export class UsersModule {}
💡
模块的作用

模块通过 @Module() 装饰器定义，将相关的控制器、服务、管道等组织在一起，形成独立的功能单元。

🔧 模块元数据属性

属性 说明
controllers 声明本模块的控制器，处理请求
providers 声明本模块的服务，可被注入
imports 导入其他模块，使用其导出的服务
exports 导出服务，供其他模块使用

🔄 模块与依赖注入

// users.module.ts @Module({ controllers: [UsersController], providers: [UsersService], exports: [UsersService], // 导出服务供其他模块使用 }) export class UsersModule {} // auth.module.ts @Module({ imports: [UsersModule], // 导入 UsersModule，可以使用其导出的服务 controllers: [AuthController], providers: [AuthService], }) export class AuthModule {} // auth.service.ts @Injectable() export class AuthService { constructor( private usersService: UsersService, // 注入 UsersService ) {} }
⚠️
重要提示

只有在 exports 中声明的服务才能被其他模块使用。imports 只能使用其他模块 exports 出来的服务。

📝 本节小结

✅
  • • 模块是 NestJS 组织代码的基本单元
  • • @Module() 装饰器定义模块元数据
  • • controllers 声明控制器，providers 声明服务
  • • exports 导出服务供其他模块使用
