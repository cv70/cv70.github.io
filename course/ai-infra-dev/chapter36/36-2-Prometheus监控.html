Prometheus架构

Prometheus是一个开源的监控告警系统，采用Pull模式采集时序数据。

🏗️ 核心组件

📡

Prometheus Server

核心服务，负责采集、存储、查询

🔌

Exporters

指标暴露器，采集各类服务指标

📊

Grafana

可视化面板，展示监控数据

📊 常用Exporters

Exporter 用途 端口 适用场景
Node Exporter 系统级指标 9100 CPU、内存、磁盘、网络
NVIDIA DCGM Exporter GPU指标 9400 GPU利用率、显存、温度
cAdvisor 容器指标 8080 Kubernetes容器监控
Blackbox Exporter 探测服务 9115 HTTP/HTTPS/TCP探测
Process Exporter 进程级指标 9256 特定进程监控
Slurm Exporter Slurm集群 9264 HPC作业调度监控

🔍 PromQL查询语言

💡
常用查询示例

PromQL是Prometheus的查询语言，功能强大：

# 查询GPU利用率 nvidia_gpu_utilization_gpu # 查询平均GPU利用率 avg(nvidia_gpu_utilization_gpu) # 按节点聚合GPU利用率 avg by (hostname) (nvidia_gpu_utilization_gpu) # 计算GPU显存使用率 nvidia_gpu_memory_used_bytes / nvidia_gpu_memory_total_bytes * 100 # 查询过去5分钟的速率 rate(nvidia_gpu_utilization_gpu[5m]) # 计算p99延迟 histogram_quantile(0.99, rate(request_duration_seconds_bucket[5m]) ) # 条件查询 node_memory_MemAvailable_bytes / node_memory_MemTotal_bytes * 100 < 10 # 多指标组合 up{job="training"} == 0

📋 Prometheus配置示例

# prometheus.yml global: scrape_interval: 15s evaluation_interval: 15s external_labels: cluster: 'ai-training' environment: 'production' # 告警规则文件 rule_files: - '/etc/prometheus/rules/*.yml' # 服务发现配置 scrape_configs: # GPU监控 - job_name: 'dcgm-exporter' static_configs: - targets: - 'gpu-node-01:9400' - 'gpu-node-02:9400' labels: cluster: 'gpu-cluster' # Kubernetes服务发现 - job_name: 'kubernetes-pods' kubernetes_sd_configs: - role: pod relabel_configs: - source_labels: [__meta_kubernetes_pod_annotation_prometheus_io_scrape] action: keep regex: true - source_labels: [__meta_kubernetes_pod_annotation_prometheus_io_path] action: replace target_label: __metrics_path__ regex: (.+) # Slurm监控 - job_name: 'slurm-exporter' static_configs: - targets: ['slurm-head:9264']

⚠️ 告警规则配置

# alerts.yml groups: - name: gpu_alerts interval: 30s rules: # GPU高利用率告警 - alert: HighGPUUtilization expr: nvidia_gpu_utilization_gpu > 90 for: 5m labels: severity: warning component: gpu annotations: summary: "GPU {{ $labels.gpu }} 高利用率" description: "GPU {{ $labels.gpu }} 在节点 {{ $labels.hostname }} 利用率超过90%" # GPU温度告警 - alert: HighGPUTemperature expr: nvidia_gpu_temperature_gpu > 85 for: 3m labels: severity: critical component: gpu annotations: summary: "GPU温度过高" description: "GPU {{ $labels.gpu }} 温度达到 {{ $value }}°C" # 训练任务异常 - alert: TrainingJobFailed expr: training_job_status == 0 for: 1m labels: severity: critical component: training annotations: summary: "训练任务失败" description: "任务 {{ $labels.job_id }} 训练失败" - name: system_alerts rules: # 磁盘空间告警 - alert: DiskSpaceLow expr: node_filesystem_avail_bytes / node_filesystem_size_bytes < 0.1 for: 5m labels: severity: warning annotations: summary: "磁盘空间不足" description: "挂载点 {{ $labels.mountpoint }} 空间不足10%"

🎯 Recording Rules

💡
预计算规则

Recording Rules可以预计算常用查询，提升查询性能：

# recording.yml groups: - name: gpu_recording interval: 30s rules: # GPU显存使用率 - record: job:gpu_memory_usage:percent expr: nvidia_gpu_memory_used_bytes / nvidia_gpu_memory_total_bytes * 100 # 集群GPU平均利用率 - record: cluster:gpu_utilization:avg expr: avg(nvidia_gpu_utilization_gpu) # 集群GPU总数 - record: cluster:gpu:total expr: count(nvidia_gpu_utilization_gpu) # 训练吞吐量 - record: job:training:throughput expr: sum(rate(training_samples_total[5m])) by (job_id)

⚠️
性能优化建议
  • • 设置合理的数据保留时间，避免存储爆炸
  • • 使用Recording Rules预计算常用查询
  • • 对高基数标签进行合理降采样
  • • 使用联邦部署实现多集群监控
  • • 定期清理无用的指标和告警规则
