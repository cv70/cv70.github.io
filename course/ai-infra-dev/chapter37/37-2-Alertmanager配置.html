Alertmanager架构

Alertmanager是Prometheus的告警管理组件，负责告警去重、分组、路由和通知。

🏗️ Alertmanager核心功能

🔀

去重

合并相同的告警

📦

分组

按规则聚合告警

🔀

路由

分发到不同接收器

🔇

抑制

控制告警传播

🔔

静默

暂时屏蔽告警

📧

通知

发送到多种渠道

🐳 基础部署配置

# docker-compose.yml version: '3' services: alertmanager: image: prom/alertmanager:latest container_name: alertmanager ports: - "9093:9093" volumes: - ./alertmanager.yml:/etc/alertmanager/alertmanager.yml - alertmanager_data:/alertmanager command: - '--config.file=/etc/alertmanager/alertmanager.yml' - '--storage.path=/alertmanager' - '--web.external-url=http://localhost:9093' prometheus: image: prom/prometheus:latest container_name: prometheus ports: - "9090:9090" volumes: - ./prometheus.yml:/etc/prometheus/prometheus.yml - ./alerts:/etc/prometheus/rules command: - '--config.file=/etc/prometheus/prometheus.yml' - '--alertmanager.url=http://alertmanager:9093' volumes: alertmanager_data:

⚙️ Alertmanager配置文件

# alertmanager.yml global: # 全局解析超时 resolve_timeout: 5m # SMTP邮件配置 smtp_smarthost: 'smtp.example.com:587' smtp_from: 'alerts@example.com' smtp_auth_username: 'alerts@example.com' smtp_auth_password: 'password' # 默认通知模板 templates: - '/etc/alertmanager/templates/*.tmpl' # 路由配置 route: # 默认接收器 receiver: 'default' # 分组等待时间 group_wait: 10s # 分组间隔 group_interval: 10s # 重复通知间隔 repeat_interval: 12h # 子路由 routes: # P0级别告警 - 电话告警 - match: severity: P0 receiver: 'oncall' group_wait: 0s # P1级别告警 - 短信告警 - match: severity: P1 receiver: 'sms-team' # GPU告警 - 基础设施团队 - match: component: gpu receiver: 'infra-team' group_by: ['alertname', 'hostname'] # 训练告警 - ML平台团队 - match: component: training receiver: 'ml-platform-team' # 推理告警 - 推理团队 - match: component: inference receiver: 'inference-team' # 接收器配置 receivers: # 默认接收器 - name: 'default' email_configs: - to: 'default@example.com' headers: Subject: '{{ .GroupLabels.alertname }}' # 值班告警 - name: 'oncall' webhook_configs: - url: 'http://oncall.example.com/api/alert' send_resolved: true # 短信告警 - name: 'sms-team' webhook_configs: - url: 'http://sms.example.com/send' send_resolved: true # 邮件告警 - 基础设施团队 - name: 'infra-team' email_configs: - to: 'infra@example.com' headers: Subject: '[告警] {{ .GroupLabels.alertname }}' # 邮件告警 - ML平台团队 - name: 'ml-platform-team' email_configs: - to: 'ml-platform@example.com' headers: Subject: '[告警] {{ .GroupLabels.alertname }}' # 邮件告警 - 推理团队 - name: 'inference-team' email_configs: - to: 'inference@example.com' headers: Subject: '[告警] {{ .GroupLabels.alertname }}'

🔇 抑制规则配置

# 抑制相同告警的重复通知 inhibit_rules: # 如果存在严重告警，抑制同一资源的警告告警 - source_match: severity: 'P0' target_match: severity: 'P1' equal: ['alertname', 'instance'] # 如果节点宕机，抑制该节点上所有服务的告警 - source_match: alertname: 'InstanceDown' target_match_re: alertname: '.*' equal: ['instance'] # 如果服务告警，抑制该服务的子组件告警 - source_match: alertname: 'ServiceDown' target_match_re: alertname: 'ServiceComponentDown' equal: ['service'] # 如果集群告警，抑制集群内节点的告警 - source_match: alertname: 'ClusterDown' target_match_re: alertname: 'NodeDown' equal: ['cluster']

🔇 静默配置

💡
静默使用场景

静默可以暂时屏蔽特定的告警，常用于：

  • 维护窗口 - 计划维护期间
  • 已知问题 - 暂时无法修复的问题
  • 误报处理 - 待修复的误报
  • 测试环境 - 测试期间的告警
# 通过API创建静默 curl -X POST \ http://alertmanager:9093/api/v2/silences \ -H 'Content-Type: application/json' \ -d '{ "matchers": [ { "name": "job", "value": "training", "isRegex": false } ], "startsAt": "2024-01-15T00:00:00Z", "endsAt": "2024-01-15T06:00:00Z", "createdBy": "admin", "comment": "训练服务维护" }' # 或通过Web UI创建 # 访问 http://alertmanager:9093/#/silences
