26.3 资源管理与调度

Kubernetes资源模型与调度机制

🎯 学习目标

  • 理解Kubernetes资源请求和限制机制
  • 掌握调度器的调度流程与策略
  • 学会配置资源配额和限制范围
  • 了解节点亲和性与污点容忍

💾 资源模型

请求与限制

Kubernetes通过Requests（请求）和Limits（限制）来管理Pod的资源使用。

Requests（请求）

Pod运行需要的最小资源量，用于调度决策。

📌

调度器确保节点有足够资源满足Pod的Requests

Limits（限制）

Pod能使用的最大资源量，防止资源耗尽。

⚠️

超出Limit会被限流或终止

⚙️ 资源配置示例

apiVersion: v1 kind: Pod metadata: name: resource-pod spec: containers: - name: main-container image: nginx resources: requests: cpu: "500m" # 0.5 CPU核心 memory: "512Mi" # 512MB内存 limits: cpu: "1" # 1 CPU核心 memory: "1Gi" # 1GB内存 - name: sidecar-container image: busybox resources: requests: cpu: "100m" memory: "64Mi" limits: cpu: "200m" memory: "128Mi"
💡
单位说明
  • • CPU：1 = 1个虚拟CPU核心，500m = 0.5个核心
  • • 内存：Mi = 兆字节，Gi = 吉字节

📊 QoS等级

根据资源配置，Pod被分配不同的QoS（服务质量）等级：

QoS等级 配置 特点
Guaranteed Requests == Limits（所有容器） 最高优先级，保证资源可用
Burstable Requests < Limits（至少一个容器） 中等优先级，可突发使用
BestEffort 未设置Requests和Limits 最低优先级，可能被驱逐

🎯 调度流程

图：Kubernetes调度器工作流程

阶段1：预选（Filter）

过滤掉不符合条件的节点

  • 资源是否足够
  • 节点是否就绪
  • 端口是否冲突
  • 是否存在污点
  • 是否匹配节点选择器

阶段2：优选（Score）

对符合条件的节点打分排序

  • 资源利用率
  • 镜像是否已存在
  • 节点亲和性得分
  • 跨可用区分布
  • Pod分布均衡性

🔗 节点亲和性与反亲和性

apiVersion: v1 kind: Pod metadata: name: affinity-pod spec: affinity: # 节点亲和性：将Pod调度到特定节点 nodeAffinity: requiredDuringSchedulingIgnoredDuringExecution: nodeSelectorTerms: - matchExpressions: - key: node-role.kubernetes.io/master operator: DoesNotExist preferredDuringSchedulingIgnoredDuringExecution: - weight: 100 preference: matchExpressions: - key: disktype operator: In values: - ssd # Pod反亲和性：避免调度到同一节点 podAntiAffinity: requiredDuringSchedulingIgnoredDuringExecution: - labelSelector: matchExpressions: - key: app operator: In values: - web topologyKey: kubernetes.io/hostname containers: - name: nginx image: nginx
💡
拓扑域

topologyKey定义了亲和性的作用域，如kubernetes.io/hostname表示节点级别，topology.kubernetes.io/zone表示可用区级别。

🚫 污点与容忍

污点（Taint）

污点标记节点，排斥不匹配的Pod。

# 给节点添加污点 kubectl taint nodes node1 key=value:NoSchedule kubectl taint nodes node1 key=value:PreferNoSchedule kubectl taint nodes node1 key=value:NoExecute # 污点类型： # NoSchedule: 除非有容忍，否则不调度 # PreferNoSchedule: 尽量不调度，但不是强制的 # NoExecute: 立即驱逐没有匹配容忍的Pod

容忍（Toleration）

容忍允许Pod调度到有污点的节点。

apiVersion: v1 kind: Pod metadata: name: toleration-pod spec: tolerations: - key: "key" operator: "Equal" value: "value" effect: "NoSchedule" # 或者 - key: "key" operator: "Exists" effect: "NoExecute" tolerationSeconds: 300 # 容忍300秒后驱逐 containers: - name: nginx image: nginx

📏 资源配额与限制范围

# ResourceQuota: 命名空间级别的资源限制 apiVersion: v1 kind: ResourceQuota metadata: name: compute-quota namespace: dev spec: hard: requests.cpu: "10" requests.memory: "20Gi" limits.cpu: "20" limits.memory: "40Gi" persistentvolumeclaims: "5" --- # LimitRange: Pod/容器的默认资源限制 apiVersion: v1 kind: LimitRange metadata: name: limits namespace: dev spec: limits: - default: # 默认Limits cpu: "1" memory: "512Mi" defaultRequest: # 默认Requests cpu: "0.5" memory: "256Mi" type: Container
✅
调度优化建议
  • • 总是设置Requests和Limits
  • • 关键服务使用Guaranteed QoS
  • • 使用节点亲和性优化资源利用率
  • • 合理配置Pod反亲和性提高可用性
  • • 使用污点保护关键节点
