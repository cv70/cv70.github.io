86.2 Git Flow

经典的 Git 分支管理模型

🎯 学习目标

  • 理解 Git Flow 工作流模型
  • 掌握各分支的作用和关系
  • 学会使用 git-flow 工具
  • 了解适用场景和优缺点

📚 Git Flow 概述

Git Flow 是由 Vincent Driessen 提出的一种 Git 分支管理策略，适用于有计划发布周期的项目。

main (生产环境) │ ──────────────────┼────────────────── │ hotfix ──────┼────── merge ─────→ main │ │ │ └─────────┼────────────────────┘ │ ──────────────────┼────────────────── │ develop (开发分支) │ ──────────────────┼────────────────── │ feature/a ────────┼─────── merge ────→ develop │ feature/b ────────┼─────── merge ────→ develop │ ──────────────────┼────────────────── │ release ─┬──── merge ─────→ main │ │ └──────────────────┘ # 分支说明 - main: 生产环境，始终稳定 - develop: 开发集成分支 - feature: 功能开发分支 - release: 发布准备分支 - hotfix: 紧急修复分支

🔧 Git Flow 工具

# 安装 git-flow # macOS brew install git-flow # Ubuntu sudo apt-get install git-flow # Windows (Git for Windows 已内置) # 初始化 git-flow git flow init # 会提示配置各分支名称 Which branch should be used for bringing forth production releases? Branch name for production releases: [main] Which branch should be used for integration of the "next release"? Branch name for "next release" development: [develop] How to name your supporting branch prefixes? Feature branches? [feature/] Release branches? [release/] Hotfix branches? [hotfix/] Support branches? [support/] Version tag prefix? []

⚙️ 功能开发流程

# 开始新功能 git flow feature start user-authentication # 等同于 git checkout -b feature/user-authentication develop # 开发过程中提交 git add . git commit -m "feat: 添加用户认证基础结构" # 完成功能开发 git flow feature finish user-authentication # 等同于 git checkout develop git merge --no-ff feature/user-authentication git branch -d feature/user-authentication # 推送到远程（团队协作） git flow feature publish user-authentication # 等同于 git push origin feature/user-authentication # 拉取远程功能分支 git flow feature pull user-authentication
💡
--no-ff 参数

使用 --no-ff 参数可以保留分支历史，创建一个合并提交，便于追溯功能的完整开发历史。

🚀 发布流程

# 开始发布 git flow release start v1.2.0 # 等同于 git checkout -b release/v1.2.0 develop # 发布准备（修复 bug、更新版本号等） # 修改 package.json 版本号 npm version 1.2.0 --no-git-tag-version git commit -am "chore: 更新版本号到 1.2.0" # 完成发布 git flow release finish v1.2.0 # 等同于 git checkout main git merge --no-ff release/v1.2.0 git tag -a v1.2.0 git checkout develop git merge --no-ff release/v1.2.0 git branch -d release/v1.2.0 # 推送发布 git push origin main git push origin develop git push origin v1.2.0

⚠️ 热修复流程

# 开始热修复 git flow hotfix start v1.2.1 # 等同于 git checkout -b hotfix/v1.2.1 main # 修复紧急问题 git commit -am "fix: 修复登录验证漏洞" # 完成热修复 git flow hotfix finish v1.2.1 # 等同于 git checkout main git merge --no-ff hotfix/v1.2.1 git tag -a v1.2.1 git checkout develop git merge --no-ff hotfix/v1.2.1 git branch -d hotfix/v1.2.1 # 推送所有变更 git push origin --all git push origin --tags

📝 本节小结

✅
  • • Git Flow 适合有计划发布周期的项目
  • • 使用 git-flow 工具可以简化操作
  • • 功能分支从 develop 创建，合并回 develop
  • • release 和 hotfix 需要合并到 main 和 develop
