16.3 模型并行原理

突破显存限制，训练超大模型

🎯 学习目标

  • 理解模型并行的核心思想
  • 掌握张量并行的实现原理
  • 了解流水线并行的机制
  • 认识模型并行的适用场景

什么是模型并行？

模型并行（Model Parallelism）是指将模型的不同部分分配到不同的GPU上。 当模型参数量超过单个GPU显存容量时，模型并行是必要的解决方案。 与数据并行不同，模型并行中每个GPU只存储模型的一部分。

🔢 模型并行的两种类型

张量并行

将单个张量（如权重矩阵）切分到多个GPU

  • 按矩阵维度切分
  • 层内并行
  • 通信密集
  • Megatron-LM实现

流水线并行

将模型的不同层分配到不同GPU

  • 按层分配
  • 层间并行
  • 通信较少
  • GPipe实现

🧮 张量并行详解

矩阵乘法的并行化

以Transformer中的自注意力层为例，说明张量并行的实现。

标准矩阵乘法：Y = X × W 张量并行切分策略： 1. 按列切分权重 W（Column Parallel） W = [W₁ | W₂ | ... | Wₙ] 每个GPU计算：Yᵢ = X × Wᵢ 最后拼接：Y = [Y₁ | Y₂ | ... | Yₙ] 2. 按行切分权重 W（Row Parallel） W = [W₁; W₂; ...; Wₙ] 每个GPU计算：Yᵢ = X × Wᵢ 最后求和：Y = ΣYᵢ Transformer并行策略： • QKV投影：列并行 • Attention输出：行并行 • MLP：列+行并行

📊 张量并行示例

2-GPU张量并行

假设有2个GPU（GPU0和GPU1），权重矩阵 W ∈ ℝ^(4096×4096) 列并行切分： ┌─────────────────────────────────┐ │ W (4096×4096) │ ├───────────────┬───────────────┤ │ W₀ (4096×2048)│ W₁ (4096×2048)│ │ GPU0 │ GPU1 │ └───────────────┴───────────────┘ 计算过程： GPU0: Y₀ = X × W₀ GPU1: Y₁ = X × W₁ AllConcat: Y = concat(Y₀, Y₁) 行并行切分： ┌───────────────────┐ │ W₀ (2048×4096) │ GPU0 ├───────────────────┤ │ W₁ (2048×4096) │ GPU1 └───────────────────┘ 计算过程： GPU0: Y₀ = X × W₀ GPU1: Y₁ = X × W₁ AllReduce: Y = Y₀ + Y₁
图：张量并行需要在多个GPU间频繁通信

🚀 流水线并行详解

流水线并行机制

将模型的层分配到不同GPU，形成流水线。每个GPU处理模型的一部分，数据像流水线一样在各GPU间流动。

4层模型，4个GPU的流水线并行： GPU0: Layer 0 → Layer 1 → Layer 2 → Layer 3 ↓ ↓ ↓ ↓ GPU1: Layer 1 → Layer 2 → Layer 3 ↓ ↓ ↓ GPU2: Layer 2 → Layer 3 ↓ ↓ GPU3: Layer 3 ↓ 优势： • 每个GPU只需存储部分层，节省显存 • 通信较少（只在层间传递激活值） • 可以增大batch size 挑战： • 流水线气泡（Bubble）问题 • 需要精心设计微批次（Micro-batch）调度

📈 流水线调度策略

GPipe（朴素流水线）

  • 微批次按顺序处理
  • 存在流水线气泡
  • 实现简单
微批次 m1, m2, m3, m4: 时间 → t1: GPU0(m1) - - - t2: GPU0(m2) GPU1(m1)- - t3: GPU0(m3) GPU1(m2)-GPU2(m1)- t4: GPU0(m4) GPU1(m3)-GPU2(m2)-GPU3(m1) t5: - GPU1(m4)-GPU2(m3)-GPU3(m2) t6: - - -GPU2(m4)-GPU3(m3) t7: - - - -GPU3(m4) 气泡率 = (p-1)/m p=流水线阶段数, m=微批次数

1F1B（交错流水线）

  • 填充和排水阶段交错
  • 减少流水线气泡
  • 更复杂的调度
1F1B调度策略： 填充阶段（Forward）： t1: GPU0(F1) t2: GPU0(F2), GPU1(F1) t3: GPU0(F3), GPU1(F2), GPU2(F1) t4: GPU0(F4), GPU1(F3), GPU2(F2), GPU3(F1) 稳态阶段（1 Forward, 1 Backward）： t5: GPU0(B1), GPU1(F4), GPU2(F3), GPU3(F2) t6: GPU0(B2), GPU1(B1), GPU2(F4), GPU3(F3) ... 排水阶段（Backward）：

⚙️ 张量并行 vs 流水线并行

维度 张量并行 流水线并行
切分方式 按张量维度切分 按模型层切分
并行粒度 层内并行 层间并行
通信开销 高（每次前向/反向都需要通信） 低（只在层间传递激活）
适用规模 适合小规模并行（≤8卡） 适合大规模并行（可扩展到千卡）
显存节省 按并行度线性减少 按流水线阶段数减少
⚠️
模型并行的挑战
  • 通信开销：张量并行通信频繁，需要高速网络
  • 实现复杂：需要手动划分模型，代码改动大
  • 调试困难：分布式系统调试复杂度高
  • 负载均衡：确保各GPU工作量均衡
  • 框架支持：需要使用专门的框架如Megatron-LM

🔧 模型并行实践框架

主流框架选择

框架 支持的并行策略 特点
Megatron-LM 张量并行、流水线并行 NVIDIA出品，高性能
DeepSpeed 流水线并行、ZeRO Microsoft出品，易用性好
Colossal-AI 多种并行策略 支持序列并行等新特性
Alpa 自动并行 自动优化并行策略

💡 实用建议

💡
  • 优先使用数据并行：除非模型太大，否则数据并行更简单高效
  • 小规模用张量并行：≤8卡时，张量并行性能更好
  • 大规模用流水线并行：≥16卡时，考虑流水线并行
  • 混合使用：实际场景常结合张量并行+流水线并行
  • 使用成熟框架：推荐Megatron-LM或DeepSpeed

📝 本节小结

✅
  • • 模型并行将模型切分到多个GPU，突破显存限制
  • • 张量并行：按张量维度切分，层内并行，通信密集
  • • 流水线并行：按模型层切分，层间并行，通信较少
  • • 实际应用常结合使用多种并行策略
  • • 推荐使用Megatron-LM或DeepSpeed等成熟框架
