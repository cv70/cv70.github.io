30.3 告警机制

构建及时有效的AI应用告警体系

🎯 学习目标

  • 理解告警设计原则和告警分级
  • 掌握Prometheus告警规则配置
  • 学会使用Alertmanager管理告警
  • 了解AI场景的特殊告警需求

为什么需要告警机制？

告警机制是保障系统稳定性的重要防线。通过及时发现问题、快速响应处理，可以最小化故障影响。对于AI应用，告警不仅关注系统可用性，还需要关注模型性能和数据质量。

📊 告警级别定义

级别 严重程度 响应时间 示例
P0 - 紧急 服务不可用 立即响应 推理服务宕机、GPU故障
P1 - 严重 核心功能受损 15分钟内 推理延迟超阈值、错误率上升
P2 - 警告 性能下降 1小时内 GPU内存不足、QPS下降
P3 - 提示 需要关注 24小时内 模型准确率轻微下降

⚡ Prometheus告警规则

# alert_rules.yml
groups:
  - name: ai_service_alerts
    interval: 30s
    rules:
      # P0: 服务不可用告警
      - alert: AIServiceDown
        expr: up{job="ai-inference"} == 0
        for: 1m
        labels:
          severity: critical
          priority: P0
        annotations:
          summary: "AI推理服务不可用"
          description: "服务 {{ $labels.instance }} 已宕机超过1分钟"

      # P1: 推理延迟告警
      - alert: HighInferenceLatency
        expr: |
          histogram_quantile(0.99,
            rate(ai_inference_latency_seconds_bucket[5m])
          ) > 2
        for: 5m
        labels:
          severity: warning
          priority: P1
        annotations:
          summary: "推理延迟过高"
          description: "P99延迟 {{ $value | humanizeDuration }}"

      # P2: GPU内存告警
      - alert: GPUMemoryHigh
        expr: |
          (nvidia_gpu_memory_used_bytes / nvidia_gpu_memory_total_bytes) > 0.9
        for: 5m
        labels:
          severity: warning
          priority: P2
        annotations:
          summary: "GPU内存使用率过高"
          description: "GPU {{ $labels.gpu }} 内存使用率 {{ $value | humanizePercentage }}"

      # AI特殊告警: 模型准确率下降
      - alert: ModelAccuracyDrop
        expr: |
          ai_model_accuracy < 0.85
        for: 30m
        labels:
          severity: warning
          priority: P2
        annotations:
          summary: "模型准确率下降"
          description: "模型 {{ $labels.model_name }} 准确率降至 {{ $value }}"

🔔 Alertmanager配置

# alertmanager.yml
global:
  resolve_timeout: 5m
  slack_api_url: 'https://hooks.slack.com/services/xxx'

route:
  group_by: ['alertname', 'priority']
  group_wait: 30s
  group_interval: 5m
  repeat_interval: 4h
  receiver: 'default'
  routes:
    # P0告警立即通知
    - match:
        priority: P0
      receiver: 'critical'
      continue: false
    # P1告警工作时间通知
    - match:
        priority: P1
      receiver: 'high'
      active_time_intervals:
        - 'business_hours'

receivers:
  - name: 'default'
    slack_configs:
      - channel: '#ai-alerts'
        send_resolved: true

  - name: 'critical'
    slack_configs:
      - channel: '#ai-critical'
    pagerduty_configs:
      - service_key: 'xxx'
    webhook_configs:
      - url: 'http://oncall-service/alert'

  - name: 'high'
    slack_configs:
      - channel: '#ai-alerts'

time_intervals:
  - name: 'business_hours'
    time_intervals:
      - times:
          - start_time: '09:00'
            end_time: '18:00'
        weekdays: ['monday:friday']

🤖 AI场景特殊告警

模型性能告警

  • 准确率/召回率下降
  • 预测分布漂移
  • 置信度异常分布
  • 模型版本不匹配

数据质量告警

  • 输入数据缺失率
  • 特征分布变化
  • 异常数据比例
  • 数据延迟/延迟
⚠️
告警疲劳

避免设置过多无效告警导致告警疲劳。建议：1) 合理设置阈值和持续时间 2) 定期审查告警规则 3) 区分真实问题和噪声 4) 实现告警静默机制

📝 本节小结

✅
  • • 告警按严重程度分为P0-P3四级，对应不同响应时间
  • • Prometheus AlertRules定义告警条件，Alertmanager管理通知
  • • AI场景需额外关注模型性能和数据质量告警
  • • 避免告警疲劳，合理设置阈值和告警静默
