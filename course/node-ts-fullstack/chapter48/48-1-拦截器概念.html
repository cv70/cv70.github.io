48.1 拦截器概念

理解 NestJS 拦截器的作用和原理

🎯 学习目标

  • 理解拦截器的概念和作用
  • 掌握拦截器的执行时机
  • 了解拦截器与其他组件的区别
  • 理解拦截器的应用场景

📚 什么是拦截器？

拦截器是用 @Injectable() 装饰器注解的类，实现 NestInterceptor 接口。拦截器可以在方法执行前后添加额外逻辑，支持修改返回结果。

请求处理流程： 客户端请求 ↓ ┌─────────────────┐ │ 中间件 │ └─────────────────┘ ↓ ┌─────────────────┐ │ 守卫 │ └─────────────────┘ ↓ ┌─────────────────┐ │ 拦截器(前) │ ← 方法执行前 └─────────────────┘ ↓ ┌─────────────────┐ │ 管道 │ └─────────────────┘ ↓ ┌─────────────────┐ │ 路由处理器 │ └─────────────────┘ ↓ ┌─────────────────┐ │ 拦截器(后) │ ← 方法执行后，可修改响应 └─────────────────┘ ↓ 响应客户端
💡
拦截器特点

拦截器使用 RxJS Observable，可以拦截请求和响应。支持：响应转换、日志记录、缓存、异常映射、超时处理等。

🔧 拦截器接口

import { Injectable, NestInterceptor, ExecutionContext, CallHandler } from '@nestjs/common'; import { Observable } from 'rxjs'; import { tap, map } from 'rxjs/operators'; @Injectable() export class LoggingInterceptor implements NestInterceptor { intercept(context: ExecutionContext, next: CallHandler): Observable { console.log('Before...'); // 方法执行前 const now = Date.now(); return next .handle() .pipe( tap(() => console.log(`After... ${Date.now() - now}ms`)), // 方法执行后 ); } } // next.handle() 返回 Observable // tap() 可以观察但不修改值 // map() 可以修改返回值

🔄 拦截器 vs 其他组件

组件 执行时机 主要能力
中间件 最早 请求预处理
守卫 中间件后 权限验证
拦截器 方法前后 响应转换、日志
管道 方法参数 数据验证转换
过滤器 异常时 异常处理

✨ 拦截器应用场景

  • 响应数据格式化
  • 请求/响应日志记录
  • 响应缓存
  • 超时处理
  • 异常映射
  • 性能监控
⚠️
RxJS 要求

拦截器使用 RxJS Observable，需要熟悉 RxJS 操作符如 map, tap, catchError, timeout 等。

📝 本节小结

✅
  • • 拦截器在方法执行前后运行
  • • 实现 NestInterceptor 接口
  • • 使用 RxJS Observable 处理响应
  • • 常用于响应转换、日志、缓存等
