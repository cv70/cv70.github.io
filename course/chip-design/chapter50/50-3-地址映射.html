📍 地址空间概述

💡
地址空间的定义

物理地址空间：处理器可以直接访问的硬件地址范围，由处理器的地址总线宽度决定。32位处理器为4GB（2^32），64位处理器为更大空间（实际使用通常小于2^64）。

虚拟地址空间：操作系统和应用程序看到的逻辑地址空间，通过MMU（内存管理单元）映射到物理地址空间。

地址空间容量示例

地址位宽 地址空间大小 典型应用
32位 4 GB 嵌入式系统、Cortex-M系列
36位 64 GB 部分ARM Cortex-A系列
40位 1 TB 中高端SoC
48位 256 TB 高性能SoC
64位 16 EB 服务器级处理器

🗺️ 地址映射原理

地址映射是将总线地址（或物理地址）映射到具体存储设备或外设寄存器地址的过程。通过地址译码器实现。

// 地址译码器示例（简化版）
module address_decoder (
    input  [31:0] addr,       // 总线地址
    input        wr_en,       // 写使能
    input        rd_en,       // 读使能
    output reg   sram_cs,     // SRAM片选
    output reg   flash_cs,    // Flash片选
    output reg   uart_cs,     // UART片选
    output reg   gpio_cs      // GPIO片选
);

// 地址空间定义
parameter SRAM_BASE  = 32'h0000_0000;
parameter SRAM_SIZE  = 32'h0010_0000;  // 1MB

parameter FLASH_BASE = 32'h0800_0000;
parameter FLASH_SIZE = 32'h0080_0000;  // 8MB

parameter UART_BASE  = 32'h4000_0000;
parameter UART_SIZE  = 32'h0000_1000;  // 4KB

parameter GPIO_BASE  = 32'h4001_0000;
parameter GPIO_SIZE  = 32'h0000_1000;  // 4KB

always @(*) begin
    sram_cs  = 0;
    flash_cs = 0;
    uart_cs  = 0;
    gpio_cs  = 0;

    if (addr >= SRAM_BASE && addr < SRAM_BASE + SRAM_SIZE)
        sram_cs = 1;
    else if (addr >= FLASH_BASE && addr < FLASH_BASE + FLASH_SIZE)
        flash_cs = 1;
    else if (addr >= UART_BASE && addr < UART_BASE + UART_SIZE)
        uart_cs = 1;
    else if (addr >= GPIO_BASE && addr < GPIO_BASE + GPIO_SIZE)
        gpio_cs = 1;
end

endmodule

🛡️ 内存保护机制

MPU（Memory Protection Unit）

MPU功能

  • 定义内存区域的访问权限
  • 支持特权级和用户级访问
  • 可配置的内存区域
  • 违规时触发异常

访问属性

  • Read/Write/Execute权限
  • Cacheable/Non-cacheable
  • Bufferable/Non-bufferable
  • Shareable/Non-shareable

MPU配置示例

// MPU区域配置示例
// Region 0: Flash (Execute-only)
MPU_RNR  = 0;
MPU_RBAR = 0x0800_0000;  // 基地址
MPU_RASR = (0x1F << 1) |  // Region size: 2^31
           (0x1 << 28) |  // XN=0 (可执行)
           (0x0 << 24) |  // AP=0 (只读，特权级)
           (0x1 << 16);   // Enable region

// Region 1: SRAM (Read/Write, Cacheable)
MPU_RNR  = 1;
MPU_RBAR = 0x2000_0000;  // 基地址
MPU_RASR = (0x1E << 1) |  // Region size: 2^30
           (0x1 << 28) |  // XN=1 (不可执行)
           (0x3 << 24) |  // AP=3 (读写，全访问)
           (0x1 << 2) |   // B=1 (Bufferable)
           (0x1 << 0);    // C=1 (Cacheable)

🔄 地址重映射

地址重映射允许在运行时改变地址空间的映射关系，常用于启动时从Boot ROM切换到外部Flash。

// 地址重映射控制器（简化）
module address_remapper (
    input  [31:0] addr_in,
    input        remap_enable,
    output [31:0] addr_out
);

// 0x0000_0000: Boot ROM (1KB)
// 0x0800_0000: External Flash (remap target)

assign addr_out = remap_enable ?
                  (addr_in < 32'h0000_0400 ? addr_in + 32'h0800_0000 : addr_in) :
                  addr_in;

endmodule

📊 地址映射设计要点

对齐要求

  • 外设寄存器通常4KB对齐
  • 存储器块大小应为2的幂
  • 考虑DMA传输的对齐要求
  • Cache line对齐考虑

预留空间

  • 为未来扩展预留地址空间
  • 考虑IP升级的地址需求
  • 保留一定的地址间隙
  • 避免地址碎片化

访问属性

  • 正确配置Cache属性
  • 区分可执行和非可执行区域
  • 设置适当的访问权限
  • 考虑多核的一致性要求

安全考虑

  • 使用MPU保护关键区域
  • 隔离安全世界和非安全世界
  • 防止未授权的寄存器访问
  • 支持TrustZone安全扩展

⚠️ 常见问题

地址冲突

多个设备映射到同一地址空间。解决方法：使用互斥的地址范围，通过译码器确保只有一个设备被选中。

地址重叠

设备地址范围部分重叠。解决方法：明确地址边界，避免重叠区域。

未映射区域

访问未映射的地址空间。解决方法：添加默认错误响应，触发总线异常。

大小不匹配

IP要求的地址空间大于分配空间。解决方法：重新规划地址映射或更换IP。
