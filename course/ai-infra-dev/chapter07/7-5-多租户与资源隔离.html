7.5 多租户与资源隔离

构建安全的资源共享平台

🎯 学习目标

  • 理解多租户架构的设计原则
  • 掌握资源隔离的实现方法
  • 学会配额管理和限制
  • 了解网络和存储的隔离策略

多租户需求

多租户AI平台需要为不同团队、项目或用户提供隔离的计算资源， 确保资源公平分配、防止资源争抢、保障数据安全和性能稳定。

⚙️ Kubernetes资源隔离

命名空间隔离

Namespace配置：

# 创建租户命名空间
kubectl create namespace team-a
kubectl create namespace team-b
kubectl create namespace team-c

# 设置资源配额
apiVersion: v1
kind: ResourceQuota
metadata:
  name: team-a-quota
  namespace: team-a
spec:
  hard:
    requests.cpu: "4000"
    requests.memory: 16Gi
    limits.cpu: "8000"
    limits.memory: 32Gi
    nvidia.com/gpu: "256"
    persistentvolumeclaims: "50"

LimitRange限制

资源限制范围：

apiVersion: v1
kind: LimitRange
metadata:
  name: team-a-limits
  namespace: team-a
spec:
  limits:
  - default:  # 默认limit
      cpu: "8"
      memory: 16Gi
      nvidia.com/gpu: "1"
    defaultRequest:  # 默认request
      cpu: "4"
      memory: 8Gi
      nvidia.com/gpu: "1"
    type: Container
  - max:
      cpu: "32"
      memory: 64Gi
      nvidia.com/gpu: "8"
    type: Container

🔐 Slurm多租户

账户与配额管理

Slurm账户配置：

# 创建账户
sacctmgr add account team-a Description="研发团队"
sacctmgr add account team-b Description="训练团队"
sacctmgr add account team-c Description="推理团队"

# 设置用户与账户关联
sacctmgr add user alice cluster=ai-cluster account=team-a DefaultAccount=team-a
sacctmgr add user bob cluster=ai-cluster account=team-b DefaultAccount=team-b

# 设置配额
sacctmgr modify account team-a \
    set GrpJobs=100 GrpNodes=50 GrpCPUS=8000 GrpGPUS=256

sacctmgr modify account team-b \
    set GrpJobs=200 GrpNodes=100 GrpCPUS=16000 GrpGPUS=512

# 设置QOS
sacctmgr add qos high-priority Priority=1000 MaxJobs=50
sacctmgr add qos normal Priority=100 MaxJobs=200
sacctmgr add qos low-priority Priority=10 MaxJobs=500

# 账户QOS关联
sacctmgr modify account team-a set qos=normal,high-priority
💡
资源隔离策略

硬隔离：通过配额和限制，严格隔离各租户资源

软隔离：通过优先级和调度策略，实现相对公平

弹性隔离：允许资源借用，但需要归还

混合模式：结合硬隔离和弹性机制

🌐 网络隔离

NetworkPolicy隔离

网络策略配置：

# 默认拒绝所有流量
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: default-deny-all
  namespace: team-a
spec:
  podSelector: {}
  policyTypes:
  - Ingress
  - Egress

# 允许命名空间内通信
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: allow-namespace
  namespace: team-a
spec:
  podSelector: {}
  policyTypes:
  - Ingress
  - Egress
  ingress:
  - from:
    - podSelector: {}
  egress:
  - to:
    - podSelector: {}

多网络平面

多网络配置：

# CNI配置
apiVersion: "k8s.cni.cncf.io/v1"
kind: NetworkAttachmentDefinition
metadata:
  name: team-a-network
  namespace: team-a
spec:
  config: '{
    "cniVersion": "0.3.1",
    "type": "macvlan",
    "master": "eth1",
    "mode": "bridge",
    "ipam": {
      "type": "host-local",
      "subnet": "192.168.100.0/24",
      "rangeStart": "192.168.100.10",
      "rangeEnd": "192.168.100.250"
    }
  }'

# Pod使用多网络
apiVersion: v1
kind: Pod
metadata:
  name: multi-net-pod
  annotations:
    k8s.v1.cni.cncf.io/networks: team-a-network

💾 存储隔离

存储配额与隔离

存储隔离策略：

# PV配额
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: team-a-pvc
  namespace: team-a
spec:
  accessModes:
  - ReadWriteMany
  resources:
    requests:
      storage: 500Gi
  storageClassName: team-a-storage

# StorageClass隔离
apiVersion: storage.k8s.io/v1
kind: StorageClass
metadata:
  name: team-a-storage
provisioner: kubernetes.io/aws-ebs
parameters:
  type: gp3
  fsType: ext4
  encrypted: "true"
  kmsKeyId: arn:aws:kms:us-east-1:123456789012:key/...
allowVolumeExpansion: true
volumeBindingMode: WaitForFirstConsumer
reclaimPolicy: Retain

# NFS共享存储
apiVersion: v1
kind: PersistentVolume
metadata:
  name: team-a-nfs-pv
spec:
  capacity:
    storage: 2Ti
  accessModes:
  - ReadWriteMany
  persistentVolumeReclaimPolicy: Retain
  nfs:
    server: 10.0.10.100
    path: /exports/team-a

🔑 认证与授权

RBAC配置

基于角色的访问控制：

# 创建用户ServiceAccount
apiVersion: v1
kind: ServiceAccount
metadata:
  name: team-a-user
  namespace: team-a

# 创建角色
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata:
  name: team-a-developer
  namespace: team-a
rules:
- apiGroups: [""]
  resources: ["pods", "pods/log", "configmaps", "secrets"]
  verbs: ["get", "list", "watch", "create", "update", "delete"]
- apiGroups: ["batch"]
  resources: ["jobs"]
  verbs: ["get", "list", "watch", "create", "delete"]
- apiGroups: [""]
  resources: ["nodes"]
  verbs: ["get", "list"]
- apiGroups: ["nvidia.com"]
  resources: ["migdevices"]
  verbs: ["get", "list"]

# 角色绑定
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata:
  name: team-a-developer-binding
  namespace: team-a
subjects:
- kind: ServiceAccount
  name: team-a-user
  namespace: team-a
roleRef:
  kind: Role
  name: team-a-developer
  apiGroup: rbac.authorization.k8s.io

📊 资源监控与计费

监控指标

租户资源监控：

# Prometheus规则
groups:
- name: tenant_resources
  rules:
  # 租户GPU使用量
  - record: tenant_gpu_usage
    expr: sum(kube_pod_container_resource_requests{resource="nvidia.com/gpu", namespace=~"team-.*"}) by (namespace)

  # 租户CPU使用率
  - record: tenant_cpu_usage
    expr: sum(rate(container_cpu_usage_seconds_total{namespace=~"team-.*"}[5m])) by (namespace)

  # 租户内存使用量
  - record: tenant_memory_usage
    expr: sum(container_memory_working_set_bytes{namespace=~"team-.*"}) by (namespace)

  # 租户作业数量
  - record: tenant_job_count
    expr: count(kube_job_info{namespace=~"team-.*"}) by (namespace)

# 告警规则
- alert: TenantOverQuota
  expr: tenant_gpu_usage{namespace="team-a"} > 256
  for: 5m
  annotations:
    summary: "租户{{ $labels.namespace }}超过GPU配额"
⚠️
多租户注意事项

安全隔离：确保租户间数据和计算完全隔离

公平调度：防止某个租户独占资源

弹性配额：允许临时借用，提高资源利用率

审计日志：记录所有资源使用和操作
