📚 依赖安全风险

# 依赖安全问题的严重性 ## 现状 - 现代 Web 应用 90% 以上代码来自依赖 - 平均每个项目有数百个直接和间接依赖 - 依赖中的漏洞会被继承到应用中 ## 常见问题 1. 已知漏洞未修复 2. 过时依赖 3. 恶意依赖 4. 依赖供应链攻击 # 知名安全事件 ## event-stream 事件 恶意代码注入，窃取加密货币钱包 ## left-pad 事件 一个包被删除，导致大量项目构建失败 ## node-ipc 事件 作者在包中添加恶意代码抗议战争 ## ua-parser-js 事件 包被劫持，植入挖矿和窃密代码 # 供应链攻击风险 攻击者目标从应用转向依赖 因为： - 一次攻击影响所有使用者 - 依赖更新慢，漏洞窗口长 - 难以检测和防范
⚠️
依赖安全

依赖安全是应用安全的重要组成部分。一个有漏洞的依赖可能让你的所有安全措施付诸东流。

🔧 npm audit

# 使用 npm audit ## 检查漏洞 npm audit # 输出示例 found 3 vulnerabilities (1 low, 1 moderate, 1 high) - high: Remote Code Execution in lodash - moderate: Denial of Service in node-fetch - low: Regular Expression Denial of Service ## 自动修复 npm audit fix # 只修复安全的补丁版本 npm audit fix --only=prod # 强制修复（可能有破坏性变更） npm audit fix --force ## 查看详细信息 npm audit --json npm audit --audit-level=high ## 生成报告 npm audit --json > audit-report.json # yarn audit yarn audit yarn audit --level high # pnpm audit pnpm audit pnpm audit --audit-level=high # 输出说明 - Critical: 严重漏洞，立即修复 - High: 高危漏洞，尽快修复 - Moderate: 中危漏洞，计划修复 - Low: 低危漏洞，酌情修复

⚙️ 依赖更新策略

# 语义化版本 (SemVer) 版本格式: MAJOR.MINOR.PATCH - MAJOR: 不兼容的 API 变更 - MINOR: 向后兼容的功能新增 - PATCH: 向后兼容的问题修复 # package.json 版本范围 { "dependencies": { "lodash": "^4.17.21", // 允许 minor 和 patch 更新 "express": "~4.18.0", // 只允许 patch 更新 "axios": "1.4.0", // 锁定版本 "moment": "*" // 任意版本（不推荐） } } # 检查过时依赖 npm outdated # 输出示例 Package Current Wanted Latest Location lodash 4.17.15 4.17.21 4.17.21 node_modules/lodash express 4.17.0 4.18.2 4.18.2 node_modules/express # 更新依赖 ## 更新到 package.json 允许的版本 npm update ## 更新到最新版本 npm install lodash@latest ## 更新所有依赖（交互式） npx npm-check-updates -i # 使用锁文件 - package-lock.json (npm) - yarn.lock (yarn) - pnpm-lock.yaml (pnpm) # 锁文件确保团队成员使用相同版本 # 提交到版本控制

🚀 自动化安全检查

# GitHub Dependabot # .github/dependabot.yml version: 2 updates: - package-ecosystem: "npm" directory: "/" schedule: interval: "weekly" open-pull-requests-limit: 10 reviewers: - "your-team" labels: - "dependencies" - "security" # CI/CD 集成 # .github/workflows/security.yml name: Security Audit on: push: branches: [main] pull_request: branches: [main] schedule: - cron: '0 0 * * *' # 每天运行 jobs: audit: runs-on: ubuntu-latest steps: - uses: actions/checkout@v4 - uses: actions/setup-node@v4 with: node-version: '20' - run: npm ci - name: Run audit run: npm audit --audit-level=high - name: Check for vulnerabilities run: npx better-npm-audit audit # 使用 Snyk # 安装 npm install -g snyk # 认证 snyk auth # 测试 snyk test # 监控 snyk monitor # 自动修复 snyk fix # package.json scripts { "scripts": { "audit": "npm audit", "audit:fix": "npm audit fix", "snyk": "snyk test", "snyk:monitor": "snyk monitor" } }

📊 最佳实践

# 依赖安全检查清单 ## 选择依赖 □ 检查包的维护状态 □ 检查下载量和 star 数 □ 检查是否有已知漏洞 □ 检查依赖数量是否合理 □ 考虑是否真的需要这个依赖 ## 管理依赖 □ 定期运行 npm audit □ 使用 Dependabot 自动更新 □ 锁定依赖版本 □ 最小化依赖数量 □ 及时更新有漏洞的依赖 ## CI/CD 集成 □ 构建前检查漏洞 □ 高危漏洞阻止合并 □ 定期扫描依赖 □ 自动更新 PR # 依赖最小化原则 // 问自己：真的需要这个依赖吗？ // 很多小功能可以自己实现 // 不需要 lodash 的所有功能 import _ from 'lodash'; // 完整库 // 只导入需要的 import debounce from 'lodash/debounce'; // 或者自己实现 function debounce(fn: Function, delay: number) { let timer: NodeJS.Timeout; return (...args: any[]) => { clearTimeout(timer); timer = setTimeout(() => fn(...args), delay); }; }
