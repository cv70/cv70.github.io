37.3 告警分级与路由

构建智能的告警分发体系

  • 理解告警分级的意义

告警路由架构

告警路由确保每个告警都能及时发送给合适的人员，实现高效的故障响应。

📊 告警分级体系

级别 响应时间 通知方式 通知对象 升级策略
P0 5分钟内 电话 + 短信 + IM OnCall值班人员 10分钟 → 技术负责人
P1 15分钟内 短信 + IM 团队负责人 30分钟 → 技术总监
P2 1小时内 IM + 邮件 相关团队 4小时 → 部门经理
P3 工作时间内 邮件 开发人员 第二天 → 团队负责人

🔀 路由策略

按级别路由

  • P0告警：OnCall人员
  • P1告警：团队值班
  • P2告警：技术支持
  • P3告警：开发团队

按组件路由

  • GPU告警：基础设施团队
  • 训练告警：ML平台团队
  • 推理告警：推理服务团队
  • 数据告警：数据工程团队

按服务路由

  • 用户服务：产品团队
  • 内部服务：技术团队
  • 测试环境：开发团队
  • 生产环境：运维团队

按时间路由

  • 工作时间：技术团队
  • 非工作时间：OnCall人员
  • 周末：值班经理
  • 节假日：应急团队

📦 告警分组策略

💡
分组的目的

合理的分组能减少通知数量，提高处理效率：

# 按告警名称分组 group_by: ['alertname'] # 按告警名称和集群分组 group_by: ['alertname', 'cluster'] # 按告警名称、集群和服务分组 group_by: ['alertname', 'cluster', 'service'] # 按告警类型和主机分组 group_by: ['alertname', 'instance'] # 按团队分组 group_by: ['team'] # 不分组（每条告警单独通知） group_by: []

🔇 告警抑制策略

# 抑制规则 inhibit_rules: # 严重告警抑制警告告警 - source_match: severity: 'P0' target_match: severity: 'P1' equal: ['alertname', 'instance'] # 宕机抑制相关告警 - source_match: alertname: 'InstanceDown' target_match_re: alertname: '.*' equal: ['instance'] # 服务宕机抑制组件告警 - source_match: alertname: 'ServiceDown' target_match_re: alertname: 'ComponentDown' equal: ['service'] # 集群宕机抑制节点告警 - source_match: alertname: 'ClusterDown' target_match_re: alertname: 'NodeDown' equal: ['cluster'] # GPU XID错误抑制GPU温度告警 - source_match: alertname: 'GPUXIDError' target_match: alertname: 'HighGPUTemperature' equal: ['instance', 'gpu']

🤖 智能路由

基于AI的智能告警路由

  • 历史数据分析 - 学习告警处理模式
  • 相似告警聚合 - 自动识别相关告警
  • 优先级调整 - 动态调整告警优先级
  • 责任人推荐 - 基于处理历史推荐处理人
  • 自动分流 - 根据内容自动分配

📊 路由性能指标

指标 定义 目标值
路由准确率 告警发送给正确人员的比例 >95%
路由延迟 从告警触发到接收到通知的时间 <1分钟
告警分组率 成功分组的告警比例 >80%
抑制效果 成功抑制的重复告警比例 >60%
误报率 错误路由的告警比例 <5%
