18.2 ZeRO优化器原理

零冗余优化器，极致显存优化

🎯 学习目标

  • 理解ZeRO的核心思想和原理
  • 掌握ZeRO-1/2/3的区别
  • 了解ZeRO的显存优化机制
  • 认识ZeRO的通信开销

什么是ZeRO？

ZeRO（Zero Redundancy Optimizer）是DeepSpeed的核心优化技术， 旨在消除分布式训练中的冗余。传统数据并行中，每个GPU都存储完整的模型参数、 梯度和优化器状态，存在大量冗余。ZeRO通过将这些状态分片到不同GPU上， 极大地减少了显存占用，使训练超大模型成为可能。

📊 传统数据并行的冗余

显存占用分析

传统数据并行（DDP）的显存占用： 假设： • 模型参数：Φ = 1000亿（100B） • 参数精度：FP16（2 bytes） • 优化器：Adam（需要2倍FP32存储） 显存计算： 1. 模型参数（FP16） Parameters = 100B × 2 bytes = 200 GB 2. 梯度（FP16） Gradients = 100B × 2 bytes = 200 GB 3. 优化器状态（FP32） Adam需要：momentum + variance Optimizer State = 100B × 4 bytes × 2 = 800 GB 4. 激活值 Activations = 约100-200 GB（取决于序列长度和batch size） 每GPU总显存需求： = Parameters + Gradients + Optimizer State + Activations = 200 + 200 + 800 + 200 = 1400 GB 问题： • A100 80GB显存无法容纳 • 需要很多GPU，成本高昂 • 大部分显存是冗余的 冗余分析： • 参数：每个GPU都有完整副本 → N倍冗余 • 梯度：每个GPU都有完整副本 → N倍冗余 • 优化器状态：每个GPU都有完整副本 → N倍冗余

⚙️ ZeRO的核心思想

分片消除冗余

🔧 ZeRO-1详解

优化器状态分片

ZeRO-1工作原理： 1. 分片优化器状态 • 每个GPU只存储部分优化器状态 • Adam：momentum和variance分片存储 2. 前向传播 • 所有GPU都有完整模型参数 • 独立计算前向传播 • 计算损失和梯度 3. 反向传播 • 独立计算梯度 • 所有GPU都有完整梯度副本 4. 参数更新 a. 通过AllReduce聚合梯度（与传统相同） b. 每个GPU更新自己负责的参数分片 • GPU0更新参数0-N/4 • GPU1更新参数N/4-N/2 • GPU2更新参数N/2-3N/4 • GPU3更新参数3N/4-N c. 通过AllBroadcat同步更新的参数 • 所有GPU获得完整更新后的参数 显存节省： • 优化器状态：4倍 • 总显存：约2倍 通信开销： • 与传统DDP相同（AllReduce梯度） • 额外：AllBroadcast参数（更新后同步）

🔧 ZeRO-2详解

梯度分片

ZeRO-2工作原理： 1. 分片优化器状态和梯度 • 每个GPU只存储部分优化器状态和梯度 • 参数仍然是完整的 2. 前向传播 • 所有GPU都有完整模型参数 • 独立计算前向传播 3. 反向传播 a. 计算梯度 b. 通过ReduceScatter聚合并分片梯度 • GPU0获得梯度0-N/4 • GPU1获得梯度N/4-N/2 • GPU2获得梯度N/2-3N/4 • GPU3获得梯度3N/4-N c. 每个GPU使用分片梯度更新参数 4. 参数更新 a. 每个GPU更新自己负责的参数分片 b. 通过AllGather同步更新后的参数 显存节省： • 优化器状态：4倍 • 梯度：4倍 • 总显存：约4倍 通信开销： • 使用ReduceScatter替代AllReduce（更高效） • 使用AllGather同步参数 • 通信总量与ZeRO-1相同，但更高效

🔧 ZeRO-3详解

参数分片

ZeRO-3工作原理： 1. 分片优化器状态、梯度和参数 • 所有状态都分片存储 • 每个GPU只存储部分参数 2. 前向传播（动态收集） 对于每一层： a. AllGather：收集该层的完整参数 b. 计算该层输出 c. Free：释放不需要的参数 3. 反向传播 对于每一层： a. 计算梯度 b. ReduceScatter：聚合并分片梯度 c. Free：释放不需要的梯度 4. 参数更新 a. 每个GPU更新自己的参数分片 b. 不需要同步（参数本来就是分片的） 显存节省： • 优化器状态：4倍 • 梯度：4倍 • 参数：4倍 • 总显存：约10倍（如果考虑激活值检查点） 通信开销： • 前向传播：每层AllGather • 反向传播：每层ReduceScatter • 通信量显著增加 • 可通过prefetch和bucketing优化 关键优化： • Prefetch：提前收集下一层的参数 • Bucketing：减少通信次数 • Offload：将参数卸载到CPU

💡 实用建议

选择合适的ZeRO阶段

选择指南： ZeRO-1 适用场景： • 显存略微不足 • 模型不大（<10B参数） • GPU数量适中（≤16） • 通信网络一般 ZeRO-2 适用场景： • 显存不足比较明显 • 模型较大（10-100B参数） • GPU数量较多（16-64） • 需要更好的显存优化 ZeRO-3 适用场景： • 显存严重不足 • 超大模型（>100B参数） • GPU数量很多（≥64） • 有高速网络（InfiniBand） • 必须配合CPU Offload使用 推荐配置： • 小规模（≤8卡）：ZeRO-2 • 中规模（8-64卡）：ZeRO-2或ZeRO-3 • 大规模（≥64卡）：ZeRO-3 + Offload
⚠️
注意事项
  • ZeRO-3通信开销：显著增加，需要高速网络
  • 模型保存：需要先gather参数再保存
  • 自定义层：需要正确注册可训练参数
  • 调试困难：分片后模型状态难以直接检查
  • 性能监控：密切监控通信时间占比

📝 本节小结

✅

  • • ZeRO-2：+梯度分片，约4倍节省
