模型注册中心概述

模型注册中心（Model Registry）是集中管理模型版本和部署状态的平台。 它提供模型的版本控制、阶段管理、部署跟踪等功能，是MLOps中连接实验和生产的关键组件。

📦 注册模型

从实验注册

from mlflow import log_model, register_model from mlflow.sklearn import log_model as sklearn_log_model # 训练模型 model = train_model(X_train, y_train) # 记录并注册模型 model_info = mlflow.sklearn.log_model( sk_model=model, artifact_path="model", registered_model_name="my-model" ) # 记录额外的模型信息 mlflow.set_tag("model_type", "RandomForest") mlflow.set_tag("training_data", "2024-01-01") mlflow.set_tag("author", "AI Team")

手动注册

from mlflow.tracking import MlflowClient client = MlflowClient() # 从已有run注册模型 model_uri = "runs://model" model_details = client.create_registered_model( name="my-model", description="Customer churn prediction model" ) # 添加模型版本 model_version = client.create_model_version( name="my-model", source=model_uri, run_id="", description="Initial version" )

记录模型签名

import mlflow from mlflow.models.signature import infer_signature import pandas as pd # 推断模型签名 signature = infer_signature( model_input=X_train, model_output=model.predict(X_train) ) # 记录带签名的模型 mlflow.sklearn.log_model( sk_model=model, artifact_path="model", signature=signature, registered_model_name="my-model" ) # 签名信息包括： # - 输入schema（列名、类型） # - 输出schema（类型、形状） # - 参数schema
💡
模型签名的作用

模型签名定义了输入输出的结构，在部署时自动验证数据格式，提高可靠性。

🔄 版本管理

模型版本

from mlflow.tracking import MlflowClient client = MlflowClient() # 列出所有模型版本 model_versions = client.search_model_versions("name='my-model'") for version in model_versions: print(f"Version: {version.version}") print(f"Stage: {version.current_stage}") print(f"Run ID: {version.run_id}") print(f"Status: {version.status}") # 获取特定版本 model_version = client.get_model_version( name="my-model", version=2 )

阶段转换

# 将模型版本转换为Production client.transition_model_version_stage( name="my-model", version=2, stage="Production", archive_existing_versions=True ) # 可用阶段： # - Staging：预发布测试 # - Production：生产环境 # - Archived：已归档 # - None：未分配 # 自定义阶段 # 需要在配置中启用

获取最佳模型

# 获取Production阶段的模型 model_uri = "models:/my-model/Production" model = mlflow.pyfunc.load_model(model_uri) # 使用模型预测 predictions = model.predict(X_test) # 获取Staging模型进行测试 staging_model = mlflow.pyfunc.load_model( "models:/my-model/Staging" )

📝 模型元数据

添加元数据

from mlflow.tracking import MlflowClient client = MlflowClient() # 更新模型描述 client.update_registered_model( name="my-model", description="Customer churn prediction model v2.0" ) # 添加标签 client.set_registered_model_tag( name="my-model", key="business_unit", value="retention" ) # 添加自定义属性 client.set_model_version_tag( name="my-model", version=2, key="accuracy", value="0.95" ) # 查询元数据 model = client.get_registered_model("my-model") print(model.description) print(model.tags)

记录评估结果

from mlflow.entities import Metric # 记录评估指标 metrics = [ Metric(key="accuracy", value=0.95, timestamp=None, step=0), Metric(key="precision", value=0.93, timestamp=None, step=0), Metric(key="recall", value=0.91, timestamp=None, step=0), Metric(key="f1_score", value=0.92, timestamp=None, step=0) ] client.log_batch( run_id="", metrics=metrics, params=[], tags=[] ) # 在模型版本中查看评估结果 model_version = client.get_model_version("my-model", 2)

🚀 模型部署

MLflow Serving

# 启动MLflow模型服务 mlflow models serve \ -m models:/my-model/Production \ -p 5000 \ -h 0.0.0.0 # 或使用环境变量 export MLFLOW_MODEL_NAME="my-model" export MLFLOW_MODEL_VERSION="Production" mlflow models serve \ -p 5000 \ --env-manager local # 测试服务 curl -X POST \ -H "Content-Type: application/json" \ -d '{"data": [[1, 2, 3]]}' \ http://localhost:5000/invocations

Docker容器化部署

# 构建Docker镜像 mlflow models build-docker \ -m models:/my-model/Production \ -n my-model:latest # 推送到镜像仓库 docker tag my-model:latest registry.example.com/my-model:latest docker push registry.example.com/my-model:latest # 在Kubernetes中部署 apiVersion: apps/v1 kind: Deployment metadata: name: my-model spec: replicas: 3 selector: matchLabels: app: my-model template: metadata: labels: app: my-model spec: containers: - name: model image: registry.example.com/my-model:latest ports: - containerPort: 5000

Kubernetes Serving

# 使用KServe部署模型 apiVersion: serving.kserve.io/v1beta1 kind: InferenceService metadata: name: my-model spec: predictor: model: modelFormat: name: mlflow storageUri: s3://mlflow-models/my-model/Production runtimeVersion: "1.28.0" serviceAccountName: kserve-sa scaleTarget: minReplicas: 1 maxReplicas: 5

🔄 模型更新策略

蓝绿部署

两个版本同时运行，切换流量。

# Blue: 旧版本 # Green: 新版本 # 部署Green版本 kubectl apply -f model-green.yaml # 切换流量 kubectl patch service my-model \ -p '{"spec":{"selector":{"version":"green"}}}' # 验证后删除Blue版本 kubectl delete -f model-blue.yaml

金丝雀发布

逐步切换流量到新版本。

# 1. 部署新版本 kubectl apply -f model-v2.yaml # 2. 10%流量到v2 kubectl patch service my-model \ -p '{"spec":{"selector":{"version":"v2"}}}' \ --type=json \ -p='[{"op":"replace","path":"/spec/selector/version","value":"v2"}]' # 3. 逐步增加到50%、90%、100% # 4. 完全切换后删除v1

A/B测试

# 使用Istio流量分割 apiVersion: networking.istio.io/v1alpha3 kind: VirtualService metadata: name: my-model spec: hosts: - my-model http: - match: - headers: x-model-version: exact: v2 route: - destination: host: my-model-v2 - route: - destination: host: my-model-v1 weight: 90 - destination: host: my-model-v2 weight: 10
