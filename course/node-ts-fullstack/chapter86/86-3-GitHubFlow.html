📚 GitHub Flow 概述

GitHub Flow 是 GitHub 推荐的一种简化的工作流，适合持续部署的项目，只需要一个长期分支 main。

GitHub Flow 核心原则： 1. main 分支永远可部署 2. 从 main 创建功能分支 3. 功能分支提交 Pull Request 4. Code Review 后合并到 main 5. 合并后立即部署 main │ ────────────────────┼────────────────── │ feature/login ──────┼────── PR ────→ main │ │ │ Review │ │ feature/cart ───────┼────── PR ────→ main │ ────────────────────┼────────────────── │ Deploy # 特点 - 只有一个长期分支 main - 所有开发都在功能分支进行 - 通过 PR 进行代码审查 - 合并后自动部署

🔧 GitHub Flow 操作流程

# 1. 从 main 创建功能分支 git checkout main git pull origin main git checkout -b feature/user-dashboard # 2. 开发并提交代码 # ... 编写代码 ... git add . git commit -m "feat: 添加用户仪表盘组件" # 3. 推送到远程 git push -u origin feature/user-dashboard # 4. 在 GitHub 创建 Pull Request # - 访问仓库页面 # - 点击 "Compare & pull request" # - 填写 PR 标题和描述 # - 指定审查者 # - 创建 PR # 5. Code Review 通过后合并 # - 使用 GitHub 界面合并 # - 或使用命令行 git checkout main git pull origin main git merge --no-ff feature/user-dashboard git push origin main # 6. 删除功能分支 git branch -d feature/user-dashboard git push origin --delete feature/user-dashboard

⚙️ CI/CD 集成

# .github/workflows/ci.yml name: CI/CD Pipeline on: push: branches: [main] pull_request: branches: [main] jobs: test: runs-on: ubuntu-latest steps: - uses: actions/checkout@v4 - uses: actions/setup-node@v4 with: node-version: '20' cache: 'npm' - run: npm ci - run: npm run lint - run: npm run test:coverage deploy: needs: test if: github.ref == 'refs/heads/main' runs-on: ubuntu-latest steps: - uses: actions/checkout@v4 - uses: actions/setup-node@v4 with: node-version: '20' cache: 'npm' - run: npm ci - run: npm run build - name: Deploy to Production run: | # 部署脚本 echo "Deploying to production..." # 环境部署 # main 分支 → 生产环境 # PR 预览 → 测试环境
💡
持续部署

GitHub Flow 非常适合持续部署场景。每次合并到 main 后自动触发部署流程，实现快速迭代。

📊 Git Flow vs GitHub Flow

┌─────────────────┬────────────────────┬────────────────────┐ │ 对比项 │ Git Flow │ GitHub Flow │ ├─────────────────┼────────────────────┼────────────────────┤ │ 长期分支数量 │ 2 (main + develop) │ 1 (main) │ │ 发布周期 │ 计划发布 │ 持续部署 │ │ 复杂度 │ 较高 │ 简单 │ │ release 分支 │ 有 │ 无 │ │ hotfix 分支 │ 从 main 创建 │ 直接从 main 创建 │ │ 适用场景 │ 版本化产品 │ SaaS/Web 应用 │ │ 部署频率 │ 较低 │ 很高 │ │ 团队规模 │ 中大型团队 │ 小型敏捷团队 │ └─────────────────┴────────────────────┴────────────────────┘ # GitHub Flow 优势 - 流程简单，易于理解 - 适合持续部署 - 减少分支管理成本 # GitHub Flow 劣势 - 不适合需要维护多版本的项目 - 缺乏发布准备阶段 - 紧急修复流程不够明确

📝 本节小结

✅
  • • GitHub Flow 只有一个长期分支 main
  • • 所有开发通过 Pull Request 进行
  • • 适合持续部署的 Web 应用
  • • 比 Git Flow 更简洁但功能较少
