7.2 同名属性合并

处理交叉类型中的同名属性

🎯 学习目标

  • 理解同名属性的类型合并规则
  • 掌握不同类型属性的合并结果
  • 了解 never 类型的情况
  • 学会避免属性冲突

📝 同名属性的类型合并

// 当交叉类型中的多个类型有同名属性时 // 该属性的类型也会进行交叉 interface A { name: string; age: number; } interface B { name: string; city: string; } type AB = A & B; // AB 的结构： // { // name: string & string = string // age: number // city: string // } const ab: AB = { name: 'Alice', age: 30, city: 'Beijing' }; // 相同类型的同名属性：保持原类型

⚠️ 不同类型的同名属性

interface X { prop: string; } interface Y { prop: number; } type XY = X & Y; // prop: string & number = never // 这会导致该属性无法赋值 const xy: XY = { prop: '' as never // 必须使用 never }; // 实际开发中应避免这种情况 // 解决方案：使用联合类型或重命名属性 // 方案1：使用联合类型 interface X2 { prop: string | number; } interface Y2 { prop: string | number; } type XY2 = X2 & Y2; // prop: (string | number) & (string | number) = string | number // 方案2：重命名属性 interface X3 { stringProp: string; } interface Y3 { numberProp: number; } type XY3 = X3 & Y3; // 无冲突
⚠️
注意

当同名属性的类型不兼容时（如 string 和 number），合并结果为 never，表示该属性无法被赋任何值。

🔧 对象类型的同名属性

// 对象类型的同名属性会递归合并 interface Config { settings: { theme: string; lang: string; }; } interface Options { settings: { lang: string; debug: boolean; }; } type Merged = Config & Options; // settings 的类型是两个对象类型的交叉： // { // settings: { // theme: string; // lang: string; // string & string = string // debug: boolean; // } // } const config: Merged = { settings: { theme: 'dark', lang: 'zh-CN', debug: true } }; // 实际应用：合并配置对象 function mergeConfig(a: T, b: U): T & U { return { ...a, ...b }; }

📝 本节小结

✅
  • • 同名属性的类型会进行交叉合并
  • • 相同类型保持不变
  • • 不兼容类型合并为 never
  • • 对象类型递归合并嵌套属性
