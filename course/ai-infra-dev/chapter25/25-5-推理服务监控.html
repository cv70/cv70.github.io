🔧 Prometheus配置

指标采集配置

# prometheus.yml
global:
  scrape_interval: 15s
  evaluation_interval: 15s

scrape_configs:
  - job_name: 'llm-inference'
    kubernetes_sd_configs:
      - role: pod
        namespaces:
          names:
            - inference
    relabel_configs:
      - source_labels: [__meta_kubernetes_pod_annotation_prometheus_io_scrape]
        action: keep
        regex: true
      - source_labels: [__meta_kubernetes_pod_name]
        target_label: pod
      - source_labels: [__meta_kubernetes_pod_node_name]
        target_label: node

  - job_name: 'nvidia-dcgm'
    static_configs:
      - targets: ['nvidia-dcgm-exporter:9400']

# 推理服务Prometheus指标暴露（Python示例）
from prometheus_client import Counter, Histogram, Gauge, start_http_server
import time

# 定义指标
inference_requests_total = Counter(
    'inference_requests_total',
    'Total number of inference requests'
)

inference_latency_seconds = Histogram(
    'inference_latency_seconds',
    'Inference latency in seconds',
    buckets=[0.1, 0.5, 1.0, 2.0, 5.0, 10.0, 30.0, 60.0]
)

gpu_utilization = Gauge(
    'gpu_utilization',
    'GPU utilization percentage',
    ['gpu_id']
)

tokens_per_second = Gauge(
    'tokens_per_second',
    'Tokens generated per second'
)

# 模拟推理服务
def inference_service():
    # 启动指标服务器
    start_http_server(8001)

    while True:
        # 处理推理请求
        start_time = time.time()

        # 模拟推理
        time.sleep(0.5)

        # 记录指标
        inference_requests_total.inc()
        inference_latency_seconds.observe(time.time() - start_time)

        # 模拟GPU利用率
        gpu_utilization.labels(gpu_id=0).set(80)
        tokens_per_second.set(150)

        time.sleep(0.1)

# 在Kubernetes中暴露指标端口
"""
在Pod的annotations中添加：
prometheus.io/scrape: "true"
prometheus.io/port: "8001"
prometheus.io/path: "/metrics"
"""

🚨 告警规则

Prometheus告警配置

# alerting_rules.yml
groups:
  - name: inference_alerts
    rules:
      # 高延迟告警
      - alert: HighLatency
        expr: histogram_quantile(0.99,
               rate(inference_latency_seconds_bucket[5m])) > 5
        for: 5m
        labels:
          severity: warning
        annotations:
          summary: "P99延迟超过5秒"
          description: "P99延迟: {{ $value }}s"

      # 高错误率告警
      - alert: HighErrorRate
        expr: rate(inference_errors_total[5m]) / rate(inference_requests_total[5m]) > 0.01
        for: 2m
        labels:
          severity: critical
        annotations:
          summary: "错误率超过1%"
          description: "错误率: {{ $value | humanizePercentage }}"

      # GPU利用率告警
      - alert: HighGPUUtilization
        expr: gpu_utilization > 95
        for: 10m
        labels:
          severity: warning
        annotations:
          summary: "GPU利用率过高"
          description: "GPU {{ $labels.gpu_id }} 利用率: {{ $value }}%"

      # 低GPU利用率告警
      - alert: LowGPUUtilization
        expr: avg_over_time(gpu_utilization[30m]) < 20
        for: 30m
        labels:
          severity: info
        annotations:
          summary: "GPU利用率过低"
          description: "可能存在资源浪费"

      # 服务不可用告警
      - alert: ServiceDown
        expr: up{job="llm-inference"} == 0
        for: 1m
        labels:
          severity: critical
        annotations:
          summary: "推理服务不可用"
          description: "实例 {{ $labels.instance }} 无法访问"

🔍 故障排查

常见问题诊断

症状 可能原因 排查方法
延迟高 GPU满载、批处理问题 检查GPU利用率、批处理大小
错误率高 OOM、模型加载失败 检查内存、显存、日志
吞吐低 批处理小、GPU利用率低 检查配置、调整参数
服务不可用 Pod崩溃、网络问题 检查Pod状态、网络连通性
💡
监控实践建议
  • 监控指标要全面，覆盖业务、资源、推理三层
  • 关注P99延迟而非平均值
  • 设置合理的告警阈值，避免告警疲劳
  • 建立完善的故障排查流程
  • 定期回顾和优化监控体系
