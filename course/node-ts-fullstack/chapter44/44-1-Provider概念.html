44.1 Provider 概念

理解 NestJS 依赖注入的核心

🎯 学习目标

  • 理解 Provider 的概念和作用
  • 掌握 @Injectable() 装饰器
  • 了解 Provider 的类型
  • 理解依赖注入原理

📚 什么是 Provider？

Provider 是 NestJS 中可以被注入的类，通常用于封装业务逻辑、数据访问等功能。使用 @Injectable() 装饰器声明一个类为 Provider。

import { Injectable } from '@nestjs/common'; @Injectable() // 声明这是一个可注入的 Provider export class UsersService { private users = [ { id: 1, name: 'John' }, { id: 2, name: 'Jane' }, ]; findAll() { return this.users; } findOne(id: number) { return this.users.find(user => user.id === id); } } // 在控制器中注入使用 @Controller('users') export class UsersController { constructor(private readonly usersService: UsersService) {} @Get() findAll() { return this.usersService.findAll(); } }
💡
Provider 特点

Provider 通过依赖注入机制管理，NestJS 自动创建实例并处理依赖关系。默认情况下 Provider 是单例的。

🔧 Provider 注册

// 在模块中注册 Provider @Module({ controllers: [UsersController], providers: [UsersService], // 注册 Provider exports: [UsersService], // 可选：导出供其他模块使用 }) export class UsersModule {} // Provider 会在模块中自动可用 // 控制器和其他 Provider 可以通过构造函数注入

📦 Provider 类型

类型 说明 使用场景
Service 业务逻辑服务 数据处理、业务规则
Repository 数据访问层 数据库操作
Factory 工厂提供者 动态创建实例
Value 值提供者 配置值、常量
Alias 别名提供者 创建 Provider 别名

🔄 依赖注入原理

// NestJS 使用 TypeScript 的反射机制实现依赖注入 // 编译后需要在 tsconfig.json 启用 emitDecoratorMetadata { "compilerOptions": { "emitDecoratorMetadata": true, "experimentalDecorators": true } } // 注入流程： // 1. NestJS 扫描模块中的 providers // 2. 分析每个 Provider 的构造函数依赖 // 3. 按依赖顺序创建实例 // 4. 将实例注入到需要的地方 @Injectable() export class UsersService { // 注入其他 Provider constructor( private readonly databaseService: DatabaseService, private readonly logger: LoggerService, ) {} }
⚠️
循环依赖

如果两个 Provider 相互依赖，会导致循环依赖问题。可以使用 forwardRef() 解决，但最好通过重构避免。
