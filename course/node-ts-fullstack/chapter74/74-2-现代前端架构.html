组件化、模块化与工程化

📚 组件化架构

// 组件化思想：将 UI 拆分为独立、可复用的单元 // 基础组件：Button const Button = ({ children, onClick, variant = 'primary' }) => { return ( <button className={`btn btn-${variant}`} onClick={onClick} > {children} </button> ); }; // 组合组件：Card const Card = ({ title, children, footer }) => ( <div className="card"> <div className="card-header">{title}</div> <div className="card-body">{children}</div> {footer && <div className="card-footer">{footer}</div>} </div> ); // 页面组件：使用基础组件组合 const UserProfile = ({ user }) => ( <Card title="用户信息"> <img src={user.avatar} alt={user.name} /> <h3>{user.name}</h3> <p>{user.email}</p> <Button variant="outline">编辑资料</Button> </Card> ); // 组件树结构 // App // ├── Header // │ ├── Logo // │ └── Navigation // ├── Main // │ ├── Sidebar // │ └── Content // │ └── UserProfile // └── Footer

// 项目目录结构示例 src/ ├── components/ # 可复用组件 │ ├── Button/ │ │ ├── Button.tsx │ │ ├── Button.styles.ts │ │ └── Button.test.tsx │ └── Card/ │ └── Card.tsx ├── hooks/ # 自定义 Hooks │ ├── useAuth.ts │ └── useApi.ts ├── services/ # API 服务 │ ├── api.ts │ └── auth.service.ts ├── store/ # 状态管理 │ ├── index.ts │ └── slices/ ├── utils/ # 工具函数 │ ├── format.ts │ └── validate.ts ├── types/ # 类型定义 │ └── index.ts └── pages/ # 页面组件 ├── Home.tsx └── User.tsx // 模块导入示例 import { Button } from '@/components/Button'; import { useAuth } from '@/hooks/useAuth'; import { userService } from '@/services/user.service'; import { formatDate } from '@/utils/format'; import type { User } from '@/types';

📊 前端架构模式

// 1. 单页应用（SPA） // - 客户端路由 // - 动态渲染 // - 首屏加载较慢，后续交互快 // 2. 服务端渲染（SSR） // - 服务器生成 HTML // - SEO 友好 // - 首屏加载快 // 3. 静态站点生成（SSG） // - 构建时生成静态页面 // - 适合内容型网站 // - 部署简单 // 4. 增量静态再生（ISR） // - 静态页面定时更新 // - 兼顾性能和实时性 // Next.js 支持多种渲染模式 // pages/index.tsx export async function getStaticProps() { const posts = await getPosts(); return { props: { posts }, revalidate: 60, // ISR: 60秒后重新生成 }; }

📝 本节小结

✅
  • • 组件化将 UI 拆分为独立可复用的单元
  • • 模块化让代码组织更清晰、更易维护
  • • 现代架构支持 SPA、SSR、SSG 等多种模式
  • • 合理的目录结构是项目可维护性的基础
