63.1 WebSocket 协议

深入理解 WebSocket 通信机制

🎯 学习目标

  • 理解 WebSocket 协议的基本概念
  • 掌握 WebSocket 的工作原理
  • 了解 WebSocket 握手过程
  • 熟悉 WebSocket 数据帧格式

什么是 WebSocket

WebSocket是一种在单个 TCP 连接上进行全双工通信的协议。它于2011年被 IETF 定为标准 RFC 6455，并由 W3C 将 WebSocket API 纳入 HTML5 标准。

WebSocket 使得客户端和服务器之间的数据交换变得更加简单，允许服务端主动向客户端推送数据。在 WebSocket API 中，浏览器和服务器只需要完成一次握手，两者之间就直接可以创建持久性的连接，并进行双向数据传输。

🔗 WebSocket 协议特点

核心特性

  • 基于 TCP 协议，支持二进制和文本数据
  • 全双工通信，服务端可主动推送
  • 握手阶段使用 HTTP 协议
  • 数据格式轻量，性能开销小
  • 没有同源限制，客户端可以与任意服务器通信

协议标识

ws://example.com:8080/path wss://example.com:8080/path // 加密连接

ws:// 是非加密连接，wss:// 是加密连接（WebSocket Secure），类似于 HTTP 和 HTTPS 的关系。

🤝 WebSocket 握手过程

WebSocket 连接建立需要经过 HTTP 握手升级过程：

1
客户端发起请求
2
服务端响应确认
3
建立 WebSocket 连接
客户端请求： GET /chat HTTP/1.1 Host: server.example.com Upgrade: websocket Connection: Upgrade Sec-WebSocket-Key: dGhlIHNhbXBsZSBub25jZQ== Sec-WebSocket-Version: 13 Origin: http://example.com 服务端响应： HTTP/1.1 101 Switching Protocols Upgrade: websocket Connection: Upgrade Sec-WebSocket-Accept: s3pPLMBiTxaQ9kYGzzhZRbK+xOo=
💡
握手验证原理

Sec-WebSocket-Accept 的值是服务端将 Sec-WebSocket-Key 与固定的 GUID "258EAFA5-E914-47DA-95CA-C5AB0DC85B11" 拼接后，进行 SHA-1 哈希，再进行 Base64 编码得到的。

📦 WebSocket 数据帧格式

WebSocket 使用帧（Frame）来传输数据，基本帧格式如下：

字段 长度 说明
FIN 1 bit 是否为最后一帧
RSV1-3 3 bits 保留位，用于扩展
Opcode 4 bits 帧类型（文本、二进制等）
Mask 1 bit 是否使用掩码
Payload length 7/7+16/7+64 bits 负载数据长度
Masking-key 0/32 bits 掩码密钥（客户端必须使用）
Payload data 变长 实际数据内容

Opcode 类型说明

0x0: 继续帧 (Continuation Frame) 0x1: 文本帧 (Text Frame) 0x2: 二进制帧 (Binary Frame) 0x8: 关闭帧 (Connection Close) 0x9: Ping 帧 0xA: Pong 帧

⚡ 心跳机制

WebSocket 提供了内置的心跳机制，通过 Ping/Pong 帧来保持连接活跃：

Ping 帧

服务端或客户端可以发送 Ping 帧来探测对方是否仍然存活。Ping 帧可以携带数据。

Pong 帧

收到 Ping 帧的一方必须回复 Pong 帧。Pong 帧携带与 Ping 帧相同的数据。

📝 本节小结

✅
  • • WebSocket 是一种全双工通信协议，基于 TCP 实现
  • • 通过 HTTP Upgrade 机制完成握手升级
  • • 使用数据帧格式传输，支持文本和二进制数据
  • • 内置 Ping/Pong 心跳机制保持连接
  • • 相比 HTTP，WebSocket 更适合实时通信场景
