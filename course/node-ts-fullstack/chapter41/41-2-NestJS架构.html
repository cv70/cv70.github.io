41.2 NestJS 架构

理解 NestJS 的核心架构设计

🎯 学习目标

  • 理解 NestJS 的分层架构
  • 掌握核心组件的作用
  • 了解请求处理流程
  • 理解模块化设计思想

📚 核心架构组件

NestJS 采用分层架构设计，主要包含以下核心组件：

NestJS 核心组件层次结构 ┌─────────────────────────────────────────┐ │ Modules (模块) │ │ ┌─────────────────────────────────────┐ │ │ │ Controllers (控制器) │ │ │ │ 处理 HTTP 请求，定义路由 │ │ │ └─────────────────────────────────────┘ │ │ ┌─────────────────────────────────────┐ │ │ │ Providers (提供者) │ │ │ │ Services, Repositories, etc. │ │ │ └─────────────────────────────────────┘ │ │ ┌─────────────────────────────────────┐ │ │ │ Pipes (管道) │ │ │ │ 数据验证与转换 │ │ │ └─────────────────────────────────────┘ │ │ ┌─────────────────────────────────────┐ │ │ │ Guards (守卫) │ │ │ │ 权限验证 │ │ │ └─────────────────────────────────────┘ │ │ ┌─────────────────────────────────────┐ │ │ │ Interceptors (拦截器) │ │ │ │ 请求/响应拦截 │ │ │ └─────────────────────────────────────┘ │ │ ┌─────────────────────────────────────┐ │ │ │ Filters (过滤器) │ │ │ │ 异常处理 │ │ │ └─────────────────────────────────────┘ │ └─────────────────────────────────────────┘

🔄 请求处理流程

请求处理顺序： 客户端请求 ↓ ┌───────────────┐ │ 中间件 │ ← 请求预处理 └───────────────┘ ↓ ┌───────────────┐ │ 守卫 │ ← 权限验证 └───────────────┘ ↓ ┌───────────────┐ │ 拦截器(前) │ ← 请求拦截 └───────────────┘ ↓ ┌───────────────┐ │ 管道 │ ← 数据验证/转换 └───────────────┘ ↓ ┌───────────────┐ │ 路由处理器 │ ← 控制器方法 └───────────────┘ ↓ ┌───────────────┐ │ 拦截器(后) │ ← 响应拦截 └───────────────┘ ↓ ┌───────────────┐ │ 异常过滤器 │ ← 异常处理 └───────────────┘ ↓ 响应客户端

🔧 核心组件说明

组件 作用 装饰器
Module 组织应用结构，管理依赖 @Module()
Controller 处理 HTTP 请求 @Controller()
Provider 提供业务逻辑服务 @Injectable()
Guard 权限验证 @Injectable(), @UseGuards()
Interceptor 请求/响应拦截 @Injectable(), @UseInterceptors()
Pipe 数据验证转换 @Injectable(), @UsePipes()
Filter 异常处理 @Catch(), @UseFilters()

📝 本节小结

✅
  • • NestJS 采用模块化分层架构
  • • 模块是组织代码的基本单元
  • • 请求经过中间件、守卫、拦截器、管道层层处理
  • • 每个组件都有特定的职责和装饰器
