GPU设备插件概述

Kubernetes通过设备插件（Device Plugin）机制支持特殊硬件资源，如GPU、FPGA、高速网卡等。 NVIDIA GPU设备插件是Kubernetes中使用最广泛的设备插件，用于在Kubernetes中管理和调度GPU资源。

🏗️ 设备插件架构

图：Kubernetes设备插件架构

工作原理

  • 设备插件作为DaemonSet在每个节点运行
  • 通过gRPC与Kubelet通信
  • 发现并上报硬件资源
  • 管理设备的分配与释放
  • 提供设备健康检查

📦 安装NVIDIA设备插件

前提条件

# 节点必须安装的组件 - NVIDIA驱动 - nvidia-container-toolkit (或 nvidia-docker2) - Docker/Containerd支持nvidia运行时
⚠️
注意事项

确保NVIDIA驱动版本与GPU兼容，建议使用LTS版本。

安装方式1：Helm Chart

# 添加NVIDIA Helm仓库 helm repo add nvidia https://nvidia.github.io/k8s-device-plugin helm repo update # 安装设备插件 helm install nvidia-device-plugin nvidia/k8s-device-plugin \ --namespace gpu-operator \ --create-namespace \ --set deviceListStrategy=volumeMounts # 验证安装 kubectl get pods -n gpu-operator kubectl describe node | grep nvidia.com/gpu

安装方式2：kubectl apply

# 从官方仓库部署 kubectl apply -f https://raw.githubusercontent.com/NVIDIA/k8s-device-plugin/v0.14.0/deployments/static/nvidia-device-plugin.yml # 或者使用DaemonSet部署 kubectl apply -f https://raw.githubusercontent.com/NVIDIA/k8s-device-plugin/v0.14.0/deployments/static/nvidia-device-plugin-daemonset.yaml

安装方式3：GPU Operator（推荐生产环境）

# 安装GPU Operator（包含设备插件、驱动、监控等） helm repo add nvidia https://nvidia.github.io/gpu-operator helm repo update helm install --wait --generate-name \ nvidia/gpu-operator \ --namespace gpu-operator \ --create-namespace \ --set driver.enabled=true

🔍 验证GPU资源

# 查看节点GPU资源 kubectl describe nodes | grep -A 3 nvidia.com/gpu # 输出示例： # Capacity: # nvidia.com/gpu: 4 # Allocatable: # nvidia.com/gpu: 4 # Allocated resources: # nvidia.com/gpu: 0 # 查看设备插件Pod kubectl get pods -n gpu-operator -l name=nvidia-device-plugin-ds

🚀 在Pod中使用GPU

单GPU Pod

apiVersion: v1 kind: Pod metadata: name: gpu-pod spec: containers: - name: cuda-container image: nvidia/cuda:11.8.0-base-ubuntu22.04 resources: limits: nvidia.com/gpu: 1 command: ["nvidia-smi"]

多GPU Pod

apiVersion: v1 kind: Pod metadata: name: multi-gpu-pod spec: containers: - name: training image: pytorch/pytorch:2.0.0-cuda11.7-cudnn8-runtime resources: limits: nvidia.com/gpu: 4 # 请求4个GPU command: ["python", "train.py"] args: - "--gpus=all"

Deployment使用GPU

apiVersion: apps/v1 kind: Deployment metadata: name: gpu-training spec: replicas: 2 selector: matchLabels: app: training template: metadata: labels: app: training spec: containers: - name: training image: pytorch/pytorch:2.0.0-cuda11.7-cudnn8-runtime resources: requests: nvidia.com/gpu: 1 limits: nvidia.com/gpu: 1 command: ["python", "train.py"]

🔧 高级配置

MIG（Multi-Instance GPU）支持

# 配置MIG设备 apiVersion: v1 kind: ConfigMap metadata: name: nvidia-device-plugin-config namespace: gpu-operator data: mig-strategy: single # single | mixed | none
💡
MIG策略说明
  • • single：所有GPU配置相同的MIG实例
  • • mixed：部分GPU使用MIG，部分保持完整
  • • none：禁用MIG，使用完整GPU

指定GPU类型

apiVersion: v1 kind: Pod metadata: name: select-gpu-type spec: containers: - name: training image: pytorch/pytorch:2.0.0-cuda11.7-cudnn8-runtime resources: limits: nvidia.com/gpu: 1 nvidia.com/gpu.product: A100-SXM4-40GB # 指定GPU型号 nodeSelector: accelerator: nvidia-tesla-a100

GPU亲和性

apiVersion: v1 kind: Pod metadata: name: gpu-affinity spec: affinity: nodeAffinity: requiredDuringSchedulingIgnoredDuringExecution: nodeSelectorTerms: - matchExpressions: - key: nvidia.com/gpu.count operator: Gt values: - 0 # 节点反亲和性，分散到不同节点 podAntiAffinity: preferredDuringSchedulingIgnoredDuringExecution: - weight: 100 podAffinityTerm: labelSelector: matchExpressions: - key: app operator: In values: - training topologyKey: kubernetes.io/hostname containers: - name: training image: pytorch/pytorch:2.0.0-cuda11.7-cudnn8-runtime resources: limits: nvidia.com/gpu: 2

📊 GPU共享与切分

GPU共享方案

原生设备插件不支持GPU共享，需要第三方方案：

NVIDIA MPS

  • 官方共享方案
  • 进程级共享
  • 需要适配应用
# MPS配置示例 env: - name: CUDA_MPS_PIPE_DIRECTORY value: /tmp/nvidia-mps - name: CUDA_MPS_LOG_DIRECTORY value: /tmp/nvidia-mps-log

Aliyun cGPU

  • 阿里云方案
  • 显存与算力隔离
  • 无需修改应用

Volcano vGPU

  • 开源方案
  • 支持多种切分策略
  • 社区活跃

Run:AI

  • 商业方案
  • 完整的GPU池化
  • 企业级支持
