44.3 依赖注入

深入理解 NestJS 的依赖注入机制

🎯 学习目标

  • 理解依赖注入的概念
  • 掌握构造函数注入
  • 了解属性注入
  • 学会解决循环依赖

📚 什么是依赖注入？

依赖注入（DI）是一种设计模式，类的依赖不由类自己创建，而是由外部系统（NestJS 的 IoC 容器）注入。这样可以实现松耦合，方便测试和维护。

// 没有依赖注入 class UsersController { private usersService = new UsersService(); // 紧耦合 } // 使用依赖注入 @Controller('users') export class UsersController { constructor(private readonly usersService: UsersService) {} // 松耦合 } // NestJS 自动： // 1. 创建 UsersService 实例 // 2. 将实例注入到 UsersController
💡
IoC 容器

NestJS 内置了 IoC（Inversion of Control）容器，负责管理所有 Provider 的生命周期和依赖关系。

🔧 构造函数注入

import { Injectable } from '@nestjs/common'; @Injectable() export class UsersService { constructor( private readonly databaseService: DatabaseService, private readonly loggerService: LoggerService, private readonly cacheService: CacheService, ) {} async findAll() { this.loggerService.log('Finding all users'); const cached = await this.cacheService.get('users'); if (cached) return cached; const users = await this.databaseService.query('SELECT * FROM users'); await this.cacheService.set('users', users, 3600); return users; } } // TypeScript 会自动推断类型，无需 @Inject() 装饰器 // 因为类类型本身就是 token

🌐 属性注入

import { Controller, Inject, Injectable, Optional } from '@nestjs/common'; @Injectable() export class UsersService { // 使用 @Inject() 进行属性注入 @Inject() private readonly logger: LoggerService; // 可选注入 @Optional() @Inject('CACHE_SERVICE') private readonly cacheService?: CacheService; findAll() { this.logger.log('Finding users'); if (this.cacheService) { // 缓存服务可用 } } }
⚠️
推荐构造函数注入

构造函数注入是推荐的方式，因为依赖关系更清晰，且便于单元测试时 mock 依赖。属性注入主要用于可选依赖。

🔄 循环依赖处理

import { Injectable, Inject, forwardRef } from '@nestjs/common'; // 情况1：模块循环依赖 // users.module.ts @Module({ imports: [forwardRef(() => AuthModule)], }) export class UsersModule {} // auth.module.ts @Module({ imports: [forwardRef(() => UsersModule)], }) export class AuthModule {} // 情况2：服务循环依赖 @Injectable() export class UsersService { constructor( @Inject(forwardRef(() => AuthService)) private readonly authService: AuthService, ) {} } @Injectable() export class AuthService { constructor( @Inject(forwardRef(() => UsersService)) private readonly usersService: UsersService, ) {} }
❌
避免循环依赖

forwardRef 可以解决循环依赖，但更好的做法是重构代码，提取公共逻辑到第三个服务，避免循环依赖。

📝 本节小结

✅

  • • 构造函数注入是推荐方式
  • • @Optional() 声明可选依赖
  • • forwardRef 解决循环依赖
