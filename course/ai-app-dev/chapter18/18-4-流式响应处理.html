18.4 流式响应处理

实现实时输出的用户体验

🎯 学习目标

  • 理解流式响应的原理和优势
  • 掌握各平台流式API的使用方法

  • 能够在前端实现流式显示

什么是流式响应

流式响应（Streaming）是指模型生成内容时，逐token或逐块返回结果，而不是等待全部生成完毕后一次性返回。这种方式让用户能够实时看到生成过程，大幅提升用户体验。

📊 流式 vs 非流式对比

特性 流式响应 非流式响应
首字响应时间 极快（几百毫秒） 慢（需等待全部生成）
用户感知 实时反馈，体验好 等待感强，体验差
错误处理 复杂，需要中断机制 简单，一次返回
适用场景 对话、实时生成 批处理、后台任务
token统计 需要累计计算 直接返回总数

🔧 OpenAI流式调用

from openai import OpenAI client = OpenAI(api_key="your-api-key") # 流式调用 stream = client.chat.completions.create( model="gpt-4o-mini", messages=[{"role": "user", "content": "写一首关于春天的诗"}], stream=True ) # 逐块处理 for chunk in stream: if chunk.choices[0].delta.content: print(chunk.choices[0].delta.content, end="", flush=True) # 使用迭代器方式 def stream_chat(messages): response = client.chat.completions.create( model="gpt-4o-mini", messages=messages, stream=True ) for chunk in response: content = chunk.choices[0].delta.content if content: yield content

🌐 Web应用流式实现

FastAPI后端

from fastapi import FastAPI from fastapi.responses import StreamingResponse from openai import OpenAI app = FastAPI() client = OpenAI() def generate_stream(prompt: str): stream = client.chat.completions.create( model="gpt-4o-mini", messages=[{"role": "user", "content": prompt}], stream=True ) for chunk in stream: content = chunk.choices[0].delta.content if content: yield f"data: {content}\n\n" yield "data: [DONE]\n\n" # SSE (Server-Sent Events) 端点 @app.get("/chat/stream") async def chat_stream(prompt: str): return StreamingResponse( generate_stream(prompt), media_type="text/event-stream" )

⚠️ 流式响应异常处理

async def safe_stream(prompt: str): full_content = [] try: stream = client.chat.completions.create( model="gpt-4o-mini", messages=[{"role": "user", "content": prompt}], stream=True, timeout=30 # 设置超时 ) for chunk in stream: content = chunk.choices[0].delta.content if content: full_content.append(content) yield content except Exception as e: # 异常时返回已接收内容 yield f"\n[错误: {str(e)}]" # 可以选择保存已接收内容用于恢复 save_partial("".join(full_content))
💡
最佳实践

对于对话类应用，强烈推荐使用流式响应。实现时注意：设置合理的超时时间、保存部分内容用于断点续传、提供取消机制让用户可以中断生成。

⚠️
注意事项

流式响应时token统计需要累计计算，不是一次性返回。另外，部分API在流式模式下不支持某些参数（如logprobs），需要查阅文档确认。
