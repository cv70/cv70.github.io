70.4 测试覆盖率

第十部分：测试篇 - 理解和提升测试覆盖率

1. 测试覆盖率简介

测试覆盖率是衡量测试完整性的指标，表示代码被测试覆盖的程度。

💡
覆盖率的意义

高覆盖率不等于高质量测试，但覆盖率低通常意味着测试不足。覆盖率是发现问题的一种手段，而不是目标。

2. 四种覆盖率类型

类型 说明 示例
语句覆盖率
(Statements)		 每个语句是否被执行 代码行数百分比
分支覆盖率
(Branches)		 每个分支是否被执行 if/else、switch 分支
函数覆盖率
(Functions)		 每个函数是否被调用 函数调用百分比
行覆盖率
(Lines)		 每行代码是否被执行 代码行数百分比
// 示例：理解不同覆盖率 function calculateGrade(score: number): string { if (score >= 90) { // 分支 1 return 'A'; } else if (score >= 80) { // 分支 2 return 'B'; } else if (score >= 70) { // 分支 3 return 'C'; } else { // 分支 4 return 'F'; } } // 只测试 score = 95 test('returns A for score 95', () => { expect(calculateGrade(95)).toBe('A'); }); // 结果： // - 语句覆盖率：50%（只执行了部分语句） // - 分支覆盖率：25%（只覆盖了 1 个分支） // - 函数覆盖率：100%（函数被调用了） // - 行覆盖率：50%

# 运行测试并生成覆盖率 npm test -- --coverage # 或者使用 npm script npm run test:coverage

HTML 报告

# Jest 会在 coverage/lcov-report 目录生成 HTML 报告 # 打开查看详细覆盖情况 open coverage/lcov-report/index.html
💡
HTML 报告优势

HTML 报告可以直观地看到哪些代码行未被覆盖，便于针对性地补充测试用例。

4. 配置覆盖率

// jest.config.ts export default { // 收集覆盖率的文件 collectCoverage: true, // 或通过 --coverage 启用 collectCoverageFrom: [ 'src/**/*.{ts,tsx}', '!src/**/*.d.ts', // 排除类型声明 '!src/**/index.ts', // 排除索引文件 '!src/main.ts', // 排除入口文件 '!src/**/types.ts', // 排除类型文件 ], // 覆盖率输出目录 coverageDirectory: 'coverage', // 覆盖率报告格式 coverageReporters: [ 'text', // 命令行文本 'text-summary', // 命令行摘要 'lcov', // HTML 报告 'html', // HTML 报告 'json-summary', // JSON 摘要 'json', // 详细 JSON ], // 覆盖率提供者 coverageProvider: 'v8', // 或 'babel' // 覆盖率阈值（低于此值测试失败） coverageThreshold: { global: { branches: 80, functions: 80, lines: 80, statements: 80 }, // 可以针对特定目录或文件设置 './src/services/': { branches: 90, functions: 90, lines: 90 } } };

5. 覆盖率报告格式

// 不同的报告格式适合不同场景 // text - 命令行输出 npm test -- --coverage --coverageReporters=text // text-summary - 简洁摘要 npm test -- --coverage --coverageReporters=text-summary // lcov - 生成 HTML 报告 npm test -- --coverage --coverageReporters=lcov // json - 供其他工具使用 npm test -- --coverage --coverageReporters=json // 多个报告器 npm test -- --coverage --coverageReporters=text --coverageReporters=lcov

6. 提升覆盖率的策略

优先覆盖

  • 核心业务逻辑
  • 复杂算法
  • 错误处理分支
  • 边界条件

不必强求

  • 简单的 getter/setter
  • 框架生成的代码
  • 第三方库封装
  • 配置文件

从覆盖率报告发现问题

// 1. 打开 HTML 报告 // 2. 找到覆盖率低的文件 // 3. 查看未覆盖的代码行（红色标记） // 4. 分析为什么未覆盖： // - 缺少测试用例？ // - 死代码？ // - 错误处理分支？ // 示例：发现未覆盖的错误处理 function divide(a: number, b: number): number { if (b === 0) { throw new Error('Division by zero'); // 未覆盖 } return a / b; } // 补充测试 test('throws error when dividing by zero', () => { expect(() => divide(10, 0)).toThrow('Division by zero'); });

8. 覆盖率误区

⚠️
常见误区
  • 高覆盖率 = 高质量：覆盖率只表示代码被执行，不验证断言是否正确
  • 100% 覆盖率是目标：追求 100% 可能得不偿失
  • 只看总体覆盖率：应该关注关键模块的覆盖率
// 高覆盖率但测试质量差的例子 test('bad test', () => { const result = add(1, 2); // 没有断言！覆盖率 100%，但测试无意义 }); test('meaningless test', () => { // 断言了但不验证正确性 expect(add(1, 2)).toBeDefined(); // 应该是 toBe(3) });

📚
关键要点
