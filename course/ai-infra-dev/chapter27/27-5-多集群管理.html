多集群管理概述

在AI基础设施中，多集群管理用于统一管理分布在不同地域、不同云厂商的Kubernetes集群。 通过多集群管理，可以实现跨集群的任务调度、资源复用、故障容灾，提高整体资源利用率和系统可靠性。

🏗️ 多集群架构

图：多集群管理架构

Hub集群

控制平面，集中管理和决策。

  • 集中管理控制
  • 策略制定与分发
  • 统一监控视图
  • 跨集群调度

Managed集群

工作集群，执行具体任务。

  • 运行AI工作负载
  • 本地资源管理
  • 状态上报
  • 本地策略执行

Agent组件

连接Hub和Managed集群。

  • 建立安全连接
  • 同步资源和状态
  • 执行远程命令
  • 事件上报

📦 Open Cluster Management

OCM简介

Open Cluster Management（OCM）是CNCF托管的Kubernetes多集群管理项目， 提供统一的控制平面来管理多个Kubernetes集群，支持应用分发、策略管理、跨集群监控等。

核心概念

ManagedCluster

代表一个被管理的集群。

apiVersion: cluster.open-cluster-management.io/v1 kind: ManagedCluster metadata: name: cluster1 labels: cloud: aws region: us-east-1 gpu-type: A100 spec: hubAcceptsClient: true

ClusterRoleBinding

定义集群间的访问权限。

apiVersion: rbac.authorization.k8s.io/v1 kind: ClusterRoleBinding metadata: name: cluster-admin-binding roleRef: apiGroup: rbac.authorization.k8s.io kind: ClusterRole name: cluster-admin subjects: - kind: Group name: system:authenticated

🚀 安装OCM

安装Hub集群

# 添加OCM Helm仓库 helm repo add open-cluster-management https://open-cluster-management.io/helm-charts helm repo update # 安装OCM Hub组件 kubectl apply -f https://raw.githubusercontent.com/open-cluster-management-io/ocm/release-0.10/deploy/cluster-manager/components.yaml # 验证安装 kubectl get pods -n open-cluster-management-hub kubectl get crd | grep open-cluster-management # 安装klusterlet（用于Managed集群） kubectl apply -f https://raw.githubusercontent.com/open-cluster-management-io/ocm/release-0.10/deploy/klusterlet/components.yaml
💡
OCM组件
  • • cluster-manager：Hub集群的核心组件
  • • klusterlet：Managed集群的代理
  • • application-manager：应用分发
  • • policy-controller：策略管理

🔗 注册Managed集群

使用klusterlet注册

# 在Hub集群创建ManagedCluster cat > managed-cluster.yaml << 'EOF' apiVersion: cluster.open-cluster-management.io/v1 kind: ManagedCluster metadata: name: gpu-cluster-1 labels: cloud: aws region: us-west-2 gpu-count: "8" spec: hubAcceptsClient: true EOF kubectl apply -f managed-cluster.yaml # 获取bootstrap token kubectl get secret -n gpu-cluster-1 bootstrap-token-gpu-cluster-1 -o jsonpath='{.data.token}' | base64 -d # 在Managed集群安装klusterlet kubectl apply -f https://raw.githubusercontent.com/open-cluster-management-io/ocm/release-0.10/deploy/klusterlet/components.yaml # 配置klusterlet cat > klusterlet-config.yaml << 'EOF' apiVersion: operator.open-cluster-management.io/v1 kind: KlusterletConfig metadata: name: gpu-cluster-1 namespace: open-cluster-management-agent spec: clusterName: gpu-cluster-1 serverURL: https://hub-cluster-apiserver:6443 registrationImagePullSpec: quay.io/open-cluster-management/registration:latest workImagePullSpec: quay.io/open-cluster-management/work:latest EOF kubectl apply -f klusterlet-config.yaml
✅
验证注册
# 在Hub集群查看Managed集群状态 kubectl get managedclusters # 查看集群详情 kubectl describe managedcluster gpu-cluster-1

📤 应用分发

使用Placement规则

apiVersion: cluster.open-cluster-management.io/v1beta1 kind: Placement metadata: name: gpu-placement namespace: application-samples spec: predicates: - requiredClusterSelector: labelSelector: matchExpressions: - key: gpu-count operator: In values: - "4" - "8" - requiredClusterSelector: labelSelector: matchExpressions: - key: region operator: In values: - us-west-2 - us-east-1

分发应用

apiVersion: app.k8s.io/v1beta1 kind: Application metadata: name: pytorch-training-app namespace: application-samples spec: componentKinds: - group: apps.open-cluster-management.io kind: Subscription descriptor: description: PyTorch distributed training displayName: PyTorch Training keywords: - AI - Training links: - description: Training code url: https://github.com/example/pytorch-training type: training selector: matchExpressions: - key: app operator: In values: - pytorch-training --- apiVersion: apps.open-cluster-management.io/v1beta1 kind: Subscription metadata: name: pytorch-training-subscription namespace: application-samples labels: app: pytorch-training annotations: apps.open-cluster-management.io/github-path: deploy apps.open-cluster-management.io/github-branch: main spec: channel: application-samples/github-channel placement: placementRef: name: gpu-placement

🧠 跨集群AI任务调度

多集群训练策略

数据并行

不同集群处理不同数据分片。

  • 大规模数据处理
  • 地理位置分布
  • 数据本地性优化
# 集群1处理数据集A cluster1: data_shard = [A1, A2, A3] # 集群2处理数据集B cluster2: data_shard = [B1, B2, B3] # 集群3处理数据集C cluster3: data_shard = [C1, C2, C3]

模型并行

不同集群处理模型不同部分。

  • 超大模型训练
  • 显存限制场景
  • 流水线并行
# 集群1处理模型层1-10 cluster1: layers = [1, 2, ..., 10] # 集群2处理模型层11-20 cluster2: layers = [11, 12, ..., 20] # 集群3处理模型层21-30 cluster3: layers = [21, 22, ..., 30]

跨集群Ray集群

# 在多个集群部署Ray集群 # cluster1 - Ray Head apiVersion: ray.io/v1 kind: RayCluster metadata: name: ray-head namespace: ray-system spec: rayVersion: '2.8.0' headGroupSpec: rayStartParams: dashboard-host: '0.0.0.0' serviceType: LoadBalancer # 公网暴露 replicas: 1 --- # cluster2 - Ray Worker apiVersion: ray.io/v1 kind: RayCluster metadata: name: ray-worker-1 namespace: ray-system spec: rayVersion: '2.8.0' headGroupSpec: rayStartParams: address: "ray-head-ray-head.ray-system.svc.cluster.local:6379" replicas: 0 # 不创建Head workerGroupSpecs: - replicas: 4 groupName: worker template: spec: containers: - name: ray-worker resources: limits: nvidia.com/gpu: 2
✅
跨集群优势
  • • 提高总体训练吞吐量
  • • 利用不同地域的GPU资源
  • • 数据本地性优化
  • • 提高系统容错能力

⚖️ 策略管理

创建策略

apiVersion: policy.open-cluster-management.io/v1 kind: Policy metadata: name: gpu-policy namespace: policies spec: remediationAction: enforce disabled: false policy-templates: - objectDefinition: apiVersion: policy.open-cluster-management.io/v1 kind: ConfigurationPolicy metadata: name: gpu-quota spec: remediationAction: enforce namespaceSelector: include: - "gpu-*" object-templates: - complianceType: musthave objectDefinition: apiVersion: v1 kind: ResourceQuota metadata: name: gpu-quota spec: hard: nvidia.com/gpu: "10" --- apiVersion: policy.open-cluster-management.io/v1 kind: PlacementBinding metadata: name: gpu-policy-binding namespace: policies placementRef: name: gpu-placement apiGroup: cluster.open-cluster-management.io subjects: - name: gpu-policy kind: Policy apiGroup: policy.open-cluster-management.io

策略类型

策略类型 用途
ConfigurationPolicy 配置管理
CertificatePolicy 证书管理
IAMPolicy 权限管理
NamespacePolicy 命名空间管理
