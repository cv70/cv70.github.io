48.6 ARM TrustZone

ARM的安全架构技术

🎯 学习目标

  • 理解TrustZone的基本概念与架构
  • 掌握安全世界与非安全世界的隔离机制
  • 了解TrustZone的关键组件
  • 认识TrustZone在实际系统中的应用

TrustZone概述

ARM TrustZone是ARM架构的硬件级安全扩展，通过创建两个隔离的执行环境—— 安全世界（Secure World）和非安全世界（Normal World）， 实现了系统级的安全保护。

🔐 双世界架构

安全世界

  • 运行可信代码（TrustZone软件）
  • 访问所有硬件资源
  • 处理安全敏感操作
  • EL3权限级别
  • 存储密钥和敏感数据

非安全世界

  • 运行普通操作系统和应用
  • 受限访问硬件资源
  • 通过SMC调用安全服务
  • EL0/EL1权限级别
  • 无法直接访问安全资源

🏗️ TrustZone架构组件

💾

安全内存

TZC控制器保护安全区域

🔄

NS位

总线信号标识安全状态

⚙️

外设安全

安全外设只接受安全访问

🔄 世界切换机制

SMC（Secure Monitor Call）

非安全世界通过SMC指令请求安全世界服务：

// 非安全世界调用安全服务
mov x0, #SERVICE_ID    // 服务ID
mov x1, #param1        // 参数1
mov x2, #param2        // 参数2
smc #0                 // 切换到安全世界
// 结果通过x0-x3返回

📊 TrustZone应用场景

应用领域 安全功能 典型实现
移动支付 密钥管理、加密运算 Secure Element、TEE
DRM保护 内容解密、权限验证 Widevine、PlayReady
生物识别 指纹/人脸数据存储 TEE生物识别框架
设备启动 安全启动链验证 AFDD（Authenticated Firmware）
网络通信 TLS/SSL密钥保护 安全网络栈
⚠️
安全世界的重要性

即使非安全世界的操作系统被完全攻破，安全世界的代码和数据仍然受到保护。这是实现可信执行环境（TEE）的基础。

🚀 TrustZone for ARMv8-M

微控制器的安全扩展

ARMv8-M架构为Cortex-M33等处理器引入了TrustZone-M：

  • SAU（Security Attribution Unit）：内存区域安全属性定义
  • IDAU（Implementation Defined AU）：厂商自定义的安全区域
  • SG（Secure Gateway）：非安全到安全的跳转机制
  • 低开销设计：适合资源受限的MCU
