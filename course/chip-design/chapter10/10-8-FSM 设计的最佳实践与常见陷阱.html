10.8 FSM 设计的最佳实践与常见陷阱

有限状态机（FSM）设计

🎯 学习目标

  • 掌握FSM设计的最佳实践
  • 了解常见设计陷阱及避免方法
  • 理解三段式FSM的编码风格
  • 能够编写高质量的状态机代码

✅ FSM设计最佳实践

使用三段式编码

  • 第一段：状态寄存器（时序逻辑）
  • 第二段：次态逻辑（组合逻辑）
  • 第三段：输出逻辑（组合逻辑）

清晰分离时序和组合逻辑，便于综合和调试

使用参数定义状态

parameter IDLE = 3'b000;
parameter S1   = 3'b001;
parameter S2   = 3'b010;

使用有意义的名称，便于阅读和维护

完整的case语句

  • 覆盖所有状态
  • 添加default分支
  • 处理所有输入组合

异步复位

always @(posedge clk or posedge rst) begin
  if (rst) state <= IDLE;
  else     state <= next_state;
end

确保能恢复到已知状态

⚠️ 常见设计陷阱

陷阱1：锁存器推断

问题：在组合逻辑中，if或case语句分支不完整，综合工具会推断出锁存器。

解决：确保所有分支都有赋值，或使用default赋初值。

陷阱2：未处理的无效状态

问题：状态编码存在未定义的状态（如独热码的非独热值）。

解决：在default分支中跳转到安全状态（如IDLE）。

陷阱3：多驱动冲突

问题：在多个always块中对同一信号赋值。

解决：每个信号只在一个always块中赋值。

陷阱4：时序与组合逻辑混合

问题：在同一always块中混合时序和组合逻辑。

解决：严格分离，使用三段式编码风格。

📊 状态机编码风格对比

风格优点缺点
一段式代码紧凑难以综合优化
两段式较清晰输出可能有毛刺
三段式清晰，易优化代码较长

推荐：使用三段式编码风格

✅
设计检查清单

1. 所有状态都有定义
2. default分支跳转到安全状态
3. 组合逻辑无锁存器推断
4. 输出逻辑覆盖所有状态
5. 有异步复位到初始状态
6. 状态名称有意义
7. 无多驱动冲突
