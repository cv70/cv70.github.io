92.5 双重 Cookie 验证

无状态 CSRF 防护方案

🎯 学习目标

  • 理解双重 Cookie 验证原理
  • 掌握实现方法
  • 了解优缺点
  • 学会选择合适的防护方案

📚 双重 Cookie 验证原理

# 工作原理 1. 服务器生成随机 Token 2. Token 同时设置到 Cookie 和返回给前端 3. 前端发送请求时，从 Cookie 读取 Token 4. 将 Token 放入请求参数或请求头 5. 服务器验证 Cookie 和请求中的 Token 是否一致 # 为什么有效 ## CSRF 攻击的限制 - 攻击者可以发送 Cookie（浏览器自动携带） - 攻击者无法读取 Cookie（同源策略） - 攻击者无法获取正确的 Token 值 ## 双重 Cookie 验证 - Cookie 中的 Token：浏览器自动发送 - 请求中的 Token：前端代码读取后发送 - 两者必须匹配，攻击者无法满足 # 与 Session CSRF Token 的区别 ┌─────────────────┬──────────────────┬──────────────────┐ │ 对比项 │ Session Token │ 双重 Cookie │ ├─────────────────┼──────────────────┼──────────────────┤ │ 服务端存储 │ 需要 │ 不需要 │ │ 无状态 │ 否 │ 是 │ │ 实现复杂度 │ 中等 │ 简单 │ │ 安全性 │ 高 │ 中高 │ │ 子域名支持 │ 需要共享 Session │ 天然支持 │ └─────────────────┴──────────────────┴──────────────────┘
💡
适用场景

双重 Cookie 验证适合无状态 API、跨子域应用。对于高安全要求的应用，推荐使用 Session Token 方式。

🔧 实现 Double Cookie

# 服务端实现 import express from 'express'; import cookieParser from 'cookie-parser'; import crypto from 'crypto'; const app = express(); app.use(cookieParser()); // 生成 CSRF Token function generateCsrfToken(): string { return crypto.randomBytes(32).toString('hex'); } // 设置 CSRF Token 中间件 function csrfMiddleware(req, res, next) { // 检查是否已有 Token if (!req.cookies.csrfToken) { const token = generateCsrfToken(); res.cookie('csrfToken', token, { httpOnly: false, // 允许 JavaScript 读取 secure: true, sameSite: 'strict', }); res.locals.csrfToken = token; } else { res.locals.csrfToken = req.cookies.csrfToken; } next(); } // 验证 CSRF Token 中间件 function validateCsrf(req, res, next) { const cookieToken = req.cookies.csrfToken; const requestToken = req.headers['x-csrf-token'] || req.body._csrf || req.query._csrf; if (!cookieToken || !requestToken) { return res.status(403).json({ error: 'CSRF token missing' }); } if (cookieToken !== requestToken) { return res.status(403).json({ error: 'Invalid CSRF token' }); } next(); } // 获取 Token 接口 app.get('/api/csrf-token', csrfMiddleware, (req, res) => { res.json({ csrfToken: res.locals.csrfToken }); }); // 受保护的路由 app.post('/api/transfer', csrfMiddleware, validateCsrf, (req, res) => { // 处理请求 });

⚙️ 前端实现

# 方式一：从 Cookie 读取 // 读取 Cookie function getCookie(name: string): string | null { const match = document.cookie.match( new RegExp('(^| )' + name + '=([^;]+)') ); return match ? match[2] : null; } // 发送请求 async function transfer(to: string, amount: number) { const csrfToken = getCookie('csrfToken'); const response = await fetch('/api/transfer', { method: 'POST', headers: { 'Content-Type': 'application/json', 'X-CSRF-Token': csrfToken || '', }, body: JSON.stringify({ to, amount }), }); return response.json(); } # 方式二：axios 拦截器 import axios from 'axios'; // 读取 Cookie function getCsrfFromCookie(): string { const match = document.cookie.match(/csrfToken=([^;]+)/); return match ? match[1] : ''; } // 请求拦截器 axios.interceptors.request.use((config) => { const method = config.method?.toLowerCase(); if (['post', 'put', 'delete', 'patch'].includes(method || '')) { config.headers['X-CSRF-Token'] = getCsrfFromCookie(); } return config; }); # 方式三：表单提交 // 服务端渲染 <form action="/api/transfer" method="POST"> <input type="hidden" name="_csrf" id="csrfToken"> <!-- 其他字段 --> </form> <script> // 从 Cookie 读取并填充 const csrfToken = getCookie('csrfToken'); document.getElementById('csrfToken').value = csrfToken; </script>

🚀 安全注意事项

# 潜在风险 ## 1. Cookie 可被读取 - httpOnly: false 允许 JS 读取 - 如果存在 XSS 漏洞，Token 可被窃取 - 应确保 XSS 防护到位 ## 2. 子域名风险 - Cookie 可能被子域名访问 - 确保子域名安全 ## 3. HTTPS 必需 - secure: true 必须配置 - 防止中间人攻击 # 增强安全性 // 1. 使用独立的 CSRF Cookie res.cookie('csrfToken', token, { httpOnly: false, secure: true, sameSite: 'strict', path: '/api', // 限制路径 }); // 2. 添加过期时间 res.cookie('csrfToken', token, { httpOnly: false, secure: true, sameSite: 'strict', maxAge: 3600000, // 1 小时 }); // 3. Token 签名（可选） const signedToken = signToken(token, secret); // 4. 定期轮换 Token // 在敏感操作后重新生成 # 最佳实践推荐 ## 简单应用 双重 Cookie 验证 + SameSite Cookie ## 企业应用 Session CSRF Token + SameSite Cookie + Origin 验证 ## 高安全应用 多重验证 + 二次验证 + 监控告警
