73.3 测试隔离

第十部分：测试篇 - 保证测试的独立性和可靠性

1. 为什么需要测试隔离

测试隔离确保每个测试独立运行，不依赖其他测试的状态或执行顺序。

💡
隔离的好处
  • 测试可以并行执行
  • 测试失败不影响其他测试
  • 测试可以单独运行
  • 测试结果可重复

2. 隔离原则

✅ 应该做到

  • 每个测试有独立的初始状态
  • 测试后清理所有副作用
  • 不共享可变状态
  • 不依赖执行顺序

❌ 应该避免

  • 测试间共享变量
  • 依赖前一个测试的结果
  • 修改全局状态
  • 留下未清理的资源

3. 使用钩子函数隔离

describe('UserService', () => { let service: UserService; let mockRepository: jest.Mocked<UserRepository>; // 每个测试前重置状态 beforeEach(() => { mockRepository = createMockRepository(); service = new UserService(mockRepository); }); // 每个测试后清理 afterEach(() => { jest.clearAllMocks(); }); // 所有测试前执行一次 beforeAll(async () => { // 连接数据库等一次性操作 }); // 所有测试后执行一次 afterAll(async () => { // 关闭连接等清理操作 }); test('test 1', () => { // 使用独立的 service 实例 }); test('test 2', () => { // 使用另一个独立的 service 实例 }); });

4. 数据库隔离

describe('Database Tests', () => { let connection: Connection; beforeAll(async () => { // 使用内存数据库 connection = await createConnection({ type: 'sqlite', database: ':memory:', entities: [User], synchronize: true }); }); afterAll(async () => { await connection.close(); }); // 方式一：每个测试后清空数据 afterEach(async () => { await connection.getRepository(User).clear(); }); // 方式二：使用事务回滚 let queryRunner: QueryRunner; beforeEach(async () => { queryRunner = connection.createQueryRunner(); await queryRunner.startTransaction(); }); afterEach(async () => { await queryRunner.rollbackTransaction(); await queryRunner.release(); }); test('should create user', async () => { // 在事务中操作 const repo = queryRunner.manager.getRepository(User); await repo.save({ name: 'John' }); }); });

5. 隔离反模式

// ❌ 反模式：共享可变状态 describe('Bad Example', () => { let sharedUser: User; test('creates user', async () => { sharedUser = await service.create({ name: 'John' }); expect(sharedUser.id).toBeDefined(); }); test('updates user', async () => { // 依赖前一个测试创建的 user await service.update(sharedUser.id, { name: 'Jane' }); }); }); // ✅ 正确：独立测试 describe('Good Example', () => { test('creates user', async () => { const user = await service.create({ name: 'John' }); expect(user.id).toBeDefined(); }); test('updates user', async () => { // 独立创建测试数据 const user = await service.create({ name: 'John' }); const updated = await service.update(user.id, { name: 'Jane' }); expect(updated.name).toBe('Jane'); }); });

6. 全局状态隔离

describe('Environment Variables', () => { const originalEnv = process.env; beforeEach(() => { // 重置环境变量 jest.resetModules(); process.env = { ...originalEnv }; }); afterEach(() => { process.env = originalEnv; }); test('uses test environment', () => { process.env.NODE_ENV = 'test'; // ... }); }); describe('Global State', () => { let originalConfig: Config; beforeAll(() => { originalConfig = { ...globalConfig }; }); afterAll(() => { Object.assign(globalConfig, originalConfig); }); test('modifies config', () => { globalConfig.debug = true; // ... }); });

7. Mock 隔离

describe('Mock Isolation', () => { let mockFn: jest.Mock; beforeEach(() => { // 每个测试使用新的 Mock mockFn = jest.fn(); }); afterEach(() => { // 清理 Mock 调用记录 jest.clearAllMocks(); }); test('test 1', () => { mockFn.mockReturnValue('value1'); // ... }); test('test 2', () => { // 不会受 test 1 的影响 mockFn.mockReturnValue('value2'); // ... }); });

8. 本节小结

📚
关键要点
  • 每个测试应该有独立的初始状态
  • 使用 beforeEach/afterEach 重置状态
  • 使用事务或清空数据保证数据库隔离
  • 避免测试间共享可变状态
  • 每个测试后清理 Mock 和全局状态
