73.1 测试命名规范

第十部分：测试篇 - 编写清晰可读的测试

1. 为什么命名很重要

好的测试命名可以：

  • 作为代码文档，说明预期行为
  • 在测试失败时快速定位问题
  • 提高测试可读性和可维护性
  • 帮助新成员理解代码逻辑

2. 测试文件命名

# 推荐的命名方式 # 单元测试：与源文件对应 src/ services/ user.service.ts tests/ services/ user.service.spec.ts # 或 user.service.test.ts # E2E 测试：按功能模块 tests/ e2e/ auth.e2e-spec.ts users.e2e-spec.ts products.e2e-spec.ts

命名约定

测试类型 后缀 示例
单元测试 .spec.ts 或 .test.ts user.service.spec.ts
集成测试 .integration.spec.ts user.integration.spec.ts
E2E 测试 .e2e-spec.ts auth.e2e-spec.ts

3. describe 命名

// ✅ 好的命名：使用被测试的类或模块名 describe('UserService', () => { // ... }); describe('Calculator', () => { // ... }); // ✅ 嵌套 describe 使用方法名或功能名 describe('UserService', () => { describe('findById', () => { // ... }); describe('create', () => { describe('validation', () => { // ... }); }); }); // ❌ 不好的命名：模糊或不相关 describe('test user stuff', () => { // ... }); describe('tests', () => { // ... });

4. it/test 命名

命名模式

// 推荐的命名模式 // should + 预期行为 + when + 条件 it('should return user when user exists', () => {}); it('should throw error when user not found', () => {}); it('should create user when data is valid', () => {}); // 或更简洁的形式 it('returns user by id', () => {}); it('throws error for invalid input', () => {}); it('creates new user', () => {});

示例对比

// ✅ 好的命名：清晰描述预期行为 describe('UserService', () => { describe('findById', () => { it('should return user when user exists', async () => { // ... }); it('should return null when user not found', async () => { // ... }); it('should throw error when id is invalid', async () => { // ... }); }); describe('create', () => { it('should create user with valid data', async () => { // ... }); it('should reject duplicate email', async () => { // ... }); it('should validate required fields', async () => { // ... }); }); }); // ❌ 不好的命名 describe('UserService', () => { it('test 1', () => {}); it('works', () => {}); it('test create', () => {}); it('should work correctly', () => {}); // 太模糊 });

5. 命名风格指南

✅ 推荐做法

  • 使用完整的句子描述预期行为
  • 包含输入条件和预期结果
  • 使用 should/will 等情态动词
  • 描述具体的行为而非实现细节

❌ 避免做法

  • 使用模糊的名称
  • 只描述方法名
  • 使用技术术语代替业务含义
  • 过长的测试名称

更多示例

describe('PaymentService', () => { describe('processPayment', () => { it('should charge correct amount for valid card', () => {}); it('should decline payment for insufficient funds', () => {}); it('should refund payment within 30 days', () => {}); it('should apply discount for premium members', () => {}); }); describe('calculateTotal', () => { it('should sum all item prices', () => {}); it('should apply tax rate to subtotal', () => {}); it('should return 0 for empty cart', () => {}); it('should handle negative prices', () => {}); }); });

6. 变量命名

describe('UserService', () => { // ✅ 好的变量命名 it('should create user', async () => { const validUserData = { name: 'John Doe', email: 'john@example.com' }; const createdUser = await service.create(validUserData); expect(createdUser.id).toBeDefined(); }); it('should reject duplicate email', async () => { const existingUser = await createTestUser({ email: 'existing@example.com' }); const newUserWithSameEmail = { name: 'Jane', email: existingUser.email }; await expect(service.create(newUserWithSameEmail)) .rejects.toThrow(); }); // ❌ 不好的变量命名 it('test', async () => { const data = { name: 'John', email: 'john@example.com' }; const result = await service.create(data); expect(result.id).toBeDefined(); }); });

7. 测试输出示例

# 好的命名让测试报告更易读 PASS src/services/user.service.spec.ts UserService findById ✓ should return user when user exists (5 ms) ✓ should return null when user not found (1 ms) ✓ should throw error when id is invalid (1 ms) create ✓ should create user with valid data (2 ms) ✓ should reject duplicate email (3 ms) ✓ should validate required fields (1 ms) # 不好的命名难以理解 PASS src/services/user.service.spec.ts UserService ✓ test 1 ✓ test 2 ✓ test 3 ✓ works ✓ another test

8. 本节小结

📚
关键要点
  • 测试文件名应与源文件对应
  • describe 使用类名/模块名/方法名
  • it 使用 should + 行为 + 条件 模式
  • 变量名要有意义，描述数据用途
  • 好的命名就是最好的文档
