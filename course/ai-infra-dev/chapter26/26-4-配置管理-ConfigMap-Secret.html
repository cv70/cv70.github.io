26.4 配置管理

ConfigMap与Secret详解

🎯 学习目标

  • 掌握ConfigMap的创建与使用方法
  • 理解Secret的存储与安全机制
  • 学会配置注入的不同方式
  • 了解配置热更新与版本管理

📝 ConfigMap：应用配置

ConfigMap简介

ConfigMap用于存储非敏感的配置数据，如配置文件、命令行参数、环境变量等。 配置与镜像解耦，实现配置的集中管理和动态更新。

ConfigMap特性

  • 键值对存储
  • 支持多种数据格式
  • 可注入为环境变量
  • 可挂载为配置文件
  • 支持动态更新

使用场景

  • 应用配置文件
  • 命令行参数
  • 环境变量
  • 容器入口命令
  • 配置模板

📦 创建ConfigMap

方式1：命令行创建

# 从字面值创建 kubectl create configmap app-config \ --from-literal=app.name=myapp \ --from-literal=app.port=8080 \ --from-literal=log.level=info # 从文件创建 kubectl create configmap nginx-config \ --from-file=nginx.conf # 从目录创建 kubectl create configmap app-config \ --from-file=./config/ # 从环境文件创建 kubectl create configmap env-config \ --from-env-file=app.env

方式2：YAML创建

apiVersion: v1 kind: ConfigMap metadata: name: app-config namespace: default data: # 键值对形式 app.name: "myapp" app.port: "8080" log.level: "info" # 多行配置文件 nginx.conf: | user nginx; worker_processes auto; error_log /var/log/nginx/error.log; pid /run/nginx.pid; events { worker_connections 1024; } http { server { listen 80; server_name localhost; location / { root /usr/share/nginx/html; index index.html; } } }

💉 使用ConfigMap

方式1：环境变量

apiVersion: v1 kind: Pod metadata: name: configmap-pod spec: containers: - name: app image: nginx env: # 引用单个键 - name: APP_NAME valueFrom: configMapKeyRef: name: app-config key: app.name # 引用所有键 envFrom: - configMapRef: name: app-config

方式2：命令行参数

apiVersion: v1 kind: Pod metadata: name: configmap-args-pod spec: containers: - name: app image: myapp command: ["/bin/sh", "-c"] args: ["echo $(APP_NAME) is running on port $(APP_PORT)"] env: - name: APP_NAME valueFrom: configMapKeyRef: name: app-config key: app.name - name: APP_PORT valueFrom: configMapKeyRef: name: app-config key: app.port

方式3：挂载为文件

apiVersion: v1 kind: Pod metadata: name: configmap-volume-pod spec: containers: - name: app image: nginx volumeMounts: - name: config-volume mountPath: /etc/config readOnly: true volumes: - name: config-volume configMap: name: app-config # 可选：只挂载特定键 items: - key: nginx.conf path: nginx.conf
💡
挂载特性
  • • ConfigMap中的每个键都会被创建为文件
  • • 文件内容为键对应的值
  • • 更新ConfigMap会自动更新挂载的文件
  • • 可选使用subPath挂载单个文件

🔒 Secret：敏感信息管理

Secret简介

Secret用于存储敏感信息，如密码、密钥、证书、Token等。 数据以Base64编码存储，可以启用etcd加密提供更强保护。

⚠️
安全提示

Base64不是加密，只是编码。敏感数据应配合RBAC、etcd加密等安全措施使用。

🔑 Secret类型

类型 用途 键
Opaque 任意用户数据 自定义
kubernetes.io/service-account-token ServiceAccount Token token, ca.crt, namespace
kubernetes.io/dockercfg Docker Registry凭证 .dockercfg
kubernetes.io/dockerconfigjson Docker Registry凭证（新版） .dockerconfigjson
kubernetes.io/basic-auth 基本认证 username, password
kubernetes.io/ssh-auth SSH密钥 ssh-privatekey
kubernetes.io/tls TLS证书 tls.crt, tls.key

📦 创建Secret

Opaque Secret

# 命令行创建 kubectl create secret generic db-secret \ --from-literal=username=admin \ --from-literal=password=secret123 # YAML创建 apiVersion: v1 kind: Secret metadata: name: db-secret type: Opaque data: username: YWRtaW4= # admin的Base64编码 password: c2VjcmV0MTIz # secret123的Base64编码

TLS Secret

# 命令行创建 kubectl create secret tls tls-cert \ --cert=path/to/tls.crt \ --key=path/to/tls.key # YAML创建 apiVersion: v1 kind: Secret metadata: name: tls-cert type: kubernetes.io/tls data: tls.crt: LS0tLS1CRUdJTi... tls.key: LS0tLS1CRUdJTi...

Docker Registry Secret

# 命令行创建 kubectl create secret docker-registry regcred \ --docker-server=registry.example.com \ --docker-username=user \ --docker-password=password \ --docker-email=user@example.com

💉 使用Secret

apiVersion: v1 kind: Pod metadata: name: secret-pod spec: containers: - name: app image: nginx # 环境变量方式 env: - name: DB_USERNAME valueFrom: secretKeyRef: name: db-secret key: username # 挂载为文件方式 volumeMounts: - name: secret-volume mountPath: /etc/secrets readOnly: true # 拉取镜像凭证 imagePullSecrets: - name: regcred volumes: - name: secret-volume secret: secretName: db-secret defaultMode: 0400 # 设置文件权限

🔄 配置更新

ConfigMap/Secret更新机制

  • 环境变量：不会自动更新，需要重启Pod
  • Volume挂载：自动更新，但应用需要监听变化
  • 不可变：设置immutable防止意外修改
# 设置ConfigMap为不可变 apiVersion: v1 kind: ConfigMap metadata: name: app-config immutable: true data: app.name: "myapp"
✅
最佳实践
  • • 敏感信息使用Secret而非ConfigMap
  • • 生产环境启用etcd加密
  • • 使用版本化的配置文件
  • • 配置变更先在测试环境验证
  • • 使用CI/CD管理配置的创建和更新

📝 本节小结

💡
  • • ConfigMap用于非敏感配置，Secret用于敏感信息
  • • 配置可注入为环境变量或挂载为文件
  • • Secret支持多种预设类型
  • • 合理使用不可变配置和版本管理
