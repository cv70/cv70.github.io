26.5 存储管理

PV与PVC详解

🎯 学习目标

  • 理解PV和PVC的概念与关系
  • 掌握存储类的动态供给机制
  • 学会配置不同类型的存储卷
  • 了解存储卷的生命周期管理

💾 存储概念概述

为什么需要存储管理？

容器是临时的，容器重启后数据会丢失。Kubernetes通过存储卷（Volume） 提供持久化存储能力，让数据独立于容器生命周期。

图：Kubernetes存储架构

📦 核心概念

PV

PersistentVolume

集群级别的存储资源，由管理员或存储系统动态创建。

📌

独立于Pod生命周期存在

PVC

PersistentVolumeClaim

命名空间级别的存储请求，用户申请存储资源的方式。

📌

绑定到特定的PV

StorageClass

存储类

定义存储的"类型"，支持动态供给存储。

📌

动态创建PV

🔄 PV生命周期

Available（可用） → Bound（已绑定） → Released（已释放） → Failed（失败） ↓ Retained（保留）
阶段 说明
Available PV可用，未被任何PVC绑定
Bound PV已与PVC绑定
Released PVC被删除，但PV中的数据还未处理
Failed 自动回收失败
💡
回收策略
  • • Retain：手动回收，需要管理员清理数据
  • • Delete：自动删除底层存储资源
  • • Recycle：已废弃，使用Delete替代

📝 静态供给示例

1. 创建PV

apiVersion: v1 kind: PersistentVolume metadata: name: pv-nfs spec: capacity: storage: 10Gi accessModes: - ReadWriteMany persistentVolumeReclaimPolicy: Retain storageClassName: nfs nfs: server: 192.168.1.100 path: /data/nfs

2. 创建PVC

apiVersion: v1 kind: PersistentVolumeClaim metadata: name: pvc-nfs namespace: default spec: accessModes: - ReadWriteMany resources: requests: storage: 5Gi storageClassName: nfs

3. 在Pod中使用

apiVersion: v1 kind: Pod metadata: name: pod-with-pvc spec: containers: - name: app image: nginx volumeMounts: - name: data mountPath: /usr/share/nginx/html volumes: - name: data persistentVolumeClaim: claimName: pvc-nfs

🚀 动态供给

动态供给优势

  • 无需预先创建PV
  • 自动匹配PVC和StorageClass
  • 支持多种存储后端
  • 简化存储管理

StorageClass示例

# AWS EBS StorageClass apiVersion: storage.k8s.io/v1 kind: StorageClass metadata: name: ebs-sc provisioner: kubernetes.io/aws-ebs parameters: type: gp3 fsType: ext4 encrypted: "true" reclaimPolicy: Delete allowVolumeExpansion: true volumeBindingMode: WaitForFirstConsumer --- # NFS StorageClass（需要NFS CSI驱动） apiVersion: storage.k8s.io/v1 kind: StorageClass metadata: name: nfs-sc provisioner: nfs.csi.k8s.io parameters: server: 192.168.1.100 share: /data/nfs reclaimPolicy: Retain allowVolumeExpansion: true volumeBindingMode: Immediate
✅
卷绑定模式
  • • Immediate：PVC创建时立即绑定
  • • WaitForFirstConsumer：延迟到Pod使用时绑定，支持拓扑感知

📊 访问模式

访问模式 说明 支持的后端
RWO ReadWriteOnce：单节点读写 大多数存储
RWX ReadWriteMany：多节点读写 NFS, CephFS
ROX ReadOnlyMany：多节点只读 NFS, CephFS
RWOP ReadWriteOncePod：单Pod读写 部分CSI驱动

🔧 常用存储类型

临时存储

  • emptyDir：临时目录
  • Pod删除后数据丢失
  • 用于缓存、临时文件
volumes: - name: cache emptyDir: sizeLimit: 1Gi

节点本地存储

  • hostPath：节点路径
  • Pod重启数据保留
  • 节点故障数据丢失
volumes: - name: host-data hostPath: path: /data type: DirectoryOrCreate

配置存储

  • configMap：配置文件
  • secret：敏感信息
  • downwardAPI：Pod信息

云存储

  • AWS EBS
  • Azure Disk
  • GCE PD
  • 阿里云盘

🔍 状态查询

# 查看PV kubectl get pv kubectl describe pv pv-name # 查看PVC kubectl get pvc -A kubectl describe pvc pvc-name # 查看StorageClass kubectl get sc kubectl describe sc sc-name # 查看PV使用情况 kubectl get pv -o custom-columns=NAME:.metadata.name,CAPACITY:.spec.capacity.storage,STATUS:.status.phase

⚠️ 常见问题

⚠️
PVC一直Pending
  • • 没有匹配的PV
  • • StorageClass不存在
  • • 访问模式不匹配
  • • 容量不足
⚠️
Pod无法挂载
  • • CSI驱动未安装
  • • 存储后端连接失败
  • • 权限不足
  • • 卷已绑定给其他PVC
✅
最佳实践
  • • 生产环境优先使用动态供给
  • • 为不同工作负载创建不同的StorageClass
  • • 设置合理的资源请求和限制
  • • 定期监控存储使用情况
  • • 制定数据备份策略

📝 本节小结

💡
  • • PV是存储资源，PVC是存储请求
  • • StorageClass支持动态供给存储
  • • 根据访问模式选择合适的存储类型
  • • 合理配置回收策略和扩容策略
