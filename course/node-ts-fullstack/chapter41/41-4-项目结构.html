41.4 项目结构

了解 NestJS 项目的目录结构

🎯 学习目标

  • 理解项目的目录结构
  • 了解各配置文件的作用
  • 掌握源代码的组织方式
  • 了解构建输出目录

📁 默认目录结构

my-nest-project/ ├── node_modules/ # 依赖包 ├── src/ # 源代码目录 │ ├── app.controller.spec.ts # 控制器单元测试 │ ├── app.controller.ts # 应用控制器 │ ├── app.module.ts # 应用根模块 │ ├── app.service.ts # 应用服务 │ └── main.ts # 应用入口文件 ├── test/ # e2e 测试目录 │ ├── app.e2e-spec.ts │ └── jest-e2e.json ├── .eslintrc.js # ESLint 配置 ├── .gitignore # Git 忽略文件 ├── .prettierrc # Prettier 配置 ├── nest-cli.json # Nest CLI 配置 ├── package.json # 项目配置 ├── README.md # 项目说明 ├── tsconfig.build.json # 构建时 TS 配置 └── tsconfig.json # TypeScript 配置

📚 核心文件说明

文件 作用
main.ts 应用入口，创建 Nest 应用实例并启动
app.module.ts 根模块，组织所有模块和组件
app.controller.ts 根控制器，处理根路由请求
app.service.ts 根服务，提供业务逻辑
nest-cli.json Nest CLI 配置文件
tsconfig.json TypeScript 编译配置

🔧 main.ts 入口文件

import { NestFactory } from '@nestjs/core'; import { AppModule } from './app.module'; async function bootstrap() { // 创建 Nest 应用实例 const app = await NestFactory.create(AppModule); // 设置全局前缀 app.setGlobalPrefix('api'); // 启用 CORS app.enableCors(); // 监听端口 await app.listen(3000); console.log(`Application is running on: ${await app.getUrl()}`); } bootstrap();
💡
NestFactory

NestFactory 是创建 Nest 应用的工厂类，create() 方法返回一个应用实例，支持配置 Express 或 Fastify 作为底层 HTTP 服务器。

📦 模块化目录结构

推荐按功能模块组织项目结构：

src/ ├── modules/ # 功能模块 │ ├── users/ │ │ ├── dto/ # 数据传输对象 │ │ ├── entities/ # 数据库实体 │ │ ├── users.controller.ts │ │ ├── users.service.ts │ │ └── users.module.ts │ └── auth/ │ ├── dto/ │ ├── auth.controller.ts │ ├── auth.service.ts │ └── auth.module.ts ├── common/ # 公共模块 │ ├── decorators/ # 自定义装饰器 │ ├── filters/ # 异常过滤器 │ ├── guards/ # 守卫 │ ├── interceptors/ # 拦截器 │ └── pipes/ # 管道 ├── config/ # 配置文件 └── main.ts

📝 本节小结

✅
  • • src/ 是源代码目录，main.ts 是入口文件
  • • app.module.ts 是根模块
  • • 推荐按功能模块组织项目结构
  • • common/ 存放公共组件如守卫、拦截器等
