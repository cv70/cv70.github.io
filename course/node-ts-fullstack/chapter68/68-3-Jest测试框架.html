68.3 Jest 测试框架

第十部分：测试篇 - 认识 JavaScript/TypeScript 最流行的测试框架

1. Jest 简介

Jest 是由 Facebook 开发的 JavaScript 测试框架，专注于简洁性和性能。它是目前最流行的 JavaScript/TypeScript 测试框架之一。

💡
为什么选择 Jest？

Jest 开箱即用，无需复杂配置，内置断言、Mock、快照测试等功能，是 React 官方推荐的测试框架。

Jest 核心特性

  • 零配置开箱即用
  • 内置断言库和 Mock 功能
  • 支持快照测试
  • 并行测试执行，速度快
  • 内置代码覆盖率报告
  • 完美的 TypeScript 支持
  • 优秀的 Watch 模式

2. 安装 Jest

安装核心依赖

# 安装 Jest 核心和 TypeScript 支持 npm install --save-dev jest ts-jest @types/jest # 或者使用 yarn yarn add --dev jest ts-jest @types/jest

package.json 配置

{ "scripts": { "test": "jest", "test:watch": "jest --watch", "test:coverage": "jest --coverage" }, "devDependencies": { "jest": "^29.7.0", "ts-jest": "^29.1.1", "@types/jest": "^29.5.11" } }
✅
版本说明

推荐使用 Jest 29+ 版本，它提供了更好的 TypeScript 支持和性能优化。

3. Jest 工作原理

1
发现测试文件
2
编译 TypeScript
3
执行测试
4
生成报告

测试文件命名约定

Jest 默认会查找以下模式的文件作为测试文件：

# 测试文件命名模式 *.test.ts # 例如：calculator.test.ts *.spec.ts # 例如：calculator.spec.ts __tests__/*.ts # 例如：__tests__/calculator.ts

测试执行流程

阶段 说明
收集阶段 扫描项目，找出所有测试文件
编译阶段 使用 ts-jest 将 TypeScript 编译为 JavaScript
执行阶段 并行运行所有测试
报告阶段 输出测试结果和覆盖率报告

4. Jest 基本语法

测试结构

// 基本测试结构 describe('测试套件名称', () => { // 测试前后的钩子 beforeAll(() => { // 所有测试前执行一次 }); afterAll(() => { // 所有测试后执行一次 }); beforeEach(() => { // 每个测试前执行 }); afterEach(() => { // 每个测试后执行 }); // 测试用例 test('测试用例描述', () => { // 测试逻辑 expect(1 + 1).toBe(2); }); // it 是 test 的别名 it('也可以用 it', () => { expect(true).toBeTruthy(); }); });

断言方式

// expect 断言 test('基本断言示例', () => { // 相等性 expect(1 + 1).toBe(2); // 严格相等 === expect({ a: 1 }).toEqual({ a: 1 }); // 深度相等 // 真值 expect(true).toBeTruthy(); expect(false).toBeFalsy(); expect(null).toBeNull(); expect(undefined).toBeUndefined(); // 数字比较 expect(5).toBeGreaterThan(3); expect(5).toBeLessThan(10); expect(0.1 + 0.2).toBeCloseTo(0.3); // 字符串匹配 expect('hello world').toMatch(/world/); expect('hello world').toContain('world'); // 数组 expect([1, 2, 3]).toContain(2); expect([1, 2, 3]).toHaveLength(3); // 异常 expect(() => { throw new Error('error'); }).toThrow('error'); });

5. Jest 常用命令

命令 说明
npm test 运行所有测试
npm test -- --watch 监视模式，文件变化自动重新测试
npm test -- --coverage 生成覆盖率报告
npm test -- --verbose 显示详细输出
npm test filename 只运行指定文件的测试
npm test -- -t "pattern" 只运行匹配的测试用例
npm test -- --detectOpenHandles 检测未关闭的资源
# 运行特定测试文件 npm test calculator.test.ts # 运行匹配名称的测试 npm test -- -t "should add numbers" # 监视模式下只运行相关测试 npm test -- --watch --testPathPattern=calculator

6. Jest 配置文件

jest.config.js

/** @type {import('ts-jest').JestConfigWithTsJest} */ module.exports = { // 预设配置 preset: 'ts-jest', // 测试环境 testEnvironment: 'node', // 根目录 roots: ['<rootDir>/src'], // 测试文件匹配模式 testMatch: [ '**/__tests__/**/*.+(ts|tsx|js)', '**/?(*.)+(spec|test).+(ts|tsx|js)' ], // 转换配置 transform: { '^.+\\.(ts|tsx)$': ['ts-jest', { tsconfig: 'tsconfig.json' }] }, // 模块路径映射 moduleNameMapper: { '^@/(.*)$': '<rootDir>/src/$1', '^@tests/(.*)$': '<rootDir>/tests/$1' }, // 覆盖率配置 collectCoverageFrom: [ 'src/**/*.{ts,tsx}', '!src/**/*.d.ts', '!src/**/index.ts' ], // 覆盖率阈值 coverageThreshold: { global: { branches: 80, functions: 80, lines: 80, statements: 80 } } };

7. Jest 与其他框架对比

特性 Jest Mocha Vitest
配置复杂度 低（零配置） 高（需要组合） 低（零配置）
内置断言 是 否（需 Chai） 是
内置 Mock 是 否（需 Sinon） 是
快照测试 是 否 是
执行速度 快 中等 极快
Watch 模式 优秀 基础 优秀
生态成熟度 高 高 发展中
⚠️
选择建议

Jest 适合大多数 Node.js 项目；Vitest 更适合 Vite 项目，启动更快；Mocha 适合需要高度定制化的项目。

8. 本节小结

📚
关键要点
  • Jest 是功能全面、零配置的测试框架
  • 内置断言、Mock、快照测试等功能
  • 支持 TypeScript，需要 ts-jest 预设
  • 测试文件命名约定：*.test.ts 或 *.spec.ts
  • Watch 模式提供即时反馈，提升开发效率
