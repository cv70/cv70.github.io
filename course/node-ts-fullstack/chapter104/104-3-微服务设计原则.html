104.3 微服务设计原则

构建高质量微服务的指导原则

🎯 学习目标

  • 掌握单一职责原则
  • 理解服务自治原则
  • 学习去中心化原则
  • 了解容错设计原则

📚 单一职责原则

// 每个服务只负责一个业务能力 // 错误示例：一个服务承担过多职责 class BadOrderService { // 订单相关 createOrder() {} cancelOrder() {} // 用户相关（不应该在这里） getUser() {} updateUserProfile() {} // 支付相关（不应该在这里） processPayment() {} refundPayment() {} // 库存相关（不应该在这里） updateInventory() {} checkInventory() {} } // 正确示例：职责清晰的服务 class OrderService { // 只处理订单相关的逻辑 async createOrder(orderData: CreateOrderDto) { // 调用其他服务完成相关工作 await this.userService.validateUser(orderData.userId); await this.inventoryService.reserveItems(orderData.items); await this.paymentService.processPayment(orderData.payment); return this.orderRepository.create(orderData); } async cancelOrder(orderId: string) { const order = await this.orderRepository.findById(orderId); if (order.canCancel()) { await this.inventoryService.releaseItems(order.items); await this.paymentService.refund(order.paymentId); await this.orderRepository.updateStatus(orderId, 'cancelled'); } } }
💡
服务粒度

服务粒度要适中，太大导致耦合，太小增加通信开销。一般遵循"一个服务=一个业务能力"的原则。

🔧 服务自治原则

// 服务应该独立自治，不依赖其他服务的内部实现 interface UserService { // 只暴露必要的接口 getUser(id: string): Promise; validateToken(token: string): Promise; createUser(data: CreateUserDto): Promise; } class OrderService { // 依赖抽象接口，而非具体实现 constructor( private readonly userService: UserService, private readonly eventBus: EventBus ) {} async createOrder(userId: string, items: OrderItem[]) { // 通过接口调用，不关心对方如何实现 const user = await this.userService.getUser(userId); // 发布事件，让其他服务自行决定如何响应 this.eventBus.publish('order.created', { orderId: this.generateOrderId(), userId, items, createdAt: new Date() }); } } // 每个服务有自己的数据存储 // 不直接访问其他服务的数据库

🛡️ 容错设计原则

// 假设任何服务都可能失败，设计时考虑容错 import { CircuitBreaker } from 'opossum'; class OrderService { private userClient: UserClient; private inventoryClient: InventoryClient; // 使用熔断器保护服务调用 private getUserBreaker: CircuitBreaker; private checkInventoryBreaker: CircuitBreaker; constructor() { // 配置熔断器 this.getUserBreaker = new CircuitBreaker( (id: string) => this.userClient.getUser(id), { timeout: 3000, errorThresholdPercentage: 50, resetTimeout: 30000 } ); // 设置降级策略 this.getUserBreaker.fallback(() => ({ id: 'unknown', name: 'Guest User', isGuest: true })); } async createOrder(userId: string, items: OrderItem[]) { // 使用熔断器调用 const user = await this.getUserBreaker.fire(userId); // 超时和重试策略 const inventory = await this.checkInventoryWithRetry(items); // 幂等性设计：防止重复创建 const idempotencyKey = this.generateIdempotencyKey(userId, items); const existingOrder = await this.findOrderByIdempotencyKey(idempotencyKey); if (existingOrder) { return existingOrder; } return this.createOrderInternal(userId, items); } private async checkInventoryWithRetry(items: OrderItem[], retries = 3) { for (let i = 0; i < retries; i++) { try { return await this.inventoryClient.checkAvailability(items); } catch (error) { if (i === retries - 1) throw error; await this.delay(1000 * Math.pow(2, i)); // 指数退避 } } } }

📝 本节小结

✅
  • • 单一职责：每个服务专注一个业务能力
  • • 服务自治：独立开发、部署、运行
  • • 去中心化：数据和治理分散管理
  • • 容错设计：假设失败，设计降级方案
