70.2 快照测试

第十部分：测试篇 - 掌握快照测试技术

1. 快照测试简介

快照测试是一种测试方法，它会保存值的快照，并在后续测试中比较当前值是否与快照匹配。

💡
快照测试的价值
  • 捕获意外的变化
  • 适合测试配置对象、API 响应、UI 组件渲染结果
  • 减少手动编写断言的工作量
  • 作为"活文档"记录预期输出

2. toMatchSnapshot

// 基本快照测试 describe('Snapshot Testing', () => { test('object snapshot', () => { const user = { name: 'John Doe', email: 'john@example.com', age: 30 }; // 第一次运行会创建快照 // 后续运行会比较是否匹配 expect(user).toMatchSnapshot(); }); test('array snapshot', () => { const items = [ { id: 1, name: 'Item 1' }, { id: 2, name: 'Item 2' }, { id: 3, name: 'Item 3' } ]; expect(items).toMatchSnapshot(); }); });

生成的快照文件

// __snapshots__/example.test.ts.snap exports[`Snapshot Testing array snapshot 1`] = ` Array [ Object { "id": 1, "name": "Item 1", }, Object { "id": 2, "name": "Item 2", }, Object { "id": 3, "name": "Item 3", }, ] `;

3. toMatchInlineSnapshot

// 内联快照：快照内容直接写在代码中 describe('Inline Snapshot', () => { test('inline object snapshot', () => { const config = { apiUrl: 'https://api.example.com', timeout: 5000, retries: 3 }; // 快照内容会自动生成并插入到代码中 expect(config).toMatchInlineSnapshot(` Object { "apiUrl": "https://api.example.com", "retries": 3, "timeout": 5000, } `); }); test('string inline snapshot', () => { const greeting = 'Hello, World!'; expect(greeting).toMatchInlineSnapshot(`"Hello, World!"`); }); });
💡
内联快照 vs 外部快照
  • 内联快照：快照在测试文件中，便于代码审查
  • 外部快照：快照在独立文件中，适合大型对象

4. 属性匹配器

// 对于动态值，使用属性匹配器 describe('Property Matchers', () => { test('user with dynamic values', () => { const user = { id: 'random-uuid-12345', name: 'John Doe', createdAt: new Date(), updatedAt: new Date() }; // 对于动态值，使用 expect.any expect(user).toMatchSnapshot({ id: expect.any(String), createdAt: expect.any(Date), updatedAt: expect.any(Date) }); }); test('API response with dynamic data', () => { const response = { data: { users: [ { id: 'user-1', name: 'John' }, { id: 'user-2', name: 'Jane' } ] }, meta: { total: 2, page: 1, timestamp: Date.now() } }; expect(response).toMatchSnapshot({ meta: { total: expect.any(Number), page: expect.any(Number), timestamp: expect.any(Number) } }); }); });

5. 更新快照

# 当快照不匹配且是预期变化时，更新快照 # 更新所有失败的快照 npm test -- -u # 或 npm test -- --updateSnapshot # 只更新特定测试的快照 npm test -- -u -t "test name"
⚠️
注意事项

更新快照时应该仔细审查变化，确保不是 Bug 导致的不匹配。建议在代码审查中检查快照变化。

6. 快照测试最佳实践

应该测试的

// ✅ 配置对象 test('default config', () => { expect(getDefaultConfig()).toMatchSnapshot(); }); // ✅ API 响应结构 test('API response structure', async () => { const response = await fetchUser(1); expect(response).toMatchSnapshot({ id: expect.any(String), createdAt: expect.any(String) }); }); // ✅ 生成的代码 test('generated code', () => { const code = generateCode(schema); expect(code).toMatchSnapshot(); });

应该避免的

// ❌ 避免快照过大 test('large data', () => { // 快照太大，难以审查 expect(largeDataset).toMatchSnapshot(); }); // ❌ 避免快照频繁变化 test('timestamp', () => { expect({ time: Date.now() }).toMatchSnapshot(); }); // ✅ 正确做法：使用属性匹配器 test('timestamp', () => { expect({ time: Date.now() }).toMatchSnapshot({ time: expect.any(Number) }); });

8. 异常快照

describe('Error Snapshots', () => { test('error message snapshot', () => { const error = new Error('Something went wrong'); expect(error).toMatchSnapshot(); }); test('toThrowErrorMatchingSnapshot', () => { const throwError = () => { throw new Error('Custom error message'); }; expect(throwError).toThrowErrorMatchingSnapshot(); }); test('toThrowErrorMatchingInlineSnapshot', () => { const throwError = () => { throw new Error('Custom error message'); }; expect(throwError).toThrowErrorMatchingInlineSnapshot(`"Custom error message"`); }); });

9. 快照文件管理

# 快照文件结构 __snapshots__/ api.test.ts.snap config.test.ts.snap user.test.ts.snap # .gitignore 通常不忽略快照文件 # 快照应该提交到版本控制 # 清理未使用的快照 npm test -- -u --testPathPattern="none"

快照文件配置

10. 本节小结

📚
关键要点
  • toMatchSnapshot 将快照保存在独立文件
  • toMatchInlineSnapshot 将快照嵌入测试代码
  • 使用属性匹配器处理动态值
  • 快照应该提交到版本控制
  • 避免快照过大或过于频繁变化
