16.5 混合并行策略

组合多种并行策略，实现最优训练效率

🎯 学习目标

  • 理解混合并行的必要性
  • 掌握常见的混合并行组合
  • 了解如何设计并行策略
  • 认识业界最佳实践

什么是混合并行？

混合并行（Hybrid Parallelism）是指同时使用多种并行策略来训练模型。 没有一种并行策略是完美的，不同的策略各有优劣。通过组合多种策略， 可以充分利用集群资源，达到最优的训练效率。

🔄 为什么需要混合并行？

单一并行策略的局限性

数据并行的局限： • 显存限制：每个GPU需要存储完整模型 • 通信瓶颈：大规模集群下通信开销大 模型并行的局限： • 实现复杂：需要手动划分模型 • 通信频繁：张量并行通信密集 • 可扩展性：张量并行不适合大规模集群 流水线并行的局限： • 流水线气泡：填充和排水阶段GPU空闲 • 微批次调优：需要仔细调整 • 负载均衡：难以保证完全均衡 混合并行的优势： • 结合多种策略的优点 • 规避单一策略的缺点 • 适应不同的场景需求 • 最大化资源利用率

⚙️ 常见混合并行组合

数据并行 + 模型并行

最常用的组合，兼顾显存和效率

  • 模型并行：解决显存限制
  • 数据并行：提升训练速度
  • 适用：大模型训练
示例配置： • 8节点 × 8 GPU = 64 GPU • 模型并行：8（跨节点） • 数据并行：8（节点内） • 每个：张量并行 × 数据并行

张量并行 + 流水线并行

Megatron-LM的经典组合

  • 张量并行：层内并行
  • 流水线并行：层间并行
  • 适用：超大模型
示例配置： • 128 GPU • 张量并行：8 • 流水线并行：16 • 总并行度：8 × 16 = 128

🏗️ 三维并行架构

DeepSpeed + Megatron-LM的三维并行

最强大的并行组合，支持万卡级别训练。

三维并行维度： 1. 数据并行（Data Parallelism, DP） • 多个副本并行处理不同数据 • 通过AllReduce同步梯度 • 支持梯度累积 2. 张量并行（Tensor Parallelism, TP） • 单个张量切分到多个GPU • 层内并行 • 高带宽通信 3. 流水线并行（Pipeline Parallelism, PP） • 模型层分配到不同GPU • 层间并行 • 1F1B调度 示例：训练GPT-3 175B模型 配置： • 总GPU数：1024 • DP：32 • TP：8 • PP：4 • 验证：32 × 8 × 4 = 1024 ✓ 显存分配： • 每GPU模型参数：175B / (TP×PP) = 175B / 32 = 5.5B • 使用FP16：5.5B × 2 bytes = 11GB • 加上梯度和优化器状态：约35GB • A100 80GB显存可以满足
图：三维并行架构结合了数据、张量和流水线并行

📊 并行策略设计指南

如何选择并行策略？

场景 推荐策略 理由
小模型（<1B） 纯数据并行 实现简单，效率高
中模型（1-10B） DP + TP 平衡显存和通信
大模型（10-100B） DP + TP + PP 充分利用资源
超大模型（>100B） 3D并行 + ZeRO 极致显存优化

🔧 并行度分配策略

如何分配DP、TP、PP？

给定总GPU数，需要合理分配各维度的并行度。

分配原则： 1. 优先保证数据并行 • 数据并行对通信要求相对较低 • 可以使用梯度累积减少同步频率 • 建议DP ≥ 4 2. 张量并行度不宜过大 • TP通信密集，需要高带宽 • 建议TP ≤ 8（通常4或8） • 单机内TP效果最好 3. 流水线并行度适中 • PP会增加流水线气泡 • 建议PP ≤ 16 • 与TP配合使用 示例计算： 总GPU：256 方案1： • TP = 4 • PP = 4 • DP = 256 / (4×4) = 16 • 评价：DP较小，但通信开销可控 方案2： • TP = 8 • PP = 4 • DP = 256 / (8×4) = 8 • 评价：DP偏小，可能影响训练速度 方案3（推荐）： • TP = 4 • PP = 2 • DP = 256 / (4×2) = 32 • 评价：DP较大，通信开销适中

🏢 集群拓扑感知并行

根据集群拓扑设计并行策略

利用集群的层次结构优化并行效率。

集群层次结构： ┌─────────────────────────────────────┐ │ 节点间网络（高速互联） │ │ ┌───────┐ ┌───────┐ ┌───────┐ │ │ │Node 0 │ │Node 1 │ │Node 2 │ │ │ │ │ │ │ │ │ │ │ │GPU0-7 │ │GPU0-7 │ │GPU0-7 │ │ │ │ NVLink│ │ NVLink│ │ NVLink│ │ │ └───────┘ └───────┘ └───────┘ │ └─────────────────────────────────────┘ 并行策略设计： 1. 节点内：张量并行 • NVLink提供高带宽低延迟 • TP通信密集，适合NVLink 2. 节点间：流水线并行 • PP通信较少，可以容忍网络延迟 • 每个节点包含一个或多个流水线阶段 3. 全局：数据并行 • 使用InfiniBand/RoCE同步梯度 • 可以跨越多个机架 示例：32节点 × 8 GPU = 256 GPU 配置： • 节点内TP = 8（NVLink） • 跨节点PP = 4（8个节点/流水线） • 数据并行副本 = 32 / 4 = 8 通信路径： TP：NVLink（300GB/s） PP：节点间网络（200-400Gbps） DP：InfiniBand AllReduce
💡
并行策略优化技巧
  • 监控通信时间：确保计算时间 >> 通信时间
  • 调整batch size：增大batch size可掩盖通信开销
  • 使用混合精度：FP16/BF16可减少通信数据量
  • 梯度压缩：进一步减少通信量
  • 通信计算重叠：异步通信与计算并行

🔮 未来趋势

自动化并行优化

随着模型规模增长，手动设计并行策略越来越困难。自动化工具正在兴起。

  • Alpa：自动优化和编译并行策略
  • GSPMD：Google的自动并行编译器
  • Ray Tune：自动搜索最优并行配置
  • Triton：可扩展的并行计算语言
💡

未来，自动化并行工具将使并行策略设计更加简单，让开发者专注于模型本身而非底层并行细节。
