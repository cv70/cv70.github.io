21.3 非关系型数据库

探索 NoSQL 数据库的多样化世界

🎯 学习目标

  • 理解 NoSQL 数据库的特点
  • 掌握四种主要 NoSQL 类型
  • 了解各类型的应用场景
  • 学会对比选择合适的数据库

📚 NoSQL 特点

NoSQL（Not Only SQL）数据库是为了解决大规模数据集合和多重数据种类挑战而设计的数据库系统。

NoSQL 主要特点： ├── 灵活的数据模型：无需预定义模式 ├── 水平扩展：轻松添加更多节点 ├── 高性能：针对特定场景优化 ├── 弱一致性：BASE 模型 └── 大数据支持：处理海量数据 BASE 模型： ├── Basically Available（基本可用） ├── Soft State（软状态） └── Eventually Consistent（最终一致性）
💡
CAP 定理

分布式系统最多只能同时满足三项中的两项：一致性（Consistency）、可用性（Availability）、分区容错性（Partition tolerance）。

🔧 四种 NoSQL 类型

1. 文档型数据库（Document Store） 代表：MongoDB、CouchDB { "_id": "user_001", "name": "Alice", "email": "alice@mail.com", "address": { "city": "Beijing", "zip": "100000" }, "tags": ["developer", "nodejs"] } 2. 键值型数据库（Key-Value Store） 代表：Redis、DynamoDB SET user:001 '{"name":"Alice","age":25}' GET user:001 INCR page_views 3. 列族型数据库（Column-Family Store） 代表：Cassandra、HBase Users = { "user_001": { "profile:name": "Alice", "profile:email": "alice@mail.com", "stats:login_count": 100 } } 4. 图数据库（Graph Database） 代表：Neo4j、JanusGraph CREATE (u:User {name: 'Alice'}) CREATE (p:Post {title: 'Hello'}) CREATE (u)-[:PUBLISHED]->(p)

📊 应用场景对比

类型 适用场景 代表产品
文档型 内容管理、日志分析、用户画像 MongoDB
键值型 缓存、会话存储、计数器 Redis
列族型 时序数据、物联网、大数据分析 Cassandra
图数据库 社交网络、推荐系统、知识图谱 Neo4j

📝 本节小结

✅
  • • NoSQL 适合非结构化和半结构化数据
  • • 文档型适合内容管理和复杂数据结构
  • • 键值型适合缓存和高性能读写
  • • 选择数据库需根据具体业务场景
