74.3 前后端分离

解耦前后端开发流程

🎯 学习目标

  • 理解前后端分离的概念
  • 掌握 RESTful API 设计
  • 了解前后端协作方式
  • 认识分离架构的优缺点

📚 传统架构 vs 分离架构

// 传统架构：服务端渲染（SSR） // 浏览器 ──请求──> 服务器 ──返回 HTML──> 浏览器 // 前端代码嵌入在后端项目中 // 后端代码示例（传统方式） app.get('/users', (req, res) => { const users = db.query('SELECT * FROM users'); // 服务端拼接 HTML const html = ` <html> <body> <ul> ${users.map(u => `<li>${u.name}</li>`).join('')} </ul> </body> </html> `; res.send(html); }); // 前后端分离架构 // 浏览器 ──请求静态资源──> CDN/Nginx // 浏览器 ──请求 API──> API 服务器 ──返回 JSON──> 浏览器 // 后端代码示例（分离方式） app.get('/api/users', (req, res) => { const users = db.query('SELECT * FROM users'); res.json({ users }); // 只返回数据 }); // 前端代码示例 async function fetchUsers() { const response = await fetch('/api/users'); const { users } = await response.json(); // 前端负责渲染 renderUsers(users); }

🔧 RESTful API 设计

// RESTful API 设计原则 // 资源命名：使用名词复数 GET /api/users // 获取用户列表 GET /api/users/:id // 获取单个用户 POST /api/users // 创建用户 PUT /api/users/:id // 更新用户（完整） PATCH /api/users/:id // 更新用户（部分） DELETE /api/users/:id // 删除用户 // 嵌套资源 GET /api/users/:id/posts // 用户的文章列表 GET /api/users/:id/posts/:postId // 用户的具体文章 // 查询参数 GET /api/users?page=1&limit=10&sort=name GET /api/users?role=admin&status=active // 状态码规范 200 OK // 成功 201 Created // 创建成功 204 No Content // 删除成功 400 Bad Request // 请求参数错误 401 Unauthorized // 未认证 403 Forbidden // 无权限 404 Not Found // 资源不存在 500 Server Error // 服务器错误 // 响应格式规范 { "success": true, "data": { ... }, "message": "操作成功" } // 错误响应格式 { "success": false, "error": { "code": "VALIDATION_ERROR", "message": "参数验证失败", "details": [...] } }

📊 前后端协作流程

💡
高效的前后端协作

1. API 设计先行：先定义接口文档，再并行开发
2. Mock 数据：前端使用模拟数据进行开发
3. 接口联调：后端完成后进行接口联调
4. 文档维护：使用 Swagger/OpenAPI 维护接口文档

📝 本节小结

✅
  • • 前后端分离让前端和后端独立开发、部署
  • • API 是前后端通信的桥梁
  • • RESTful API 提供了统一的设计规范
  • • 分离架构提高了开发效率和可维护性
