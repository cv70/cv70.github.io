59.1 GraphQL 简介

一种用于 API 的查询语言

📖 什么是 GraphQL

GraphQL 是由 Facebook 开发的一种用于 API 的查询语言和运行时环境。它允许客户端精确地指定需要的数据，而不是像 REST 那样由服务器决定返回什么数据。

💡
核心概念

GraphQL = Graph（图）+ QL（Query Language，查询语言）。它将数据建模为图结构，客户端可以按需查询图中的节点和边。

GraphQL 的发展历程

时间 事件

2015 开源发布
2018 移交给 GraphQL 基金会
现在 广泛应用于各大公司

🎯 GraphQL 的核心特点

精确查询

客户端可以精确指定需要的字段，避免过度获取或获取不足。

// 只查询需要的字段 query { user(id: 123) { name email } }

单一端点

所有请求通过一个端点处理，简化 API 管理。

// 所有请求都发往同一端点 POST /graphql // 而不是多个 REST 端点 // GET /users/123 // GET /users/123/posts

强类型系统

GraphQL Schema 定义了完整的类型系统，提供类型安全和自动补全。

type User { id: ID! name: String! email: String! posts: [Post!]! }

实时更新

通过 Subscription 支持实时数据订阅。

// 订阅用户变化 subscription { userUpdated { id name } }

📊 GraphQL vs REST

请求对比

REST API

// 获取用户及其文章 // 请求 1 GET /users/123 // 返回所有用户字段，可能包含不需要的数据 // 请求 2 GET /users/123/posts // 再次请求获取文章 // 问题：多次请求、过度获取

GraphQL

// 一次请求获取所需数据 query { user(id: 123) { name email posts { title createdAt } } } // 精确获取，一次请求

详细对比

特性 REST GraphQL
端点 多个端点 单一端点
数据获取 服务器决定 客户端决定
请求次数 可能多次 通常一次
类型系统 无/自定义 内置强类型
缓存 HTTP 级别原生支持 需要额外处理
版本管理 URL 版本号 无版本/演进式
学习曲线 低 中等
工具生态 成熟 丰富且活跃

🔧 GraphQL 核心概念

1. Schema（模式）

Schema 定义了 API 的类型系统和 API 的能力范围。

type Query { user(id: ID!): User users: [User!]! } type Mutation { createUser(input: CreateUserInput!): User! updateUser(id: ID!, input: UpdateUserInput!): User! } type User { id: ID! name: String! email: String! createdAt: DateTime! }

2. Query（查询）

Query 用于读取数据，类似于 REST 的 GET 请求。

// 查询用户 query GetUser { user(id: 123) { id name email } } // 查询多个资源 query GetUserAndPosts { user(id: 123) { name posts { title } } }

3. Mutation（变更）

Mutation 用于修改数据，类似于 REST 的 POST/PUT/DELETE 请求。

// 创建用户 mutation CreateUser { createUser(input: { name: "张三" email: "zhangsan@example.com" }) { id name email } } // 更新用户 mutation UpdateUser { updateUser(id: 123, input: { name: "李四" }) { id name } }

4. Subscription（订阅）

Subscription 用于实时数据推送，基于 WebSocket 实现。

// 订阅新用户创建事件 subscription OnUserCreated { userCreated { id name email } } // 订阅消息更新 subscription OnMessageUpdated($roomId: ID!) { messageUpdated(roomId: $roomId) { id content sender { name } } }

✅ GraphQL 的优势

  • 避免过度获取（Over-fetching）和获取不足（Under-fetching）
  • 一次请求获取多个资源
  • 强类型系统提供类型安全和文档
  • 强大的开发工具（GraphiQL、Apollo DevTools）
  • 无需版本管理，API 可持续演进
  • 支持实时数据订阅

⚠️ GraphQL 的挑战

⚠️
需要注意的问题
  • 缓存：无法使用 HTTP 缓存，需要额外实现
  • 复杂性：查询复杂性控制、深度限制
  • 安全：需要防止恶意查询消耗资源
  • 学习曲线：团队需要学习新概念
  • N+1 问题：需要 DataLoader 等工具解决

📝 小结

  • GraphQL 是一种用于 API 的查询语言和运行时
  • 客户端可以精确指定需要的数据
  • 核心概念：Schema、Query、Mutation、Subscription
  • 相比 REST，解决了过度获取和多次请求的问题
  • 强类型系统提供更好的开发体验
  • 需要注意缓存、安全性和性能优化
