2.10 设计流程中的关键里程碑与评审节点

项目管理的核心要素

🎯 学习目标

  • 理解里程碑在项目管理中的作用
  • 掌握各阶段评审的重点内容
  • 了解评审流程与决策机制
  • 学习风险管理的方法

里程碑管理的重要性

里程碑（Milestone）是项目进度的重要节点，标志着某个阶段的完成或关键决策点。通过里程碑管理，可以有效追踪项目进度，及时发现和解决问题，确保项目按计划推进。

评审节点是里程碑的核心组成部分，通过正式的技术评审，确保设计质量和风险可控。缺乏有效评审的项目往往面临进度失控、质量问题和成本超支的风险。

📊 主要里程碑总览

📋
里程碑 时间点 核心交付物 决策内容
DR0 项目启动 项目章程、需求文档 项目立项
DR1 架构设计完成 架构文档、规格书 架构评审通过
DR2 RTL 冻结 RTL 代码、验证计划 进入实现阶段
DR3 网表冻结 综合网表、DFT 网表 进入后端设计
DR4 版图冻结 GDSII、签核报告 流片决策
DR5 样品验证完成 测试报告、性能数据 量产决策

🔍 各阶段评审详解

DR1 - 架构评审

评审重点

  • 架构是否满足需求规格
  • 技术可行性分析是否充分
  • IP 选型是否合理
  • 风险评估是否全面
  • 资源估算是否准确

关键产出

  • 系统架构文档
  • 模块接口规格
  • 验证策略文档
  • 风险评估报告
  • 项目计划

DR2 - RTL 冻结评审

评审重点

  • 功能覆盖率是否达标
  • 代码质量检查结果
  • CDC/RDC 检查结果
  • Lint 检查结果
  • 回归测试通过情况

准入标准

  • 功能覆盖率 ≥95%
  • 代码覆盖率 100%
  • 无严重 Lint 警告
  • CDC 违例已清零
  • 所有 Bug 已修复或有豁免

DR3 - 网表评审

评审重点

  • 综合时序是否收敛
  • 形式验证是否通过
  • DFT 覆盖率是否达标
  • 面积功耗是否符合预期
  • 测试向量生成完成

关键检查项

  • Setup/Hold 无违例
  • RTL-Netlist 等价性通过
  • Stuck-at 覆盖率 ≥98%
  • ATPG 向量数量合理

DR4 - 流片评审（TR）

⚠️
最重要的评审节点

DR4 是流片前的最终评审，也称为 TR（Technical Review）。此评审通过后，设计将被锁定并交付晶圆厂。流片成本高昂，任何遗漏问题都可能导致重大损失，因此 DR4 评审必须严格、全面。

检查类别 检查内容 通过标准
时序签核 所有角 Setup/Hold 检查 无违例
功耗签核 功耗、IR Drop 分析 满足规格
物理验证 DRC、LVS、ERC 零错误
可靠性 天线、电迁移、ESD 符合要求
文档完整性 设计文档、测试计划 齐全

👥 评审流程与组织

评审参与者

  • 评审主席：资深技术专家
  • 设计团队：提交评审材料
  • 验证团队：提供验证数据
  • 项目经理：进度和风险
  • 独立评审人：客观评估

评审流程

  • 评审材料准备与分发
  • 预评审问题收集
  • 正式评审会议
  • 问题清单确认
  • 决策（通过/有条件通过/不通过）
  • 问题跟踪关闭

📊 决策标准

评审结果 说明 后续行动
通过 所有检查项满足标准 进入下一阶段
有条件通过 存在次要问题，可并行修复 问题跟踪关闭后进入下一阶段
不通过 存在重大问题需要解决 修复后重新评审
💡
豁免（Waiver）管理

某些情况下，可能需要对非关键问题申请豁免。豁免需要经过严格的审批流程，说明风险影响和应对措施，并由相关责任人签字确认。豁免应有明确的关闭条件。

⚠️ 风险管理

风险管理贯穿整个项目周期，是评审的重要内容之一。

🔍

风险识别

技术风险、进度风险、资源风险

📊

风险评估

概率、影响、优先级排序

🛡️

风险应对

规避、转移、缓解、接受

常见风险类型

风险类型 典型风险 应对策略
技术风险 新技术、新 IP、复杂设计 前期调研、原型验证、备份方案
进度风险 评估过于乐观、资源不足 合理缓冲、关键路径管理
质量风险 验证不充分、遗漏问题 严格评审、覆盖率目标
供应链风险 IP 交付延迟、产能不足 多供应商策略、提前规划

📝 本节小结

✅
  • • 里程碑是项目进度管理的关键节点
  • • 评审确保设计质量，降低流片风险
  • • DR1-DR5 覆盖从架构到量产的全流程
  • • DR4（TR）是流片前最重要的评审
  • • 评审决策基于客观数据和明确标准
  • • 风险管理贯穿项目始终
  • • 豁免需要严格审批，不可滥用
