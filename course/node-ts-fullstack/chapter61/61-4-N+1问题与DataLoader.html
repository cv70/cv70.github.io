61.4 N+1 问题与 DataLoader

GraphQL 性能优化的关键技术

⚠️ N+1 问题

N+1 问题是 GraphQL 中常见的性能问题。当查询关联数据时，如果不加处理，会产生大量数据库查询。

// 问题查询 query { users { name posts { title } } } // 执行过程（假设有 10 个用户） // 1. 查询用户列表: SELECT * FROM users // 2. 查询用户1的文章: SELECT * FROM posts WHERE authorId = 1 // 3. 查询用户2的文章: SELECT * FROM posts WHERE authorId = 2 // ... // 11. 查询用户10的文章: SELECT * FROM posts WHERE authorId = 10 // 总共 1 + 10 = 11 次查询！
⚠️
N+1 问题的影响
  • 数据库查询次数爆炸
  • 响应时间显著增加
  • 数据库负载过高
  • 影响整体系统性能

🔧 DataLoader 简介

DataLoader 是 Facebook 开发的批量数据加载工具，通过批处理和缓存解决 N+1 问题。

批处理（Batching）

将多个单独请求合并为一个批量请求

// 单独请求 SELECT * FROM posts WHERE authorId = 1 SELECT * FROM posts WHERE authorId = 2 SELECT * FROM posts WHERE authorId = 3 // 批处理 SELECT * FROM posts WHERE authorId IN (1, 2, 3)

缓存（Caching）

同一请求中相同 key 只加载一次

// 第一次请求 authorId=1 // 从数据库加载 // 第二次请求 authorId=1 // 从缓存返回

📝 DataLoader 实现

import DataLoader from 'dataloader'; // 创建 DataLoader const userLoader = new DataLoader<number, User>(async (ids) => { // 批量查询 const users = await prisma.user.findMany({ where: { id: { in: ids as number[] } }, }); // 创建 ID 到 User 的映射 const userMap = new Map(users.map(user => [user.id, user])); // 按输入顺序返回结果 return ids.map(id => userMap.get(id) || null); }); // 帖子 DataLoader const postsByAuthorLoader = new DataLoader<number, Post[]>(async (authorIds) => { // 批量查询所有作者的文章 const posts = await prisma.post.findMany({ where: { authorId: { in: authorIds as number[] } }, }); // 按作者 ID 分组 const postsByAuthor = new Map<number, Post[]>(); posts.forEach(post => { const authorPosts = postsByAuthor.get(post.authorId) || []; authorPosts.push(post); postsByAuthor.set(post.authorId, authorPosts); }); // 按输入顺序返回 return authorIds.map(id => postsByAuthor.get(id) || []); });

🔄 在 Resolver 中使用 DataLoader

import DataLoader from 'dataloader'; // 创建 DataLoader 工厂函数 function createLoaders(prisma: PrismaClient) { return { user: new DataLoader<number, User>(async (ids) => { const users = await prisma.user.findMany({ where: { id: { in: [...ids] } }, }); const userMap = new Map(users.map(u => [u.id, u])); return [...ids].map(id => userMap.get(id) || null); }), postsByAuthor: new DataLoader<number, Post[]>(async (authorIds) => { const posts = await prisma.post.findMany({ where: { authorId: { in: [...authorIds] } }, }); const grouped = new Map<number, Post[]>(); posts.forEach(post => { const list = grouped.get(post.authorId) || []; list.push(post); grouped.set(post.authorId, list); }); return [...authorIds].map(id => grouped.get(id) || []); }), commentsByPost: new DataLoader<number, Comment[]>(async (postIds) => { const comments = await prisma.comment.findMany({ where: { postId: { in: [...postIds] } }, }); const grouped = new Map<number, Comment[]>(); comments.forEach(comment => { const list = grouped.get(comment.postId) || []; list.push(comment); grouped.set(comment.postId, list); }); return [...postIds].map(id => grouped.get(id) || []); }), }; } // Context 类型 interface Context { prisma: PrismaClient; loaders: ReturnType<typeof createLoaders>; } // Resolvers const resolvers = { User: { posts: async (parent, _, context) => { return context.loaders.postsByAuthor.load(parent.id); }, }, Post: { author: async (parent, _, context) => { return context.loaders.user.load(parent.authorId); }, comments: async (parent, _, context) => { return context.loaders.commentsByPost.load(parent.id); }, }, }; // Apollo Server 配置 const server = new ApolloServer({ typeDefs, resolvers }); await startStandaloneServer(server, { context: async () => ({ prisma, loaders: createLoaders(prisma), // 每个请求创建新的 DataLoader }), });

📝 小结

  • N+1 问题会导致大量数据库查询
  • DataLoader 通过批处理和缓存解决 N+1 问题
  • 每个请求创建新的 DataLoader 实例
  • 正确处理返回结果的排序
  • 一对多关系需要特殊处理
  • 显著提升 GraphQL 查询性能
