47.1 守卫概念

理解 NestJS 守卫的作用和原理

🎯 学习目标

  • 理解守卫的概念和作用
  • 掌握守卫的执行时机
  • 了解守卫与中间件的区别
  • 理解守卫的返回值含义

📚 什么是守卫？

守卫是用 @Injectable() 装饰器注解的类，实现 CanActivate 接口。守卫根据运行时的条件决定请求是否可以继续访问路由处理器。

请求处理流程： 客户端请求 ↓ ┌─────────────────┐ │ 中间件 │ └─────────────────┘ ↓ ┌─────────────────┐ │ 守卫 │ ← 在这里决定是否允许访问 └─────────────────┘ ↓ (守卫返回 true) ┌─────────────────┐ │ 拦截器 │ └─────────────────┘ ↓ ┌─────────────────┐ │ 管道 │ └─────────────────┘ ↓ ┌─────────────────┐ │ 路由处理器 │ └─────────────────┘
💡
守卫特点

守卫返回 true 时请求继续，返回 false 时请求被拒绝（403 Forbidden）。守卫可以抛出异常来返回自定义的错误响应。

🔧 守卫接口

import { Injectable, CanActivate, ExecutionContext } from '@nestjs/common'; import { Observable } from 'rxjs'; @Injectable() export class AuthGuard implements CanActivate { canActivate( context: ExecutionContext, ): boolean | Promise | Observable { const request = context.switchToHttp().getRequest(); // 验证逻辑 const isAuthenticated = this.validateRequest(request); // 返回 true 继续请求，返回 false 拒绝请求 return isAuthenticated; } private validateRequest(request: Request): boolean { // 验证逻辑 return true; } }

🔄 守卫 vs 中间件

特性 中间件 守卫
执行时机 路由处理前 中间件后
上下文 只有请求/响应对象 ExecutionContext（包含执行上下文）
依赖注入 函数式无依赖注入 完全支持依赖注入
主要用途 请求预处理 权限验证
返回值 无（调用 next() 继续） boolean（决定是否继续）
⚠️
守卫选择

需要权限验证时使用守卫，需要请求预处理时使用中间件。守卫可以访问 ExecutionContext，获取更多执行信息。

🌐 ExecutionContext

import { ExecutionContext } from '@nestjs/common'; // ExecutionContext 提供丰富的上下文信息 @Injectable() export class MyGuard implements CanActivate { canActivate(context: ExecutionContext): boolean { // HTTP 请求对象 const request = context.switchToHttp().getRequest(); const response = context.switchToHttp().getResponse(); // 获取控制器类和方法名 const controllerClass = context.getClass(); const handler = context.getHandler(); // 获取装饰器元数据 const roles = this.reflector.get('roles', handler); console.log('Controller:', controllerClass.name); console.log('Handler:', handler.name); console.log('Roles:', roles); return true; } }
