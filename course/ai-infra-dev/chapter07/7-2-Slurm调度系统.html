Slurm简介

Slurm (Simple Linux Utility for Resource Management)是广泛用于HPC和AI集群的开源资源管理系统。 它提供了高效的作业调度、资源分配和监控功能，能够管理数千个节点和数万个作业。

⚙️ Slurm配置

关键配置文件

/etc/slurm/slurm.conf 主配置文件：

# 集群信息
ClusterName=ai-cluster
SlurmctldHost=controller01

# 调度参数
SchedulerType=sched/backfill
SelectType=select/cons_tres
SelectTypeParameters=CR_Core_Memory

# 时间限制
MaxJobCount=10000
MaxArraySize=5000

# GPU资源配置
GresTypes=gpu
Gres=gpu:8:node01-64

# 日志配置
SlurmctldLogFile=/var/log/slurm/slurmctld.log
SlurmdLogFile=/var/log/slurm/slurmd.log

# 调度策略
DefMemPerCPU=4096
MaxMemPerCPU=32768

# 账户与QOS
AccountingStorageType=accounting_storage/slurmdbd
JobAcctGatherType=jobacct_gather/linux

💡
GPU配置要点

Gres (Generic Resource Scheduling)：Slurm通过Gres机制管理GPU

GPU绑定：使用Gres=gpu:N指定每节点的GPU数量

GPU类型：支持不同型号GPU（Gres=gpu:A100:8）

亲和性：可配置GPU与CPU核心的绑定关系

📝 作业提交

批处理作业 (sbatch)

训练任务提交脚本：

#!/bin/bash
#SBATCH --job-name=gpt-train
#SBATCH --partition=gpu
#SBATCH --nodes=4
#SBATCH --ntasks-per-node=1
#SBATCH --cpus-per-task=32
#SBATCH --gres=gpu:8
#SBATCH --mem=0
#SBATCH --time=7-00:00:00
#SBATCH --output=logs/%j.out
#SBATCH --error=logs/%j.err

# 加载环境
module load cuda/11.8
module load python/3.10

# 分布式训练
python train.py \
    --nodes 4 \
    --gpus 8 \
    --batch-size 256 \
    --epochs 100

交互式作业 (srun)

交互式调试：

# 申请2节点交互式会话
srun --partition=gpu \
     --nodes=2 \
     --gres=gpu:4 \
     --pty bash

# 直接运行命令
srun --partition=gpu \
     --gres=gpu:1 \
     python test.py

# 调试环境
srun --partition=debug \
     --gres=gpu:1 \
     --time=1:00:00 \
     --pty bash

# 申请整个节点
srun --exclusive \
     --gres=gpu:8 \
     --pty bash

📊 作业管理

常用管理命令

作业查询与管理：

# 查看作业队列
squeue -o "%.18i %.9P %.30j %.8u %.8T %.10M %.6D %R"
squeue -u username  # 查看特定用户
squeue -p gpu      # 查看特定分区

# 查看作业详情
scontrol show job JOBID

# 取消作业
scancel JOBID
scancel -u username  # 取消用户所有作业

# 查看节点状态
sinfo -N -l
sinfo -o "%.10n %.10c %.10m %.10e %.14G %.10D %P"

# 查看节点详情
scontrol show node node01

# 查看分区信息
sinfo -s

# 作业统计
sacct -j JOBID --format=JobID,JobName,State,Elapsed,MaxRSS

# 更新作业
scontrol update jobid=JOBID time=2-00:00:00
scontrol update jobid=JOBID priority=1000

🔧 高级调度特性

作业数组

批量参数扫描：

#SBATCH --array=1-100
#SBATCH --job-name=param-sweep

# 获取数组索引
TASK_ID=$SLURM_ARRAY_TASK_ID

# 根据索引设置参数
python train.py \
    --lr 0.0$TASK_ID \
    --batch-size $(($TASK_ID * 16))

# 提交作业数组
sbatch --array=1-100 script.sh

# 查看数组作业
squeue -u username

依赖调度

作业依赖：

# 先提交数据准备作业
JOB1=$(sbatch --parsable data_prep.sh)

# 再提交训练作业，依赖数据准备
sbatch --dependency=afterok:$JOB1 train.sh

# 多重依赖
sbatch --dependency=afterok:$JOB1:$JOB2:$JOB3 eval.sh

# 单任务完成后
sbatch --dependency=afterany:$JOB1 clean.sh

# 失败时运行
sbatch --dependency=afternotok:$JOB1 notify.sh

🚨 优先级与抢占

优先级调度配置

优先级配置：

# slurm.conf 配置
PriorityType=priority/multifactor
PriorityWeightAge=1000
PriorityWeightFairshare=10000
PriorityWeightJobSize=1000
PriorityWeightPartition=1000
PriorityWeightQOS=0

# 用户使用份额
sacctmgr add user username cluster=ai-cluster fairshare=100

# QOS配置
sacctmgr add qos high-priority priority=1000 maxjobs=50
sacctmgr add qos normal priority=100 maxjobs=200

# 抢占配置
PreemptType=preempt/qos
PreemptMode=REQUEUE
PreemptExemptTime=0

# 账户配额
sacctmgr add account team1 cluster=ai-cluster \
    Fairshare=100 GrpJobs=100 GrpNodes=50

📈 监控与统计

资源使用统计

作业统计报告：

# 按用户统计
sreport cluster utilization start=2024-01-01 end=2024-01-31
sreport user top start=2024-01-01 end=2024-01-31

sreport cluster AccountUtilizationByUser

# 作业效率分析
sacct -j JOBID \
    --format=JobID,JobName,State,ExitCode,MaxRSS,MaxVMSize,AveRSS,AveVMSize,NTasks,Elapsed,TotalCPU

# GPU利用率
sacct -j JOBID --format=JobID,AllocGRES,ReqGRES

# 实时监控
sview  # 图形界面
squeue -o "%.18i %.9P %.30j %.8u %.8T %.10M %.6D %R"

Slurm最佳实践

📝 本节小结

✅
  • • Slurm是成熟的HPC/AI集群调度系统，支持大规模作业调度
  • • 核心组件包括slurmctld（控制）、slurmd（计算节点）和slurmdbd（数据库）
  • • 通过Gres机制管理GPU资源，支持灵活的GPU分配
  • • 提供批处理（sbatch）和交互式（srun）两种作业提交方式
  • • 支持作业数组、依赖调度等高级特性
  • • 通过多因子优先级机制实现公平调度
  • • 提供丰富的监控和统计功能
