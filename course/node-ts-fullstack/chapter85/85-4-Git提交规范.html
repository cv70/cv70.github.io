85.4 Git 提交规范

规范化 Git 提交信息

🎯 学习目标

  • 理解 Git 提交规范的重要性
  • 掌握 Conventional Commits 规范
  • 学会使用 Commitlint 工具
  • 了解提交自动化配置

📚 Conventional Commits

Conventional Commits 是一种规范的提交信息格式，便于自动化工具生成变更日志和版本管理。

# 提交信息格式 ():
# 示例 feat(user): 添加用户登录功能 - 实现邮箱密码登录 - 添加 JWT token 验证 - 添加登录日志记录 Closes #123 # 类型说明 feat: 新功能 fix: 修复 bug docs: 文档更新 style: 代码格式（不影响功能） refactor: 重构代码 perf: 性能优化 test: 测试相关 chore: 构建/工具变动 ci: CI 配置变动 revert: 回滚提交

🔧 Commitlint 配置

# 安装依赖 npm install --save-dev @commitlint/cli @commitlint/config-conventional # commitlint.config.js module.exports = { extends: ['@commitlint/config-conventional'], rules: { 'type-enum': [ 2, 'always', [ 'feat', 'fix', 'docs', 'style', 'refactor', 'perf', 'test', 'build', 'ci', 'chore', 'revert', ], ], 'subject-case': [2, 'always', 'lower-case'], 'subject-max-length': [2, 'always', 72], 'body-max-line-length': [2, 'always', 100], }, }; # 测试提交信息 echo "feat: add new feature" | npx commitlint

⚙️ Husky 钩子配置

# 安装 husky npm install --save-dev husky # 初始化 husky npx husky init # 添加 commit-msg 钩子 echo "npx --no -- commitlint --edit \$1" > .husky/commit-msg # 添加 pre-commit 钩子 echo "npx lint-staged" > .husky/pre-commit # package.json { "scripts": { "prepare": "husky install" }, "lint-staged": { "*.{ts,tsx}": [ "eslint --fix", "prettier --write" ] } } # 安装 lint-staged npm install --save-dev lint-staged
💡
自动化流程

husky 在 git commit 前自动运行 lint-staged 检查代码格式，commitlint 验证提交信息格式。

🚀 交互式提交

# 安装 commitizen npm install --save-dev commitizen cz-conventional-changelog # package.json { "scripts": { "commit": "cz" }, "config": { "commitizen": { "path": "cz-conventional-changelog" } } } # 使用交互式提交 git add . npm run commit # 输出示例： ?
