RAG服务架构概述

RAG服务架构需要支持高并发、低延迟、可扩展的检索和生成。采用微服务架构实现关注点分离，通过负载均衡、缓存、异步处理等技术提升性能和可靠性。

💾 向量数据库部署

数据库 部署方式 优势 适用场景
Milvus 开源部署/云服务 高性能、可扩展 企业级RAG
Pinecone 托管服务 零运维、易用 快速原型
Weaviate 托管/自部署 混合搜索、模块化 灵活需求
Qdrant 开源部署 轻量、易部署 中小规模
Chroma 嵌入式 简单、轻量 开发测试
💡
向量数据库选择

生产环境推荐Milvus或Weaviate；快速验证使用Pinecone；本地开发使用Chroma。根据数据规模、性能需求和运维能力选择合适的方案。

🔧 Milvus部署配置

Milvus集群部署

# Docker Compose部署Milvus
version: '3.5'

services:
  etcd:
    image: quay.io/coreos/etcd:v3.5.5
    environment:
      - ETCD_AUTO_COMPACTION_MODE=revision
      - ETCD_AUTO_COMPACTION_RETENTION=1000
      - ETCD_QUOTA_BACKEND_BYTES=4294967296
    volumes:
      - etcd:/etcd

  minio:
    image: minio/minio:RELEASE.2023-03-20T20-16-18Z
    environment:
      MINIO_ACCESS_KEY: minioadmin
      MINIO_SECRET_KEY: minioadmin
    volumes:
      - minio:/minio_data

  standalone:
    image: milvusdb/milvus:v2.3.3
    command: ["milvus", "run", "standalone"]
    environment:
      ETCD_ENDPOINTS: etcd:2379
      MINIO_ADDRESS: minio:9000
    ports:
      - "19530:19530"
      - "9091:9091"
    volumes:
      - milvus:/var/lib/milvus
    depends_on:
      - "etcd"
      - "minio"

volumes:
  etcd:
  minio:
  milvus:

🌐 负载均衡

多层负载均衡

负载均衡策略：

1. API层负载均衡
   ├── 负载均衡器：Nginx/HAProxy/ALB
   ├── 算法：轮询/最少连接/哈希
   ├── 健康检查：定期探测
   └── 故障转移：自动切换

2. 服务层负载均衡
   ├── 服务发现：Consul/Etcd/K8s
   ├── 负载均衡：客户端/服务端
   ├── 限流：令牌桶/漏桶
   └── 熔断：Hystrix/Sentinel

3. 数据层负载均衡
   ├── 读写分离
   ├── 分片路由
   ├── 缓存分层
   └── 主从复制

Nginx配置示例：
upstream rag_backend {
    least_conn;
    server backend-1:8000 weight=3 max_fails=3;
    server backend-2:8000 weight=3 max_fails=3;
    server backend-3:8000 weight=2 max_fails=3;
    keepalive 128;
}

server {
    listen 80;
    location / {
        proxy_pass http://rag_backend;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_http_version 1.1;
        proxy_set_header Connection "";
    }
}
⚠️
负载均衡注意事项

负载均衡要考虑会话保持（多轮对话）、故障隔离、流量控制。对于有状态服务，需要使用一致性哈希或会话保持。

监控指标体系

监控维度 关键指标 告警阈值

🔄 服务扩展

水平扩展策略

  • 无状态服务：直接水平扩展
  • 有状态服务：使用会话保持或一致性哈希
  • 数据库扩展：分片、读写分离
  • 缓存扩展：分布式缓存集群
  • 自动扩缩容：基于CPU/内存/QPS
