26.1 Kubernetes架构

深入理解Kubernetes的核心架构与设计原理

🎯 学习目标

  • 掌握Kubernetes的整体架构设计
  • 理解Master节点和Worker节点的职责
  • 熟悉控制平面组件的功能与交互
  • 了解Kubernetes的核心工作流程

Kubernetes简介

Kubernetes（K8s）是一个开源的容器编排平台，用于自动化容器化应用的部署、扩展和管理。 作为CNCF（云原生计算基金会）的毕业项目，Kubernetes已成为云原生时代的操作系统。

🎛️ 控制平面组件

API Server

集群的统一入口，处理REST操作，提供认证、授权、准入控制。

📌
端口说明

默认端口：6443（HTTPS）、8080（不安全HTTP，生产环境禁用）

etcd

键值存储数据库，保存集群的所有配置数据和状态信息。

⚠️
重要提示

etcd是集群的大脑，需要做好备份和HA配置

Scheduler

负责将新创建的Pod调度到合适的Worker节点上。

  • 预选：过滤不符合条件的节点
  • 优选：对符合条件的节点打分

Controller Manager

运行多种控制器，维护集群状态。

  • Node Controller
  • Replication Controller
  • Endpoints Controller

⚙️ Worker节点组件

组件 功能 默认端口
Kubelet 节点代理，与API Server通信，管理Pod生命周期 10250
Kube-proxy 网络代理，维护网络规则，实现Service负载均衡 10256
Container Runtime 容器运行时，负责拉取镜像、运行容器 varies

🔄 工作流程

# 1. 用户通过kubectl提交部署请求 $ kubectl create deployment nginx --image=nginx # 2. API Server接收请求并存储到etcd # 3. Controller Manager检测到新资源，创建ReplicaSet # 4. Scheduler调度Pod到合适节点 # 5. Kubelet在节点上启动Pod # 6. Kube-proxy配置网络规则

📊 架构设计原则

🎯

声明式API

通过YAML声明期望状态，系统自动达成

🔌

控制器模式

持续协调，确保实际状态与期望一致

📦

模块化设计

组件解耦，易于扩展和替换

✅
架构优势
  • • 高可用性：多Master节点部署，无单点故障
  • • 可扩展性：水平扩展，支持大规模集群
  • • 自愈能力：自动故障检测与恢复
  • • 资源利用率：智能调度，提高资源使用效率

📝 本节小结

💡
  • • Kubernetes采用控制平面+工作节点的架构
  • • 控制平面负责决策和协调，工作节点负责执行
  • • API Server是集群的唯一入口
  • • etcd存储集群所有状态数据
