73.2 AAA 模式

第十部分：测试篇 - 结构化测试的最佳实践

1. AAA 模式简介

AAA 模式（Arrange-Act-Assert）是一种组织测试代码的结构模式，将测试分为三个清晰的阶段。

1
Arrange
准备
2
Act
执行
3
Assert
断言

2. 三个阶段详解

Arrange 准备

设置测试所需的所有条件和数据。

  • 创建测试对象
  • 设置输入参数
  • 配置 Mock 行为
  • 准备预期数据

Act 执行

调用被测试的方法或函数。

  • 执行单个操作
  • 调用一个方法
  • 触发一个事件
  • 发送一个请求

Assert 断言

验证实际结果是否符合预期。

  • 检查返回值
  • 验证状态变化
  • 确认方法调用
  • 验证异常抛出

3. 基本 AAA 示例

describe('Calculator', () => { describe('add', () => { it('should add two positive numbers', () => { // Arrange - 准备 const calculator = new Calculator(); const a = 5; const b = 3; const expected = 8; // Act - 执行 const result = calculator.add(a, b); // Assert - 断言 expect(result).toBe(expected); }); it('should handle negative numbers', () => { // Arrange const calculator = new Calculator(); const a = -5; const b = -3; // Act const result = calculator.add(a, b); // Assert expect(result).toBe(-8); }); }); });

4. 复杂 AAA 示例

describe('UserService', () => { describe('create', () => { it('should create user with valid data', async () => { // Arrange const mockRepository = { create: jest.fn(), save: jest.fn() }; const service = new UserService(mockRepository as any); const userData = { name: 'John Doe', email: 'john@example.com' }; const savedUser = { id: '1', ...userData, createdAt: new Date() }; mockRepository.create.mockReturnValue(savedUser); mockRepository.save.mockResolvedValue(savedUser); // Act const result = await service.create(userData); // Assert expect(result).toEqual(savedUser); expect(mockRepository.create).toHaveBeenCalledWith(userData); expect(mockRepository.save).toHaveBeenCalled(); }); it('should throw error for duplicate email', async () => { // Arrange const mockRepository = { findOne: jest.fn(), create: jest.fn() }; const service = new UserService(mockRepository as any); const userData = { name: 'John', email: 'existing@example.com' }; mockRepository.findOne.mockResolvedValue({ id: '1', email: userData.email }); // Act & Assert await expect(service.create(userData)) .rejects.toThrow('Email already exists'); expect(mockRepository.create).not.toHaveBeenCalled(); }); }); });

5. 多断言场景

describe('UserService', () => { it('should update user with valid data', async () => { // Arrange const userId = '1'; const updateData = { name: 'Updated Name' }; const existingUser = { id: userId, name: 'Old Name', email: 'test@example.com' }; const updatedUser = { ...existingUser, ...updateData }; mockRepository.findOne.mockResolvedValue(existingUser); mockRepository.save.mockResolvedValue(updatedUser); // Act const result = await service.update(userId, updateData); // Assert - 多个断言 expect(result.name).toBe('Updated Name'); expect(result.email).toBe('test@example.com'); expect(result.id).toBe(userId); expect(mockRepository.findOne).toHaveBeenCalledWith({ where: { id: userId } }); expect(mockRepository.save).toHaveBeenCalled(); }); });
💡
多断言原则

虽然一个测试可以有多个断言，但它们应该验证同一个行为。如果一个测试需要验证多个独立行为，考虑拆分成多个测试。

6. AAA 变体：Given-When-Then

// BDD 风格的 Given-When-Then describe('User Registration', () => { it('should register new user', async () => { // Given - 给定初始条件 const userData = { name: 'John Doe', email: 'john@example.com', password: 'Password123!' }; const mockUser = { id: '1', ...userData }; mockRepository.create.mockResolvedValue(mockUser); // When - 当执行操作时 const result = await service.register(userData); // Then - 那么应该发生 expect(result).toBeDefined(); expect(result.id).toBe('1'); expect(result.email).toBe(userData.email); }); });

7. 常见错误

// ❌ 错误：阶段混在一起 it('should create user', async () => { const result = await service.create({ name: 'John' }); expect(result.name).toBe('John'); const user2 = await service.create({ name: 'Jane' }); expect(user2.name).toBe('Jane'); }); // ✅ 正确：清晰的 AAA 分离 it('should create user with name', async () => { // Arrange const userData = { name: 'John' }; // Act const result = await service.create(userData); // Assert expect(result.name).toBe('John'); }); // ❌ 错误：Act 中有多个操作 it('should update user', async () => { const user = await service.create({ name: 'John' }); // Act 1 const result = await service.update(user.id, { name: 'Jane' }); // Act 2 expect(result.name).toBe('Jane'); }); // ✅ 正确：每个测试一个行为 it('should update existing user', async () => { // Arrange const existingUser = await createTestUser({ name: 'John' }); // Act const result = await service.update(existingUser.id, { name: 'Jane' }); // Assert expect(result.name).toBe('Jane'); });

8. 本节小结

📚
关键要点
  • AAA 模式将测试分为三个清晰的阶段
  • Arrange：准备测试数据和条件
  • Act：执行被测试的方法
  • Assert：验证结果是否符合预期
  • 每个测试应该只验证一个行为
