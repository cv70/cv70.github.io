📈 自动扩缩容原理

为什么需要自动扩缩容

自动扩缩容（Auto Scaling）根据负载动态调整资源，实现资源的按需分配。

☸️ Kubernetes HPA

水平Pod自动扩缩容

# hpa.yaml
apiVersion: autoscaling/v2
kind: HorizontalPodAutoscaler
metadata:
  name: llm-inference-hpa
spec:
  scaleTargetRef:
    apiVersion: apps/v1
    kind: Deployment
    name: llm-inference
  minReplicas: 2
  maxReplicas: 20
  metrics:
  - type: Resource
    resource:
      name: cpu
      target:
        type: Utilization
        averageUtilization: 70
  - type: Resource
    resource:
      name: memory
      target:
        type: Utilization
        averageUtilization: 80
  behavior:
    scaleDown:
      stabilizationWindowSeconds: 300
      policies:
      - type: Percent
        value: 50
        periodSeconds: 60
    scaleUp:
      stabilizationWindowSeconds: 60
      policies:
      - type: Percent
        value: 100
        periodSeconds: 30

# 部署HPA
# kubectl apply -f hpa.yaml

💻 自定义Metrics Server

实现推理服务专用指标

# custom-metrics-server.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: inference-metrics-server
spec:
  replicas: 1
  selector:
    matchLabels:
      app: inference-metrics-server
  template:
    metadata:
      labels:
        app: inference-metrics-server
    spec:
      containers:
      - name: metrics-server
        image: inference-metrics-server:latest
        ports:
        - containerPort: 8080
        env:
        - name: INFERENCESERVICE_URL
          value: "http://llm-inference:8000"
        resources:
          limits:
            cpu: 500m
            memory: 512Mi

---
apiVersion: v1
kind: Service
metadata:
  name: inference-metrics-server
spec:
  selector:
    app: inference-metrics-server
  ports:
  - port: 8080
    targetPort: 8080

# 使用自定义指标的HPA
apiVersion: autoscaling/v2
kind: HorizontalPodAutoscaler
metadata:
  name: llm-inference-hpa-custom
spec:
  scaleTargetRef:
    apiVersion: apps/v1
    kind: Deployment
    name: llm-inference
  minReplicas: 2
  maxReplicas: 20
  metrics:
  - type: Pods
    pods:
      metric:
        name: inference_qps
      target:
        type: AverageValue
        averageValue: 100
  - type: Pods
    pods:
      metric:
        name: inference_p99_latency
      target:
        type: AverageValue
        averageValue: 500

🤖 推理服务扩缩容策略

LLM推理的扩缩容考虑

扩容策略

  • 快速扩容：应对突发流量
  • GPU预热：提前加载模型
  • 渐进式：避免雪崩
  • 预测扩容：基于历史数据

缩容策略

  • 保守缩容：避免频繁波动
  • 延迟缩容：等待一段时间
  • 最小实例：保持baseline
  • 优雅关闭：完成当前请求

📊 扩缩容模式对比

模式 触发条件 响应速度 复杂度 适用场景
反应式 当前指标超标 中 低 一般场景
预测式 预测未来负载 快 高 有规律负载
混合式 结合两者 快 中 复杂场景
定时 预设时间 快 低 规律负载
💡
自动扩缩容实践建议
  • 设置合理的最小和最大副本数
  • 使用多种指标避免误判
  • 扩容快、缩容慢的策略
  • LLM推理考虑GPU预热时间
  • 监控扩缩容效果，持续优化
