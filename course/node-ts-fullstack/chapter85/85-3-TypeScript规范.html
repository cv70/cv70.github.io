📚 命名规范

// ✅ 好的命名 interface UserService { getUserById(id: string): Promise<User>; } type UserRole = 'admin' | 'user' | 'guest'; class UserRepository { private readonly users: Map<string, User>; constructor() { this.users = new Map(); } } const MAX_RETRY_COUNT = 3; const API_BASE_URL = 'https://api.example.com'; // ❌ 不好的命名 interface user_service { } // 接口应该用 PascalCase type userrole = string; // 类型别名应该用 PascalCase const max_retry_count = 3; // 常量应该用 UPPER_SNAKE_CASE
💡
命名约定

接口/类/类型别名/枚举使用 PascalCase，变量/函数使用 camelCase，常量使用 UPPER_SNAKE_CASE。

🔧 类型定义规范

// ✅ 使用 interface 定义对象类型 interface User { id: string; name: string; email: string; createdAt: Date; } // ✅ 使用 type 定义联合类型、工具类型 type Status = 'pending' | 'active' | 'inactive'; type UserKeys = keyof User; type PartialUser = Partial<User>; // ✅ 明确的返回类型 function formatDate(date: Date): string { return date.toISOString().split('T')[0]; } // ✅ 使用泛型提高复用性 interface ApiResponse<T> { data: T; status: number; message: string; } // ❌ 避免使用 any function process(data: any) { // 不推荐 return data.value; } // ✅ 使用 unknown 或具体类型 function processSafe(data: unknown) { if (typeof data === 'object' && data !== null && 'value' in data) { return (data as { value: string }).value; } }

🚀 项目结构规范

src/ ├── types/ # 全局类型定义 │ ├── index.d.ts │ └── express.d.ts ├── interfaces/ # 接口定义 │ ├── user.interface.ts │ └── product.interface.ts ├── enums/ # 枚举定义 │ └── status.enum.ts ├── utils/ # 工具函数 │ └── format.ts ├── services/ # 业务服务 │ └── user.service.ts ├── repositories/ # 数据访问层 │ └── user.repository.ts ├── controllers/ # 控制器 │ └── user.controller.ts ├── middlewares/ # 中间件 │ └── auth.middleware.ts ├── routes/ # 路由 │ └── user.routes.ts └── app.ts # 应用入口

✅
  • • 遵循统一的命名规范
