21.4 数据库选型

如何为项目选择合适的数据库

🎯 学习目标

  • 掌握数据库选型的关键因素
  • 了解不同场景的数据库选择
  • 学会权衡各种数据库特性
  • 理解多数据库组合使用策略

📚 选型关键因素

数据库选型考虑因素： 1. 数据特性 ├── 数据结构：结构化 / 半结构化 / 非结构化 ├── 数据量级：小 / 中 / 大 / 海量 ├── 数据关系：简单 / 复杂关联 └── 数据变化：频繁更新 / 只读为主 2. 业务需求 ├── 查询复杂度：简单 CRUD / 复杂关联查询 ├── 事务要求：强一致性 / 最终一致性 ├── 实时性：实时响应 / 批处理 └── 扩展需求：垂直扩展 / 水平扩展 3. 技术因素 ├── 团队熟悉度 ├── 社区支持 ├── 运维成本 └── 云服务支持 4. 成本因素 ├── 许可费用 ├── 硬件成本 ├── 人力成本 └── 培训成本

🔧 典型场景选型

场景一：电商系统 ├── 商品、订单：MySQL（关系复杂、事务强） ├── 商品搜索：Elasticsearch（全文检索） ├── 购物车、库存：Redis（高性能、实时） └── 用户行为日志：MongoDB（灵活、大量写入） 场景二：社交应用 ├── 用户信息：PostgreSQL（JSON 支持） ├── 好友关系：Neo4j（图结构） ├── 动态 Feed：Redis + MongoDB └── 消息队列：Redis / Kafka 场景三：内容管理 ├── 文章内容：MongoDB（灵活 Schema） ├── 用户评论：MySQL（关联查询） ├── 搜索服务：Elasticsearch └── 缓存层：Redis 场景四：物联网平台 ├── 设备数据：InfluxDB（时序数据） ├── 设备状态：Redis（实时性） ├── 告警规则：MySQL └── 历史分析：ClickHouse（列存储）
💡
多语言持久化

现代应用通常使用多种数据库组合，每种数据库处理其擅长的场景。这被称为"多语言持久化"（Polyglot Persistence）策略。

📊 主流数据库对比

数据库 类型 优势 典型场景
MySQL 关系型 成熟稳定、生态丰富 Web 应用、电商
PostgreSQL 关系型 功能强大、扩展性好 复杂查询、GIS
MongoDB 文档型 灵活 Schema、易扩展 内容管理、日志
Redis 键值型 极高性能、丰富数据类型 缓存、会话、排行榜
Elasticsearch 搜索引擎 全文检索、聚合分析 搜索、日志分析

📝 本节小结

✅
  • • 选型需考虑数据特性、业务需求、技术因素和成本
  • • 关系型数据库适合结构化数据和复杂事务
  • • NoSQL 适合非结构化数据和高扩展性需求
  • • 现代应用常采用多数据库组合策略
