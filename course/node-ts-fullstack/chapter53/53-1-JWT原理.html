📚 什么是 JWT？

JWT（JSON Web Token）是一种开放标准（RFC 7519），用于在各方之间安全地传输信息。它是一种紧凑、URL 安全的方式，用于在客户端和服务器之间传递声明（claims）。

// JWT 示例 // 由三部分组成，用 . 分隔 const token = 'eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJzdWIiOiIxMjM0NTY3ODkwIiwibmFtZSI6IkpvaG4gRG9lIiwiaWF0IjoxNTE2MjM5MDIyfQ.SflKxwRJSMeKKF2QT4fwpMeJf36POk6yJV_adQssw5c'; // 解码后： // Header: { "alg": "HS256", "typ": "JWT" } // Payload: { "sub": "1234567890", "name": "John Doe", "iat": 1516239022 } // Signature: HMACSHA256(base64UrlEncode(header) + "." + base64UrlEncode(payload), secret)
💡
JWT 特点

JWT 是自包含的，所有必要信息都在 token 中，无需在服务器端存储会话状态，这使得它非常适合分布式系统和微服务架构。

🔧 JWT 的三部分结构

// 1. Header（头部） // 包含令牌类型和签名算法 const header = { "alg": "HS256", // 签名算法：HMAC SHA256 "typ": "JWT" // 令牌类型 }; // 2. Payload（载荷） // 包含声明（claims），即用户信息和元数据 const payload = { "sub": "1234567890", // Subject - 用户ID "name": "John Doe", // 用户名 "email": "john@example.com", // 邮箱 "role": "admin", // 角色 "iat": 1516239022, // Issued At - 签发时间 "exp": 1516242622 // Expiration - 过期时间 }; // 3. Signature（签名） // 用于验证 token 是否被篡改 // HMACSHA256( // base64UrlEncode(header) + "." + base64UrlEncode(payload), // secret // ) // Base64Url 编码示例 function base64UrlEncode(str: string): string { return Buffer.from(str) .toString('base64') .replace(/\+/g, '-') .replace(/\//g, '_') .replace(/=/g, ''); }

📊 JWT vs Session 对比

┌─────────────────┬──────────────────────┬──────────────────────┐ │ 特性 │ Session │ JWT │ ├─────────────────┼──────────────────────┼──────────────────────┤ │ 存储位置 │ 服务器端 │ 客户端 │ │ 扩展性 │ 需要共享存储 │ 天然支持分布式 │ │ 跨域支持 │ 需要额外配置 │ 天然支持 │ │ 性能 │ 需要查询存储 │ 无需查询，直接验证 │ │ 注销 │ 立即生效 │ 需要额外机制 │ │ 安全性 │ CSRF 风险 │ XSS 风险 │ │ 大小 │ Cookie 大小限制 │ Token 可能较大 │ └─────────────────┴──────────────────────┴──────────────────────┘
⚠️
注意事项

JWT 不适合存储敏感信息，因为 Payload 只是 Base64 编码，不是加密，任何人都可以解码查看内容。

🔄 JWT 认证流程

// 1. 用户登录 POST /api/login { "username": "john", "password": "secret123" } // 2. 服务器验证后返回 JWT Response: { "token": "eyJhbGciOiJIUzI1NiIs...", "expiresIn": 3600 } // 3. 客户端存储 Token（localStorage / cookie） localStorage.setItem('token', token); // 4. 后续请求携带 Token GET /api/profile Headers: { "Authorization": "Bearer eyJhbGciOiJIUzI1NiIs..." } // 5. 服务器验证 Token 并返回数据 // - 验证签名 // - 检查过期时间 // - 提取用户信息

📝 本节小结

✅
  • • JWT 由 Header、Payload、Signature 三部分组成
  • • JWT 是无状态的，所有信息都存储在 token 中
  • • JWT 适合分布式系统和微服务架构
  • • 不要在 JWT 中存储敏感信息
  • • JWT 认证流程：登录 → 获取 Token → 携带 Token 请求
