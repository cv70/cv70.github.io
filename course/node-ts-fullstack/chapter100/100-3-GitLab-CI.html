100.3 GitLab CI

使用 GitLab CI/CD 构建自动化流水线

🎯 学习目标

  • 理解 GitLab CI/CD 的架构与特点
  • 掌握 .gitlab-ci.yml 配置文件编写
  • 学会使用 Runner 和变量管理
  • 了解 GitLab Auto DevOps 功能

GitLab CI/CD 简介

GitLab CI/CD 是 GitLab 内置的持续集成和持续交付平台。 它与 GitLab 代码仓库深度集成，配置简单，支持 Docker 容器、Kubernetes 部署，适合企业级使用。

📋 核心概念

概念 说明
Pipeline 流水线，包含多个 Stage，按顺序执行
Stage 阶段，同一阶段的 Job 并行执行
Job 任务，定义具体操作，在 Runner 上执行
Runner 执行器，可以是共享的或项目专用的
Artifact 制品，Job 产出的文件，可在 Job 间传递
Cache 缓存，加速后续 Pipeline 执行

📁 基础配置文件

# .gitlab-ci.yml stages: - build - test - deploy variables: NODE_VERSION: "20" DOCKER_REGISTRY: registry.example.com # 构建任务 build: stage: build image: node:${NODE_VERSION} script: - npm ci - npm run build artifacts: paths: - dist/ expire_in: 1 hour # 测试任务 test: stage: test image: node:${NODE_VERSION} script: - npm ci - npm run lint - npm test coverage: '/Statements\s*:\s*(\d+\.?\d*)%/' # 部署任务 deploy: stage: deploy image: docker:latest services: - docker:dind script: - docker build -t ${DOCKER_REGISTRY}/myapp:${CI_COMMIT_SHA} . - docker push ${DOCKER_REGISTRY}/myapp:${CI_COMMIT_SHA} only: - main when: manual

🚀 完整 CI/CD 配置

# .gitlab-ci.yml stages: - lint - test - build - deploy_staging - deploy_production variables: DOCKER_TLS_CERTDIR: "/certs" DOCKER_HOST: "tcp://docker:2376" cache: key: ${CI_COMMIT_REF_SLUG} paths: - node_modules/ # ========== Lint 阶段 ========== lint: stage: lint image: node:20-alpine script: - npm ci - npm run lint # ========== 测试阶段 ========== test:unit: stage: test image: node:20-alpine script: - npm ci - npm run test:unit -- --coverage coverage: '/All files\s*\|\s*(\d+\.?\d*)/' artifacts: reports: coverage_report: coverage_format: cobertura path: coverage/cobertura-coverage.xml test:integration: stage: test image: node:20-alpine services: - postgres:15-alpine - redis:7-alpine variables: POSTGRES_HOST: postgres POSTGRES_PASSWORD: test REDIS_HOST: redis script: - npm ci - npm run test:integration # ========== 构建阶段 ========== build:image: stage: build image: docker:24 services: - docker:24-dind before_script: - docker login -u $CI_REGISTRY_USER -p $CI_REGISTRY_PASSWORD $CI_REGISTRY script: - docker build -t $CI_REGISTRY_IMAGE:$CI_COMMIT_SHA . - docker push $CI_REGISTRY_IMAGE:$CI_COMMIT_SHA - | if [ "$CI_COMMIT_BRANCH" == "main" ]; then docker tag $CI_REGISTRY_IMAGE:$CI_COMMIT_SHA $CI_REGISTRY_IMAGE:latest docker push $CI_REGISTRY_IMAGE:latest fi only: - main - develop # ========== 部署阶段 ========== deploy:staging: stage: deploy_staging image: alpine:latest before_script: - apk add --no-cache openssh-client script: - | ssh -o StrictHostKeyChecking=no $DEPLOY_USER@$STAGING_SERVER << EOF cd /app/myapp docker compose -f docker-compose.staging.yml pull docker compose -f docker-compose.staging.yml up -d EOF environment: name: staging url: https://staging.example.com only: - develop deploy:production: stage: deploy_production image: alpine:latest before_script: - apk add --no-cache openssh-client script: - | ssh -o StrictHostKeyChecking=no $DEPLOY_USER@$PRODUCTION_SERVER << EOF cd /app/myapp docker compose pull docker compose up -d --no-deps --build app EOF environment: name: production url: https://example.com only: - main when: manual

⚙️ Runner 配置

注册 GitLab Runner

# 安装 GitLab Runner # Linux curl -L https://packages.gitlab.com/install/repositories/runner/gitlab-runner/script.deb.sh | sudo bash sudo apt-get install gitlab-runner # 注册 Runner sudo gitlab-runner register # 输入 GitLab URL 和注册令牌 # 选择执行器 (docker, shell, kubernetes 等) # 启动 Runner sudo gitlab-runner start

🔐 变量管理

预定义变量

  • CI_COMMIT_SHA - 提交哈希
  • CI_COMMIT_REF_NAME - 分支名
  • CI_REGISTRY - 容器仓库地址
  • CI_PROJECT_DIR - 项目目录

自定义变量

  • Settings -> CI/CD -> Variables
  • 支持 Protected 和 Masked
  • 可设置环境范围
  • 支持文件类型变量
💡
Auto DevOps

GitLab 提供开箱即用的 Auto DevOps 功能，自动检测项目类型并配置完整的 CI/CD 流水线。只需启用即可获得：自动构建、测试、代码质量检查、安全扫描、部署等功能。

📝 本节小结

✅
  • • GitLab CI 内置于 GitLab，配置文件是 .gitlab-ci.yml
  • • Pipeline 由多个 Stage 组成，Stage 内 Job 并行执行
  • • 使用 Artifact 在 Job 间传递构建产物
  • • 支持 Docker-in-Docker 构建镜像
