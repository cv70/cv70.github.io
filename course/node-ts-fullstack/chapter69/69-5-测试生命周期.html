69.5 测试生命周期

第十部分：测试篇 - 掌握 Jest 的钩子函数

1. 生命周期钩子概述

Jest 提供了四个生命周期钩子函数，用于在测试前后执行设置和清理操作。

describe('Test Suite', () => { beforeAll(() => { // 所有测试之前执行一次 }); afterAll(() => { // 所有测试之后执行一次 }); beforeEach(() => { // 每个测试之前执行 }); afterEach(() => { // 每个测试之后执行 }); test('test 1', () => {}); test('test 2', () => {}); });

执行顺序

beforeAll
beforeEach
test 1
afterEach
beforeEach
test 2
afterEach
afterAll

2. beforeAll 和 afterAll

// beforeAll: 所有测试前执行一次 // afterAll: 所有测试后执行一次 describe('Database Tests', () => { let connection: DatabaseConnection; // 在所有测试前建立连接 beforeAll(async () => { connection = await createConnection({ host: 'localhost', database: 'test_db' }); console.log('Database connected'); }); // 在所有测试后关闭连接 afterAll(async () => { await connection.close(); console.log('Database closed'); }); test('should query users', async () => { const users = await connection.query('SELECT * FROM users'); expect(users.length).toBeGreaterThan(0); }); test('should insert user', async () => { const result = await connection.insert('users', { name: 'Test' }); expect(result.affectedRows).toBe(1); }); });
💡
使用场景
  • beforeAll: 建立数据库连接、启动服务器、加载配置
  • afterAll: 关闭数据库连接、停止服务器、清理资源

3. beforeEach 和 afterEach

// beforeEach: 每个测试前执行 // afterEach: 每个测试后执行 describe('UserService', () => { let service: UserService; let mockRepository: MockRepository; beforeEach(() => { // 每个测试前创建新的实例 mockRepository = new MockRepository(); service = new UserService(mockRepository); console.log('Test setup'); }); afterEach(() => { // 每个测试后清理 mockRepository.clear(); jest.clearAllMocks(); console.log('Test cleanup'); }); test('should create user', () => { service.create({ name: 'John' }); expect(mockRepository.data.length).toBe(1); }); test('should find user', () => { // 这个测试开始时 mockRepository 是空的 mockRepository.add({ id: 1, name: 'John' }); const user = service.findById(1); expect(user).toBeDefined(); }); });

执行顺序示例

// 输出顺序： // Database connected (beforeAll) // Test setup (beforeEach) // Test cleanup (afterEach) // Test setup (beforeEach) // Test cleanup (afterEach) // Database closed (afterAll)

4. 嵌套 describe 的生命周期

describe('Outer', () => { beforeAll(() => console.log('Outer beforeAll')); afterAll(() => console.log('Outer afterAll')); beforeEach(() => console.log('Outer beforeEach')); afterEach(() => console.log('Outer afterEach')); describe('Inner', () => { beforeAll(() => console.log('Inner beforeAll')); afterAll(() => console.log('Inner afterAll')); beforeEach(() => console.log('Inner beforeEach')); afterEach(() => console.log('Inner afterEach')); test('test', () => { console.log('Test'); }); }); }); // 执行顺序： // Outer beforeAll // Inner beforeAll // Outer beforeEach // Inner beforeEach // Test // Inner afterEach // Outer afterEach // Inner afterAll // Outer afterAll

5. 异步钩子

describe('Async Hooks', () => { let db: Database; // 异步 beforeAll beforeAll(async () => { db = await connectDatabase(); await db.migrate(); }); // 异步 afterAll afterAll(async () => { await db.cleanup(); await db.disconnect(); }); // 异步 beforeEach beforeEach(async () => { await db.seed(); }); // 异步 afterEach afterEach(async () => { await db.truncate(); }); test('should have data', async () => { const users = await db.users.findAll(); expect(users.length).toBeGreaterThan(0); }); });
⚠️
注意

异步钩子必须使用 async/await 或返回 Promise。如果忘记 await，测试可能会在设置完成前开始。

6. 钩子作用域

describe('Scope Example', () => { let outerVar: string; beforeAll(() => { outerVar = 'initialized'; }); test('outer test', () => { expect(outerVar).toBe('initialized'); }); describe('Inner', () => { let innerVar: number; beforeEach(() => { innerVar = Math.random(); }); test('inner test', () => { // 可以访问外层变量 expect(outerVar).toBe('initialized'); // 也可以访问内层变量 expect(innerVar).toBeDefined(); }); }); test('cannot access inner var', () => { // ❌ 错误：无法访问内层变量 // expect(innerVar).toBeDefined(); expect(outerVar).toBe('initialized'); }); });

7. 钩子最佳实践

✅ 推荐做法

  • 每个测试独立，不依赖执行顺序
  • 在 beforeEach 中重置状态
  • 在 afterAll 中清理资源
  • 使用描述性的变量名

❌ 避免做法

  • 测试之间共享可变状态
  • 在测试中修改共享变量
  • 依赖测试执行顺序
  • 忘记清理资源

完整的测试结构模板

describe('ServiceName', () => { // 模块级别的资源 let moduleResource: Resource; beforeAll(async () => { // 初始化模块资源 moduleResource = await initModule(); }); afterAll(async () => { // 清理模块资源 await moduleResource.cleanup(); }); describe('methodName', () => { // 测试级别的资源 let service: Service; let mockDependency: MockType; beforeEach(() => { // 初始化测试资源 mockDependency = createMock(); service = new Service(mockDependency); }); afterEach(() => { // 清理测试资源 jest.clearAllMocks(); }); test('should do something', () => { // 测试逻辑 }); test('should handle error', () => { // 错误处理测试 }); }); });

8. 一次性设置

// 使用 describe 的作用域控制 describe('Test Group', () => { // 只在第一个测试前执行 let hasSetup = false; beforeAll(() => { hasSetup = true; }); // 这里的测试共享状态（不推荐，但有时需要） test('first test', () => { expect(hasSetup).toBe(true); hasSetup = 'modified'; }); test('second test sees modified state', () => { expect(hasSetup).toBe('modified'); }); });
⚠️
注意

共享状态会使测试变得脆弱和难以调试。尽量避免测试之间的依赖关系。

9. 本节小结

📚
关键要点
  • beforeAll/afterAll 在所有测试前后各执行一次
  • beforeEach/afterEach 在每个测试前后执行
  • 嵌套 describe 的钩子从外到内执行
  • 钩子可以是异步函数
  • 保持测试独立性，避免共享可变状态
