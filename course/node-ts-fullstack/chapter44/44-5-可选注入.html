44.5 可选注入

处理可选的依赖关系

🎯 学习目标

  • 理解可选注入的概念
  • 掌握 @Optional() 装饰器
  • 学会设置默认值
  • 了解可选注入的应用场景

📚 什么是可选注入？

默认情况下，注入的依赖必须存在，否则会抛出错误。使用 @Optional() 装饰器可以声明依赖是可选的，如果不存在则注入 undefined。

import { Injectable, Optional, Inject } from '@nestjs/common'; @Injectable() export class UsersService { constructor( @Optional() private readonly cacheService?: CacheService, ) { if (this.cacheService) { // 缓存服务可用，启用缓存 } else { // 缓存服务不可用，直接查询数据库 } } async findOne(id: number) { // 可选使用缓存 if (this.cacheService) { const cached = await this.cacheService.get(`user:${id}`); if (cached) return cached; } const user = await this.findInDatabase(id); if (this.cacheService) { await this.cacheService.set(`user:${id}`, user); } return user; } }
💡
可选注入特点

可选注入使用 TypeScript 的可选参数语法（?:），配合 @Optional() 装饰器，当依赖不存在时不会报错。

🔧 设置默认值

import { Injectable, Optional, Inject } from '@nestjs/common'; @Injectable() export class NotificationService { constructor( @Optional() @Inject('EMAIL_SERVICE') private readonly emailService: EmailService = new DefaultEmailService(), ) {} } // 或者使用工厂提供默认值 @Module({ providers: [ { provide: 'LOGGER', useFactory: () => { // 如果没有配置日志服务，使用默认 if (process.env.LOGGER_TYPE === 'file') { return new FileLogger(); } return new ConsoleLogger(); }, }, // 可以不提供 EMAIL_SERVICE，使用默认值 // { // provide: 'EMAIL_SERVICE', // useClass: EmailService, // }, ], }) export class AppModule {} // 在服务中使用 @Injectable() export class UsersService { constructor( @Optional() @Inject('EMAIL_SERVICE') private readonly emailService = new DefaultEmailService(), ) {} }

📦 属性注入与可选

@Injectable() export class OrdersService { // 可选属性注入 @Optional() @Inject('CACHE_SERVICE') private readonly cacheService?: CacheService; @Optional() @Inject('METRICS_SERVICE') private readonly metricsService?: MetricsService; async create(order: CreateOrderDto) { const result = await this.saveOrder(order); // 可选地记录指标 if (this.metricsService) { this.metricsService.increment('orders.created'); } return result; } }

✨ 应用场景

场景 说明
缓存服务 可选的缓存功能，没有则直接查库
日志服务 可选的增强日志，没有则使用基础日志
监控服务 可选的监控上报，不影响主功能
通知服务 可选的通知渠道，降级处理
测试 Mock 测试时注入 Mock，生产环境可选
⚠️
谨慎使用

可选注入会增加代码复杂度，每次使用都需要判断是否存在。建议只在真正可选的功能上使用，核心依赖不应设为可选。

📝 本节小结

✅
  • • @Optional() 声明可选依赖
  • • 可选依赖不存在时注入 undefined
  • • 可设置默认值作为降级方案
  • • 适用于非核心功能模块
