57.1 REST 架构风格

理解 REST 的核心概念与设计原则

📖 什么是 REST

REST（Representational State Transfer，表述性状态转移）是一种软件架构风格，由 Roy Fielding 在 2000 年的博士论文中提出。REST 并不是一个标准或协议，而是一组架构约束条件和原则。

💡
核心概念

REST 的核心思想是：客户端和服务器之间的通信必须是 Stateless（无状态）的，所有资源都通过统一的接口进行访问。

REST 架构的六大约束

约束 说明 重要性
Client-Server（客户端-服务器） 关注点分离，客户端负责用户界面，服务器负责数据存储 核心
Stateless（无状态） 每个请求都包含所有必要信息，服务器不保存客户端状态 核心
Cacheable（可缓存） 响应数据应标明是否可缓存，提高网络效率 重要
Uniform Interface（统一接口） 组件之间通过统一的接口进行交互 核心
Layered System（分层系统） 客户端无法知道连接的是终端服务器还是中间层 重要
Code on Demand（按需代码） 服务器可以临时扩展客户端功能（可选） 可选

🎯 REST 核心概念

1. 资源（Resource）

资源是 REST 架构的核心概念。任何可以被命名的信息都可以作为资源：文档、图片、服务等。每个资源都有一个唯一的 URI 标识。

// 资源 URI 示例 // 用户资源 GET /users/123 // 文章资源 GET /articles/456 // 评论资源 GET /articles/456/comments/789

2. 表述（Representation）

资源在网络传输中的具体形式称为表述。常见的表述格式包括 JSON、XML、HTML 等。

// JSON 表述示例 { "id": 123, "name": "张三", "email": "zhangsan@example.com", "createdAt": "2024-01-15T10:30:00Z" }

3. 状态转移（State Transfer）

客户端通过 HTTP 动词（GET、POST、PUT、DELETE 等）对资源进行操作，实现状态的转移。

⚙️ 统一接口的四个约束

资源的标识

每个资源通过 URI 进行唯一标识，URI 作为资源的地址。

// 好的设计 /users/123 /articles?status=published // 不好的设计 /getUser?id=123 /articleService?action=list

通过表述操作资源

客户端持有资源的表述，可以通过表述来操作资源。

// 创建用户 - 发送表述 POST /users { "name": "李四", "email": "lisi@example.com" }

自描述消息

每个消息都包含足够的信息来描述如何处理该消息。

HTTP/1.1 200 OK Content-Type: application/json Cache-Control: max-age=3600 ETag: "abc123" { "data": ... }

HATEOAS

超媒体作为应用状态引擎，客户端可以通过链接发现可执行的操作。

{ "id": 123, "name": "张三", "_links": { "self": { "href": "/users/123" }, "articles": { "href": "/users/123/articles" } } }

💻 NestJS 中的 REST 实现

// user.controller.ts import { Controller, Get, Post, Put, Delete, Param, Body } from '@nestjs/common'; import { UserService } from './user.service'; @Controller('users') export class UserController { constructor(private readonly userService: UserService) {} // 获取所有用户 @Get() async findAll(): Promise { return this.userService.findAll(); } // 获取单个用户 @Get(':id') async findOne(@Param('id') id: string): Promise { return this.userService.findOne(+id); } // 创建用户 @Post() async create(@Body() createUserDto: CreateUserDto): Promise { return this.userService.create(createUserDto); } // 更新用户 @Put(':id') async update( @Param('id') id: string, @Body() updateUserDto: UpdateUserDto, ): Promise { return this.userService.update(+id, updateUserDto); } // 删除用户 @Delete(':id') async remove(@Param('id') id: string): Promise<{ message: string }> { await this.userService.remove(+id); return { message: '用户删除成功' }; } }
⚠️
注意事项

REST 是一种架构风格，不是严格的标准。在实际开发中，应该根据项目需求灵活运用 REST 原则，不必过于教条。

📊 REST vs 非 REST 对比

特性 RESTful API 传统 RPC 风格
URL 设计 /users/123 /getUser?id=123
操作语义 HTTP 方法表达（GET/POST/PUT/DELETE） URL 中包含动作
无状态 每个请求独立 可能依赖 Session
可缓存 GET 请求天然可缓存 需要额外处理
统一接口 标准化的接口设计 接口风格不统一

📝 小结

  • REST 是一种架构风格，不是协议或标准
  • 六大约束确保系统的可扩展性、简单性和可移植性
  • 资源通过 URI 标识，使用 HTTP 动词进行操作
  • 统一接口是 REST 架构的核心特征
  • NestJS 提供了优雅的装饰器来构建 RESTful API
