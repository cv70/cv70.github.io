100.5 自动化部署

构建端到端的自动化部署流程

🎯 学习目标

  • 理解不同部署策略的适用场景
  • 掌握 Docker 镜像构建与推送
  • 学会配置自动化部署流水线
  • 了解回滚机制与安全实践

部署策略

选择合适的部署策略对于保证服务稳定性和用户体验至关重要。 不同的策略适用于不同的场景和风险承受能力。

📊 部署策略对比

策略 特点 适用场景
滚动更新 逐步替换旧版本 常规发布，资源有限
蓝绿部署 两套环境，瞬间切换 需要快速回滚的场景
金丝雀发布 小流量验证后全量 风险较高的重大更新
A/B 测试 同时运行多个版本 功能验证和数据对比

🐳 Docker 镜像构建与推送

# GitHub Actions Docker 构建 jobs: build-and-push: runs-on: ubuntu-latest permissions: contents: read packages: write steps: - uses: actions/checkout@v4 - name: Set up QEMU uses: docker/setup-qemu-action@v3 - name: Set up Docker Buildx uses: docker/setup-buildx-action@v3 - name: Login to GitHub Container Registry uses: docker/login-action@v3 with: registry: ghcr.io username: ${{ github.actor }} password: ${{ secrets.GITHUB_TOKEN }} - name: Extract metadata id: meta uses: docker/metadata-action@v5 with: images: ghcr.io/${{ github.repository }} tags: | type=ref,event=branch type=semver,pattern={{version}} type=sha,prefix= - name: Build and push uses: docker/build-push-action@v5 with: context: . platforms: linux/amd64,linux/arm64 push: true tags: ${{ steps.meta.outputs.tags }} labels: ${{ steps.meta.outputs.labels }} cache-from: type=gha cache-to: type=gha,mode=max

🚀 SSH 部署配置

jobs: deploy: runs-on: ubuntu-latest needs: build-and-push if: github.ref == 'refs/heads/main' environment: name: production url: https://example.com steps: - name: Deploy to server uses: appleboy/ssh-action@v1.0.0 with: host: ${{ secrets.SERVER_HOST }} username: ${{ secrets.SERVER_USER }} key: ${{ secrets.SSH_PRIVATE_KEY }} port: 22 script: | cd /app/myapp # 拉取最新镜像 docker compose pull # 滚动更新 docker compose up -d --no-deps --build app # 清理旧镜像 docker image prune -f # 健康检查 sleep 10 curl -f http://localhost:3000/health || exit 1 echo "Deployment successful!"

⎈ Kubernetes 部署

jobs: deploy-k8s: runs-on: ubuntu-latest needs: build-and-push steps: - uses: actions/checkout@v4 - name: Set up kubectl uses: azure/setup-kubectl@v3 - name: Configure kubeconfig run: | mkdir -p ~/.kube echo "${{ secrets.KUBE_CONFIG }}" | base64 -d > ~/.kube/config - name: Deploy to Kubernetes run: | # 更新镜像版本 kubectl set image deployment/myapp \ myapp=ghcr.io/${{ github.repository }}:${{ github.sha }} \ -n production # 等待滚动更新完成 kubectl rollout status deployment/myapp -n production --timeout=300s # 验证部署 kubectl get pods -n production -l app=myapp - name: Rollback on failure if: failure() run: kubectl rollout undo deployment/myapp -n production

🔄 回滚机制

自动回滚

# 健康检查失败自动回滚 - name: Health check run: | for i in {1..30}; do if curl -f http://localhost:3000/health; then exit 0 fi sleep 2 done exit 1 - name: Rollback if: failure() run: | docker compose down docker compose up -d --force-recreate

手动回滚

# 保留历史版本便于回滚 tags: | type=semver,pattern={{version}} type=sha,prefix=v type=raw,value=latest # 回滚到指定版本 docker compose down docker tag myapp:v-abc123 myapp:latest docker compose up -d
⚠️
部署安全检查清单
  • 确保敏感信息通过 Secrets 管理，不要硬编码
  • 使用环境保护规则，审批后再部署生产
  • 配置部署通知，及时获知部署状态
  • 保留足够的历史版本用于回滚
  • 测试回滚流程，确保紧急情况可用
