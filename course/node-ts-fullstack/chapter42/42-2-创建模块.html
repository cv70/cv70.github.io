42.2 创建模块

使用 CLI 和手动方式创建模块

🎯 学习目标

  • 掌握使用 CLI 创建模块
  • 学会手动创建模块
  • 理解模块注册流程
  • 了解模块最佳实践

🚀 使用 CLI 创建模块

# 创建模块 nest g module users # 输出 CREATE src/users/users.module.ts (82 bytes) # 同时创建模块、控制器、服务 nest g resource users # 选择传输层 ? What transport layer do you use? REST API ? Would you like to generate CRUD entry points? Yes # 创建结果 CREATE src/users/users.module.ts (82 bytes) CREATE src/users/users.controller.ts (518 bytes) CREATE src/users/users.controller.spec.ts (482 bytes) CREATE src/users/users.service.ts (90 bytes) CREATE src/users/users.service.spec.ts (453 bytes) CREATE src/users/dto/create-user.dto.ts (31 bytes) CREATE src/users/dto/update-user.dto.ts (93 bytes) CREATE src/users/entities/user.entity.ts (22 bytes) UPDATE src/app.module.ts (326 bytes)
💡
CLI 简写

nest g mo users 等价于 nest g module users。常用简写：mo(module), co(controller), s(service), res(resource)。

🔧 手动创建模块

// 1. 创建 src/products/products.module.ts import { Module } from '@nestjs/common'; import { ProductsController } from './products.controller'; import { ProductsService } from './products.service'; @Module({ controllers: [ProductsController], providers: [ProductsService], }) export class ProductsModule {} // 2. 在根模块中注册 // src/app.module.ts import { Module } from '@nestjs/common'; import { ProductsModule } from './products/products.module'; @Module({ imports: [ProductsModule], // 注册 ProductsModule }) export class AppModule {}

📁 模块文件组织

src/users/ ├── dto/ # 数据传输对象 │ ├── create-user.dto.ts │ └── update-user.dto.ts ├── entities/ # 数据库实体 │ └── user.entity.ts ├── users.controller.ts # 控制器 ├── users.controller.spec.ts # 控制器测试 ├── users.service.ts # 服务 ├── users.service.spec.ts # 服务测试 └── users.module.ts # 模块定义
⚠️
文件命名规范

模块文件名使用小写-连字符格式（如 users.module.ts），类名使用帕斯卡命名（如 UsersModule）。

✨ 模块最佳实践

  • 每个功能模块独立管理自己的控制器和服务
  • 将共享服务放入共享模块并导出
  • 使用领域驱动设计(DDD)组织模块结构
  • 保持模块职责单一，高内聚低耦合
  • 避免循环依赖，必要时使用 forwardRef

📝 本节小结

✅
  • • nest g module 创建模块并自动注册
  • • nest g resource 创建完整资源（模块+控制器+服务）
  • • 手动创建需要在根模块 imports 中注册
  • • 遵循单一职责原则组织模块
