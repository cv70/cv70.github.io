索引构建概述

索引构建是RAG系统的基础工程，将原始文档转换为可检索的向量索引。高质量的索引直接影响检索效果和系统性能。一个完整的索引构建流水线包含数据收集、预处理、分块、嵌入、索引等多个环节。

📄 数据预处理

文档解析

支持的文档类型：
├── 文本文件：txt, md, csv
├── 文档文件：pdf, docx, pptx
├── 网页文件：html, xml
├── 代码文件：py, js, java
└── 其他：json, yaml
  • PDF解析：pdfplumber, PyPDF2
  • Word解析：python-docx
  • HTML解析：BeautifulSoup
  • 表格解析：pandas

数据清洗

  • 去除HTML标签
  • 去除特殊字符
  • 统一编码格式
  • 去除空章节
  • 文档去重

🔪 文本分块策略

分块策略 方法 优势 劣势 适用场景
固定长度 按字符/词数切分 简单、高效 破坏语义 结构化文档
段落分块 按段落切分 保持语义 长度不均 自然文本
语义分块 按语义边界切分 语义完整 计算复杂 复杂文档
递归分块 多级递归切分 灵活适应 实现复杂 混合文档

🧠 嵌入模型

主流嵌入模型

嵌入模型选择：

1. OpenAI Embeddings
   ├── text-embedding-3-small
   ├── text-embedding-3-large
   └── text-embedding-ada-002

2. HuggingFace Embeddings
   ├── BAAI/bge-large-zh（中文）
   ├── BAAI/bge-large-en-v1.5（英文）
   ├── sentence-transformers/all-MiniLM
   └── intfloat/e5-large-v2

3. 本地部署选项
   ├── TextEmbeddings-Inference
   ├── fastembed
   └── FlagEmbedding

选择标准：
• 语言支持：中文/英文/多语言
• 维度大小：768/1024/1536
• 性能：准确率 vs 速度
• 部署方式：云端/本地
• 成本：API费用 vs 硬件成本
💡
嵌入模型选择建议

对于中文RAG，推荐bge-large-zh系列；对于英文，推荐e5-large-v2或bge-en。如果追求极致性能，可以考虑M3E或OpenAI text-embedding-3。

🔍 向量索引算法

主流索引算法

向量索引算法：

1. HNSW（Hierarchical Navigable Small World）
   ├── 图结构索引
   ├── 高精度，中等速度
   ├── 支持动态更新
   └── 适用于：中等规模索引

2. IVF（Inverted File）
   ├── 聚类分区索引
   ├── 速度快，精度中等
   ├── 支持动态更新
   └── 适用于：大规模索引

3. Flat（暴力搜索）
   ├── 精确搜索
   ├── 速度慢
   ├── 内存占用大
   └── 适用于：小规模索引

4. PQ（Product Quantization）
   ├── 量化压缩
   ├── 大幅降低内存
   ├── 精度略有损失
   └── 适用于：超大规模索引

5. 稀疏索引
   ├── BM25/TF-IDF
   ├── 关键词检索
   ├── 不需要嵌入
   └── 适用于：混合检索

⚙️ 索引配置优化

HNSW参数

  • M：连接数（16-64）
  • efConstruction：构建参数（40-400）
  • efSearch：搜索参数（10-100）

IVF参数

  • nlist：聚类数（100-10000）
  • nprobe：搜索聚类数（10-100）
  • quantizer：底层量化器

📊 混合检索

向量+关键词混合检索

混合检索策略：

1. 早期融合（Early Fusion）
   ├── 向量检索
   ├── 关键词检索
   ├── 结果合并（加权平均）
   └── 重新排序

2. 后期融合（Late Fusion）
   ├── 向量检索：Top-K1
   ├── 关键词检索：Top-K2
   ├── 结果去重
   └── 分数融合

3. 紧密融合（Tight Fusion）
   ├── 联合特征表示
   ├── 统一相似度计算
   └── 复杂度高，效果好

融合权重优化：
• 向量权重：0.6-0.8
• 关键词权重：0.2-0.4
• 根据场景动态调整

混合检索结合了语义检索和关键词检索的优势，能够同时捕获语义相关性和精确匹配，提升检索质量。

🔄 索引更新策略

实时索引更新

更新策略 方法 优势 劣势
增量更新 实时添加新文档 延迟低 需要支持动态索引
批量更新 定期批量更新 效率高 有延迟
重建索引 全量重建 质量最高 成本高

🔧 LangChain索引构建

LangChain实践示例

from langchain.text_splitter import RecursiveCharacterTextSplitter
from langchain.embeddings import HuggingFaceEmbeddings
from langchain.vectorstores import Chroma
from langchain.document_loaders import PyPDFLoader

# 1. 加载文档
loader = PyPDFLoader("document.pdf")
documents = loader.load()

# 2. 文本分块
text_splitter = RecursiveCharacterTextSplitter(
    chunk_size=1000,
    chunk_overlap=200,
    length_function=len,
    separators=["\n\n", "\n", " ", ""]
)
splits = text_splitter.split_documents(documents)

# 3. 加载嵌入模型
embeddings = HuggingFaceEmbeddings(
    model_name="BAAI/bge-large-zh",
    model_kwargs={'device': 'cuda'}
)

# 4. 构建索引
vectorstore = Chroma.from_documents(
    documents=splits,
    embedding=embeddings,
    persist_directory="./chroma_db"
)

# 5. 保存索引
vectorstore.persist()
⚠️
索引构建注意事项

索引构建要考虑数据质量、分块策略、嵌入模型、索引参数的相互配合。建立质量评估和A/B测试机制，持续优化索引质量。

📈 性能优化

索引构建优化策略

  • 并行处理：多进程/多GPU并行嵌入
  • 批量处理：批量嵌入减少开销
  • 缓存机制：缓存已处理文档
  • 增量构建：只处理新文档
  • 索引压缩：量化、剪枝降低存储
  • 分布式构建：大规模数据分布式处理
