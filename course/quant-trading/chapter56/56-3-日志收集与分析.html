56.3 日志收集与分析

集中式日志管理与分析

🎯 学习目标

  • 理解日志管理的重要性和挑战
  • 掌握日志收集、存储、分析的方法
  • 能够搭建集中式日志系统
  • 了解日志查询和故障排查技巧

日志收集与分析

日志是系统运行的"黑匣子"，记录了系统运行过程中的所有事件。完善的日志体系对故障排查、审计追踪、性能分析都至关重要。

📋 日志分类

系统日志

  • 操作系统日志：/var/log系统日志
  • 服务日志：Nginx、Systemd等
  • 容器日志：Docker/Kubernetes日志
  • 安全日志：登录、权限等安全事件

应用日志

  • 错误日志：ERROR级别日志
  • 警告日志：WARN级别日志
  • 访问日志：HTTP/RPC访问日志
  • 业务日志：关键业务操作日志

交易日志

  • 信号日志：交易信号生成日志
  • 订单日志：订单提交/成交日志
  • 成交日志：成交确认日志
  • 风控日志：风控触发日志

🔧 日志收集架构

ELK架构

  • Filebeat：轻量级日志收集器
  • Logstash：数据处理管道
  • Elasticsearch：日志存储和检索
  • Kibana：日志可视化

EFK架构

  • Fluentd：日志收集和处理
  • Elasticsearch：日志存储
  • Kibana：日志可视化

Loki架构

  • Promtail：日志采集
  • Loki：日志存储（时序）
  • Grafana：日志可视化

📝 日志规范

日志格式

  • 结构化日志：使用JSON格式
  • 标准字段：时间、级别、消息、上下文
  • 唯一标识：trace_id、request_id
  • 上下文信息：用户、环境、服务

日志级别

级别 含义 使用场景
DEBUG 调试信息 开发调试
INFO 常规信息 正常运行记录
WARN 警告信息 潜在问题
ERROR 错误信息 错误但可恢复
FATAL 致命错误 系统不可用

日志最佳实践

  • 上下文完整：包含足够的上下文信息
  • 避免敏感信息：不记录密码、密钥等
  • 性能考虑：异步日志、合理采样
  • 日志轮转：定期轮转日志文件

🔍 日志查询与分析

日志查询

  • 关键词搜索：搜索关键词
  • 正则表达式：复杂模式匹配
  • 范围查询：时间范围查询
  • 聚合分析：统计聚合

日志分析

  • 趋势分析：日志量随时间变化
  • 错误分析：错误日志统计和分布
  • 关联分析：关联不同来源日志
  • 异常检测：异常模式识别

故障排查

  • 时间线：构建事件时间线
  • 链路追踪：追踪请求链路
  • 根因分析：定位故障根本原因
  • 证据收集：收集故障证据

💾 日志存储与管理

日志保留

  • 热日志：近7天热数据
  • 温日志：30天内温数据
  • 冷日志：30天后归档
  • 合规要求：按法规要求保留

日志备份

  • 异地备份：日志异地备份
  • 压缩存储：历史日志压缩
  • 加密存储：敏感日志加密
  • 恢复测试：定期测试恢复
✨
最佳实践

建议采用结构化日志，统一日志格式。使用集中式日志系统，便于统一管理和查询。建立日志规范，明确不同级别日志的使用场景。定期分析日志，发现潜在问题和优化机会。
