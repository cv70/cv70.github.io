57.3 HTTP 方法语义

正确使用 HTTP 方法表达资源操作意图

📖 HTTP 方法概述

HTTP 方法定义了对资源执行的操作类型。在 RESTful API 设计中，正确使用 HTTP 方法语义是关键。

方法 语义 幂等性 安全性 可缓存
GET 获取资源 是 是 是
POST 创建资源 否 否 否
PUT 完整更新资源 是 否 否
PATCH 部分更新资源 否 否 否
DELETE 删除资源 是 否 否
HEAD 获取资源头部信息 是 是 是
OPTIONS 获取支持的方法 是 是 否

🔍 GET 方法

GET 方法用于获取资源，是安全且幂等的方法。多次执行相同的 GET 请求应该返回相同的结果。

获取资源列表

// 请求 GET /users HTTP/1.1 Host: api.example.com Accept: application/json // 响应 HTTP/1.1 200 OK Content-Type: application/json { "data": [ { "id": 1, "name": "张三" }, { "id": 2, "name": "李四" } ], "total": 100 }

获取单个资源

// 请求 GET /users/123 HTTP/1.1 Host: api.example.com // 响应 HTTP/1.1 200 OK Content-Type: application/json { "id": 123, "name": "张三", "email": "zhangsan@example.com" }

带查询参数

// 分页查询 GET /users?page=1&pageSize=10 // 过滤查询 GET /users?status=active&role=admin // 排序 GET /users?sort=-createdAt,name // 字段选择 GET /users?fields=id,name,email // 搜索 GET /users?q=zhang

➕ POST 方法

POST 方法用于创建资源。POST 请求不是幂等的，多次执行相同的 POST 请求会创建多个资源。

// 创建用户 POST /users HTTP/1.1 Host: api.example.com Content-Type: application/json { "name": "王五", "email": "wangwu@example.com", "password": "securePassword123" } // 响应 - 201 Created HTTP/1.1 201 Created Location: /users/124 Content-Type: application/json { "id": 124, "name": "王五", "email": "wangwu@example.com", "createdAt": "2024-01-15T10:30:00Z" }
💡
POST 的其他用途

POST 不仅用于创建资源，还可用于：复杂查询、批量操作、登录认证、文件上传等不适合用 GET 表达的场景。

✏️ PUT 方法

PUT 方法用于完整更新资源，是幂等的。PUT 请求会替换整个资源，未提供的字段会被设为默认值或 null。

// 完整更新用户 PUT /users/123 HTTP/1.1 Host: api.example.com Content-Type: application/json { "name": "张三更新", "email": "newemail@example.com", "age": 25, "role": "user" } // 响应 - 200 OK HTTP/1.1 200 OK Content-Type: application/json { "id": 123, "name": "张三更新", "email": "newemail@example.com", "age": 25, "role": "user", "updatedAt": "2024-01-15T12:00:00Z" }
⚠️
PUT vs POST

PUT 用于更新已知 URI 的资源，POST 用于在集合中创建新资源。PUT 是幂等的，POST 不是。

🔧 PATCH 方法

PATCH 方法用于部分更新资源，只更新请求中包含的字段。PATCH 不是幂等的。

// 部分更新用户 - 只更新 email PATCH /users/123 HTTP/1.1 Host: api.example.com Content-Type: application/json { "email": "updated@example.com" } // 响应 - 200 OK HTTP/1.1 200 OK Content-Type: application/json { "id": 123, "name": "张三", // 保持不变 "email": "updated@example.com", // 已更新 "age": 25 // 保持不变 }

PATCH 操作格式（JSON Patch）

// RFC 6902 JSON Patch 格式 PATCH /users/123 HTTP/1.1 Content-Type: application/json-patch+json [ { "op": "replace", "path": "/email", "value": "new@example.com" }, { "op": "add", "path": "/tags/-", "value": "vip" }, { "op": "remove", "path": "/temp" } ]

🗑️ DELETE 方法

DELETE 方法用于删除资源，是幂等的。删除已删除的资源仍返回成功。

// 删除用户 DELETE /users/123 HTTP/1.1 Host: api.example.com // 响应 - 204 No Content HTTP/1.1 204 No Content // 或返回删除确认信息 HTTP/1.1 200 OK Content-Type: application/json { "message": "用户已成功删除", "id": 123 }

💻 NestJS HTTP 方法实现

import { Controller, Get, Post, Put, Patch, Delete, Param, Body, HttpCode, HttpStatus, } from '@nestjs/common'; @Controller('users') export class UserController { // GET - 获取列表 @Get() async findAll(): Promise { return this.userService.findAll(); } // GET - 获取单个 @Get(':id') async findOne(@Param('id') id: string): Promise { return this.userService.findOne(+id); } // POST - 创建 @Post() @HttpCode(HttpStatus.CREATED) async create(@Body() createUserDto: CreateUserDto): Promise { return this.userService.create(createUserDto); } // PUT - 完整更新 @Put(':id') async update( @Param('id') id: string, @Body() updateUserDto: UpdateUserDto, ): Promise { return this.userService.update(+id, updateUserDto); } // PATCH - 部分更新 @Patch(':id') async partialUpdate( @Param('id') id: string, @Body() partialUpdateDto: PartialUpdateUserDto, ): Promise { return this.userService.partialUpdate(+id, partialUpdateDto); } // DELETE - 删除 @Delete(':id') @HttpCode(HttpStatus.NO_CONTENT) async remove(@Param('id') id: string): Promise<void> { await this.userService.remove(+id); } }

📊 幂等性与安全性详解

安全性（Safe）

安全方法不会修改服务器状态。多次调用安全方法不会产生副作用。

  • GET - 只读取数据
  • HEAD - 只获取头部
  • OPTIONS - 只获取选项

幂等性（Idempotent）

幂等方法多次执行同一请求，结果与执行一次相同。

  • GET、HEAD、OPTIONS - 安全且幂等
  • PUT - 幂等（替换整个资源）
  • DELETE - 幂等（删除已删除仍成功）
  • POST、PATCH - 非幂等

📝 小结

  • GET 用于获取资源，安全且幂等
  • POST 用于创建资源，非幂等
  • PUT 用于完整更新资源，幂等
  • PATCH 用于部分更新资源，非幂等
  • DELETE 用于删除资源，幂等
  • 正确使用 HTTP 方法语义使 API 更清晰易懂
