27.2 时序路径分析

时序路径的类型和分析方法

🎯 学习目标

  • 掌握四种基本时序路径类型
  • 理解每种路径的分析方法
  • 学会识别关键路径
  • 了解路径延迟的组成

🛤️ 时序路径类型

1. 寄存器到寄存器路径

最常见的时序路径类型，连接两个寄存器之间的组合逻辑。

起点：寄存器时钟引脚（CK） → 寄存器输出引脚（Q） → 组合逻辑网络 → 寄存器数据输入引脚（D） → 寄存器时钟引脚（CK） 终点：寄存器时钟引脚（CK）

2. 输入端口到寄存器路径

从芯片输入端口到第一个寄存器的路径。

起点：输入端口 → 输入延迟 → 组合逻辑网络 → 寄存器数据输入引脚（D） → 寄存器时钟引脚（CK） 终点：寄存器时钟引脚（CK）

3. 寄存器到输出端口路径

从最后一个寄存器到芯片输出端口的路径。

起点：寄存器时钟引脚（CK） → 寄存器输出引脚（Q） → 组合逻辑网络 → 输出端口 终点：输出端口

4. 输入端口到输出端口路径

纯组合逻辑路径，不经过任何寄存器。

起点：输入端口 → 输入延迟 → 组合逻辑网络 → 输出端口 终点：输出端口

📊 路径延迟组成

寄存器到寄存器路径延迟

数据路径延迟 = T_clk_to_q + T_comb + T_setup 其中： - T_clk_to_q: 寄存器时钟到输出的延迟 - T_comb: 组合逻辑延迟 - T_setup: 目标寄存器的建立时间

输入到寄存器路径延迟

数据路径延迟 = T_input_delay + T_comb + T_setup 其中： - T_input_delay: 输入延迟（外部电路延迟） - T_comb: 内部组合逻辑延迟 - T_setup: 寄存器建立时间

🔍 关键路径识别

关键路径特征

  • Slack最小或为负
  • 延迟最长
  • 决定设计的最高工作频率
  • 是时序优化的重点

关键路径分析命令

# 报告关键路径 report_timing -max_paths 10 # 报告特定类型的路径 report_timing -from [get_clocks CLK1] -to [get_clocks CLK2] # 报告通过特定单元的路径 report_timing -through [get_cells critical_logic*]

⚙️ 路径分析实例

# ============================================================================ # 时序路径分析示例 # ============================================================================ # 分析所有寄存器到寄存器路径 report_timing -max_paths 20 -delay_type max \ > reports/reg2reg_setup.rpt report_timing -max_paths 20 -delay_type min \ > reports/reg2reg_hold.rpt # 分析输入路径 report_timing -from [all_inputs] -max_paths 10 \ > reports/input_paths.rpt # 分析输出路径 report_timing -to [all_outputs] -max_paths 10 \ > reports/output_paths.rpt # 分析组合逻辑路径 report_timing -from [all_inputs] -to [all_outputs] \ -max_paths 10 > reports/combo_paths.rpt # 按路径组分析 foreach group [all_path_groups] { report_timing -path_group $group -max_paths 5 \ > reports/path_group_${group}.rpt }
💡
路径分析建议

1）优先分析寄存器到寄存器路径；2）关注负Slack路径； 3）识别可优化的关键路径；4）考虑路径优化对其他路径的影响； 5）使用路径分组进行分类分析。
