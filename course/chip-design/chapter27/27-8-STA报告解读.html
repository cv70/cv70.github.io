📊 时序路径报告

典型路径报告结构

Path 1: SETUP slack (MET) 0.25ns Startpoint: reg1 [DFFQ_X1] (rising edge-triggered) Endpoint: reg2 [DFFQ_X1] (rising edge-triggered) Path Group: CLK Path Type: max Point Incr Path --------------------------------------------------------- clock CLK (rise edge) 0.00 0.00 clock network delay (ideal) 0.00 0.00 reg1/CK (DFFQ_X1) 0.00 0.00 r reg1/Q (DFFQ_X1) 0.12 0.12 r U1/A (INVX1) -0.08 0.04 f U1/Y (INVX1) 0.15 0.19 r U2/A (NAND2X1) 0.18 0.37 f U2/Y (NAND2X1) 0.22 0.59 r reg2/D (DFFQ_X1) 0.00 0.59 f reg2/CK (DFFQ_X1) 0.00 0.59 r data arrival time 0.59 clock CLK (rise edge) 10.00 10.00 clock network delay (ideal) 0.00 10.00 clock uncertainty -0.30 9.70 reg2/CK (DFFQ_X1) 0.00 9.70 r library setup time -0.20 9.50 data required time 9.50 slack (MET) 0.25

报告解读要点

  • Slack: 正值表示满足时序，负值表示违例
  • Startpoint/Endpoint: 路径的起点和终点
  • Incr: 该段的延迟增量
  • Path: 累计路径延迟
  • data arrival time: 数据到达时间
  • data required time: 数据要求到达时间

📈 时序摘要报告

报告内容

========================================== Timing Summary Report ========================================== Design: top_module Version: PrimeTime 2023.12 Date: Mon Apr 13 15:30:00 2026 ------------------------------------------ Setup Summary ------------------------------------------ WNS: 0.15 ns (MET at reg1/reg2) TNS: 0.00 ns Violating Paths: 0 Total Paths: 15432 ------------------------------------------ Hold Summary ------------------------------------------ WNS: 0.08 ns (MET at reg3/reg4) TNS: 0.00 ns Violating Paths: 0 Total Paths: 15432 ------------------------------------------ Clock Summary ------------------------------------------ Clock Period WNS TNS Paths ------------------------------------------ CLK 10.0 0.15 0.00 8234 CLK2 15.0 0.35 0.00 4567 ASYNC 20.0 2.50 0.00 2631 ------------------------------------------ Path Group Summary ------------------------------------------ Group WNS TNS Paths ------------------------------------------ CLK 0.15 0.00 8234 CLK2 0.35 0.00 4567 ASYNC 2.50 0.00 2631

关键指标说明

  • WNS (Worst Negative Slack): 最差负Slack
  • TNS (Total Negative Slack): 总负Slack
  • Violating Paths: 违例路径数量
  • Total Paths: 总路径数量

📝 报告分析技巧

1. 识别关键路径

关注Slack最小的路径，这些是设计的瓶颈。

2. 分析路径组成

查看路径上的每个单元，找出延迟最大的部分。

3. 比较不同角的结果

对比SS、TT、FF角下的时序，评估设计的鲁棒性。

4. 追踪问题根源

从违例路径反向追踪，找到问题的根本原因。

5. 验证修复效果

修复前后对比报告，确认问题已解决。

⚠️ 常见报告问题

问题表现 可能原因 解决方向
大量Setup违例 设计过于复杂或时钟过快 优化设计或降低频率
Hold违例 时钟偏斜或数据路径过短 优化时钟树或增加延迟
未约束路径 约束不完整 补充缺失约束
跨角违例 OCV考虑不足 增加OCV分析
