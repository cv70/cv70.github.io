100.1 CI/CD 概念

理解持续集成与持续交付的核心思想

🎯 学习目标

  • 理解 CI/CD 的核心概念与价值
  • 区分 CI、CD、CD 三个概念
  • 了解 CI/CD 流水线的基本组成
  • 掌握 CI/CD 最佳实践

什么是 CI/CD

CI/CD（Continuous Integration/Continuous Delivery）是一套软件开发实践，旨在通过自动化构建、测试和部署流程， 让团队能够更频繁、更可靠地交付软件产品。

🔄 CI/CD 三大支柱

🔄

Continuous Integration
持续集成

开发人员频繁地将代码合并到主分支，每次合并都自动触发构建和测试

🚀

Continuous Delivery
持续交付

代码经过测试后自动部署到预生产环境，可随时手动发布到生产环境

🎯

Continuous Deployment
持续部署

代码通过所有测试后自动部署到生产环境，无需人工干预

📊 CI/CD 流水线

┌─────────┐ ┌─────────┐ ┌─────────┐ ┌─────────┐ ┌─────────┐ │ 代码 │──▶│ 构建 │──▶│ 测试 │──▶│ 发布 │──▶│ 部署 │ │ 提交 │ │ │ │ │ │ │ │ │ └─────────┘ └─────────┘ └─────────┘ └─────────┘ └─────────┘ │ │ │ │ │ ▼ ▼ ▼ ▼ ▼ Git Push 安装依赖 单元测试 打包镜像 部署到环境 PR/MR 编译代码 集成测试 推送仓库 运行容器 E2E测试

📋 流水线阶段详解

阶段 任务 目的
Source 代码检查、Lint、安全扫描 确保代码质量，发现问题
Build 安装依赖、编译代码、打包 生成可部署的制品
Test 单元测试、集成测试、E2E测试 验证功能正确性
Release 构建镜像、推送仓库、打标签 创建发布版本
Deploy 部署到目标环境、健康检查 应用上线运行

🛠️ CI/CD 工具对比

GitHub Actions

  • GitHub 原生支持，配置简单
  • 丰富的 Actions 市场生态
  • 矩阵构建支持多平台
  • 免费额度充足

GitLab CI/CD

  • 内置完整 DevOps 平台
  • 强大的 Auto DevOps
  • 自托管支持完善
  • 安全扫描功能丰富

Jenkins

  • 开源免费，社区活跃
  • 插件生态极其丰富
  • 高度可定制
  • 企业级功能成熟

CircleCI

  • 配置简洁，上手快
  • 并行执行效率高
  • 支持 Docker 和机器执行器
  • 调试 SSH 功能便捷
💡
CI/CD 的价值
  • 减少人为错误：自动化流程避免手动操作失误
  • 提高交付效率：从代码提交到部署可缩短到分钟级
  • 快速反馈循环：问题在早期发现，修复成本低
  • 提升代码质量：强制执行测试和代码检查标准
  • 增强团队信心：每次发布都是可靠的、可重复的

✨ 最佳实践

提交阶段

  • 保持小批量、频繁提交
  • 提交前本地运行测试
  • 编写有意义的提交信息
  • 使用分支保护规则

构建阶段

  • 保持构建快速（<10分钟）
  • 使用缓存加速依赖安装
  • 并行执行独立任务
  • 构建失败立即修复

测试阶段

  • 测试金字塔：单元 > 集成 > E2E
  • 保持测试覆盖率要求
  • 测试失败视为阻塞性问题
  • 测试数据与代码同步维护

部署阶段

  • 自动化一切可自动化步骤
  • 使用蓝绿或金丝雀部署
  • 配置回滚机制
  • 部署后自动健康检查

📝 本节小结

✅
  • • CI 是持续集成，CD 是持续交付或持续部署
  • • 流水线包含：Source -> Build -> Test -> Release -> Deploy
  • • 常用工具有 GitHub Actions、GitLab CI、Jenkins 等
  • • CI/CD 能提高交付效率、减少人为错误、快速发现问题
