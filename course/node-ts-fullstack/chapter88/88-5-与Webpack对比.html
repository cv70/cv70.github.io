88.5 与 Webpack 对比

Vite 与 Webpack 的差异分析

🎯 学习目标

  • 理解 Vite 和 Webpack 的核心差异
  • 掌握两者的优缺点
  • 学会根据项目选择工具
  • 了解迁移注意事项

📚 核心差异对比

┌───────────────────┬────────────────────┬────────────────────┐ │ 对比项 │ Vite │ Webpack │ ├───────────────────┼────────────────────┼────────────────────┤ │ 开发服务器启动 │ 毫秒级 │ 秒级到分钟级 │ │ 构建原理 │ 原生 ESM + esbuild │ Bundle 打包 │ │ 热更新速度 │ 毫秒级 │ 秒级 │ │ 生产构建工具 │ Rollup │ Webpack │ │ 配置复杂度 │ 简单 │ 复杂 │ │ 生态系统成熟度 │ 发展中 │ 成熟 │ │ 学习曲线 │ 平缓 │ 陡峭 │ │ TypeScript 支持 │ 内置 │ 需要配置 │ │ CSS 预处理器 │ 内置支持 │ 需要 Loader │ │ 插件数量 │ 较少 │ 丰富 │ └───────────────────┴────────────────────┴────────────────────┘ # 工作原理对比 ## Webpack 开发模式 源代码 → 编译打包 → 开发服务器 → 浏览器 （全量编译，启动慢） ## Vite 开发模式 源代码 → 开发服务器 → 浏览器（原生 ESM） （按需编译，启动快） ## 生产构建 Webpack: 自带打包器 Vite: 使用 Rollup（更优的 Tree Shaking）

🔧 配置对比

// Webpack 配置 (复杂) // webpack.config.js const path = require('path') const HtmlWebpackPlugin = require('html-webpack-plugin') const MiniCssExtractPlugin = require('mini-css-extract-plugin') module.exports = { entry: './src/index.js', output: { path: path.resolve(__dirname, 'dist'), filename: '[name].[contenthash].js', }, module: { rules: [ { test: /\.css$/, use: [MiniCssExtractPlugin.loader, 'css-loader'], }, { test: /\.(png|svg|jpg|jpeg|gif)$/i, type: 'asset/resource', }, { test: /\.tsx?$/, use: 'ts-loader', exclude: /node_modules/, }, ], }, resolve: { extensions: ['.tsx', '.ts', '.js'], }, plugins: [ new HtmlWebpackPlugin({ template: './src/index.html', }), new MiniCssExtractPlugin({ filename: '[name].[contenthash].css', }), ], devServer: { static: './dist', hot: true, port: 3000, }, } // Vite 配置 (简洁) // vite.config.ts import { defineConfig } from 'vite' export default defineConfig({ server: { port: 3000, }, }) // CSS、TypeScript、图片等开箱即用！

⚙️ 优缺点分析

# Vite 优点 ✅ 开发服务器启动极快 ✅ 热更新响应迅速 ✅ 配置简单，开箱即用 ✅ 内置 TypeScript/JSX/CSS 预处理器支持 ✅ 生产构建使用 Rollup，Tree Shaking 更好 ✅ 更好的开发体验 # Vite 缺点 ❌ 生态系统不如 Webpack 成熟 ❌ 插件数量相对较少 ❌ 部分老旧库兼容性问题 ❌ CommonJS 依赖处理可能有问题 ❌ 生产构建使用 Rollup，某些 Webpack 功能不支持 # Webpack 优点 ✅ 生态系统成熟，插件丰富 ✅ 功能强大，可定制性强 ✅ 社区支持广泛 ✅ 兼容性好，支持各种场景 ✅ 文档完善 # Webpack 缺点 ❌ 配置复杂，学习曲线陡峭 ❌ 开发服务器启动慢 ❌ 热更新速度慢 ❌ 构建时间长 # 选择建议 - 新项目推荐使用 Vite - 复杂企业级项目可考虑 Webpack - Vue/React 新项目优先 Vite - 需要特定 Webpack 插件时用 Webpack
💡
选择建议

大多数新项目推荐使用 Vite，开发体验更好。如果项目有特殊的构建需求或依赖特定的 Webpack 插件，可以继续使用 Webpack。

🚀 Webpack 迁移 Vite

# 迁移步骤 ## 1. 安装 Vite npm install -D vite @vitejs/plugin-vue ## 2. 创建配置文件 // vite.config.ts import { defineConfig } from 'vite' import vue from '@vitejs/plugin-vue' import path from 'path' export default defineConfig({ plugins: [vue()], resolve: { alias: { '@': path.resolve(__dirname, 'src'), }, }, }) ## 3. 移动 index.html # 将 index.html 移到项目根目录 # 修改脚本引用 <script type="module" src="/src/main.js"></script> ## 4. 更新环境变量 # 将 VUE_APP_* 改为 VITE_* # process.env 改为 import.meta.env ## 5. 更新 package.json { "scripts": { "dev": "vite", "build": "vite build", "preview": "vite preview" } } ## 6. 处理特定语法 // Webpack require.context → Vite import.meta.glob const modules = import.meta.glob('./modules/*.js') // Webpack 动态 import const module = await import(`./views/${name}.vue`) ## 7. 处理 CSS // 移除 style-loader, css-loader 配置 // Vite 自动处理 CSS ## 8. 测试验证 npm run dev npm run build npm run preview

📝 本节小结

✅
  • • Vite 开发体验更好，Webpack 生态更成熟
  • • Vite 配置简单，Webpack 可定制性强
  • • 新项目推荐 Vite，特殊需求可用 Webpack
  • • 迁移时注意环境变量和动态导入语法差异
