63.2 WebSocket vs HTTP

深入对比两种通信协议

🎯 学习目标

  • 理解 HTTP 与 WebSocket 的本质区别
  • 掌握各自的适用场景
  • 了解轮询、长轮询等实时通信方案
  • 能够根据场景选择合适的通信方式

⚖️ 核心对比

特性 HTTP WebSocket
通信模式 半双工（请求-响应） 全双工（双向通信）
连接方式 短连接（HTTP/1.1 默认 Keep-Alive） 持久连接
服务端推送 不支持（需轮询） 原生支持
协议开销 每次请求都有完整 HTTP 头 仅握手时有 HTTP 头，之后帧头很小
连接状态 无状态 有状态
数据格式 文本为主 文本和二进制
兼容性 所有环境 现代浏览器

🔄 HTTP 实现实时通信的方案

1. 短轮询（Short Polling）

客户端定时向服务端发送请求，询问是否有新数据。

// 客户端定时轮询 setInterval(async () => { const response = await fetch('/api/messages'); const data = await response.json(); if (data.length > 0) { // 处理新消息 } }, 3000);
⚠️
缺点

频繁请求浪费资源，延迟取决于轮询间隔，无法真正实现实时。

2. 长轮询（Long Polling）

客户端发送请求后，服务端保持连接直到有数据或超时。

// 服务端示例（Express） app.get('/api/long-poll', async (req, res) => { const checkForData = () => { return new Promise((resolve) => { const interval = setInterval(() => { const data = checkNewData(); if (data) { clearInterval(interval); resolve(data); } }, 1000); // 超时处理 setTimeout(() => { clearInterval(interval); resolve(null); }, 30000); }); }; const data = await checkForData(); res.json(data || []); });
⚠️
缺点

服务端需要维护大量挂起的请求，资源消耗大；重连时有延迟。

3. Server-Sent Events (SSE)

服务端向客户端的单向推送，基于 HTTP 实现。

// 客户端 const eventSource = new EventSource('/api/events'); eventSource.onmessage = (event) => { console.log('收到消息:', event.data); }; // 服务端（Express） app.get('/api/events', (req, res) => { res.setHeader('Content-Type', 'text/event-stream'); res.setHeader('Cache-Control', 'no-cache'); res.setHeader('Connection', 'keep-alive'); const sendEvent = () => { res.write(`data: ${JSON.stringify({ time: Date.now() })}\n\n`); }; const interval = setInterval(sendEvent, 1000); req.on('close', () => clearInterval(interval)); });
💡
适用场景

SSE 适合服务端单向推送（如股票行情、通知），实现简单，自动重连。

📊 性能对比

📈

延迟

WebSocket < SSE < 长轮询 < 短轮询

💾

资源消耗

WebSocket < SSE < 长轮询 < 短轮询

🔧

实现复杂度

短轮询 < SSE < 长轮询 < WebSocket

🎯 如何选择

场景 推荐方案 原因
普通 API 请求 HTTP REST 简单、无状态、易于缓存
服务端单向推送通知 SSE 实现简单，自动重连
即时聊天/协作 WebSocket 双向实时通信
在线游戏 WebSocket 低延迟双向通信
股票行情/数据监控 SSE/WebSocket 实时数据推送
文件上传/下载 HTTP 支持断点续传，有标准
✅
最佳实践

在实际项目中，通常会将 HTTP 和 WebSocket 结合使用：HTTP 用于普通 API 请求，WebSocket 用于需要实时通信的功能。这种混合架构可以兼顾开发效率和实时性需求。

📝 本节小结

✅
  • • HTTP 是请求-响应模式，WebSocket 是全双工通信
  • • HTTP 实现实时通信有轮询、长轮询、SSE 等方案
  • • WebSocket 适合双向实时通信场景，性能最优
  • • SSE 适合服务端单向推送，实现简单
  • • 实际项目常采用 HTTP + WebSocket 混合架构
