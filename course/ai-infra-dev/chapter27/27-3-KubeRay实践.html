27.3 KubeRay实践

Kubernetes上的Ray集群管理

🎯 学习目标

  • 理解Ray在分布式AI中的角色
  • 掌握KubeRay Operator的安装与配置
  • 学会创建和管理Ray集群
  • 了解Ray Jobs和Ray Services的用法

Ray与KubeRay简介

Ray是用于分布式AI应用的高性能执行引擎，支持机器学习训练、推理、强化学习等场景。 KubeRay是Ray官方的Kubernetes Operator，简化在Kubernetes上部署和管理Ray集群。

🏗️ Ray架构

图：Ray核心架构

Head Node

集群控制节点，负责调度和协调。

  • 运行GCS服务
  • 管理集群状态
  • 调度任务
  • 提供Dashboard

Worker Node

工作节点，执行计算任务。

  • 运行Raylet
  • 管理Actor
  • 存储Object
  • 执行Task

Object Store

分布式内存存储。

  • 共享内存
  • 零拷贝传输
  • 自动分片
  • 容错恢复

📦 安装KubeRay

使用Helm安装

# 添加KubeRay Helm仓库 helm repo add kuberay https://ray-project.github.io/kuberay-helm helm repo update # 创建命名空间 kubectl create namespace kuberay-operator # 安装KubeRay Operator helm install kuberay-operator kuberay/kuberay-operator \ --namespace kuberay-operator # 验证安装 kubectl get pods -n kuberay-operator kubectl get crd | grep ray.io
💡
自定义资源

KubeRay引入了4个CRD：RayCluster、RayJob、RayService和RayClusterConfig。

使用kubectl安装

# 安装KubeRay Operator kubectl create -f https://raw.githubusercontent.com/ray-project/kuberay/release-1.0/ray-operator/config/default/kustomization.yaml # 或使用特定版本 kubectl create -k "github.com/ray-project/kuberay/ray-operator/config/default?ref=v1.0.0"

基本RayCluster配置

📊 Ray Jobs

Ray Job简介

Ray Job用于提交一次性任务到Ray集群，支持任务重试、失败恢复等特性。

提交Ray Job

apiVersion: ray.io/v1 kind: RayJob metadata: name: ray-job-sample spec: entrypoint: python /home/ray/samples/sample_code.py runtimeEnv: | pip: - requests==2.26.0 env_vars: TEST_VAR: "hello world" # shutdownAfterJobFinishes 控制Job完成后是否关闭集群 shutdownAfterJobFinishes: false # 使用已存在的RayCluster clusterSelector: ray.io/cluster: raycluster-complete # 或者动态创建RayCluster rayClusterSpec: rayVersion: '2.8.0' headGroupSpec: rayStartParams: dashboard-host: '0.0.0.0' serviceType: ClusterIP replicas: 1 template: spec: containers: - name: ray-head image: rayproject/ray:2.8.0-py310

监控Job状态

# 查看Job状态 kubectl get rayjob # 查看Job详情 kubectl describe rayjob ray-job-sample # 查看日志 kubectl logs -l ray.io/job-name=ray-job-sample

🌐 Ray Services

Ray Service简介

Ray Service用于部署长期运行的Ray服务，支持自动扩缩容、版本管理、负载均衡等。

部署Ray Service

apiVersion: ray.io/v1 kind: RayService metadata: name: ray-service-sample spec: serviceUnhealthySecondThreshold: 180 deploymentUnhealthySecondThreshold: 180 # 服务配置 serveConfigV2: | applications: - name: my_app route_prefix: / import_path: my_module:endpoint runtime_env: working_dir: "https://github.com/ray-project/serve_config_examples/archive/refs/heads/main.zip" pip: - transformers==4.27.4 - torch==2.0.0 - accelerate==0.18.0 deployments: - name: Summarizer autoscaling_config: target_num_ongoing_requests_per_replica: 1 min_replicas: 1 max_replicas: 5 # 集群配置 rayClusterConfig: rayVersion: '2.8.0' headGroupSpec: rayStartParams: dashboard-host: '0.0.0.0' serviceType: ClusterIP replicas: 1 template: spec: containers: - name: ray-head image: rayproject/ray:2.8.0-py310
💡
Service特性
  • • 自动部署和更新
  • • 零停机滚动更新
  • • 基于请求的自动扩缩容
  • • 健康检查和自动恢复

📈 自动扩缩容

配置自动扩缩容

apiVersion: ray.io/v1 kind: RayCluster metadata: name: raycluster-autoscale spec: rayVersion: '2.8.0' enableInTreeAutoscaling: true autoscalerOptions: upscalingMode: Default idleTimeoutMinutes: 5 imagePullPolicy: Always headGroupSpec: rayStartParams: dashboard-host: '0.0.0.0' autoscaling-config: | { "max_workers": 10, "upscaling_speed": 1.0, "downscaling_speed": 1.0, "idle_timeout_minutes": 5 } replicas: 1 template: spec: containers: - name: ray-head image: rayproject/ray:2.8.0-py310 workerGroupSpecs: - replicas: 2 minReplicas: 1 maxReplicas: 10 groupName: worker-group template: spec: containers: - name: ray-worker image: rayproject/ray:2.8.0-py310
✅
扩缩容策略
  • • Default：保守扩缩，避免频繁调整
  • • Aggressive：快速扩缩，响应负载变化
  • • Conservative：慢速扩缩，降低成本
