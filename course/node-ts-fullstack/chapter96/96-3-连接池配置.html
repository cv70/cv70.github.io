📚 连接池概述

# 为什么需要连接池 ## 没有连接池时 每个请求都要创建新连接 ├── TCP 三次握手 ├── 认证授权 └── 建立会话 耗时：几十到几百毫秒 ## 使用连接池 连接预先创建并复用 ├── 连接创建一次 ├── 请求复用连接 └── 连接保持活跃 耗时：几乎为零 # 连接池工作原理 应用请求 │ ▼ ┌─────────────────────────────────────┐ │ Connection Pool │ │ ┌─────┐ ┌─────┐ ┌─────┐ ┌─────┐ │ │ │ C1 │ │ C2 │ │ C3 │ │ C4 │ │ │ └─────┘ └─────┘ └─────┘ └─────┘ │ │ ↑ ↑ ↑ ↑ │ │ idle active active idle │ └─────────────────────────────────────┘ │ ▼ 数据库 # 连接池优势 - 减少连接创建开销 - 控制连接数量 - 复用连接资源 - 提高响应速度

🔧 连接池配置

# MySQL 连接池配置 import mysql from 'mysql2/promise'; const pool = mysql.createPool({ host: 'localhost', user: 'root', password: 'password', database: 'mydb', // 连接池大小 connectionLimit: 20, // 最大连接数 waitForConnections: true, // 连接用尽时是否等待 // 连接超时 connectTimeout: 10000, // 连接超时 10s acquireTimeout: 30000, // 获取连接超时 30s // 连接维护 queueLimit: 0, // 等待队列长度（0 = 无限） idleTimeout: 60000, // 空闲连接超时 // 连接测试 testOnBorrow: true, // 获取时测试连接 }); # PostgreSQL 连接池配置 import { Pool } from 'pg'; const pool = new Pool({ host: 'localhost', user: 'postgres', password: 'password', database: 'mydb', // 连接池大小 max: 20, // 最大连接数 min: 2, // 最小连接数 // 超时设置 connectionTimeoutMillis: 10000, idleTimeoutMillis: 30000, // 连接测试 allowExitOnIdle: false, }); # Prisma 连接池配置 // schema.prisma datasource db { provider = "mysql" url = env("DATABASE_URL") } // DATABASE_URL 格式 DATABASE_URL="mysql://user:password@localhost:3306/mydb?connection_limit=20&pool_timeout=30" // 代码中配置 import { PrismaClient } from '@prisma/client'; const prisma = new PrismaClient({ datasources: { db: { url: process.env.DATABASE_URL, }, }, }); # TypeORM 连接池配置 import { createConnection } from 'typeorm'; createConnection({ type: 'mysql', host: 'localhost', username: 'root', password: 'password', database: 'mydb', // 连接池配置 connectionLimit: 20, poolSize: 20, // 连接管理 extra: { connectionLimit: 20, waitForConnections: true, queueLimit: 0, }, });
💡
连接数计算

最大连接数 = (数据库最大连接数 - 预留连接) / 应用实例数。例如数据库最大 100 连接，预留 10，应用 4 实例，每个实例最大 (100-10)/4 ≈ 22。

⚙️ 连接池监控

# 监控连接池状态 // MySQL2 连接池状态 const pool = mysql.createPool({ /* ... */ }); setInterval(() => { // 获取连接池状态 console.log({ totalConnections: pool.pool._allConnections.length, freeConnections: pool.pool._freeConnections.length, queuedRequests: pool.pool._connectionQueue.length, }); }, 60000); // PostgreSQL 连接池状态 const pgPool = new Pool({ /* ... */ }); setInterval(() => { console.log({ totalCount: pgPool.totalCount, // 总连接数 idleCount: pgPool.idleCount, // 空闲连接数 waitingCount: pgPool.waitingCount, // 等待获取连接的请求数 }); }, 60000); # 连接池事件监听 pgPool.on('connect', (client) => { console.log('New client connected'); }); pgPool.on('acquire', (client) => { console.log('Client acquired from pool'); }); pgPool.on('release', (client) => { console.log('Client released back to pool'); }); pgPool.on('remove', (client) => { console.log('Client removed from pool'); }); pgPool.on('error', (err, client) => { console.error('Pool error:', err); }); # 数据库服务端监控 -- MySQL 查看连接数 SHOW STATUS LIKE 'Threads_connected'; SHOW STATUS LIKE 'Max_used_connections'; SHOW VARIABLES LIKE 'max_connections'; -- 查看当前连接 SHOW PROCESSLIST; -- PostgreSQL SELECT count(*) FROM pg_stat_activity; SELECT * FROM pg_stat_activity;

🚀 常见问题与解决

# 1. 连接泄漏 // 问题：获取连接后没有释放 const conn = await pool.getConnection(); // 使用连接... // 忘记 release() // 解决：使用 try-finally const conn = await pool.getConnection(); try { await conn.query('SELECT ...'); } finally { conn.release(); // 确保释放 } // 或使用 with 模式（自动释放） const result = await pool.execute(async (conn) => { return await conn.query('SELECT ...'); }); # 2. 连接池耗尽 // 问题：并发高峰期连接不够 Error: Too many connections // 解决方案 1. 增加连接池大小 2. 优化查询，减少连接占用时间 3. 实现请求排队等待 4. 增加数据库服务器 # 3. 连接超时 // 问题：连接空闲过久被断开 Error: Connection lost // 解决方案 // 定期发送保活查询 setInterval(async () => { await pool.query('SELECT 1'); }, 30000); // 或配置连接测试 const pool = mysql.createPool({ // ... testOnBorrow: true, }); # 4. 连接重置 // 应用启动时清理旧连接 async function initPool() { await pool.end(); // 关闭旧连接池 // 创建新连接池 const newPool = mysql.createPool({ /* ... */ }); return newPool; } // 优雅关闭 process.on('SIGTERM', async () => { await pool.end(); process.exit(0); });
