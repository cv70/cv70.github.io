2.2 规格定义与架构设计

芯片设计的起点与蓝图

🎯 学习目标

  • 掌握产品需求文档（PRD）的编写要点
  • 理解设计规格书（Spec）的核心内容
  • 学习系统架构设计的方法论
  • 了解 IP 选型与复用策略

规格定义的重要性

规格定义是芯片设计的起点，决定了产品的方向和边界。一份清晰、完整、可验证的规格文档是项目成功的基础。据统计，超过 50% 的芯片设计失败可以追溯到规格定义阶段的问题——需求不明确、规格不完整、指标不可实现等。

规格定义阶段的核心产出包括：产品需求文档（PRD）和设计规格书（Design Specification）。

📋 产品需求文档（PRD）

PRD 核心内容

  • 产品定位：目标市场、应用场景、用户群体
  • 功能需求：核心功能、扩展功能、差异化特性
  • 性能指标：处理能力、带宽、延迟要求
  • 约束条件：成本目标、功耗预算、面积限制
  • 时间规划：里程碑节点、量产时间
  • 竞品分析：对标产品、优劣势比较

PRD 编写原则

  • SMART 原则：具体、可衡量、可达成、相关、有时限
  • 可追溯性：每个需求都可追溯到来源
  • 可验证性：需求必须有明确的验收标准
  • 一致性：需求之间不应存在矛盾
  • 优先级：明确各需求的优先级排序

📖 设计规格书（Design Spec）

规格模块 主要内容 示例
总体规格 芯片概述、目标应用、关键特性 高性能 AI 推理芯片，INT8 算力 100TOPS
功能规格 功能模块列表、工作模式、操作流程 支持 CNN、Transformer 模型推理
性能规格 频率、吞吐量、延迟、带宽 核心频率 1.5GHz，内存带宽 512GB/s
接口规格 外部接口类型、数量、协议 PCIe 5.0 x16、DDR5、以太网
功耗规格 典型功耗、峰值功耗、低功耗模式 典型功耗 75W，峰值 120W
物理规格 封装类型、引脚数、工艺节点 7nm 工艺，FCBGA 封装，2000+ 引脚
环境规格 工作温度、电压范围、可靠性要求 工业级：-40°C ~ 85°C
💡
规格文档的维护

规格文档不是一次性文档，而是随项目演进的"活文档"。在设计和验证过程中发现的问题、变更的需求都需要及时更新到规格文档中。建议使用版本控制系统管理规格文档，记录每次变更的原因和影响范围。

🏛️ 系统架构设计

架构设计是将需求转化为可实现方案的关键环节，决定了芯片的整体结构和性能上限。好的架构设计能够有效平衡性能、功耗、面积，并为后续设计迭代留下合理空间。

🏗️

顶层架构

确定系统整体结构、子系统划分、数据流向

🔌

接口设计

定义模块间接口、总线协议、时序约定

📦

IP 集成

评估第三方 IP、规划自研模块

🔧 架构设计核心任务

📋
  • 1. 系统划分 - 将复杂系统分解为可管理的子系统或模块
  • 2. 数据流分析 - 确定数据在系统中的流动路径和带宽需求
  • 3. 存储架构 - 设计存储层次：片上 SRAM、Cache、外部 DRAM
  • 4. 时钟架构 - 规划时钟域、时钟树、异步边界处理
  • 5. 电源架构 - 设计电源域、电压调节、功耗管理策略
  • 6. 总线架构 - 选择总线协议（AXI/AHB/NoC），规划互联
  • 7. IP 选型 - 评估第三方 IP，权衡购买与自研

🔍 IP 选型与复用

IP 类型 特点 选型考虑因素
软核 IP（Soft IP） RTL 代码形式，可综合，灵活度高 代码质量、文档完整性、技术支持
硬核 IP（Hard IP） GDSII 形式，已物理实现，性能最优 工艺兼容性、时序性能、面积效率
固核 IP（Firm IP） 网表形式，部分物理信息 灵活性与性能的平衡
⚠️
IP 选型注意事项

选择第三方 IP 时需要评估：IP 成熟度（是否量产验证）、授权费用、技术支持质量、文档完整性、工艺兼容性、后续升级维护等。同时要预留 IP 集成的验证时间，IP 集成问题常常是项目延期的原因之一。

📊 架构验证

在正式进入 RTL 设计之前，需要进行架构验证以确认架构设计的合理性：

  • 性能建模：使用 SystemC/TLM 构建性能模型，评估吞吐量、延迟
  • 功能验证：验证架构是否满足功能需求
  • 功耗估算：基于架构模型进行早期功耗评估
  • 面积估算：基于模块划分进行面积预估
  • 风险评估：识别技术风险，制定应对策略
💡
架构评审（Architecture Review）

架构设计完成后需要组织架构评审，邀请资深工程师、验证工程师、后端工程师、IP 供应商等参与。评审重点包括：架构是否满足需求、是否有过度设计、风险是否可控、实现复杂度是否合理等。

📝 本节小结

✅
  • • 规格定义是芯片设计的起点，决定了产品方向
  • • PRD 描述产品需求，Spec 定义技术实现规格
  • • 架构设计将需求转化为可实现的系统结构
  • • IP 选型需要综合考虑成本、性能、风险因素
  • • 架构评审是确保设计方向正确的关键节点
