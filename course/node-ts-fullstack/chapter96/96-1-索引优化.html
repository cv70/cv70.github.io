96.1 索引优化

数据库索引设计与优化

🎯 学习目标

  • 理解索引的工作原理
  • 掌握索引设计原则
  • 学会分析查询性能
  • 了解索引维护方法

📚 索引概述

# 什么是索引 索引是数据库中用于加速查询的数据结构 类似于书籍的目录，快速定位数据位置 # 索引类型 ## 按数据结构 - B-Tree 索引：最常用，支持范围查询 - Hash 索引：等值查询快，不支持范围 - 全文索引：文本搜索 - 空间索引：地理位置数据 ## 按功能 - 主键索引：唯一标识记录 - 唯一索引：保证字段唯一 - 普通索引：加速查询 - 复合索引：多字段组合 # 索引的代价 - 占用存储空间 - 写入时需要更新索引 - 索引维护开销 # 索引适用场景 ✅ WHERE 条件字段 ✅ JOIN 关联字段 ✅ ORDER BY 排序字段 ✅ GROUP BY 分组字段 ❌ 频繁更新的字段 ❌ 区分度低的字段（如性别） ❌ 小表

🔧 索引创建与管理

# MySQL 索引操作 -- 创建索引 CREATE INDEX idx_user_email ON users(email); CREATE INDEX idx_user_name_age ON users(name, age); -- 复合索引 -- 创建唯一索引 CREATE UNIQUE INDEX idx_user_email ON users(email); -- 查看索引 SHOW INDEX FROM users; -- 删除索引 DROP INDEX idx_user_email ON users; -- 查看查询执行计划 EXPLAIN SELECT * FROM users WHERE email = 'test@example.com'; # 索引设计原则 ## 1. 选择性原则 -- 选择性 = 不同值数量 / 总行数 -- 选择性越高，索引效果越好 SELECT COUNT(DISTINCT email) / COUNT(*) as email_selectivity, COUNT(DISTINCT status) / COUNT(*) as status_selectivity FROM users; -- email_selectivity: 0.99 (高，适合索引) -- status_selectivity: 0.01 (低，不适合索引) ## 2. 最左前缀原则 -- 复合索引 (name, age, city) -- 有效查询 WHERE name = 'John' WHERE name = 'John' AND age = 25 WHERE name = 'John' AND age = 25 AND city = 'NYC' -- 无效查询 WHERE age = 25 -- 跳过了 name WHERE city = 'NYC' -- 跳过了 name 和 age ## 3. 覆盖索引 -- 创建包含查询字段的索引 CREATE INDEX idx_user_cover ON users(name, age, email); -- 查询只需要索引中的字段，无需回表 SELECT name, age, email FROM users WHERE name = 'John';
💡
复合索引设计

复合索引字段顺序很重要：区分度高的字段放前面，经常作为查询条件的字段放前面。

⚙️ 查询优化分析

# 使用 EXPLAIN 分析查询 EXPLAIN SELECT u.name, o.total FROM users u JOIN orders o ON u.id = o.user_id WHERE u.email = 'test@example.com' AND o.status = 'paid'; # 关键指标 ## type（访问类型） - system: 表只有一行 - const: 通过主键或唯一索引一次找到 - eq_ref: 唯一索引扫描 - ref: 非唯一索引扫描 - range: 范围扫描 - index: 全索引扫描 - ALL: 全表扫描（最差） ## key（使用的索引） - 显示实际使用的索引名 - NULL 表示未使用索引 ## rows（扫描行数） - 预估需要扫描的行数 - 越少越好 ## Extra（额外信息） - Using index: 使用覆盖索引 - Using where: 服务器层过滤 - Using filesort: 需要额外排序 - Using temporary: 使用临时表 # 优化示例 ## 问题查询 EXPLAIN SELECT * FROM orders WHERE YEAR(created_at) = 2024; -- type: ALL, 索引失效（函数操作） ## 优化后 EXPLAIN SELECT * FROM orders WHERE created_at >= '2024-01-01' AND created_at < '2025-01-01'; -- type: range, 使用索引 ## 问题查询 EXPLAIN SELECT * FROM users WHERE name LIKE '%john%'; -- type: ALL, 前缀通配符导致索引失效 ## 优化后 EXPLAIN SELECT * FROM users WHERE name LIKE 'john%'; -- type: range, 使用索引

🚀 索引维护

# 索引统计信息更新 -- MySQL ANALYZE TABLE users; -- PostgreSQL ANALYZE users; # 重建索引 -- MySQL ALTER TABLE users ENGINE=InnoDB; -- 重建表 -- PostgreSQL REINDEX INDEX idx_user_email; # 检查索引使用情况 -- MySQL SELECT TABLE_NAME, INDEX_NAME, CARDINALITY, SEQ_IN_INDEX FROM information_schema.STATISTICS WHERE TABLE_SCHEMA = 'mydb'; -- 查找未使用的索引 SELECT OBJECT_SCHEMA, OBJECT_NAME, INDEX_NAME FROM performance_schema.table_io_waits_summary_by_index_usage WHERE INDEX_NAME IS NOT NULL AND COUNT_STAR = 0 AND OBJECT_SCHEMA = 'mydb'; # 索引碎片整理 -- 查看表碎片 SELECT TABLE_NAME, DATA_FREE / 1024 / 1024 as Fragment_MB FROM information_schema.TABLES WHERE TABLE_SCHEMA = 'mydb' AND DATA_FREE > 0; -- 优化表（整理碎片） OPTIMIZE TABLE users;

📝 本节小结

✅
  • • 索引加速查询但有写入代价
  • • 复合索引遵循最左前缀原则
  • • 使用 EXPLAIN 分析查询性能
  • • 避免在索引列上使用函数
