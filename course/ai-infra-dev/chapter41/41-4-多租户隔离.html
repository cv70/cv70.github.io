41.4 多租户隔离

构建安全的租户隔离机制

🎯 学习目标

  • 理解多租户架构的核心概念

  • 学会设计安全的隔离方案

多租户架构概述

多租户架构是指单个应用实例同时服务于多个租户（客户/组织/用户）， 通过适当的隔离机制确保各租户的数据和操作互不干扰。在AI基础设施中，多租户隔离 是保障安全、公平性和资源利用率的关键。

🔀 多租户隔离模式

模式 隔离程度 资源利用率 成本 适用场景
共享数据库 低 高 低 小规模、低敏感度
独立Schema 中 中 中 中等规模、中等敏感度
独立数据库 高 中 中高 大规模、高敏感度
独立实例 极高 低 高 超高安全要求

💾 数据隔离策略

逻辑隔离

-- 共享表 + 租户ID
CREATE TABLE models (
  id BIGINT PRIMARY KEY,
  tenant_id VARCHAR(64) NOT NULL,
  name VARCHAR(256),
  -- 查询时必须过滤
  WHERE tenant_id = ?
);
  • 成本低，实现简单
  • 隔离程度有限
  • 需要严格查询过滤

物理隔离

-- 独立数据库
CREATE DATABASE tenant_001;
CREATE DATABASE tenant_002;

-- 或独立Schema
CREATE SCHEMA tenant_001;
CREATE SCHEMA tenant_002;
  • 隔离程度高
  • 管理复杂度高
  • 资源成本较高

🖥️ 计算资源隔离

Kubernetes命名空间隔离

# 为每个租户创建命名空间
apiVersion: v1
kind: Namespace
metadata:
  name: tenant-001
  labels:
    tenant: "001"
    environment: production

ResourceQuota资源配额

apiVersion: v1
kind: ResourceQuota
metadata:
  name: compute-quota
  namespace: tenant-001
spec:
  hard:
    requests.cpu: "100"
    requests.memory: 400Gi
    limits.cpu: "200"
    limits.memory: 800Gi
    requests.nvidia.com/gpu: "16"
    persistentvolumeclaims: "20"

📊 网络隔离策略

  • VLAN/VXLAN隔离: 在网络层隔离租户流量
  • Network Policy: Kubernetes网络策略控制Pod间通信
  • Security Groups: 云平台的网络安全组规则
  • 服务网格: 使用Istio等实现零信任网络
  • 租户网关: 为每个租户提供独立的API网关
💡
零信任架构

在多租户环境中，应采用零信任架构原则： 不信任任何内部流量，所有通信都需要认证和授权。

🎯 资源配额管理

资源类型 配额项 说明
计算资源 CPU、GPU、内存 限制租户的计算能力
存储资源 磁盘、对象存储 限制租户的存储空间
网络资源 带宽、连接数 限制租户的网络使用
API资源 调用频率、并发数 限制租户的API访问

📝 多租户代码实践

# 多租户上下文管理
class TenantContext:
    def __init__(self):
        self._context = threading.local()

    def set_tenant(self, tenant_id):
        self._context.tenant_id = tenant_id

    def get_tenant(self):
        return getattr(self._context, 'tenant_id', None)

# 全局租户上下文
tenant_context = TenantContext()

# 使用中间件设置租户
class TenantMiddleware:
    def __init__(self, app):
        self.app = app

    def __call__(self, environ, start_response):
        # 从请求头获取租户ID
        tenant_id = environ.get('HTTP_X_TENANT_ID')

        if tenant_id:
            # 验证租户是否存在
            if not self.validate_tenant(tenant_id):
                start_response('403 Forbidden', [])
                return [b'Tenant not found']

            # 设置租户上下文
            tenant_context.set_tenant(tenant_id)

        return self.app(environ, start_response)

🛡️ 隔离安全最佳实践

设计原则

  • 最小共享原则
  • 深度防御
  • 默认拒绝
  • 最小权限

运维要点

  • 定期审查配额
  • 监控租户行为
  • 隔离故障域
  • 快速隔离响应
⚠️
常见风险
  • Noisy Neighbor: 一个租户消耗过多资源影响其他租户
  • 数据泄露: 错误配置导致租户间数据访问
  • 权限提升: 利用漏洞突破租户边界
  • 资源耗尽: 拒绝服务攻击影响所有租户
