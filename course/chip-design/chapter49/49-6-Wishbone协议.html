Wishbone协议简介

Wishbone是由OpenCores组织推出的开放源码片上总线标准。与AMBA不同，Wishbone完全开放，没有授权费用，这使得它在FPGA设计和开源项目中非常受欢迎。Wishbone的设计目标是提供简单、灵活、可扩展的片上互联解决方案。

Wishbone的独特之处在于其模块化的信号定义和灵活的互联拓扑。设计者可以根据需要选择实现哪些信号，这使得Wishbone可以适应从简单到复杂的各种应用场景。

🔓 Wishbone核心特性

开放性

  • 完全开放标准
  • 无授权费用
  • 自由使用和修改
  • 社区驱动

灵活性

  • 模块化信号定义

  • 可配置数据宽度
  • 适应多种应用

简洁性

  • 信号数量少
  • 协议简单易懂
  • 易于实现
  • 快速验证

📊 Wishbone信号定义

Wishbone定义了两组基本信号：主设备（Master）信号和从设备（Slave）信号：

CLK_I 输入 时钟输入 公共
RST_I 输入 复位输入（同步） 公共
ADR_O 输出 地址输出 主设备
DAT_O 输出 数据输出 主设备
DAT_I 输入 数据输入 主设备
SEL_O 输出 字节选择信号 主设备
WE_O 输出 写使能（1=写，0=读） 主设备
STB_O 输出 选通信号（有效周期） 主设备
CYC_O 输出 周期信号（总线周期） 主设备
ACK_I 输入 应答信号 主设备
ADR_I 输入 地址输入 从设备
DAT_I 输入 数据输入 从设备
DAT_O 输出 数据输出 从设备
SEL_I 输入 字节选择信号 从设备

⚡ Wishbone握手协议

Wishbone使用STB/CYC/ACK握手机制：

🔄
握手流程
  1. 主设备发起：
    • 拉高CYC_O，表示总线周期开始
    • 拉高STB_O，表示有效传输
    • 输出地址、数据和控制信号
  2. 从设备响应：
    • 检测到STB_I和CYC_I有效
    • 执行请求的操作
    • 拉高ACK_O表示完成
  3. 传输完成：
    • 主设备检测到ACK_I
    • 拉低CYC_O和STB_O
    • 可以开始新的传输

🌐 Wishbone互联拓扑

Wishbone支持多种互联拓扑结构，这是其灵活性的重要体现：

点对点（Point-to-Point）

  • 一个主设备连接一个从设备
  • 最简单的拓扑
  • 延迟最低
  • 适合模块间直接通信

共享总线（Shared Bus）

  • 多个主设备共享总线
  • 需要仲裁器
  • 简单但可扩展性有限
  • 适合中小规模系统

交叉开关（Crossbar）

  • 全互联结构
  • 支持多主多从并发
  • 性能最高但面积大
  • 适合高性能系统

数据流（Data Flow）

  • 点对点数据流连接
  • 适合FIFO或流水线
  • 高性能低延迟
  • 适合数据通路

🔧 Wishbone可选信号

Wishbone还定义了许多可选信号，用于扩展功能：

  • ERR（Error）：错误信号，报告传输错误
  • RTY（Retry）：重试信号，请求重试传输
  • LOCK（Lock）：锁定信号，用于原子操作
  • TAG（Tag）：标签信号，用于附加信息
  • GNT（Grant）：授权信号，用于仲裁
  • REQ（Request）：请求信号，用于仲裁

Wishbone的优势

Wishbone的最大优势在于其开放性和灵活性。对于FPGA设计和开源项目，Wishbone提供了无负担的互联解决方案。其模块化的设计使得开发者可以根据需要选择实现哪些功能，既保持了简洁性，又提供了扩展能力。
