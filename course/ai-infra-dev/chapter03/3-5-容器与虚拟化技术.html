容器与虚拟化概述

容器和虚拟化技术为AI应用提供了隔离、可移植、可扩展的运行环境。Docker、Singularity等容器技术解决了环境依赖问题，GPU虚拟化技术实现了GPU资源的灵活分配和共享。

🐳 Docker

容器化AI环境

Docker是主流的容器平台，为AI应用提供一致的开发、测试和部署环境：

Docker优势

  • 环境一致性
  • 快速启动
  • 资源隔离
  • 易于分发

AI应用场景

  • 模型训练环境
  • 推理服务部署
  • CI/CD流水线
  • 多版本并存
Dockerfile示例（PyTorch训练环境）： FROM nvidia/cuda:12.1.0-runtime-ubuntu22.04 # 设置环境变量 ENV DEBIAN_FRONTEND=noninteractive ENV PYTHONUNBUFFERED=1 # 安装依赖 RUN apt-get update && apt-get install -y \ python3.10 \ python3-pip \ git \ wget \ && rm -rf /var/lib/apt/lists/* # 安装PyTorch RUN pip3 install torch torchvision torchaudio \ --index-url https://download.pytorch.org/whl/cu121 # 安装其他依赖 COPY requirements.txt /tmp/ RUN pip3 install -r /tmp/requirements.txt # 设置工作目录 WORKDIR /workspace # 复制代码 COPY . /workspace/ # 启动命令 CMD ["python3", "train.py"]
Docker使用命令： # 构建镜像 docker build -t my-ai-env . # 运行容器（带GPU） docker run --gpus all -it --shm-size=16g \ -v $(pwd):/workspace \ -p 8888:8888 \ my-ai-env # 后台运行 docker run -d --gpus all \ --name training \ my-ai-env python train.py # 查看日志 docker logs -f training # 停止容器 docker stop training docker rm training

🏔️ Singularity

HPC容器平台

Singularity（现更名为Apptainer）是为HPC环境设计的容器平台，更适合超算中心使用：

Singularity特点

  • 用户权限运行
  • 更好的安全性
  • HPC友好
  • 与Docker兼容

vs Docker

  • 无需root权限
  • 更适合HPC
  • 安全性更高
  • 生态相对小
Singularity使用： # 从Docker镜像构建 singularity build my-ai-env.sif docker://nvidia/cuda:12.1.0-runtime-ubuntu22.04 # 运行容器（带GPU） singularity exec --nv my-ai-env.sif python train.py # 交互式运行 singularity shell --nv my-ai-env.sif # 运行命令 singularity run --nv my-ai-env.sif # 转换Docker镜像 singularity pull docker://pytorch/pytorch:latest

🎮 GPU虚拟化

共享GPU资源

GPU虚拟化技术允许多个容器或进程共享GPU资源，提高利用率：

技术 原理 优点 缺点
MPS 多进程服务 原生支持，简单 隔离性弱
vGPU GPU切分 强隔离，灵活 需要许可
MIG 多实例GPU 硬件隔离 仅支持A100/H100
Time-slicing 时间片调度 无需特殊硬件 性能波动
Docker GPU配置： # 指定GPU数量 docker run --gpus 2 my-image # 指定GPU ID docker run --gpus '"device=0,1"' my-image # MIG设备 docker run --gpus '"device=mig-gpu0-1g.5gb"' my-image # MPS服务 nvidia-cuda-mps-control -d docker run --gpus all my-image

📦 镜像优化

构建高效镜像

优化Docker镜像可以减少构建时间、存储空间和启动延迟：

优化策略

  • 使用多阶段构建
  • 选择精简基础镜像
  • 合并RUN指令
  • 清理缓存和临时文件

最佳实践

  • .dockerignore排除文件
  • 利用Docker层缓存
  • 使用构建缓存
  • 定期更新基础镜像
优化后的Dockerfile： # 多阶段构建 FROM nvidia/cuda:12.1.0-devel-ubuntu22.04 AS builder # 安装构建依赖 RUN apt-get update && apt-get install -y \ cmake build-essential # 构建项目 COPY . /src WORKDIR /src RUN cmake . && make # 运行阶段 FROM nvidia/cuda:12.1.0-runtime-ubuntu22.04 # 只复制必要的文件 COPY --from=builder /src/model /app/model COPY --from=builder /src/requirements.txt /app/ # 安装运行时依赖 RUN pip install --no-cache-dir -r /app/requirements.txt # 清理APT缓存 RUN apt-get clean && rm -rf /var/lib/apt/lists/* WORKDIR /app CMD ["python", "serve.py"]

⚖️ 技术对比

技术 优势 劣势 适用场景
Docker 生态成熟，易用 需要root权限 云环境，企业
Singularity HPC友好，安全 生态较小 超算中心
Kubernetes 编排能力强 复杂度高 大规模部署
VM 强隔离 重，慢 传统应用
