云函数执行模型

云函数采用事件驱动模型。当触发器（HTTP 请求、定时任务、数据库变更等）触发函数时， 云平台会启动一个执行实例，运行函数代码，处理完成后返回结果。

🔄 函数执行生命周期

┌─────────────┐ ┌─────────────┐ ┌─────────────┐ │ 触发器 │────▶│ 冷启动 │────▶│ 执行函数 │ │ HTTP/API │ │ 加载运行时 │ │ 处理事件 │ │ 定时任务 │ │ 初始化环境 │ │ 返回结果 │ │ 消息队列 │ └─────────────┘ └─────────────┘ └─────────────┘ │ ▼ # 热启动：复用已有实例，跳过冷启动 ┌─────────────┐ ┌─────────────┐ │ 触发器 │────▶│ 执行函数 │ │ (后续) │ │ (热启动) │ └─────────────┘ └─────────────┘

📁 函数代码结构

// 基本函数结构 (AWS Lambda / 阿里云函数计算) exports.handler = async (event, context) => { // event: 触发事件数据 // context: 运行时上下文 // 业务逻辑处理 const result = await processData(event); // 返回结果 return { statusCode: 200, body: JSON.stringify(result) }; }; // Vercel / Next.js API Route export default async function handler(req, res) { // req: HTTP 请求对象 // res: HTTP 响应对象 if (req.method !== 'POST') { return res.status(405).json({ error: 'Method not allowed' }); } const { name, email } = req.body; // 处理逻辑 const user = await createUser({ name, email }); res.status(200).json({ user }); }

⚡ 触发器类型

触发器类型 说明 典型场景
HTTP 触发器 通过 HTTP 请求触发 API 接口、Webhook
定时触发器 按计划定时触发 定时任务、报表生成
对象存储触发 文件上传/删除时触发 图片处理、文件转换
数据库触发 数据变更时触发 数据同步、审计日志
消息队列触发 消息到达时触发 异步处理、事件驱动
API 网关触发 通过 API 网关调用 REST API、微服务

🔧 TypeScript 云函数开发

// src/handlers/user.ts import { APIGatewayProxyEvent, APIGatewayProxyResult } from 'aws-lambda'; import { UserService } from '../services/user.service'; const userService = new UserService(); export const getUser = async ( event: APIGatewayProxyEvent ): Promise => { try { const userId = event.pathParameters?.id; if (!userId) { return { statusCode: 400, body: JSON.stringify({ error: 'User ID is required' }) }; } const user = await userService.findById(userId); if (!user) { return { statusCode: 404, body: JSON.stringify({ error: 'User not found' }) }; } return { statusCode: 200, body: JSON.stringify(user) }; } catch (error) { console.error('Error fetching user:', error); return { statusCode: 500, body: JSON.stringify({ error: 'Internal server error' }) }; } }; export const createUser = async ( event: APIGatewayProxyEvent ): Promise => { try { const body = JSON.parse(event.body || '{}'); const { name, email } = body; // 验证输入 if (!name || !email) { return { statusCode: 400, body: JSON.stringify({ error: 'Name and email are required' }) }; } const user = await userService.create({ name, email }); return { statusCode: 201, body: JSON.stringify(user) }; } catch (error) { console.error('Error creating user:', error); return { statusCode: 500, body: JSON.stringify({ error: 'Internal server error' }) }; } };

⚡ 冷启动优化

减少冷启动时间

  • 减少依赖包大小
  • 延迟初始化非必要资源
  • 使用 Provisioned Concurrency
  • 保持函数活跃（定时 ping）

代码优化示例

// 不推荐：每次调用都初始化 export const handler = async (event) => { const db = new Database(); // 冷启动慢 return db.query(event.id); }; // 推荐：复用连接 let db: Database | null = null; export const handler = async (event) => { if (!db) { db = new Database(); // 只初始化一次 } return db.query(event.id); };
💡
云函数最佳实践
  • 单一职责：每个函数只做一件事
  • 无状态设计：避免依赖本地状态
  • 幂等性：同一请求多次执行结果相同
  • 合理设置超时和内存
  • 使用环境变量管理配置
  • 完善的错误处理和日志

  • • 遵循单一职责、无状态、幂等性原则
