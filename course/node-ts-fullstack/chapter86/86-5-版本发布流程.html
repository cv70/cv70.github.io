📚 语义化版本 (SemVer)

语义化版本是一种版本号命名规范，格式为 MAJOR.MINOR.PATCH，清晰传达版本变更的影响。

# 语义化版本格式 MAJOR.MINOR.PATCH[-PRERELEASE][+BUILD] 示例: 2.1.3-beta.1+build.123 # 版本号规则 ## MAJOR (主版本号) - 不兼容的 API 变更 - 重大架构调整 - 破坏性变更 ## MINOR (次版本号) - 向后兼容的功能新增 - 功能增强 - 不影响现有使用 ## PATCH (修订号) - 向后兼容的问题修复 - Bug 修复 - 文档更新 ## PRERELEASE (预发布) - alpha: 早期测试版 - beta: 公开测试版 - rc: 候选发布版 # 示例 1.0.0 → 1.0.1 # Bug 修复 1.0.1 → 1.1.0 # 新增功能 1.1.0 → 2.0.0 # 破坏性变更 2.0.0-alpha.1 # 早期测试版
💡
版本号决策

每次发布前评估变更内容：是否有破坏性变更（MAJOR）、新增功能（MINOR）、还是仅修复 Bug（PATCH）。

🔧 发布流程

# 标准发布流程 ## 1. 准备发布 # 从 develop 创建 release 分支 git checkout develop git pull origin develop git checkout -b release/v1.2.0 ## 2. 发布准备 # 更新版本号 npm version 1.2.0 --no-git-tag-version # 更新 CHANGELOG # 手动或使用工具生成 # 更新文档 # 确保文档与代码同步 # 最终测试 npm run test npm run build ## 3. 提交变更 git add . git commit -m "chore: 准备发布 v1.2.0" ## 4. 合并到主分支 git checkout main git merge --no-ff release/v1.2.0 ## 5. 创建标签 git tag -a v1.2.0 -m "Release v1.2.0" git push origin v1.2.0 ## 6. 合并回 develop git checkout develop git merge --no-ff release/v1.2.0 ## 7. 清理 git branch -d release/v1.2.0 git push origin --delete release/v1.2.0

⚙️ 自动化发布工具

# 使用 standard-version 自动化 # 安装 npm install --save-dev standard-version # package.json { "scripts": { "release": "standard-version", "release:first": "standard-version --first-release" } } # .versionrc.json { "types": [ { "type": "feat", "section": "Features" }, { "type": "fix", "section": "Bug Fixes" }, { "type": "perf", "section": "Performance" }, { "type": "refactor", "section": "Refactoring" } ], "skip": { "tag": false } } # 执行发布 npm run release # 自动完成： # 1. 分析提交信息 # 2. 确定版本号 # 3. 更新 CHANGELOG.md # 4. 更新 package.json # 5. 创建 git commit # 6. 创建 git tag

🚀 CHANGELOG 生成

# CHANGELOG.md 格式示例 # Changelog All notable changes to this project will be documented in this file. ## [1.2.0] - 2024-01-15 ### Features - 用户登录功能 (abc123) - 添加用户头像上传 (def456) ### Bug Fixes - 修复分页参数错误 (ghi789) - 修复登录验证问题 (jkl012) ### Performance - 优化数据库查询性能 (mno345) ## [1.1.0] - 2024-01-01 ### Features - 添加用户注册功能 (pqr678) # 使用 conventional-changelog 生成 npm install --save-dev conventional-changelog-cli # 生成 CHANGELOG npx conventional-changelog -p angular -i CHANGELOG.md -s # package.json scripts { "scripts": { "changelog": "conventional-changelog -p angular -i CHANGELOG.md -s" } }

📝 GitHub Release

# GitHub Release 自动化 # .github/workflows/release.yml name: Release on: push: tags: - 'v*' jobs: release: runs-on: ubuntu-latest steps: - uses: actions/checkout@v4 with: fetch-depth: 0 - uses: actions/setup-node@v4 with: node-version: '20' - name: Install dependencies run: npm ci - name: Build run: npm run build - name: Create Release uses: softprops/action-gh-release@v1 with: generate_release_notes: true files: | dist/*.zip env: GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }} - name: Publish to npm run: npm publish env: NODE_AUTH_TOKEN: ${{ secrets.NPM_TOKEN }}
