58.2 Swagger/OpenAPI 规范

API 文档的行业标准

📖 OpenAPI 规范简介

OpenAPI 规范（OAS，原名 Swagger 规范）是描述 RESTful API 的行业标准格式。它定义了一套结构化的方式来描述 API 的各个方面，使人和机器都能理解 API 的功能。

💡
OpenAPI vs Swagger

Swagger 是最初的项目名称，后被 SmartBear 收购并捐赠给 Linux 基金会，更名为 OpenAPI。Swagger 现指围绕 OpenAPI 规范的工具集。

OpenAPI 版本

版本 发布时间 主要特性
3.1.0 2021 完全兼容 JSON Schema，改进描述能力
3.0.0 2017 支持 oneOf/anyOf，回调，链接
2.0 2014 原 Swagger 规范，广泛支持

📄 OpenAPI 文档结构

// openapi.yaml - YAML 格式 openapi: 3.0.0 // 基本信息 info: title: 用户管理 API description: 用户注册、登录、信息管理 version: 1.0.0 contact: name: API 支持 email: support@example.com // 服务器地址 servers: - url: https://api.example.com/v1 description: 生产环境 - url: https://dev-api.example.com/v1 description: 开发环境 // API 路径 paths: /users: get: summary: 获取用户列表 tags: - 用户 parameters: - name: page in: query schema: type: integer default: 1 responses: '200': description: 成功 content: application/json: schema: $ref: '#/components/schemas/UserList' // 组件定义 components: schemas: User: type: object properties: id: type: integer name: type: string email: type: string format: email securitySchemes: bearerAuth: type: http scheme: bearer bearerFormat: JWT

📋 核心组件详解

1. Info 对象 - 基本信息

info: title: API 标题 description: | 多行描述 支持 Markdown 格式 version: 1.0.0 termsOfService: https://example.com/terms contact: name: 技术支持 url: https://example.com/support email: support@example.com license: name: MIT url: https://opensource.org/licenses/MIT

2. Servers 对象 - 服务器配置

servers: - url: https://{environment}.example.com/{version} description: API 服务器 variables: environment: default: api description: 环境 enum: - api - dev-api - staging-api version: default: v1 enum: - v1 - v2

3. Paths 对象 - API 路径

paths: /users: get: tags: [用户] summary: 简短描述 description: 详细描述 operationId: getUsers parameters: - name: page in: query required: false schema: type: integer responses: '200': description: 成功 content: application/json: schema: $ref: '#/components/schemas/UserList' '400': description: 参数错误 '401': description: 未认证 post: tags: [用户] summary: 创建用户 requestBody: required: true content: application/json: schema: $ref: '#/components/schemas/CreateUser' responses: '201': description: 创建成功 /users/{id}: get: parameters: - name: id in: path required: true schema: type: integer responses: '200': description: 成功 '404': description: 用户不存在

4. Components 对象 - 可复用组件

components: // 数据模型 schemas: User: type: object required: [id, name, email] properties: id: type: integer example: 123 name: type: string example: 张三 email: type: string format: email createdAt: type: string format: date-time UserList: type: object properties: data: type: array items: $ref: '#/components/schemas/User' total: type: integer // 安全方案 securitySchemes: bearerAuth: type: http scheme: bearer bearerFormat: JWT apiKey: type: apiKey in: header name: X-API-Key oauth2: type: oauth2 flows: authorizationCode: authorizationUrl: https://example.com/oauth/authorize tokenUrl: https://example.com/oauth/token scopes: read:users: 读取用户 write:users: 写入用户 // 可复用参数 parameters: PageParam: name: page in: query schema: type: integer default: 1 // 可复用响应 responses: Unauthorized: description: 未认证 content: application/json: schema: type: object properties: error: type: string example: Unauthorized

🔐 安全配置

// 定义安全方案 components: securitySchemes: bearerAuth: type: http scheme: bearer bearerFormat: JWT // 全局安全配置 security: - bearerAuth: [] // 特定操作的安全配置 paths: /public/info: get: security: [] // 无需认证 /users: get: security: - bearerAuth: [] - apiKey: [] // 或 API Key /admin/users: get: security: - oauth2: [admin:read] // 需要 admin:read 权限

💻 JSON 格式示例

{ "openapi": "3.0.0", "info": { "title": "用户管理 API", "version": "1.0.0" }, "paths": { "/users": { "get": { "summary": "获取用户列表", "responses": { "200": { "description": "成功" } } } } } }

📝 小结

  • OpenAPI 是描述 RESTful API 的行业标准
  • 支持 YAML 和 JSON 两种格式
  • 核心组件：info、servers、paths、components
  • 支持多种认证方式的描述
  • 丰富的数据类型定义
  • 组件复用减少重复定义
