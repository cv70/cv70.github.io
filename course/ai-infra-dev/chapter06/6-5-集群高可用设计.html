6.5 集群高可用设计

构建可靠的AI基础设施

🎯 学习目标

  • 理解高可用设计的基本原则
  • 掌握集群各组件的冗余设计方法
  • 了解故障检测与自动恢复机制
  • 学会设计容错和备份策略

高可用的重要性

大模型训练可能持续数周甚至数月，任何单点故障都可能导致训练中断和巨大损失。 高可用设计确保集群在硬件故障、网络中断等异常情况下仍能持续运行，保障AI任务的稳定进行。

关键技术：

1. 纠删码（Erasure Coding）
   • RAID 6: N+2保护
   • RS编码: 可配置N+M
   • 容忍M个磁盘/节点故障

2. 多副本机制
   • 2副本或3副本
   • 跨机架分布
   • 实时同步

3. 数据修复
   • 自动重建
   • 异步修复
   • 影响最小化

🌐 网络高可用

网络冗余设计

网络冗余策略：

链路冗余：
• LACP聚合链路
• 多上行链路
• 跨不同交换机

设备冗余：
• 核心交换机双机热备
• VRRP虚拟路由
• M-LAG跨设备链路

路径冗余：
• ECMP多路径
• 不同物理路径
• 机架级分布

故障快速检测

BFD (双向转发检测)

• 毫秒级故障检测
• 独立于上层协议
• 全网快速收敛

配置示例：
interface HundredGigE1/0/1
  bfd enable
  bfd min-tx-interval 50
  bfd min-rx-interval 50
  bfd detect-multiplier 3

检测时间 = 50ms × 3 = 150ms
💡
网络收敛时间

传统路由收敛：秒级到分钟级（OSPF、BGP）

二层收敛：亚秒级（STP、MLAG）

BFD+快速路由：毫秒级（100-500ms）

建议：AI集群优先采用MLAG+BFD实现快速收敛

部署建议：

1. Slurm调度器HA

     slurmctld (active)

💾 Checkpoint与断点续训

Checkpoint策略

Checkpoint最佳实践：

频率规划：
• 小模型: 每1-2小时
• 大模型: 每4-6小时
• 超大模型: 每12-24小时

存储位置：
• 高速SSD: 最新的3-5个
• 分布式存储: 保留更多
• 冷存储: 每天归档

增量保存：
• 仅保存变化的参数
• 减少IO开销
• 加快保存速度

断点续训实现

PyTorch Checkpoint示例：

import torch
import os

def save_checkpoint(model, optimizer, epoch, loss, path):
    checkpoint = {
        'epoch': epoch,
        'model_state_dict': model.state_dict(),
        'optimizer_state_dict': optimizer.state_dict(),
        'loss': loss,
    }
    torch.save(checkpoint, path)

def load_checkpoint(model, optimizer, path):
    if os.path.exists(path):
        checkpoint = torch.load(path)
        model.load_state_dict(checkpoint['model_state_dict'])
        optimizer.load_state_dict(checkpoint['optimizer_state_dict'])
        epoch = checkpoint['epoch']
        loss = checkpoint['loss']
        return epoch, loss
    return 0, 0

📊 故障检测与告警

监控告警体系

多层次监控：

硬件监控：
• GPU健康状态 (DCGM)
• 温度、功耗、风扇转速
• 磁盘健康 (SMART)
• 网络链路状态

系统监控：
• CPU、内存利用率
• 进程状态
• 系统日志
• 内核日志

应用监控：
• 训练进度
• 损失变化
• 梯度统计
• Checkpoint状态

服务监控：
• 调度器状态
• 存储服务健康
• 网络连通性
• 资源可用性

告警规则示例：

# GPU温度告警
- alert: GPUHighTemperature
  expr: DCGM_FI_DEV_GPU_TEMP > 85
  for: 5m
  annotations:
    summary: "GPU温度过高"

# 节点宕机告警
- alert: NodeDown
  expr: up{job="node_exporter"} == 0
  for: 2m
  annotations:
    summary: "节点{{ $labels.instance }}宕机"

# 训练停滞告警
- alert: TrainingStuck
  expr: increase(loss[30m]) == 0
  for: 30m
  annotations:
    summary: "训练任务可能停滞"
⚠️
故障响应SLA

P0严重故障：5分钟内响应，1小时内恢复

P1重要故障：15分钟内响应，4小时内恢复

P2一般故障：30分钟内响应，24小时内恢复

建议：建立On-call轮值制度，确保7x24小时有人响应

🔄 灾难恢复

DR策略设计

灾难恢复等级：

RPO (Recovery Point Objective):
• RPO=0: 实时复制
• RPO<1h: 每小时备份
• RPO<1d: 每日备份

RTO (Recovery Time Objective):
• RTO<1h: 热备切换
• RTO<4h: 温备恢复
• RTO<24h: 冷备恢复

备份策略：

数据备份：
• 每日增量备份
• 每周全量备份
• 异地容灾复制

系统备份：
• 配置文件版本控制
• 镜像仓库备份
• 服务配置备份

模型备份：
• 关键模型多副本
• 云存储冗余
• 版本控制
