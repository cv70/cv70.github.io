线程层次概述

GPU的线程层次结构是CUDA编程的核心概念。从Grid到Block再到Thread，每一层都有其特定的用途和限制。理解这一层次结构对于编写高效的GPU程序至关重要。

🏗️ 三级线程结构

Grid、Block、Thread

线程层次结构： Grid (线程网格) ┌────────┴────────┐ Block 0 Block 1 ┌────┴────┐ ┌────┴────┐ Thread Thread Thread Thread | | | | v v v v 维度定义： Grid: dim3 gridSize(gridDim.x, gridSize.y, gridSize.z) Block: dim3 blockSize(blockDim.x, blockDim.y, blockDim.z) Thread: threadIdx.x, threadIdx.y, threadIdx.z blockIdx.x, blockIdx.y, blockIdx.z 限制： • 每个Block最多1024个线程 • Block维度最大：1024x1024x64 • Grid维度最大：2^31-1 x 65535 x 65535

🧮 线程索引计算

多维索引映射

线程索引计算是将多维线程映射到一维数组的关键：

1D索引计算： // 计算全局线程ID int tid = blockIdx.x * blockDim.x + threadIdx.x; // 示例：处理一维数组 __global__ void add_arrays(float *a, float *b, float *c, int n) { int tid = blockIdx.x * blockDim.x + threadIdx.x; if (tid < n) { c[tid] = a[tid] + b[tid]; } } 2D索引计算： // 计算全局线程ID int tid = blockIdx.y * blockDim.y + threadIdx.y; int idx = tid * blockDim.x * gridDim.x + blockIdx.x * blockDim.x + threadIdx.x; // 更清晰的写法 int row = blockIdx.y * blockDim.y + threadIdx.y; int col = blockIdx.x * blockDim.x + threadIdx.x; int idx = row * width + col; // 2D数组访问示例 __global__ void process_image(uchar4 *image, int width, int height) { int x = blockIdx.x * blockDim.x + threadIdx.x; int y = blockIdx.y * blockDim.y + threadIdx.y; if (x < width && y < height) { int idx = y * width + x; // 处理像素 } }

🔢 Grid和Block配置

配置策略

Kernel启动配置： // 标准配置 int n = 1024 * 1024; int blockSize = 256; int numBlocks = (n + blockSize - 1) / blockSize; kernel<<>>(data, n); // 2D配置 int width = 1920; int height = 1080; dim3 blockSize(16, 16); // 256个线程 dim3 gridSize((width + blockSize.x - 1) / blockSize.x, (height + blockSize.y - 1) / blockSize.y); kernel<<>>(image, width, height); // 3D配置 int depth = 32; dim3 blockSize3d(8, 8, 8); // 512个线程 dim3 gridSize3d((width + 7) / 8, (height + 7) / 8, (depth + 7) / 8); kernel<<>>(volume, width, height, depth); // 最大线程数限制 // 当前架构：每个Block最多1024个线程 // 典型配置：32x32 = 1024（2D） // 典型配置：8x8x16 = 1024（3D）

🔗 线程同步

同步机制

CUDA提供多种同步原语来协调线程间的执行：

同步类型 作用域 API 开销
__syncthreads() Block内 线程块同步 高
__syncwarp() Warp内 Warp同步 低
cudaDeviceSynchronize() 设备 设备同步 很高
cudaStreamSynchronize() 流 流同步 中
同步使用示例： // Block内同步 __global__ void shared_memory_example(float *input, float *output, int n) { __shared__ float shared_data[256]; int tid = threadIdx.x; // 加载数据到共享内存 shared_data[tid] = input[tid]; __syncthreads(); // 等待所有线程完成加载 // 处理共享内存数据 shared_data[tid] = shared_data[tid] * 2; __syncthreads(); // 等待所有线程完成处理 // 写回结果 output[tid] = shared_data[tid]; } // Warp内同步 __global__ void warp_reduce(float *data, int n) { int tid = threadIdx.x; float sum = data[tid]; // Warp内归约 for (int offset = warpSize/2; offset > 0; offset /= 2) { sum += __shfl_down_sync(0xffffffff, sum, offset); } __syncwarp(); // Warp内同步 if (tid % warpSize == 0) { data[tid / warpSize] = sum; } }

🎭 Warp执行模型

SIMT执行

GPU以Warp为单位执行，32个线程同时执行相同指令：

Warp特性

  • 32个线程一组
  • 锁步执行
  • 相同指令
  • 数据可以不同

分支问题

  • 分支导致分化
  • 串行执行各分支
  • 性能下降
  • 避免嵌套分支
分支分化示例： // 不好：分支导致分化 __global__ void conditional_process(float *data) { int tid = threadIdx.x; if (tid % 2 == 0) { data[tid] = data[tid] * 2; } else { data[tid] = data[tid] / 2; } // Warp需要执行两个分支，性能差 } // 好：避免分支 __global__ void optimized_process(float *data) { int tid = threadIdx.x; float factor = (tid % 2 == 0) ? 2.0f : 0.5f; data[tid] = data[tid] * factor; // 无分支，性能好 }

⚖️ 资源分配

SM资源管理

资源类型 限制 说明
寄存器 64K per SM (H100) 线程私有，限制Block数量
共享内存 228KB per SM (H100) Block内共享，限制Block大小
线程数 2048 per SM (H100) 限制并发Block数
Block数 32 per SM 限制并发执行
💡
优化建议

减少寄存器和共享内存使用可以增加并发Block数，提高GPU利用率。
