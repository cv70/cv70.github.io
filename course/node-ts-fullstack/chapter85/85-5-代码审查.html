📚 代码审查的重要性

代码审查是保证代码质量的重要环节，通过团队成员间的互相检查，可以发现潜在问题、分享知识、统一风格。

代码审查的好处： 1. 发现 Bug 和潜在问题 2. 确保代码符合规范 3. 分享知识和最佳实践 4. 提高代码可维护性 5. 促进团队协作 代码审查的关注点： ✅ 功能正确性 ✅ 代码可读性 ✅ 性能影响 ✅ 安全漏洞 ✅ 测试覆盖率 ✅ 文档完整性

🔧 Pull Request 流程

# 创建 PR 的最佳实践 ## 1. PR 标题格式 feat(user): 添加用户登录功能 fix(api): 修复分页查询参数错误 docs(readme): 更新安装说明 ## 2. PR 描述模板 (.github/PULL_REQUEST_TEMPLATE.md) ## 变更类型 - [ ] 新功能 (feat) - [ ] Bug 修复 (fix) - [ ] 重构 (refactor) - [ ] 文档更新 (docs) ## 变更描述 ## 关联 Issue Closes #issue_number ## 测试说明 ## 检查清单 - [ ] 代码通过 ESLint 检查 - [ ] 已添加相关测试 - [ ] 文档已更新 - [ ] 无破坏性变更 ## 截图（如有必要）

⚙️ 审查指南

# 审查者指南 ## 审查重点 ### 1. 代码质量 - 是否遵循项目编码规范 - 命名是否清晰有意义 - 是否有重复代码可以抽取 - 是否有过度设计 ### 2. 功能实现 - 是否满足需求 - 边界条件处理是否正确 - 错误处理是否完善 ### 3. 性能和安全 - 是否有性能问题 - 是否存在安全漏洞 - 敏感数据处理是否正确 ### 4. 测试 - 测试覆盖率是否足够 - 测试用例是否有效 ## 审查意见格式 # 好的审查意见示例 **建议**: 这里可以使用 Map 代替 Object，查找性能更好。 ```typescript // 建议改为 const userMap = new Map<string, User>(); ``` **问题**: 这里没有处理用户不存在的情况，可能导致运行时错误。 建议添加空值检查或使用可选链。 **疑问**: 为什么选择这个库而不是 xxx？有什么特殊考虑吗？
💡
审查礼仪

审查意见应客观、具体、有建设性。避免人身攻击，对事不对人。肯定好的代码，提出改进建议。
