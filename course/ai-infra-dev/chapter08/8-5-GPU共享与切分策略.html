共享与切分

GPU共享是软件层面的资源共享，GPU切分是硬件层面的物理分割。 选择合适的策略对性能和成本都有重要影响。

📊 策略对比

策略 实现方式 隔离性 性能 成本 适用场景
直通 PCI直通 硬件 100% 高 高性能训练
MPS 软件共享 进程 90% 低 推理/小训练
vGPU Hypervisor 硬件 95% 中 企业应用
MIG 硬件切分 硬件 98% 中 大模型推理
软共享 时间片轮转 无 80% 极低 测试/开发

🧩 MIG切分

MIG配置选项

A100 MIG配置：

Profile类型：
• 1g.5gb: 1/16 GPU, 5GB显存
• 2g.10gb: 1/8 GPU, 10GB显存
• 3g.20gb: 1/4 GPU, 20GB显存
• 4g.20gb: 1/4 GPU, 20GB显存
• 7g.40gb: 1/2 GPU, 40GB显存

切分配置示例：

# 切分为7个MIG实例
nvidia-smi mig -cgi 7g.40gb,7g.40gb,2g.10gb,1g.5gb,1g.5gb,1g.5gb,1g.5gb

# 查看MIG配置
nvidia-smi mig -lgi

# 启用MIG
nvidia-smi -i 0 -mig 1

# 禁用MIG
nvidia-smi -i 0 -mig 0

# 查看MIG设备
nvidia-smi -L

# Kubernetes使用MIG
apiVersion: v1
kind: Pod

  containers:
  - resources:
      limits:
        nvidia.com/mig-1g.5gb: 2

💻 切分策略

训练切分

训练场景切分：

大模型训练：
• 使用直通或MIG
• 保证性能和稳定
• 资源独占

小模型训练：
• 可使用MPS
• 提高利用率
• 注意显存

多任务训练：
• 使用vGPU隔离
• 独立资源
• 保证SLA

推理切分

推理场景切分：

在线推理：
• MIG硬隔离
• 保证低延迟
• 性能稳定

离线推理：
• MPS软共享
• 提高吞吐
• 成本优化

混合推理：
• vGPU多租户
• 资源隔离
• 灵活配置
💡
切分策略选择

性能优先：直通或MIG，硬件隔离

成本优先：MPS或软共享，软件共享

平衡方案：vGPU，性能与成本平衡

混合策略：根据场景灵活选择

📈 性能权衡

性能分析

切分性能分析：

显存切分：
• 1/2切分: ~90%性能
• 1/4切分: ~80%性能
• 1/8切分: ~70%性能
• 1/16切分: ~60%性能

性能下降原因：
• 资源开销增加
• 通信延迟增加
• 调度复杂性增加

优化策略：
• 减少切分粒度
• 优化调度算法
• 使用硬件加速

监控指标：
• GPU利用率
• 显存使用率
• 任务完成时间
• 资源浪费率

智能切分策略

自动切分算法：

# 基于工作负载的切分
def determine_slice_strategy(job):
    if job.gpu_request <= 0.25 and job.type == 'inference':
        return 'mig-1g.5gb'
    elif job.gpu_request <= 0.5:
        return 'mig-7g.40gb'
    else:
        return 'passthrough'

# 动态切分
def dynamic_slicing():
    available_gpu = get_available_gpu()
    pending_jobs = get_pending_jobs()

    for job in pending_jobs:
        if available_gpu >= job.gpu_request:
            allocate_gpu(job, available_gpu)
            available_gpu -= job.gpu_request

# 基于性能的切分
def performance_based_slicing():

💼 实践案例

切分配置示例

企业级切分配置：

GPU资源池 (1000 GPU):
- 直通池: 500 GPU (大模型训练)
- vGPU池: 300 GPU (企业应用)
- MIG池: 150 GPU (推理服务)
- MPS池: 50 GPU (开发测试)

切分规则:
- 训练 > 64GPU: 直通
- 训练 8-64GPU: vGPU
- 推理: MIG或MPS
- 开发: MPS或软共享

性能要求:
- 训练: > 90%性能
- 推理: > 80%性能
- 开发: > 60%性能

成本目标:
- GPU利用率: > 75%
- 资源浪费: < 15%
- 总成本: 降低30%
⚠️
切分注意事项

性能损失：切分粒度越小，性能损失越大

兼容性：不同应用对切分的兼容性不同

管理复杂：多切分策略增加管理复杂度

监控调优：需要持续监控和优化

📝 本节小结

✅
  • • GPU共享是软件层面，GPU切分是硬件层面
  • • 直通适合高性能训练，MPS适合推理
  • • vGPU是企业级平衡方案，MIG是硬件硬隔离
  • • 切分粒度越小，性能损失越大
  • • 根据工作负载类型选择切分策略
  • • 自动化切分能提高资源利用效率
