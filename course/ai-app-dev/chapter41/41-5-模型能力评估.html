为什么需要模型评估

大模型评估帮助我们选择合适的模型、优化提示词、监控性能变化。科学的评估体系是构建高质量AI应用的基础，确保模型在特定任务上表现符合预期。

📊 评估维度

🧠

能力维度

推理、知识、创造力、指令遵循

⚠️

安全维度

有害输出、偏见、隐私泄露

⚡

效率维度

延迟、吞吐量、成本效益

💡
LLM-as-Judge

使用强大的模型(如GPT-4)评估其他模型的输出是一种常用方法。需要注意位置偏见（倾向于选第一个）和长度偏见（倾向于更长的回答）。

代码生成评估

# 代码评估：执行测试用例 def evaluate_code(code, test_cases): results = [] for test in test_cases: try: # 执行代码 exec(code) # 运行测试 output = eval(test["call"]) passed = output == test["expected"] except Exception as e: passed = False output = str(e) results.append({ "test": test["name"], "passed": passed, "output": output }) pass_rate = sum(r["passed"] for r in results) / len(results) return {"pass_rate": pass_rate, "details": results}

🔄 人工评估流程

# 人工评估数据收集 evaluation_interface = { "task": "比较两个模型的回答", "question": "用户问题", "response_a": "模型A的回答", "response_b": "模型B的回答", "criteria": [ "A明显更好", "A略好", "两者相当", "B略好", "B明显更好" ], "dimensions": [ "准确性", "有帮助性", "安全性", "流畅性" ] } # Elo评分系统 def calculate_elo(winner_elo, loser_elo, k=32): """计算Elo评分变化""" expected = 1 / (1 + 10 ** ((loser_elo - winner_elo) / 400)) new_winner = winner_elo + k * (1 - expected) new_loser = loser_elo + k * (0 - expected) return new_winner, new_loser
