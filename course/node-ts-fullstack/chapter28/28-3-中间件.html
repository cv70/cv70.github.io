28.3 中间件

拦截和扩展数据库操作

🎯 学习目标

  • 理解中间件的概念和类型
  • 掌握 pre 和 post 中间件
  • 学会常见中间件应用场景
  • 了解错误处理中间件

📚 中间件类型

Mongoose 中间件类型： 1. Document 中间件 ├── init - 文档初始化后 ├── validate - 验证前后 ├── save - 保存前后 └── remove - 删除前后 2. Query 中间件 ├── count - 计数前后 ├── deleteOne - 删除前后 ├── deleteMany - 批量删除前后 ├── find - 查询前后 ├── findOne - 单条查询前后 ├── findOneAndDelete - 查询删除前后 ├── findOneAndRemove - 查询移除前后 ├── findOneAndUpdate - 查询更新前后 ├── update - 更新前后 ├── updateOne - 单条更新前后 └── updateMany - 批量更新前后 3. Aggregate 中间件 └── aggregate - 聚合前后 4. Model 中间件 ├── insertMany - 批量插入前后 └── bulkWrite - 批量写入前后 中间件执行顺序： pre 中间件 → 操作 → post 中间件

🔧 Pre 中间件

// pre 中间件在操作执行前运行 // 密码加密 userSchema.pre('save', async function(next) { // 只在密码被修改时加密 if (!this.isModified('password')) return next(); const bcrypt = require('bcrypt'); const salt = await bcrypt.genSalt(10); this.password = await bcrypt.hash(this.password, salt); next(); }); // 更新时间戳 userSchema.pre('save', function(next) { this.updatedAt = new Date(); next(); }); // 验证前处理 userSchema.pre('validate', function(next) { // 自动生成用户名 if (!this.username && this.email) { this.username = this.email.split('@')[0]; } next(); }); // Query 中间件 - 自动过滤已删除 userSchema.pre(/^find/, function(next) { // this 指向 Query 对象 this.where({ deletedAt: null }); next(); }); // 特定查询的中间件 userSchema.pre('findOneAndUpdate', function(next) { this.options.runValidators = true; this.options.new = true; next(); }); // 异步 pre 中间件 userSchema.pre('save', async function() { // 可以直接使用 async/await const existingUser = await User.findOne({ email: this.email }); if (existingUser && !this._id.equals(existingUser._id)) { throw new Error('邮箱已被使用'); } }); // 条件执行 userSchema.pre('save', function(next) { if (this.isNew) { // 新文档 console.log('Creating new user'); } else { // 更新文档 console.log('Updating user'); } next(); });
💡
this 的指向

在 Document 中间件中，this 指向 Document；在 Query 中间件中，this 指向 Query 对象。不要使用箭头函数，否则会丢失 this 绑定。

📊 Post 中间件

// post 中间件在操作完成后运行 // 记录日志 userSchema.post('save', function(doc, next) { console.log(`User saved: ${doc._id}`); next(); }); // 错误处理 userSchema.post('save', function(error, doc, next) { if (error.name === 'MongoServerError' && error.code === 11000) { next(new Error('邮箱已被注册')); } else { next(error); } }); // 更新后操作 userSchema.post('findOneAndUpdate', function(doc, next) { // doc 是更新后的文档 console.log(`User updated: ${doc._id}`); next(); }); // 删除后清理关联数据 userSchema.post('findOneAndDelete', async function(doc, next) { if (doc) { // 删除用户的所有文章 await Post.deleteMany({ author: doc._id }); } next(); }); // 聚合后处理 userSchema.post('aggregate', function(result, next) { // 可以修改聚合结果 result.forEach(item => { item.computedField = item.value * 2; }); next(); }); // 批量操作后处理 userSchema.post('insertMany', function(docs, next) { console.log(`Inserted ${docs.length} documents`); next(); });

⚙️ 常见应用场景

// 1. 密码加密（已在上面展示） // 2. 软删除 userSchema.pre('deleteOne', { document: true, query: false }, async function() { // 软删除：标记删除时间而非真正删除 this.deletedAt = new Date(); await this.save(); return false; // 阻止实际删除 }); // 3. 数据审计 const auditSchema = new mongoose.Schema({ action: String, collection: String, documentId: mongoose.Schema.Types.ObjectId, changes: Object, userId: mongoose.Schema.Types.ObjectId, timestamp: { type: Date, default: Date.now }, }); userSchema.pre('save', async function() { if (!this.isNew) { const original = await User.findById(this._id); const changes = {}; for (const key of Object.keys(this.toObject())) { if (!this._id.equals(original[key]) && original[key] !== this[key]) { changes[key] = { from: original[key], to: this[key] }; } } if (Object.keys(changes).length > 0) { await Audit.create({ action: 'update', collection: 'User', documentId: this._id, changes, }); } } }); // 4. 自动填充关联 userSchema.pre('findOne', function() { this.populate('posts'); }); // 5. 缓存清理 userSchema.post('save', async function() { await cache.del(`user:${this._id}`); await cache.del('users:all'); }); // 6. 通知发送 orderSchema.post('save', function(doc, next) { if (doc.status === 'completed') { notificationService.send(doc.userId, '订单已完成'); } next(); });

📝 本节小结

✅
  • • pre 中间件在操作前执行
  • • post 中间件在操作后执行
  • • 中间件常用于加密、日志、审计
  • • 不要使用箭头函数，保持 this 绑定
