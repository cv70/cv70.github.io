21.2 关系型数据库

深入理解关系型数据库的核心概念

🎯 学习目标

  • 理解关系型数据库的基本概念
  • 掌握表、行、列的关系
  • 了解主键、外键的作用
  • 熟悉 ACID 事务特性

📚 关系模型

关系型数据库基于关系模型，使用表格（Table）来存储数据，通过行（Row）和列（Column）组织数据结构。

用户表（users） ┌─────┬──────────┬─────────────────┬────────────┐ │ id │ username │ email │ created_at │ ├─────┼──────────┼─────────────────┼────────────┤ │ 1 │ alice │ alice@mail.com │ 2024-01-15 │ │ 2 │ bob │ bob@mail.com │ 2024-01-16 │ │ 3 │ charlie │ charlie@mail.com│ 2024-01-17 │ └─────┴──────────┴─────────────────┴────────────┘ 订单表（orders） ┌─────┬─────────┬────────────┬───────────┐ │ id │ user_id │ product │ amount │ ├─────┼─────────┼────────────┼───────────┤ │ 1 │ 1 │ iPhone │ 999.00 │ │ 2 │ 1 │ MacBook │ 1999.00 │ │ 3 │ 2 │ iPad │ 799.00 │ └─────┴─────────┴────────────┴───────────┘

🔧 核心概念

主键（Primary Key） ├── 唯一标识表中的每一行 ├── 不能为 NULL ├── 通常使用自增 ID 或 UUID └── 示例：users.id, orders.id 外键（Foreign Key） ├── 建立表与表之间的关联 ├── 引用另一个表的主键 ├── 保证数据完整性 └── 示例：orders.user_id → users.id 索引（Index） ├── 加速数据查询 ├── 类似书的目录 ├── 可以单列或多列 └── 示例：CREATE INDEX idx_email ON users(email)
💡
范式化

数据库范式是设计数据库表结构的规范，目的是减少数据冗余。常见范式包括第一范式（1NF）、第二范式（2NF）、第三范式（3NF）等。

📊 ACID 事务特性

ACID 是事务的四个核心特性： A - Atomicity（原子性） 事务中的所有操作要么全部完成，要么全部不完成 C - Consistency（一致性） 事务执行前后，数据库状态保持一致 I - Isolation（隔离性） 并发事务之间相互隔离，互不影响 D - Durability（持久性） 事务完成后，数据永久保存 示例：银行转账 BEGIN TRANSACTION; UPDATE accounts SET balance = balance - 100 WHERE id = 1; UPDATE accounts SET balance = balance + 100 WHERE id = 2; COMMIT; -- 两条语句要么都成功，要么都失败

📝 本节小结

✅
  • • 关系型数据库使用表格存储结构化数据
  • • 主键唯一标识行，外键建立表间关联
  • • ACID 保证事务的可靠性和一致性
  • • 范式化有助于减少数据冗余
