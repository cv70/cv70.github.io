89.1 Monorepo 概念

单一代码仓库管理多个项目

🎯 学习目标

  • 理解 Monorepo 的概念和优势
  • 掌握与 Multirepo 的区别
  • 了解常见 Monorepo 工具
  • 学会选择合适的管理策略

📚 Monorepo 定义

Monorepo（单体仓库）是一种将多个项目代码存储在同一个代码仓库中的开发策略。

# 项目管理策略 ## Multirepo（多仓库） 每个项目/包有独立的仓库 project/ ├── frontend-repo/ # 前端项目仓库 ├── backend-repo/ # 后端项目仓库 ├── shared-utils-repo/ # 公共工具仓库 └── docs-repo/ # 文档仓库 ## Monorepo（单体仓库） 所有项目在同一个仓库中 monorepo/ ├── packages/ │ ├── frontend/ # 前端项目 │ ├── backend/ # 后端项目 │ └── shared-utils/ # 公共工具 ├── apps/ │ └── web/ # Web 应用 ├── docs/ # 文档 ├── package.json # 根配置 └── pnpm-workspace.yaml # Monorepo 特点 - 统一的版本控制 - 共享的开发配置 - 简化的依赖管理 - 原子化的代码提交

🔧 对比分析

┌───────────────────┬────────────────────┬────────────────────┐ │ 对比项 │ Multirepo │ Monorepo │ ├───────────────────┼────────────────────┼────────────────────┤ │ 代码管理 │ 分散在多个仓库 │ 集中在一个仓库 │ │ 依赖共享 │ 需要发布到 npm │ 直接引用 │ │ 代码复用 │ 复杂 │ 简单 │ │ 版本协调 │ 困难 │ 容易 │ │ CI/CD │ 各自配置 │ 统一配置 │ │ 团队协作 │ 相对独立 │ 紧密协作 │ │ 仓库大小 │ 各自独立 │ 可能很大 │ │ 权限管理 │ 灵活 | 相对统一 │ │ 工具链统一 │ 困难 │ 容易 │ │ 跨项目重构 │ 困难 │ 容易 │ └───────────────────┴────────────────────┴────────────────────┘ # Monorepo 优势 ✅ 代码共享简单，无需发布 npm 包 ✅ 原子提交，一次提交修改多个项目 ✅ 统一的工具链和开发规范 ✅ 简化跨项目重构 ✅ 统一的 CI/CD 流程 ✅ 更容易发现和复用代码 # Monorepo 劣势 ❌ 仓库体积可能很大 ❌ CI 时间可能变长 ❌ 权限管理粒度较粗 ❌ 需要专门工具支持 ❌ 学习成本
💡
选择建议

多个项目有紧密依赖关系、需要频繁共享代码时，推荐 Monorepo。项目完全独立、团队较小或权限隔离要求高时，可以用 Multirepo。

⚙️ 常见 Monorepo 工具

# Monorepo 工具对比 ┌─────────────────┬────────────────┬────────────────┬────────────────┐ │ 工具 │ 包管理器 │ 构建系统 │ 特点 │ ├─────────────────┼────────────────┼────────────────┼────────────────┤ │ Lerna │ npm/yarn │ 独立 │ 发布管理强 │ │ Nx │ npm/yarn/pnpm │ 内置 │ 智能构建 │ │ Turborepo │ npm/yarn/pnpm │ 内置 │ 极速缓存 │ │ pnpm workspace │ pnpm │ 配合其他工具 │ 高效存储 │ │ Yarn Workspace │ yarn │ 配合其他工具 │ 原生支持 │ └─────────────────┴────────────────┴────────────────┴────────────────┘ # 典型组合 - pnpm + Turborepo（推荐） - pnpm + Nx - Lerna + Yarn Workspace - Nx（一站式） # 知名 Monorepo 案例 - Google：所有代码在一个仓库 - Facebook：使用内部工具 - Microsoft：TypeScript, VS Code 等 - Vue 生态：vuejs/core - React 生态：facebook/react - Vite 生态：vitejs/vite

🚀 目录结构设计

# 标准 Monorepo 结构 my-monorepo/ ├── packages/ # 共享包 │ ├── ui/ # UI 组件库 │ │ ├── package.json │ │ ├── src/ │ │ └── tsconfig.json │ ├── utils/ # 工具函数 │ │ ├── package.json │ │ └── src/ │ └── config/ # 共享配置 │ └── package.json ├── apps/ # 应用 │ ├── web/ # Web 应用 │ │ ├── package.json │ │ └── src/ │ ├── admin/ # 管理后台 │ │ └── package.json │ └── mobile/ # 移动端 │ └── package.json ├── tools/ # 开发工具 │ └── scripts/ ├── docs/ # 文档 ├── package.json # 根 package.json ├── pnpm-workspace.yaml # pnpm 工作区配置 ├── turbo.json # Turborepo 配置 ├── nx.json # Nx 配置 └── tsconfig.base.json # 共享 TypeScript 配置 # 根 package.json { "name": "my-monorepo", "private": true, "scripts": { "dev": "turbo run dev", "build": "turbo run build", "test": "turbo run test", "lint": "turbo run lint" }, "devDependencies": { "turbo": "latest" } }

📝 本节小结

✅
  • • Monorepo 将多个项目放在同一仓库
  • • 便于代码共享和跨项目重构
  • • 常用工具有 Lerna、Nx、Turborepo、pnpm
  • • 根据团队规模和项目关系选择策略
