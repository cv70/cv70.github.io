31.2 路由路径模式

掌握 Express 路由路径的各种匹配模式

🎯 学习目标

  • 掌握字符串路径的匹配规则
  • 理解路径参数的使用方法
  • 学会使用正则表达式匹配路由
  • 了解特殊的路径匹配模式

📝 字符串路径匹配

精确匹配

// 精确匹配根路径 app.get('/', (req, res) => { res.send('Root'); }); // 精确匹配 /about app.get('/about', (req, res) => { res.send('About Page'); }); // 精确匹配多层路径 app.get('/admin/dashboard', (req, res) => { res.send('Admin Dashboard'); });

特殊字符匹配

// ? - 可选字符（前面的字符出现 0 或 1 次） app.get('/ab?cd', (req, res) => { // 匹配 acd 或 abcd res.send('ab?cd'); }); // + - 重复字符（前面的字符出现 1 或多次） app.get('/ab+cd', (req, res) => { // 匹配 abcd, abbcd, abbbcd, ... res.send('ab+cd'); }); // * - 通配符（匹配任意字符串） app.get('/ab*cd', (req, res) => { // 匹配 abcd, abANYTHINGcd, ab123cd, ... res.send('ab*cd'); }); // () - 分组 app.get('/a(bc)?d', (req, res) => { // 匹配 ad 或 abcd res.send('a(bc)?d'); });
💡
特殊字符说明

?、+、*、() 这些字符在路径中被视为正则表达式语法，而不是字面字符。

🔢 路径参数

基本参数

// 单个参数 app.get('/users/:id', (req, res) => { res.send(`User ID: ${req.params.id}`); }); // 多个参数 app.get('/users/:userId/posts/:postId', (req, res) => { const { userId, postId } = req.params; res.send(`User ${userId}, Post ${postId}`); }); // 多层参数 app.get('/category/:category/subcategory/:subcategory', (req, res) => { res.json(req.params); });

参数限制 - 正则表达式

// 限制参数只能是数字 app.get('/users/:id(\\d+)', (req, res) => { // 只匹配 /users/123, /users/456 等 // 不匹配 /users/abc res.send(`Numeric User ID: ${req.params.id}`); }); // 限制参数长度 app.get('/code/:code([a-zA-Z]{6})', (req, res) => { // 只匹配 6 个字母的代码 res.send(`Code: ${req.params.code}`); }); // UUID 格式 app.get('/items/:uuid([0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12})', (req, res) => { res.send(`UUID: ${req.params.uuid}`); });

可选参数

// 可选参数 - 使用 ? 后缀 app.get('/books/:year?', (req, res) => { const year = req.params.year || new Date().getFullYear(); res.send(`Books from year: ${year}`); }); // 测试： // /books -> year = 当前年份 // /books/2024 -> year = 2024
⚠️
参数顺序

更具体的路由应该在参数化路由之前定义，避免参数化路由意外匹配到具体路径。

🔍 正则表达式路由

完整正则匹配

// 匹配任何以 .json 结尾的路径 app.get(/.*\.json$/, (req, res) => { res.send('JSON file requested'); }); // 匹配任何以数字结尾的路径 app.get(/\/\d+$/, (req, res) => { res.send('Ends with number'); }); // 匹配特定格式 app.get(/^\/api\/v[1-3]\/.*$/, (req, res) => { // 匹配 /api/v1/*, /api/v2/*, /api/v3/* res.send('API v1-v3'); });

常用正则示例

// 匹配文件路径 app.get(/^\/files\/.+\.(txt|pdf|doc)$/, (req, res) => { res.send('File download'); }); // 匹配日期格式 YYYY-MM-DD app.get(/^\/archive\/\d{4}-\d{2}-\d{2}$/, (req, res) => { res.send('Archive by date'); }); // 匹配多种格式 app.get(/\/(users|posts|comments)\/\d+/, (req, res) => { res.send('Resource by ID'); });

📊 路径匹配对照表

路由路径 匹配示例 不匹配示例
/ / /about
/about /about /about/us, /aboutus
/ab?cd /acd, /abcd /abbcd
/ab+cd /abcd, /abbcd /acd
/ab*cd /abcd, /abXYZcd /ab, /cd
/users/:id /users/123, /users/abc /users, /users/123/456
/users/:id? /users, /users/123 /users/123/456
/users/:id(\\d+) /users/123 /users/abc
/api/* /api/users, /api/v1/data /api（需要 /api/*?）
/.*\.json$ /data.json, /api/users.json /data.xml

🔧 实际应用示例

1. RESTful API 资源路由

// 用户资源 app.get('/users', listUsers); // 列表 app.get('/users/:id(\\d+)', getUser); // 详情（ID 限制为数字） app.post('/users', createUser); // 创建 app.put('/users/:id(\\d+)', updateUser); // 更新 app.delete('/users/:id(\\d+)', deleteUser); // 删除 // 文章资源 app.get('/posts', listPosts); app.get('/posts/:slug([a-z0-9-]+)', getPostBySlug); // slug 格式限制 app.post('/posts', createPost); app.put('/posts/:id(\\d+)', updatePost); app.delete('/posts/:id(\\d+)', deletePost);

2. API 版本控制

// 匹配 v1, v2, v3 版本 app.use(/^\/api\/v([1-3])(\/.*)?$/, (req, res, next) => { const version = req.params[0]; req.apiVersion = version; next(); }); // 或更简单的方式 app.use('/api/v1', v1Routes); app.use('/api/v2', v2Routes); app.use('/api/v3', v3Routes);

3. 文件服务路由

// 图片文件 app.get('/images/:filename(\\w+\\.(jpg|jpeg|png|gif|webp))', (req, res) => { const { filename } = req.params; res.sendFile(path.join(__dirname, 'images', filename)); }); // 文档文件 app.get('/docs/:category/:filename(\\w+\\.pdf)', (req, res) => { const { category, filename } = req.params; res.sendFile(path.join(__dirname, 'docs', category, filename)); }); // 下载文件 app.get('/download/*', (req, res) => { const filepath = req.params[0]; res.download(path.join(__dirname, 'files', filepath)); });

4. 多语言路由

// 匹配语言代码（如 /en/about, /zh/about） app.get('/:lang(en|zh|ja|ko)/:page?', (req, res) => { const { lang, page = 'home' } = req.params; res.render(`${lang}/${page}`); });

⚠️ 常见陷阱

1. 路由顺序问题

// ❌ 错误：参数路由在前 app.get('/users/:id', getUserById); // 会匹配 /users/admin app.get('/users/admin', getAdminPage); // 永远不会执行 // ✅ 正确：具体路由在前 app.get('/users/admin', getAdminPage); app.get('/users/:id', getUserById);

2. 路径末尾斜杠

// /about 和 /about/ 是不同的路径 app.get('/about', (req, res) => { res.send('Without trailing slash'); }); app.get('/about/', (req, res) => { res.send('With trailing slash'); }); // 处理两种情况 app.get('/about/?', (req, res) => { res.send('Both work'); });

3. 特殊字符转义

// 如果想匹配字面的 . 字符，需要转义 // ❌ 错误 app.get('/file.json', handler); // . 会匹配任意字符 // ✅ 正确 app.get('/file\\.json', handler); // 转义后只匹配 .

✅ 小结

📌
本节要点
  • Express 支持精确匹配、特殊字符匹配和正则表达式匹配
  • 路径参数使用 :param 语法，通过 req.params 获取
  • 参数可以用正则限制格式，如 :id(\\d+) 只匹配数字
  • 可选参数使用 ? 后缀，如 :id?
  • 具体路由应在参数化路由之前定义
