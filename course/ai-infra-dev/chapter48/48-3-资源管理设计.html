48.3 资源管理设计

高效调度和管理集群资源

🎯 学习目标

  • 理解资源管理的核心概念
  • 掌握资源调度策略
  • 学会配额管理方法
  • 了解GPU资源池化技术

📊 资源管理组成

计算资源

  • CPU核心
  • 内存容量
  • GPU卡数
  • 专用加速器

存储资源

  • 块存储
  • 对象存储
  • 共享存储
  • 缓存空间

网络资源

  • 带宽配额
    • IP地址
  • 负载均衡
  • 安全组

🎛️ 资源调度策略

策略 适用场景 优点 缺点
FIFO 任务队列 简单公平 资源利用率低
优先级 重要任务 保证关键任务 可能导致饥饿
公平份额 多用户 资源公平分配 配置复杂
弹性伸缩 波动负载 节约成本 启动延迟

🔧 Kubernetes资源配额

# ResourceQuota配置
apiVersion: v1
kind: ResourceQuota
metadata:
  name: ai-workload-quota
  namespace: default
spec:
  hard:
    # 计算资源限制
    requests.cpu: "64"
    requests.memory: 256Gi
    limits.cpu: "128"
    limits.memory: 512Gi

    # GPU资源限制
    nvidia.com/gpu: "16"

    # 存储资源限制
    requests.storage: 10Ti
    persistentvolumeclaims: "50"

    # 对象数量限制
    pods: "100"
    services: "20"
    secrets: "50"
    configmaps: "20"

---

# LimitRange配置
apiVersion: v1
kind: LimitRange
metadata:
  name: ai-workload-limits
  namespace: default
spec:
  limits:
  - default:
      cpu: "8"
      memory: 32Gi
    defaultRequest:
      cpu: "4"
      memory: 16Gi
    type: Container

🎮 GPU资源池化

GPU切分（MIG）

# NVIDIA MIG配置
# 查看MIG支持
nvidia-smi -mig 1

# 创建MIG实例
nvidia-smi mig -cgi 1g.5gb,2g.10gb,3g.20gb,4g.20gb

# 查看实例
nvidia-smi mig -lgi

# Kubernetes中使用
resources:
  limits:
    nvidia.com/mig-1g.5gb: 1

GPU共享（MPS）

# MPS配置
nvidia-cuda-mps-control -d

# 设置最大客户端数
export CUDA_MPS_PIPE_DIRECTORY=/tmp/nvidia-mps
export CUDA_MPS_LOG_DIRECTORY=/tmp/nvidia-mps-log

# 启动MPS服务器
nvidia-cuda-mps-control -f

# Kubernetes配置
spec:
  containers:
  - name: mps-server
    image: nvidia/cuda:12.1.0-base-ubuntu22.04
    command: ["nvidia-cuda-mps-control", "-d"]
    resources:
      limits:
        nvidia.com/gpu: 1

📈 弹性伸缩配置

# HPA（水平Pod自动伸缩）
apiVersion: autoscaling/v2
kind: HorizontalPodAutoscaler
metadata:
  name: inference-hpa
spec:
  scaleTargetRef:
    apiVersion: apps/v1
    kind: Deployment
    name: inference-deployment
  minReplicas: 2
  maxReplicas: 10
  metrics:
  - type: Resource
    resource:
      name: cpu
      target:
        type: Utilization
        averageUtilization: 70
  - type: Resource
    resource:
      name: memory
      target:
        type: Utilization
        averageUtilization: 80

---

# KEDA（基于事件的自动伸缩）
apiVersion: keda.sh/v1alpha1
kind: ScaledObject
metadata:
  name: inference-scaler
spec:
  scaleTargetRef:
    name: inference-deployment
  minReplicaCount: 1
  maxReplicaCount: 10
  cooldownPeriod: 30
  triggers:
  - type: prometheus
    metadata:
      serverAddress: http://prometheus-server:9090
      metricName: http_requests_total
      threshold: '100'
      query: sum(rate(http_requests_total[1m]))

⚡ 抢占调度

# 优先级类定义
apiVersion: scheduling.k8s.io/v1
kind: PriorityClass
metadata:
  name: high-priority
value: 1000
globalDefault: false
description: "高优先级任务"

---

apiVersion: scheduling.k8s.io/v1
kind: PriorityClass
metadata:
  name: low-priority
value: 100
globalDefault: true
description: "低优先级任务"

---

# 任务优先级设置
apiVersion: batch/v1
kind: Job
metadata:
  name: training-job
spec:
  template:
    spec:
      priorityClassName: high-priority
      containers:
      - name: trainer
        image: pytorch/pytorch:2.0.1-cuda11.7-cudnn8-runtime
        resources:
          requests:
            nvidia.com/gpu: 4
          limits:
            nvidia.com/gpu: 4

资源优化建议

需求分析：准确评估任务资源需求，避免过度分配。混合部署：将训练和推理任务混合部署，提高利用率。动态调整：根据负载情况动态调整资源配额。监控分析：持续监控资源使用，优化分配策略。
