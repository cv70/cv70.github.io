27.3 建立时间与保持时间

时序检查的核心概念

🎯 学习目标

  • 深入理解建立时间和保持时间的概念
  • 掌握Setup和Hold的检查方法
  • 理解Setup和Hold违例的原因
  • 学会分析和修复Setup/Hold问题

⏱️ 建立时间（Setup Time）

定义

建立时间（T_setup）是指在时钟沿到达之前，数据必须保持稳定的最短时间。

Setup检查公式

T_data_arrival + T_setup <= T_clock_arrival + T_period 其中： - T_data_arrival: 数据到达时间 - T_setup: 寄存器建立时间 - T_clock_arrival: 时钟到达时间 - T_period: 时钟周期 Slack = (T_clock_arrival + T_period) - (T_data_arrival + T_setup)

Setup违例

当Slack < 0时，发生Setup违例。这意味着数据到达太晚，无法在时钟沿前稳定。

🔒 保持时间（Hold Time）

定义

保持时间（T_hold）是指在时钟沿到达之后，数据必须保持稳定的最短时间。

Hold检查公式

T_data_arrival >= T_clock_arrival + T_hold 其中： - T_data_arrival: 数据到达时间 - T_clock_arrival: 时钟到达时间 - T_hold: 寄存器保持时间 Slack = T_data_arrival - (T_clock_arrival + T_hold)

Hold违例

当Slack < 0时，发生Hold违例。这意味着数据到达太早，在时钟沿后无法保持足够长时间。

📊 Setup vs Hold

特性 Setup Time Hold Time
时间参考 时钟沿之前 时钟沿之后
主要因素 数据路径延迟 时钟偏斜
与频率关系 高频时更困难 与频率无关
修复方法 减少延迟、流水线 增加延迟、缓冲
违例后果 功能错误 亚稳态

🔧 Setup违例修复

常见原因

  • 组合逻辑延迟过大
  • 时钟频率过高
  • 输入延迟设置不合理
  • 单元驱动能力不足

修复方法

# 1. 使用更大驱动能力的单元 size_cell [get_cells small_driver*] BUFX4 # 2. 减少逻辑层级 # 修改RTL，减少组合逻辑深度 # 3. 流水线化 # 插入寄存器，分割长组合路径 # 4. 设置多周期路径 set_multicycle_path -setup 2 \ -from [get_cells source_reg] \ -to [get_cells dest_reg] # 5. 优化约束 # 重新评估并放宽约束

🔧 Hold违例修复

常见原因

  • 时钟偏斜过大
  • 数据路径延迟过小
  • 时钟门控导致的时钟延迟差异
  • 多时钟域交叉

修复方法

# 1. 插入延迟单元 insert_buffer [get_pins fast_path*/A] BUFH1 # 2. 调整单元尺寸（减小驱动） size_cell [get_cells fast_driver*] BUFX1 # 3. 增加负载 set_load 0.2 [get_pins data_in] # 4. 调整时钟树 # 让时钟工具平衡时钟延迟 # 5. 设置虚假路径（如果适用） set_false_path -hold -from [get_cells source_reg] \ -to [get_cells dest_reg]

📊 时序检查实例

# ============================================================================ # Setup和Hold检查示例 # ============================================================================ # Setup检查 report_timing -max_paths 20 -delay_type max \ > reports/setup_violations.rpt # Hold检查 report_timing -max_paths 20 -delay_type min \ > reports/hold_violations.rpt # 检查特定路径的Setup和Hold report_timing -from [get_cells reg1/Q] \ -to [get_cells reg2/D] \ -max_paths 1 -delay_type max report_timing -from [get_cells reg1/Q] \ -to [get_cells reg2/D] \ -max_paths 1 -delay_type min # 检查所有寄存器的Setup和Hold check_timing -verbose > reports/check_timing.rpt
⚠️
Setup/Hold权衡

修复Setup问题通常会增加延迟，可能导致Hold问题； 修复Hold问题会增加延迟，可能影响Setup。需要平衡两者， 通常先解决Setup问题，再修复Hold问题。

📝 本节小结

✅
  • • Setup和Hold是时序检查的基础
  • • Setup关注数据在时钟沿前稳定
  • • Hold关注数据在时钟沿后保持
  • • 修复需要理解违例的根本原因
