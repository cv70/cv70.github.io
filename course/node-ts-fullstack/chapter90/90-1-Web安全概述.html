90.1 Web 安全概述

Web 应用安全基础

  • 理解 Web 安全的重要性
  • 了解 Web 安全的基本原则
  • 认识常见安全威胁
  • 了解安全开发生命周期

📚 为什么 Web 安全重要

Web 安全是应用开发中不可忽视的重要环节，安全漏洞可能导致数据泄露、服务中断、声誉损失等严重后果。

# 安全事件的影响 ## 数据层面 - 用户隐私泄露 - 敏感数据被窃取 - 数据被篡改或删除 ## 业务层面 - 服务中断 - 经济损失 - 法律责任 ## 声誉层面 - 用户信任丧失 - 品牌形象受损 - 市场份额下降 # 常见安全漏洞排名 (OWASP Top 10) 1. A01 - 访问控制失效 2. A02 - 加密失败 3. A03 - 注入攻击 4. A04 - 不安全设计 5. A05 - 安全配置错误 6. A06 - 易受攻击组件 7. A07 - 身份识别和身份验证失败 8. A08 - 软件和数据完整性失败 9. A09 - 安全日志记录不足 10. A10 - 服务端请求伪造 (SSRF)

🔧 CIA 三要素

# 信息安全三大核心属性 ┌─────────────────────────────────────────────────────┐ │ CIA 三要素 │ ├───────────────┬─────────────────────────────────────┤ │ Confidentiality│ 机密性 - 只允许授权用户访问 │ │ Integrity │ 完整性 - 数据不被未授权篡改 │ │ Availability │ 可用性 - 服务正常运行可访问 │ └───────────────┴─────────────────────────────────────┘ ## 机密性 (Confidentiality) - 数据加密存储 - 传输加密 (HTTPS) - 访问控制 - 敏感信息脱敏 ## 完整性 (Integrity) - 数据校验 - 数字签名 - 版本控制 - 输入验证 ## 可用性 (Availability) - 服务高可用 - DDoS 防护 - 容灾备份 - 负载均衡 # 扩展属性 - 认证性 (Authenticity) - 不可否认性 (Non-repudiation) - 可追溯性 (Accountability)
💡
安全平衡

安全与便利性需要平衡。过度的安全措施可能影响用户体验，而安全不足则带来风险。根据业务场景找到合适的平衡点。

⚙️ 安全威胁分类

# 按攻击来源分类 ## 客户端攻击 - XSS (跨站脚本攻击) - CSRF (跨站请求伪造) - 点击劫持 - UI 伪装攻击 ## 服务端攻击 - SQL 注入 - 命令注入 - 文件上传漏洞 - 路径遍历 ## 网络层攻击 - 中间人攻击 - DDoS 攻击 - DNS 劫持 - 会话劫持 ## 社会工程学攻击 - 钓鱼攻击 - 密码攻击 - 身份欺骗 # 按漏洞类型分类 ## 注入类 - SQL 注入 - NoSQL 注入 - 命令注入 - LDAP 注入 ## 认证授权类 - 弱密码 - 会话管理漏洞 - 权限绕过 - 越权访问 ## 配置类 - 敏感信息泄露 - 默认配置 - 错误配置 - 版本信息暴露

🚀 安全开发生命周期

# 安全开发生命周期 (SDLC) ## 1. 需求阶段 - 安全需求分析 - 威胁建模 - 合规性检查 ## 2. 设计阶段 - 安全架构设计 - 最小权限原则 - 防御深度设计 ## 3. 开发阶段 - 安全编码规范 - 代码审查 - 安全组件使用 ## 4. 测试阶段 - 安全测试 - 渗透测试 - 漏洞扫描 ## 5. 部署阶段 - 安全配置 - 环境加固 - 访问控制 ## 6. 运维阶段 - 安全监控 - 日志审计 - 应急响应 - 定期更新 # 安全开发最佳实践 1. 永远不要信任用户输入 2. 使用参数化查询 3. 实施最小权限原则 4. 加密敏感数据 5. 保持依赖更新 6. 启用安全日志 7. 实施访问控制 8. 进行安全培训
