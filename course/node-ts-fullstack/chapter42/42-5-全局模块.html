42.5 全局模块

创建随处可用的共享服务

🎯 学习目标

  • 理解全局模块的概念
  • 掌握全局模块的创建方式

  • 理解全局模块的注意事项

📚 什么是全局模块？

全局模块使用 @Global() 装饰器声明，其导出的服务可以在整个应用中直接注入，无需在 imports 中显式导入该模块。

// common/common.module.ts import { Module, Global } from '@nestjs/common'; import { LoggerService } from './logger.service'; import { ConfigService } from './config.service'; @Global() // 声明为全局模块 @Module({ providers: [LoggerService, ConfigService], exports: [LoggerService, ConfigService], }) export class CommonModule {}
💡
全局模块特点

全局模块只需要在根模块中导入一次，其导出的服务就可以在任何模块中直接注入使用。

🔧 创建和使用全局模块

// 1. 创建全局模块 // src/common/common.module.ts @Global() @Module({ providers: [LoggerService, ConfigService, CacheService], exports: [LoggerService, ConfigService, CacheService], }) export class CommonModule {} // 2. 在根模块中导入 // src/app.module.ts @Module({ imports: [CommonModule], // 只需导入一次 // ... }) export class AppModule {} // 3. 在任意模块中直接注入使用 // src/users/users.service.ts @Injectable() export class UsersService { constructor( private logger: LoggerService, // 直接注入，无需导入 CommonModule private config: ConfigService, private cache: CacheService, ) {} findAll() { this.logger.log('Finding all users'); const ttl = this.config.get('CACHE_TTL'); // ... } }

✨ 动态全局模块

// config.module.ts @Global() @Module({}) export class ConfigModule { static forRoot(options: ConfigModuleOptions = {}): DynamicModule { return { module: ConfigModule, global: true, // 动态模块也可以设为全局 providers: [ { provide: 'CONFIG_OPTIONS', useValue: options, }, ConfigService, ], exports: [ConfigService], }; } } // 使用 @Module({ imports: [ ConfigModule.forRoot({ isGlobal: true, envFilePath: '.env', }), ], }) export class AppModule {}

⚠️ 使用场景与注意事项

适合全局模块 不适合全局模块
日志服务 业务服务
配置服务 特定领域服务
缓存服务 数据访问服务
工具服务 有状态的特定服务
⚠️
谨慎使用

过度使用全局模块会导致依赖关系不清晰，增加代码理解和维护的难度。建议只将真正需要全局使用的通用服务设为全局模块。

📝 本节小结

✅
  • • @Global() 装饰器声明全局模块
  • • 全局模块只需导入一次，服务随处可用
  • • 适合日志、配置、缓存等通用服务
  • • 避免滥用，保持依赖关系清晰
