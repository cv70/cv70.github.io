18.5 错误处理与重试

构建健壮的API调用系统

🎯 学习目标

  • 了解大模型API常见错误类型
  • 掌握重试策略的设计方法
  • 学会实现健壮的错误处理机制
  • 能够设计高可用的API调用架构

为什么需要错误处理

大模型API调用过程中可能遇到网络错误、速率限制、服务不可用等各种问题。良好的错误处理和重试机制能够提高系统的可靠性和用户体验，避免因临时故障导致服务中断。

📊 常见错误类型

错误类型 HTTP状态码 原因 处理策略
认证错误 401 API密钥无效或过期 检查密钥，联系管理员
权限不足 403 账户权限或配额限制 检查账户权限
资源不存在 404 模型或端点不存在 检查模型名称
速率限制 429 请求过于频繁 指数退避重试
服务端错误 500/502/503 服务器临时故障 重试或切换服务
超时错误 - 请求处理时间过长 调整超时设置
内容过滤 400 触发内容审核 修改输入内容

🔄 重试策略设计

固定间隔重试

每次重试间隔固定时间，简单但不高效。

import time def retry_fixed(func, max_retries=3, delay=1): for attempt in range(max_retries): try: return func() except Exception as e: if attempt == max_retries - 1: raise time.sleep(delay)

指数退避重试

间隔时间指数增长，推荐用于速率限制。

import time def retry_exponential(func, max_retries=5): for attempt in range(max_retries): try: return func() except Exception as e: if attempt == max_retries - 1: raise delay = (2 ** attempt) + random.random() time.sleep(delay)

⚙️ 完整错误处理实现

import time import random from openai import OpenAI, APIError, RateLimitError, APIConnectionError client = OpenAI() def chat_with_retry( messages, model="gpt-4o-mini", max_retries=5, base_delay=1, max_delay=60 ): """ 带重试机制的API调用 Args: messages: 对话消息列表 model: 模型名称 max_retries: 最大重试次数 base_delay: 基础延迟秒数 max_delay: 最大延迟秒数 """ last_error = None for attempt in range(max_retries): try: response = client.chat.completions.create( model=model, messages=messages, timeout=30 ) return response.choices[0].message.content except RateLimitError as e: last_error = e # 速率限制，使用指数退避 delay = min(base_delay * (2 ** attempt), max_delay) delay = delay + random.uniform(0, 1) # 添加随机抖动 print(f"速率限制，{delay:.1f}秒后重试...") time.sleep(delay) except APIConnectionError as e: last_error = e # 连接错误，快速重试 time.sleep(base_delay) except APIError as e: # 服务器错误，检查状态码 if e.status_code in [500, 502, 503]: last_error = e time.sleep(base_delay * (2 ** attempt)) else: # 其他错误不重试 raise # 重试耗尽 raise Exception(f"重试{max_retries}次后仍失败: {last_error}")

🛡️ 使用tenacity库

tenacity是Python专业的重试库，提供更灵活的重试策略。

from tenacity import retry, stop_after_attempt, wait_exponential, retry_if_exception_type from openai import RateLimitError, APIConnectionError # 装饰器方式配置重试 @retry( stop=stop_after_attempt(5), wait=wait_exponential(multiplier=1, min=1, max=60), retry=retry_if_exception_type((RateLimitError, APIConnectionError)), before_sleep=lambda x: print(f"第{x.attempt_number}次重试...") ) def call_api(messages): return client.chat.completions.create( model="gpt-4o-mini", messages=messages ) # 使用 result = call_api([{"role": "user", "content": "你好"}])

class LLMFailover: """多模型故障转移""" def __init__(self, providers: list[dict]): self.providers = providers self.current_index = 0 def call(self, messages, max_retries=3): errors = [] for i in range(len(self.providers)): provider = self.providers[(self.current_index + i) % len(self.providers)] try: return self._call_provider(provider, messages) except Exception as e: errors.append((provider['name'], str(e))) print(f"{provider['name']} 调用失败: {e}") raise Exception(f"所有提供商均失败: {errors}") # 配置多个提供商 providers = [ {"name": "OpenAI", "client": openai_client, "model": "gpt-4o-mini"}, {"name": "DeepSeek", "client": deepseek_client, "model": "deepseek-chat"}, {"name": "Qwen", "client": qwen_client, "model": "qwen-turbo"} ] llm = LLMFailover(providers) result = llm.call([{"role": "user", "content": "你好"}])

📈 监控与告警

关键监控指标

  • 请求成功率：成功/总请求
  • 平均响应时间：P50/P95/P99
  • 错误分布：按类型统计
  • 重试次数：平均重试次数
  • Token使用量：输入/输出

告警规则示例

  • 成功率低于95%
  • P95延迟超过10秒
  • 429错误频率过高
  • 连续失败超过N次
  • Token使用量异常
💡
最佳实践

针对速率限制(429)使用指数退避重试；针对服务器错误(5xx)可重试但设置上限；针对认证错误(401)不重试直接报警；针对内容过滤需修改输入而非重试。

⚠️
注意事项

重试会增加请求延迟，设置合理的最大重试次数。注意幂等性，避免重复执行产生副作用。对于用户交互场景，提供取消重试的选项。
