39.7 验证度量

量化评估验证质量和进度

🎯 学习目标

  • 理解验证度量的目的和意义
  • 掌握各类覆盖率指标的定义和使用
  • 了解验证质量度量方法
  • 认识验证度量在签核中的作用

什么是验证度量？

验证度量（Verification Metrics）是指通过量化指标来评估验证活动的充分性、有效性和质量的过程。验证度量的核心是覆盖率（Coverage）。

📊 覆盖率分类

代码覆盖率

Code Coverage

  • 行覆盖率（Line）：被执行代码行的比例
  • 分支覆盖率（Branch）：条件分支被覆盖的比例
  • 条件覆盖率（Condition）：布尔表达式各条件值被覆盖的比例
  • 路径覆盖率（Path）：代码路径被覆盖的比例
  • FSM覆盖率：状态机状态和转换被覆盖的比例
  • Toggle覆盖率：信号翻转被覆盖的比例

功能覆盖率

Functional Coverage

  • 特性覆盖率：设计特性被验证的比例
  • 场景覆盖率：使用场景被覆盖的比例
  • 交叉覆盖率：多维度交叉场景被覆盖的比例
  • 配置覆盖率：不同配置被测试的比例
  • 边界覆盖率：边界条件被覆盖的比例

📈 覆盖率目标设定

典型覆盖率目标

覆盖率类型 最低目标 推荐目标 说明
行覆盖率 90% >95% 所有可执行代码行
分支覆盖率 85% >90% 所有if/else分支
条件覆盖率 80% >85% 布尔表达式的每个条件
FSM覆盖率 95% 100% 状态和转换
Toggle覆盖率 80% >90% 关键信号
功能覆盖率 90% >95% 所有设计特性

🎯 功能覆盖率建模

功能覆盖率定义方法

1. 识别待覆盖特性
从设计规范中提取所有需要验证的功能特性
2. 定义覆盖组（Covergroup）
将相关特性组织成覆盖组
3. 定义覆盖点（Coverpoint）
为每个特性定义覆盖点
4. 定义交叉覆盖（Cross）
定义多维度交叉场景
5. 设置采样事件
指定何时采样覆盖率数据
⚠️
覆盖率陷阱

高覆盖率 ≠ 高质量
• 覆盖率只衡量"测了什么"，不衡量"测得对不对"
• 100%的代码覆盖率不意味着没有Bug
• 功能覆盖率依赖于建模的正确性
• 需要结合实际Bug发现情况评估质量

✅ 验证签核标准

典型签核标准

类别 标准
代码覆盖率 行>95%, 分支>90%, FSM=100%
功能覆盖率 >95%，所有特性验证完成
断言覆盖率 >90%，所有关键属性验证
Bug状态 所有已知Bug已修复或评估
回归测试 连续N次全量回归100%通过
系统验证 关键应用场景验证通过
💡
覆盖率收敛策略

1. 定期分析：每周分析覆盖率报告
2. 识别未覆盖：找出未覆盖的代码和功能
3. 定向测试：为未覆盖点编写定向测试
4. 调整约束：修改随机约束以覆盖新场景
5. 排除分析：合理排除无法覆盖的代码

📝 本节小结

✅
  • • 验证度量通过量化指标评估验证质量
  • • 覆盖率包括代码覆盖率和功能覆盖率
  • • 需要设定合理的覆盖率目标和签核标准
  • • 高覆盖率不等于高质量，需结合实际情况
