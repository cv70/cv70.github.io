📋 故障定位流程

# 标准故障定位流程 ## 1. 问题确认 - 明确问题描述 - 确认故障现象 - 收集相关日志 - 记录时间范围 ## 2. 影响范围评估 - 受影响的服务 - 受影响的用户 - 故障严重程度 - 业务影响评估 ## 3. 信息收集 - 系统日志 - 应用日志 - 监控数据 - 告警信息 ## 4. 初步诊断 - 检查系统状态 - 验证服务状态 - 检查网络连接 - 查看资源使用 ## 5. 假设提出 - 基于信息提出假设 - 列出可能原因 - 优先级排序 - 制定验证计划 ## 6. 验证假设 - 逐一验证假设 - 使用排查工具 - 记录验证结果 - 修正假设 ## 7. 定位根本原因 - 确定根本原因 - 验证原因 - 记录分析过程 - 准备修复方案

🔍 系统级排查

# 系统级故障排查 ## 1. CPU问题排查 ```bash # 查看CPU使用 top -bn1 | head -20 # 查看CPU详情 lscpu # 查看CPU负载 uptime # 查看进程CPU使用 ps aux --sort=-%cpu | head -10 ``` ## 2. 内存问题排查 ```bash # 查看内存使用 free -h # 查看进程内存使用 ps aux --sort=-%mem | head -10 # 查看内存详细信息 cat /proc/meminfo # 查看Swap使用 swapon -s ``` ## 3. 磁盘问题排查 ```bash # 查看磁盘使用 df -h # 查看磁盘I/O iostat -x 1 10 # 查看磁盘健康 smartctl -a /dev/sda # 查看磁盘空间占用 du -sh * | sort -rh | head -10 ``` ## 4. 网络问题排查 ```bash # 查看网络接口 ifconfig # 查看网络连接 netstat -an | grep ESTABLISHED | wc -l # 查看网络延迟 ping -c 10 target_host # 查看网络路由 route -n # 查看网络带宽 iftop -i eth0 ```

🤖 AI系统排查

# AI系统故障排查 ## 1. GPU问题排查 ```bash # 查看GPU状态 nvidia-smi # 查看GPU详细信息 nvidia-smi -q # 查看GPU错误日志 journalctl -u nvidia-persistenced # 查看GPU进程 nvidia-smi pmon -c 10 # 测试GPU nvidia-smi --gpu-reset=0 ``` ## 2. 训练任务排查 ```bash # 查看训练进程 ps aux | grep train # 查看训练日志 tail -100 training.log # 查看GPU利用率 watch -n 1 nvidia-smi # 检查数据加载 python -c "from dataset import MyDataset; ds = MyDataset(); print(len(ds))" ``` ## 3. 推理服务排查 ```bash # 查看服务状态 systemctl status inference-service # 查看服务日志 journalctl -u inference-service -n 100 # 测试服务 curl http://localhost:8000/health # 查看服务进程 ps aux | grep inference ``` ## 4. 数据问题排查 ```bash # 检查数据文件 ls -lh /data/dataset/ # 检查数据格式 file /data/dataset/sample.jpg # 检查数据权限 ls -l /data/dataset/ # 检查数据完整性 md5sum /data/dataset/file* ```

# 故障定位技巧 ## 1. 二分法定位 # 快速缩小问题范围 - 服务是否正常？ - 是哪个模块？ - 是哪个函数？ ## 2. 对比法定位 # 正常 vs 异常 - 正常环境的配置 - 正常环境的日志 - 正常环境的监控 ## 3. 时间线分析 # 重现故障发生过程 - 故障发生前发生了什么 - 时间点有什么变化 - 按时间顺序分析日志 ## 4. 关联分析 # 分析故障相关性 - 同时发生的其他问题 - 共同的相关因素 - 隐含的因果关系 ## 5. 排除法 # 逐一排除可能性 - 排除不是X - 排除不是Y - 剩下的就是原因 ## 6. 假设验证 # 科学方法论 - 提出假设 - 设计实验 - 验证假设 - 修正假设

📊 故障定位示例

# 故障定位示例：训练任务失败 ## 问题现象 训练任务在运行2小时后突然失败，显存溢出错误 ## 定位过程 ### 1. 问题确认 - 错误信息：CUDA out of memory - 失败时间：2小时后 - 失败阶段：第100个epoch ### 2. 信息收集 ```bash # 查看训练日志 tail -100 training.log # 查看GPU使用历史 watch -n 1 nvidia-smi # 查看进程内存 ps aux | grep train ``` ### 3. 初步诊断 - GPU显存持续增长 - 可能存在内存泄漏 - 数据加载可能有问题 ### 4. 假设提出 - 假设1：数据加载累积 - 假设2：模型参数未释放 - 假设3：缓存无限增长 ### 5. 验证假设 ```python # 添加内存监控 import torch import psutil def monitor_memory(): while True: print(f"GPU: {torch.cuda.memory_allocated() / 1024**3:.2f} GB") print(f"CPU: {psutil.Process().memory_info().rss / 1024**3:.2f} GB") time.sleep(60) ``` ### 6. 根本原因 - DataLoader的worker进程未正确清理 - 导致显存持续增长 ### 7. 修复方案 - 设置worker的maxtasksperchild - 定期清理缓存 - 优化数据加载逻辑
