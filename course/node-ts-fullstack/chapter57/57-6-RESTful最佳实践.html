57.6 RESTful 最佳实践

构建高质量 RESTful API 的实战指南

📋 响应格式规范

统一响应结构

保持 API 响应格式的一致性，方便客户端处理。

// 成功响应 { "success": true, "data": { "id": 123, "name": "张三" }, "message": "操作成功" } // 列表响应 { "success": true, "data": [...], "meta": { "total": 100, "page": 1, "pageSize": 10, "totalPages": 10 } } // 错误响应 { "success": false, "error": { "code": "VALIDATION_ERROR", "message": "参数验证失败", "details": [ { "field": "email", "message": "邮箱格式不正确" } ] } }

📄 分页设计

分页参数

// Offset 分页 GET /users?page=1&pageSize=10 // 响应 { "data": [...], "pagination": { "total": 1000, "page": 1, "pageSize": 10, "totalPages": 100 } } // Cursor 分页（大数据量推荐） GET /users?cursor=eyJpZCI6MTAwfQ&limit=10 // 响应 { "data": [...], "pagination": { "nextCursor": "eyJpZCI6MTEwfQ", "previousCursor": null, "hasMore": true } }

NestJS 分页实现

interface PaginationParams { page?: number; pageSize?: number; } interface PaginatedResult { data: T[]; total: number; page: number; pageSize: number; totalPages: number; } @Controller('users') export class UserController { constructor(private readonly userService: UserService) {} @Get() async findAll( @Query('page') page = 1, @Query('pageSize') pageSize = 10, ): Promise> { return this.userService.findPaginated({ page, pageSize }); } } // Service 实现 @Injectable() export class UserService { constructor(@InjectRepository(User) private userRepo: Repository) {} async findPaginated({ page, pageSize }: PaginationParams): Promise> { const [data, total] = await this.userRepo.findAndCount({ skip: (page - 1) * pageSize, take: pageSize, order: { createdAt: 'DESC' }, }); return { data, total, page, pageSize, totalPages: Math.ceil(total / pageSize), }; } }

🔍 过滤、排序与字段选择

// 过滤 GET /users?status=active&role=admin GET /users?createdAt[gte]=2024-01-01&createdAt[lte]=2024-12-31 // 排序 GET /users?sort=-createdAt,name // - 表示降序 GET /users?sort=createdAt:desc,name:asc // 字段选择 GET /users?fields=id,name,email // 搜索 GET /users?search=张三 GET /users?q=张三&fields=name,email

查询参数解析实现

import { Transform } from 'class-transformer'; export class UserQueryDto { @IsOptional() @IsString() search?: string; @IsOptional() @Transform(({ value }) => value?.split(',')) @IsArray() @IsString({ each: true }) fields?: string[]; @IsOptional() @IsString() sort?: string; @IsOptional() @IsEnum(['active', 'inactive']) status?: string; } @Controller('users') export class UserController { @Get() async findAll(@Query() query: UserQueryDto) { const { search, fields, sort, status } = query; return this.userService.findAll({ search, fields, sort, status }); } }

🔗 HATEOAS 实现

HATEOAS（Hypermedia as the Engine of Application State）让 API 更加自描述。

// 带链接的响应 { "id": 123, "name": "张三", "email": "zhangsan@example.com", "_links": { "self": { "href": "/api/v1/users/123", "method": "GET" }, "update": { "href": "/api/v1/users/123", "method": "PUT" }, "delete": { "href": "/api/v1/users/123", "method": "DELETE" }, "orders": { "href": "/api/v1/users/123/orders", "method": "GET" } } } // 列表响应中的链接 { "data": [...], "_links": { "self": { "href": "/api/v1/users?page=1" }, "next": { "href": "/api/v1/users?page=2" }, "prev": null, "first": { "href": "/api/v1/users?page=1" }, "last": { "href": "/api/v1/users?page=10" } } }

压缩响应

// main.ts import compression from 'compression'; app.use(compression());

缓存控制

// 控制器中设置缓存头 @Get() @Header('Cache-Control', 'max-age=3600') findAll() { return this.userService.findAll(); }

条件请求

// ETag 实现 @Get(':id') async findOne( @Param('id') id: string, @Headers('if-none-match') ifNoneMatch: string, ) { const user = await this.userService.findOne(+id); const etag = `"${hash(user)}"`; if (ifNoneMatch === etag) { throw new NotModifiedException(); } return { ...user, _etag: etag }; }

📊 API 设计检查清单

URL 设计

  • 使用名词复数形式
  • 使用小写和连字符
  • 层级不超过 3 层
  • 避免动词
  • 版本号在 URL 中

HTTP 方法

  • GET - 获取资源
  • POST - 创建资源
  • PUT - 完整更新
  • PATCH - 部分更新
  • DELETE - 删除资源

状态码

  • 200 - 成功
  • 201 - 创建成功
  • 204 - 删除成功
  • 400 - 参数错误
  • 401/403 - 认证授权

响应格式

  • 统一响应结构
  • 分页信息
  • 错误详情
  • 时间戳 ISO 格式
  • 空值使用 null
💡
记住

RESTful API 设计原则是指导方针而非教条。在实际项目中，应根据团队规范、项目需求和客户端特点灵活调整，保持一致性和实用性。

📝 小结

  • 统一响应格式，便于客户端处理
  • 合理设计分页、过滤、排序功能
  • HATEOAS 提升 API 可发现性
  • 性能优化：压缩、缓存、条件请求
  • 安全实践：HTTPS、CORS、输入验证
  • 遵循设计检查清单确保 API 质量
