28.3 容器安全

AI容器镜像的安全防护

🎯 学习目标

  • 理解容器安全面临的威胁与挑战
  • 掌握镜像安全扫描与漏洞修复
  • 学会配置容器运行时安全
  • 了解AI应用特有的安全考虑

容器安全概述

容器安全涵盖镜像构建、传输、运行全生命周期的安全防护。AI容器由于依赖复杂、 模型文件巨大、需要GPU访问等特点，面临独特的安全挑战。构建安全的AI容器环境需要多层次防护。

🛡️ 容器安全威胁模型

镜像层威胁

  • 基础镜像漏洞
  • 恶意依赖包
  • 机密信息泄露
  • 供应链攻击

运行时威胁

  • 容器逃逸
  • 权限提升
  • DOS攻击
  • 数据窃取
⚠️
AI特有威胁
  • • 训练数据投毒
  • • 模型后门
  • • 模型窃取
  • • 对抗样本攻击

🔍 镜像安全扫描

使用Trivy扫描

# 安装Trivy brew install trivy # macOS apt-get install trivy # Ubuntu # 扫描镜像漏洞 trivy image myapp:latest # 输出示例： # 2023-04-15T10:00:00.000Z [INFO] Number of language-specific files: 1 # 2023-04-15T10:00:00.000Z [INFO] Detected OS: ubuntu # myapp:latest (ubuntu 22.04) # Total: 157 (HIGH: 12, CRITICAL: 3) # 扫描时设置严重级别阈值 trivy image --exit-code 1 --severity HIGH,CRITICAL myapp:latest # 仅扫描操作系统包 trivy image --scanners os myapp:latest # 仅扫描语言依赖 trivy image --scanners vuln myapp:latest

使用Docker Scout

# 扫描镜像 docker scout cves myapp:latest # 查看漏洞详情 docker scout cves --format json myapp:latest # 与基准镜像对比 docker scout compare myapp:v1 myapp:v2

🔐 最小权限原则

用户权限配置

# ❌ 不好的做法：以root运行 FROM python:3.10 USER root CMD ["python", "app.py"] # ✅ 好的做法：创建非root用户 FROM python:3.10 RUN groupadd -r appuser && useradd -r -g appuser appuser # 切换到非root用户 USER appuser CMD ["python", "app.py"]

能力限制

# Docker运行时限制能力 docker run --cap-drop ALL --cap-add NET_BIND_SERVICE myapp # Kubernetes配置 apiVersion: v1 kind: Pod spec: containers: - name: app image: myapp:latest securityContext: drop: - ALL add: - NET_BIND_SERVICE # 只允许绑定端口 allowPrivilegeEscalation: false

只读文件系统

# Docker运行时只读 docker run --read-only --tmpfs /tmp myapp # Kubernetes配置 apiVersion: v1 kind: Pod spec: containers: - name: app image: myapp:latest securityContext: readOnlyRootFilesystem: true volumeMounts: - mountPath: /tmp name: tmp-volume volumes: - name: tmp-volume emptyDir: {}

🔒 镜像签名与验证

使用Notary签名

# 安装Notary brew install notary # macOS # 初始化仓库 notary init docker.io/myorg/myapp # 添加签名密钥 notary key rotate docker.io/myorg/myapp snapshot # 签名镜像 docker trust sign myapp:latest # 验证镜像 docker trust verify myapp:latest

使用Cosign

# 安装Cosign go install github.com/sigstore/cosign/cmd/cosign@latest # 生成密钥对 cosign generate-key-pair # 签名镜像 cosign sign --key cosign.key myapp:latest # 验证镜像 cosign verify --key cosign.pub myapp:latest # 附加签名（OCI artifact） cosign attach signature myapp:latest \ --signature <(echo -n "signature" | base64)

🤖 AI应用安全

模型安全

# 模型加密存储 from cryptography.fernet import Fernet # 加密模型 key = Fernet.generate_key() cipher_suite = Fernet(key) encrypted_model = cipher_suite.encrypt(model_bytes) # 运行时解密 decrypted_model = cipher_suite.decrypt(encrypted_model) model = torch.load(io.BytesIO(decrypted_model)) # 模型完整性校验 import hashlib model_hash = hashlib.sha256(model_bytes).hexdigest()

数据安全

# 训练数据加密 from cryptography.fernet import Fernet # 加密数据文件 with open('data.pt', 'rb') as f: data = f.read() encrypted = cipher_suite.encrypt(data) with open('data.pt.enc', 'wb') as f: f.write(encrypted) # 运行时使用secret挂载解密密钥 # Kubernetes Secret apiVersion: v1 kind: Secret metadata: name: model-key type: Opaque data: key:

防止模型窃取

# 限制模型查询频率 from collections import defaultdict from datetime import datetime, timedelta class RateLimiter: def __init__(self, max_requests, window): self.max_requests = max_requests self.window = window self.requests = defaultdict(list) def is_allowed(self, client_id): now = datetime.now() # 清理过期记录 self.requests[client_id] = [ t for t in self.requests[client_id] if now - t < timedelta(seconds=self.window) ] # 检查是否超限 if len(self.requests[client_id]) >= self.max_requests: return False self.requests[client_id].append(now) return True # 使用 limiter = RateLimiter(max_requests=100, window=60) if not limiter.is_allowed(client_id): raise Exception("Rate limit exceeded")

📋 安全检查清单

检查项 说明 优先级
基础镜像安全 使用官方镜像，定期更新 高
漏洞扫描 CI/CD中集成安全扫描 高
非root用户 不以root用户运行容器 高
最小化依赖 只安装必要的包 中
镜像签名 验证镜像完整性和来源 中
运行时监控 监控异常行为 中
模型加密 保护模型知识产权 低
网络隔离 限制网络访问 中

最佳实践总结
  • • 在CI/CD中集成安全扫描
  • • 遵循最小权限原则
  • • 使用非root用户运行
  • • 定期更新基础镜像和依赖
  • • 启用运行时监控和告警
  • • 保护模型和数据安全
  • • 实施镜像签名和验证
