48.4 ARM异常处理

理解ARM的异常与中断机制

🎯 学习目标

  • 理解ARM异常模型的基本概念
  • 掌握异常级别（EL0-EL3）的层次结构
  • 了解异常入口与返回机制
  • 认识异常在系统安全中的作用

异常概述

异常（Exception）是改变正常程序执行流的事件，包括中断、故障、陷阱等。 ARMv8引入了四层异常级别（Exception Levels），为系统安全提供了坚实的架构基础。

🏗️ 异常级别（Exception Levels）

EL0 - 用户模式

  • 最低权限级别
  • 应用程序运行级别
  • 无法访问敏感系统资源
  • 所有特权操作需陷入内核

EL1 - 内核模式

  • 操作系统内核运行级别
  • 可访问所有用户资源
  • 管理内存和设备
  • 处理系统调用

EL2 - 虚拟化管理

  • 虚拟机监视器（Hypervisor）
  • 管理虚拟机
  • 拦截虚拟机的敏感操作
  • 实现内存和I/O虚拟化

EL3 - 安全监控

  • 最高权限级别
  • TrustZone固件运行级别
  • 安全世界与非安全世界切换
  • 安全启动和密钥管理

📊 异常类型

异常类型 描述 示例
同步异常 由指令执行引起 数据中止、未定义指令
IRQ 普通中断请求 定时器、外设中断
FIQ 快速中断请求 高优先级实时中断
SError 系统错误 异步数据中止、总线错误

🔄 异常入口与返回

异常入口流程

  • 保存处理器状态（PSTATE）
  • 保存返回地址（ELR_ELx）
  • 更新异常级别
  • 跳转到异常向量表
  • 禁用相应中断

异常返回流程

  • 执行ERET指令
  • 恢复处理器状态
  • 恢复异常级别
  • 跳转到ELR_ELx保存的地址
  • 恢复中断状态
⚠️
关键点

异常处理必须原子性地保存和恢复处理器状态，任何错误都可能导致系统崩溃。这是操作系统内核开发中最关键的部分之一。

🗺️ 异常向量表

// 异常向量表布局（每个条目128字节）
Exception Vector Table:
- 0x000: Current EL with SP0
- 0x080: Current EL with SPx
- 0x100: Lower EL using AArch64
- 0x180: Lower EL using AArch32
- 0x200: IRQ from current EL
- 0x280: IRQ from lower EL
- 0x300: FIQ from current EL
- 0x380: FIQ from lower EL

  • • 异常向量表定义了异常入口地址
