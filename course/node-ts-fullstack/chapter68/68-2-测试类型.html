68.2 测试类型：单元、集成、E2E

第十部分：测试篇 - 深入理解不同层级的测试

1. 测试类型概览

软件测试按测试范围和目的可分为多种类型。在后端开发中，最重要的三种测试类型是：单元测试、集成测试和端到端测试（E2E）。

E2E 测试 (端到端测试) - 10%
集成测试 - 20%
单元测试 - 70%
测试金字塔模型

2. 单元测试 (Unit Testing)

📌
定义

单元测试是对软件中最小的可测试单元（通常是函数或方法）进行验证的测试。它隔离测试单个组件，不依赖外部系统。

单元测试特点

特点 说明
测试范围 单个函数、方法或类
依赖 使用 Mock 隔离外部依赖
执行速度 极快（毫秒级）
数量 测试金字塔底层，数量最多
定位问题 精确定位到具体函数
// 单元测试示例：测试纯函数 describe('MathUtils', () => { describe('add', () => { it('should add two positive numbers', () => { expect(MathUtils.add(2, 3)).toBe(5); }); it('should add negative numbers', () => { expect(MathUtils.add(-2, -3)).toBe(-5); }); it('should add zero correctly', () => { expect(MathUtils.add(5, 0)).toBe(5); }); }); });

单元测试最佳实践

  • 每个测试只验证一个行为
  • 使用描述性的测试名称
  • 遵循 AAA 模式（Arrange-Act-Assert）
  • 避免测试私有方法（测试公共接口）
  • Mock 外部依赖，保持测试隔离

3. 集成测试 (Integration Testing)

📌
定义

集成测试验证多个模块或组件之间的交互是否正常。它测试组件之间的接口和数据流。

集成测试场景

常见场景

  • 服务与数据库交互
  • 服务与缓存交互
  • 服务与消息队列交互
  • 多个服务之间的调用

测试策略

  • 使用测试数据库
  • 使用内存数据库
  • 使用 Docker 容器
  • 合理使用 Mock
// 集成测试示例：测试服务与数据库交互 describe('UserService Integration', () => { let connection: DataSource; let userRepository: Repository<User>; let userService: UserService; beforeAll(async () => { // 连接测试数据库 connection = await createTestConnection(); userRepository = connection.getRepository(User); userService = new UserService(userRepository); }); afterAll(async () => { await connection.close(); }); beforeEach(async () => { // 清空测试数据 await userRepository.clear(); }); it('should create and find user', async () => { // 创建用户 const user = await userService.create({ name: 'Test User', email: 'test@example.com' }); // 验证可以查找到 const found = await userService.findById(user.id); expect(found).toBeDefined(); expect(found.name).toBe('Test User'); }); });

4. 端到端测试 (E2E Testing)

📌
定义

端到端测试模拟真实用户场景，从用户角度验证整个应用的工作流程，包括前端、后端、数据库等所有组件。

E2E 测试特点

特点 说明
测试范围 完整的用户流程
环境 接近生产环境的完整系统
执行速度 慢（秒级甚至分钟级）
数量 测试金字塔顶层，数量最少
问题定位 较难定位具体问题位置
// E2E 测试示例：测试完整的用户注册流程 describe('User Registration E2E', () => { let app: INestApplication; beforeAll(async () => { const module = await Test.createTestingModule({ imports: [AppModule] }).compile(); app = module.createNestApplication(); await app.init(); }); afterAll(async () => { await app.close(); }); it('should complete user registration flow', async () => { // 1. 注册新用户 const registerResponse = await request(app.getHttpServer()) .post('/auth/register') .send({ email: 'newuser@example.com', password: 'password123', name: 'New User' }) .expect(201); expect(registerResponse.body.accessToken).toBeDefined(); // 2. 使用 token 访问受保护资源 const profileResponse = await request(app.getHttpServer()) .get('/users/profile') .set('Authorization', `Bearer ${registerResponse.body.accessToken}`) .expect(200); expect(profileResponse.body.email).toBe('newuser@example.com'); }); });

E2E 测试工具

  • Supertest - Node.js HTTP 测试
  • Cypress - 前端 E2E 测试
  • Playwright - 跨浏览器 E2E 测试
  • Puppeteer - Chrome 自动化测试

5. 三种测试对比

维度 单元测试 集成测试 E2E 测试
测试范围 单个函数/方法 多个模块交互 完整系统流程
执行速度 极快 (毫秒) 中等 (秒) 慢 (秒/分钟)
维护成本 低 中等 高
问题定位 精确 较精确 困难
真实度 低 中等 高
依赖 Mock 外部依赖 部分真实依赖 全部真实依赖

6. 其他测试类型

功能测试

验证软件功能是否符合需求规格说明，关注"做什么"而不是"怎么做"。

性能测试

测试系统在特定负载下的响应时间、吞吐量等性能指标。

安全测试

发现系统安全漏洞，包括渗透测试、漏洞扫描等。

回归测试

在代码修改后重新测试，确保没有引入新的问题。

7. 本节小结

📚
关键要点
  • 单元测试测试最小单元，速度最快，数量最多
  • 集成测试测试模块间交互，需要真实依赖
  • E2E 测试模拟真实用户场景，真实度最高
  • 遵循测试金字塔原则分配测试比例
  • 不同测试类型相互补充，共同保障系统质量
