104.2 单体 vs 微服务

两种架构模式的对比与选择

🎯 学习目标

  • 理解单体架构的特点
  • 理解微服务架构的特点
  • 掌握两种架构的对比
  • 学会根据场景选择架构

📚 单体架构

// 单体架构：所有功能在一个应用中 // 目录结构示例 monolith-app/ ├── src/ │ ├── controllers/ │ │ ├── user.controller.ts │ │ ├── product.controller.ts │ │ └── order.controller.ts │ ├── services/ │ │ ├── user.service.ts │ │ ├── product.service.ts │ │ └── order.service.ts │ ├── models/ │ │ ├── user.model.ts │ │ ├── product.model.ts │ │ └── order.model.ts │ └── app.ts ├── package.json └── Dockerfile // 单体应用入口 // app.ts import express from 'express'; import userRouter from './routes/user.routes'; import productRouter from './routes/product.routes'; import orderRouter from './routes/order.routes'; const app = express(); app.use('/users', userRouter); app.use('/products', productRouter); app.use('/orders', orderRouter); // 一个进程处理所有请求 app.listen(3000);
💡
单体架构优势

开发简单、部署简单、调试方便、性能好（无网络开销）、事务简单。

🔧 微服务架构

// 微服务架构：功能拆分为独立服务 // 目录结构示例 microservices/ ├── services/ │ ├── user-service/ │ │ ├── src/ │ │ ├── package.json │ │ └── Dockerfile │ ├── product-service/ │ │ ├── src/ │ │ ├── package.json │ │ └── Dockerfile │ └── order-service/ │ ├── src/ │ ├── package.json │ └── Dockerfile ├── api-gateway/ │ └── gateway.config.yml └── docker-compose.yml // 每个服务独立部署 // user-service/src/app.ts import express from 'express'; import mongoose from 'mongoose'; const app = express(); // 独立的数据库连接 mongoose.connect('mongodb://localhost:27017/users'); // 独立的服务端口 app.listen(3001, () => { console.log('User Service running on port 3001'); }); // product-service/src/app.ts import express from 'express'; import { Pool } from 'pg'; const app = express(); // 独立的数据库连接（可以是不同类型的数据库） const pool = new Pool({ host: 'localhost', database: 'products' }); // 独立的服务端口 app.listen(3002, () => { console.log('Product Service running on port 3002'); });

⚖️ 架构对比

// 详细对比表 const comparison = { 开发复杂度: { 单体: '简单，统一的技术栈', 微服务: '复杂，多技术栈协调' }, 部署方式: { 单体: '整体部署', 微服务: '独立部署' }, 扩展性: { 单体: '整体扩展', 微服务: '按需独立扩展' }, 故障影响: { 单体: '可能影响整体', 微服务: '仅影响单个服务' }, 数据一致性: { 单体: '本地事务，简单', 微服务: '分布式事务，复杂' }, 运维成本: { 单体: '较低', 微服务: '较高' } }; // 选择建议 const whenToChoose = { 选择单体: [ '初创公司或项目初期', '团队规模较小', '业务逻辑相对简单', '快速迭代需要', '运维资源有限' ], 选择微服务: [ '业务复杂度高', '团队规模较大', '需要独立扩展', '高可用性要求', '已有完善DevOps体系' ] };

📝 本节小结

✅
  • • 单体架构简单高效，适合小型项目
  • • 微服务灵活可扩展，适合大型系统
  • • 没有最好的架构，只有最适合的架构
  • • 可以从单体开始，逐步演进到微服务
