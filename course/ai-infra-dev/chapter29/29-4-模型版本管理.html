模型版本管理概述

模型版本管理是追踪、组织和控制模型版本变更的实践。 良好的版本管理确保模型的可追溯性、可重现性和可控性，是MLOps的基础。

📊 版本管理核心概念

版本标识

唯一标识每个模型版本。

  • 版本号
  • Git commit
  • 时间戳
  • 校验和

版本描述

记录版本变更信息。

  • 变更说明
  • 改进内容
  • 已知问题
  • 修复记录

版本关系

跟踪版本间的依赖。

  • 前置版本
  • 分支关系
  • 合并记录
  • 影响范围

🏷️ 版本命名策略

语义化版本

# 主版本.次版本.修订号 # MAJOR.MINOR.PATCH # 示例： v1.0.0 # 初始版本 v1.1.0 # 新功能（向后兼容） v1.1.1 # Bug修复 v2.0.0 # 重大变更（不兼容）

日期版本

# YYYY.MM.DD-RELEASE # 示例： 2024.01.15 # 2024年1月15日 2024.01.15-rc1 # Release Candidate 1 2024.01.15-final # 正式版本

Git友好版本

# 使用Git commit或tag # Commit hash v1.0.0-abc1234 # Git tag v1.0.0-release # 分支名 v1.0.0-feature-xyz
💡
版本命名建议
  • • 选择一种命名策略并保持一致
  • • 语义化版本适合API/服务
  • • 日期版本适合定期发布的模型
  • • Git版本适合开发环境

🔄 版本生命周期

图：模型版本生命周期

阶段定义

阶段 说明 用途
None 未分配 新注册的模型
Staging 预发布 测试环境、灰度验证
Production 生产 线上服务、正式环境
Archived 归档 历史版本、已退役

阶段转换

from mlflow.tracking import MlflowClient client = MlflowClient() # 开发 -> Staging client.transition_model_version_stage( name="my-model", version=3, stage="Staging" ) # Staging -> Production client.transition_model_version_stage( name="my-model", version=3, stage="Production", archive_existing_versions=True # 自动归档旧Production版本 ) # Production -> Archived client.transition_model_version_stage( name="my-model", version=2, stage="Archived" )
⚠️
阶段转换规则
  • • 严格执行转换流程，避免直接到Production
  • • 每个阶段必须通过相应的测试
  • • 记录每个阶段转换的理由
  • • 定期清理Archived版本

⏪ 版本回滚

回滚策略

# 策略1：阶段回滚 client.transition_model_version_stage( name="my-model", version=2, # 回滚到v2 stage="Production", archive_existing_versions=True ) # 策略2：删除新版本 client.delete_model_version( name="my-model", version=3 # 删除有问题的v3 ) # 策略3：重新部署旧版本 # 在部署系统中指定旧版本 kubectl set image deployment/my-model \ my-model=registry.example.com/my-model:v2

快速回滚

# Kubernetes快速回滚 kubectl rollout undo deployment/my-model # 查看回滚历史 kubectl rollout history deployment/my-model # 回滚到指定版本 kubectl rollout undo deployment/my-model --to-revision=2 # 查看回滚状态 kubectl rollout status deployment/my-model

回滚检查清单

# 回滚前检查 # 1. 确认问题是否与模型相关 # 2. 验证旧版本的可用性 # 3. 评估回滚的影响范围 # 4. 准备回滚方案 # 回滚后验证 # 1. 检查服务可用性 # 2. 验证模型性能 # 3. 监控系统指标 # 4. 记录回滚原因

🔍 版本对比分析

性能对比

from mlflow.tracking import MlflowClient client = MlflowClient() # 获取多个版本 versions = [1, 2, 3] metrics = [] for version in versions: model_version = client.get_model_version("my-model", version) run = client.get_run(model_version.run_id) metrics.append({ "version": version, "accuracy": run.data.metrics.get("accuracy"), "precision": run.data.metrics.get("precision"), "recall": run.data.metrics.get("recall"), "f1_score": run.data.metrics.get("f1_score") }) # 生成对比报告 import pandas as pd df = pd.DataFrame(metrics) print(df.sort_values("accuracy", ascending=False))

参数对比

# 对比超参数 for version in versions: model_version = client.get_model_version("my-model", version) run = client.get_run(model_version.run_id) print(f"\nVersion {version}:") print(f" Learning Rate: {run.data.params.get('learning_rate')}") print(f" Batch Size: {run.data.params.get('batch_size')}") print(f" Epochs: {run.data.params.get('epochs')}")

差异可视化

import matplotlib.pyplot as plt # 绘制性能对比 versions = [1, 2, 3, 4] accuracies = [0.90, 0.92, 0.91, 0.95] plt.figure(figsize=(10, 6)) plt.plot(versions, accuracies, marker='o') plt.xlabel('Model Version') plt.ylabel('Accuracy') plt.title('Model Performance by Version') plt.grid(True) # 保存到MLflow mlflow.log_figure(plt.gcf(), "version_comparison.png") plt.close()

存储优化建议
