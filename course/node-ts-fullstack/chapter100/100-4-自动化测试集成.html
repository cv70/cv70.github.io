100.4 自动化测试集成

在 CI/CD 流水线中集成自动化测试

🎯 学习目标

  • 理解测试金字塔在 CI 中的应用
  • 掌握单元测试、集成测试的自动化配置
  • 学会生成和上报测试报告
  • 了解 E2E 测试的 CI 集成方案

测试金字塔

在 CI 流水线中，应该按照测试金字塔原则配置测试：单元测试数量最多、执行最快；集成测试次之；E2E 测试最少但最接近真实场景。

📊 测试层级

═══════════════════════════════ E2E 测试 (端到端) ─────────────────────────────── 数量少 | 执行慢 | 成本高 ═══════════════════════════════ 集成测试 (API/数据库) ─────────────────────────────── 数量中 | 执行中 | 成本中 ═══════════════════════════════ 单元测试 (函数/模块) ─────────────────────────────── 数量多 | 执行快 | 成本低 ═══════════════════════════════

🧪 单元测试配置

# .github/workflows/test.yml name: Test on: [push, pull_request] jobs: unit-test: runs-on: ubuntu-latest steps: - uses: actions/checkout@v4 - name: Setup Node.js uses: actions/setup-node@v4 with: node-version: '20' cache: 'npm' - name: Install dependencies run: npm ci - name: Run unit tests run: npm run test:unit -- --coverage - name: Upload coverage uses: codecov/codecov-action@v3 with: token: ${{ secrets.CODECOV_TOKEN }} files: ./coverage/lcov.info fail_ci_if_error: true

🔗 集成测试配置

jobs: integration-test: runs-on: ubuntu-latest services: postgres: image: postgres:15-alpine env: POSTGRES_USER: test POSTGRES_PASSWORD: test POSTGRES_DB: test_db ports: - 5432:5432 options: >- --health-cmd pg_isready --health-interval 10s --health-timeout 5s --health-retries 5 redis: image: redis:7-alpine ports: - 6379:6379 options: >- --health-cmd "redis-cli ping" --health-interval 10s --health-timeout 5s --health-retries 5 env: DATABASE_URL: postgresql://test:test@localhost:5432/test_db REDIS_URL: redis://localhost:6379 steps: - uses: actions/checkout@v4 - name: Setup Node.js uses: actions/setup-node@v4 with: node-version: '20' cache: 'npm' - name: Install dependencies run: npm ci - name: Run database migrations run: npm run db:migrate - name: Run integration tests run: npm run test:integration

🎭 E2E 测试配置

jobs: e2e-test: runs-on: ubuntu-latest steps: - uses: actions/checkout@v4 - name: Setup Node.js uses: actions/setup-node@v4 with: node-version: '20' cache: 'npm' - name: Install dependencies run: npm ci - name: Install Playwright run: npx playwright install --with-deps - name: Build application run: npm run build - name: Run E2E tests run: npx playwright test - name: Upload test results uses: actions/upload-artifact@v4 if: always() with: name: playwright-report path: playwright-report/ retention-days: 30

📈 测试报告与覆盖率

Jest 配置

// jest.config.js module.exports = { preset: 'ts-jest', testEnvironment: 'node', collectCoverage: true, coverageDirectory: 'coverage', coverageReporters: ['text', 'lcov', 'html', 'json-summary'], coverageThreshold: { global: { branches: 80, functions: 80, lines: 80, statements: 80 } }, reporters: [ 'default', ['jest-junit', { outputDirectory: './reports', outputName: 'junit.xml' }] ] };

package.json 脚本

{ "scripts": { "test": "jest", "test:unit": "jest --testPathPattern=unit", "test:integration": "jest --testPathPattern=integration", "test:e2e": "jest --testPathPattern=e2e", "test:coverage": "jest --coverage", "test:watch": "jest --watch" } }

🔧 并行测试优化

# GitHub Actions 矩阵并行 jobs: test: runs-on: ubuntu-latest strategy: fail-fast: false matrix: shard: [1/4, 2/4, 3/4, 4/4] steps: - name: Run tests run: npx jest --shard=${{ matrix.shard }}
💡
测试优化建议
  • 使用测试缓存减少重复运行
  • 按修改文件智能选择测试
  • 使用分片并行执行大型测试集
  • 设置测试超时防止无限等待
  • 失败时保留测试产物便于调试
