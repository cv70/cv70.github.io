训练监控概述

大规模LLM训练涉及上千个GPU节点，训练周期长达数周，完善的监控体系能够及时发现问题、定位故障根因、优化训练效率，确保训练任务的顺利进行。

训练指标

  • 学习率变化
  • 梯度范数
  • 吞吐量
  • 训练速度

系统指标

  • GPU利用率
  • 显存使用
  • CPU使用率
  • 内存使用
  • 磁盘I/O

网络指标

  • 网络带宽
  • 通信延迟
  • 丢包率
  • NCCL通信量
  • 集合通信时间

🌐 分布式训练监控

PyTorch Profiler集成

import torch.profiler as profiler

with profiler.profile(
    activities=[
        profiler.ProfilerActivity.CPU,
        profiler.ProfilerActivity.CUDA,
    ],
    schedule=profiler.schedule(
        wait=1,
        warmup=1,
        active=3,
        repeat=2
    ),
    on_trace_ready=profiler.tensorboard_trace_handler(
        './logs/profiler'
    ),
    record_shapes=True,
    profile_memory=True,
    with_stack=True
) as prof:
    for step, batch in enumerate(dataloader):
        train_step(batch)
        prof.step()

# 关键指标：
# - 计算时间占比
# - 通信时间占比
# - 数据加载时间
# - 内存峰值

PyTorch Profiler提供详细的性能分析，包括计算、通信、I/O各环节的时间分布，是识别训练瓶颈的重要工具。

🚨 告警规则设计

告警类别 告警条件 严重级别 响应策略
训练异常 Loss爆炸/NAN 严重 立即检查训练参数
GPU故障 GPU利用率=0持续5分钟 严重 检查节点硬件状态
内存溢出 显存使用>95% 警告 调整batch size或gradient accumulation
通信异常 NCCL超时/通信失败 严重 检查网络连接
存储异常 I/O延迟>100ms 警告 检查存储系统
进度缓慢 吞吐量下降>50% 警告 性能分析定位瓶颈

🔧 告警配置示例

Prometheus告警规则

groups:
  - name: llm_training
    interval: 30s
    rules:
      # Loss异常检测
      - alert: TrainingLossExploded
        expr: |
          (training_loss - training_loss offset 1m) / training_loss > 0.5
        for: 5m
        labels:
          severity: critical
        annotations:
          summary: "训练Loss爆炸"
          description: "Job {{ $labels.job }} Loss在5分钟内增长超过50%"

      # GPU利用率过低
      - alert: LowGPUUtilization
        expr: |
          avg(DCGM_FI_DEV_GPU_UTIL) by (job) < 30
        for: 10m
        labels:
          severity: warning
        annotations:
          summary: "GPU利用率过低"
          description: "Job {{ $labels.job }} GPU利用率低于30%"

      # GPU温度过高
      - alert: GPUTemperatureHigh
        expr: |
          DCGM_FI_DEV_GPU_TEMP > 85
        for: 5m
        labels:
          severity: warning
        annotations:
          summary: "GPU温度过高"
          description: "GPU {{ $labels.gpu }} 温度为 {{ $value }}°C"

      # NCCL通信超时
      - alert: NCCLTimeout
        expr: |
          rate(nccl_timeouts_total[5m]) > 0
        labels:
          severity: critical
        annotations:
          summary: "NCCL通信超时"
          description: "检测到NCCL通信超时，可能存在网络问题"
⚠️
告警疲劳

过多的告警会导致告警疲劳。要合理设置阈值和持续时间，实现告警分级和告警聚合，合并相似告警，确保每个告警都有明确的响应策略。

🔬 性能分析与优化

常见性能瓶颈及优化

瓶颈类型 识别方法 优化策略 预期提升
计算瓶颈 GPU利用率>90% 混合精度、算子融合 20-30%
内存瓶颈 显存使用>90% gradient checkpointing、ZeRO 2-4x模型容量
通信瓶颈 通信时间占比>50% 梯度压缩、通信重叠 30-50%
I/O瓶颈 数据加载时间长 预加载、并行数据加载 50-100%

📊 实验追踪集成

MLflow集成

import mlflow

# 启动MLflow追踪
mlflow.start_run()

# 记录训练参数
mlflow.log_params({
    "learning_rate": args.lr,
    "batch_size": args.batch_size,
    "model_size": args.model_size,
})

# 记录训练指标
for step in range(max_steps):
    loss = train_step()
    mlflow.log_metrics({
        "loss": loss,
        "lr": scheduler.get_lr()[0],
        "grad_norm": grad_norm,
    }, step=step)

# 记录模型
mlflow.pytorch.log_model(model, "model")

# 记录artifact
mlflow.log_artifact("config.yaml")

# 结束追踪
mlflow.end_run()

将监控数据与实验追踪系统集成，可以全面记录训练过程，方便后续分析和复现。
