86.1 Git 分支策略

Git 分支管理最佳实践

🎯 学习目标

  • 理解 Git 分支策略的重要性
  • 掌握常用分支类型
  • 学会选择合适的分支策略
  • 了解分支命名规范

📚 分支类型介绍

# 主要分支类型 ## 1. 主分支 (main/master) - 生产环境代码 - 永远保持可部署状态 - 受保护，禁止直接推送 ## 2. 开发分支 (develop) - 开发集成分支 - 包含下一版本的功能 - 定期合并到主分支 ## 3. 功能分支 (feature/*) - 开发新功能 - 从 develop 创建 - 完成后合并回 develop ## 4. 发布分支 (release/*) - 准备发布版本 - 从 develop 创建 - 合并到 main 和 develop ## 5. 热修复分支 (hotfix/*) - 紧急修复生产问题 - 从 main 创建 - 合并到 main 和 develop ## 6. Bug 修复分支 (bugfix/*) - 修复非紧急 bug - 从 develop 创建 - 合并回 develop

🔧 分支命名规范

# 分支命名格式 /- # 功能分支 feature/PROJ-123-user-authentication feature/PROJ-124-payment-integration # Bug 修复分支 bugfix/PROJ-125-login-error bugfix/PROJ-126-pagination-issue # 热修复分支 hotfix/PROJ-127-critical-security-fix hotfix/PROJ-128-data-loss-fix # 发布分支 release/v1.2.0 release/v2.0.0-beta # 命名规则 - 使用小写字母和连字符 - 包含 issue 编号便于追踪 - 描述简短准确（不超过 50 字符） - 避免使用特殊字符
💡
命名建议

好的分支名应该让人一目了然知道这个分支的目的。关联的 issue 编号可以帮助快速找到相关需求或问题。

⚙️ 分支保护规则

# GitHub 分支保护设置 # Settings > Branches > Add branch protection rule ## 主分支保护规则 Branch name pattern: main ☑ Require a pull request before merging ☑ Require approvals: 1 ☑ Dismiss stale pull request approvals ☑ Require status checks to pass before merging ☑ Require branches to be up to date ☑ Status checks: lint, test, build ☑ Require conversation resolution before merging ☑ Do not allow bypassing the above settings ## 开发分支保护规则 Branch name pattern: develop ☑ Require a pull request before merging ☑ Require status checks to pass before merging

🚀 常用 Git 命令

# 创建分支 git checkout -b feature/PROJ-123-new-feature develop # 推送分支到远程 git push -u origin feature/PROJ-123-new-feature # 同步远程分支 git fetch origin git checkout develop git pull origin develop # 合并分支 git checkout develop git merge --no-ff feature/PROJ-123-new-feature git push origin develop # 删除已合并的分支 git branch -d feature/PROJ-123-new-feature git push origin --delete feature/PROJ-123-new-feature # 查看所有分支 git branch -a # 查看分支合并情况 git branch --merged develop git branch --no-merged develop

📝 本节小结

✅
  • • 根据团队规模选择合适的分支策略
  • • 遵循分支命名规范便于管理
  • • 主分支必须设置保护规则
  • • 定期清理已合并的分支
