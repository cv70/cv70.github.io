41.3 长文本处理

突破上下文限制的技巧与策略

🎯 学习目标

  • 理解大模型上下文窗口的限制
  • 掌握文本分块和检索增强技术
  • 学会选择合适的长文本处理策略
  • 了解长上下文模型的应用场景

长文本处理挑战

大模型存在上下文窗口限制，无法一次性处理超长文本。长文本处理技术旨在让模型能够理解和处理超过上下文限制的文档，如完整书籍、法律文件或代码库。

⚖️ 长文本处理策略对比

策略 原理 优点 缺点
分块处理 将文本切分为小块分别处理 简单、通用 丢失全局上下文
检索增强(RAG) 检索相关段落后处理 高效、精准 需要向量索引
摘要压缩 先压缩再处理 保留核心信息 可能丢失细节
长上下文模型 使用支持长文本的模型 保留完整上下文 成本较高

💻 文本分块示例

from langchain.text_splitter import RecursiveCharacterTextSplitter def chunk_text(text, chunk_size=1000, overlap=200): """智能分块，保持语义完整性""" text_splitter = RecursiveCharacterTextSplitter( chunk_size=chunk_size, chunk_overlap=overlap, length_function=len, separators=["\n\n", "\n", "。", "！", "？", "；", " ", ""] ) chunks = text_splitter.split_text(text) return chunks # 处理长文档 long_document = open("document.txt").read() chunks = chunk_text(long_document) # 分别处理每个块 results = [] for i, chunk in enumerate(chunks): response = client.chat.completions.create( model="gpt-4-turbo-preview", messages=[ {"role": "system", "content": "请总结以下文本"}, {"role": "user", "content": chunk} ] ) results.append(response.choices[0].message.content) # 合并结果 final_summary = "\n".join(results)
💡
分块策略选择

分块大小需要平衡上下文完整性和处理效率。一般建议chunk_size为500-1500 tokens，overlap为chunk_size的10-20%。

🔧 检索增强生成(RAG)

向量检索

from langchain.embeddings import OpenAIEmbeddings from langchain.vectorstores import Chroma # 创建向量索引 embeddings = OpenAIEmbeddings() vectorstore = Chroma.from_texts( texts=chunks, embedding=embeddings ) # 检索相关内容 def retrieve_and_answer(query, k=5): # 检索最相关的k个块 docs = vectorstore.similarity_search( query, k=k ) # 构建上下文 context = "\n\n".join( doc.page_content for doc in docs ) # 使用检索到的上下文回答 response = client.chat.completions.create( model="gpt-4-turbo-preview", messages=[ {"role": "system", "content": f"基于以下内容回答：{context}"}, {"role": "user", "content": query} ] ) return response.choices[0].message.content
