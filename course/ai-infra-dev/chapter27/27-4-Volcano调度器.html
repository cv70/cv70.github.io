Volcano简介

Volcano是CNCF托管的Kubernetes批处理调度器，专为高性能计算、深度学习训练等场景设计。 相比原生Kube-scheduler，Volcano提供了更强的调度能力，支持作业级别的调度、公平调度、gang调度等特性。

🏗️ 核心特性

Gang调度

确保作业的所有Pod同时调度，避免部分Pod等待导致的资源浪费。

  • 全有或全无
  • 适合分布式训练
  • 避免死锁
  • 减少等待时间

公平调度

在多个队列间公平分配资源，保证各租户的公平性。

  • 队列资源配额
  • 权重分配
  • 抢占机制
  • 资源回收

任务调度

支持多种批处理任务类型，如Spark、TensorFlow、PyTorch等。

  • Spark on K8s
  • PyTorch Operator
  • MPI作业
  • TensorFlow训练

高级调度

提供丰富的调度策略和插件机制。

  • 拓扑感知
  • GPU亲和性
  • NUMA亲和
  • 自定义调度器

📦 安装Volcano

使用kubectl安装

# 克隆Volcano仓库 git clone https://github.com/volcano-sh/volcano.git cd volcano # 安装Volcano kubectl apply -f installer/volcano-development.yaml # 或直接使用官方发布版本 kubectl apply -f https://raw.githubusercontent.com/volcano-sh/volcano/v1.8.0/installer/volcano-development.yaml # 验证安装 kubectl get pods -n volcano-system kubectl get crd | grep volcano # 查看Volcano组件 kubectl get deploy -n volcano-system
💡
Volcano组件
  • • volcano-scheduler：调度器
  • • volcano-controllers：控制器
  • • volcano-admission：准入控制
  • • volcano-agent：节点代理

使用Helm安装

# 添加Volcano Helm仓库 helm repo add volcano-sh https://volcano-sh.github.io/helm-charts helm repo update # 安装Volcano helm install volcano volcano-sh/volcano -n volcano-system --create-namespace # 查看Volcano状态 helm status volcano -n volcano-system

📊 PodGroup概念

PodGroup

PodGroup是Volcano的核心概念，用于将一组相关的Pod作为一个整体进行调度。 PodGroup定义了作业的调度策略、资源需求、优先级等。

图：Gang调度示意图

创建PodGroup

apiVersion: scheduling.volcano.sh/v1beta1 kind: PodGroup metadata: name: mpi-job namespace: default spec: # 作业最小运行Pod数（Gang调度） minMember: 4 # 作业优先级，数值越大优先级越高 priorityClassName: high-priority # 队列名称 queue: default # 调度策略 minResources: cpu: "4" memory: "8Gi" nvidia.com/gpu: "4" # 超时时间 timeoutSeconds: 3600

使用PodGroup

apiVersion: v1 kind: Pod metadata: name: worker-0 namespace: default labels: # 关联到PodGroup volcano.sh/job-name: mpi-job volcano.sh/job-role: worker spec: schedulerName: volcano containers: - name: worker image: mpi-job:latest resources: requests: cpu: "2" memory: "4Gi" nvidia.com/gpu: "1" limits: cpu: "2" memory: "4Gi" nvidia.com/gpu: "1"

✅
Gang调度优势
  • • 确保所有训练节点同时启动
  • • 避免部分节点等待导致的资源浪费
  • • 提高训练任务的整体吞吐量
  • • 简化分布式训练的部署流程

⚖️ 队列与公平调度

创建队列

apiVersion: scheduling.volcano.sh/v1beta1 kind: Queue metadata: name: training-queue namespace: default spec: capability: cpu: "100" memory: "200Gi" nvidia.com/gpu: "10" reclaimable: true weight: 10 --- apiVersion: scheduling.volcano.sh/v1beta1 kind: Queue metadata: name: inference-queue namespace: default spec: capability: cpu: "50" memory: "100Gi" nvidia.com/gpu: "5" reclaimable: true weight: 5

配置调度器

# 编辑调度器配置 kubectl edit configmap volcano-scheduler-configmap -n volcano-system # 公平调度配置 apiVersion: config.volcano.sh/v1alpha1 kind: Configuration kind: Configuration schedulers: - name: volcano actions: "enqueue, allocate, backfill" tiers: - plugins: - name: priority - name: gang - name: conformance - plugins: - name: overcommit - name: drf - name: predicates - name: nodeorder - name: binpack # DRF（Dominant Resource Fairness）配置 drf: enable: true # 支持公平分配资源

🔧 高级调度策略

NUMA亲和性

apiVersion: v1 kind: Pod metadata: name: numa-aware-pod annotations: volcano.sh/numa-topology-policy: "best-effort" spec: schedulerName: volcano containers: - name: app image: pytorch/pytorch:latest resources: requests: cpu: "4" memory: "8Gi" nvidia.com/gpu: "1"

GPU亲和性

apiVersion: v1 kind: Pod metadata: name: gpu-affinity-pod annotations: # Pod亲和性，调度到有相同标签的Pod所在的节点 volcano.sh/pod-group-affinity: "training-group" spec: schedulerName: volcano affinity: # 节点亲和性 nodeAffinity: requiredDuringSchedulingIgnoredDuringExecution: nodeSelectorTerms: - matchExpressions: - key: gpu-type operator: In values: - A100 - V100 containers: - name: training image: pytorch/pytorch:latest resources: requests: nvidia.com/gpu: "2"

抢占调度

# 配置抢占策略 apiVersion: scheduling.volcano.sh/v1beta1 kind: PodGroup metadata: name: high-priority-job spec: minMember: 2 priorityClassName: high-priority # 高优先级 queue: training-queue
💡
抢占机制

高优先级的作业可以抢占低优先级作业的资源，被抢占的作业会重新调度到其他节点或进入等待队列。

⚠️
常见问题
  • • Pod处于Pending状态：检查资源是否足够
  • • Gang调度失败：检查minMember配置
  • • 队列资源不足：调整队列配额或权重
  • • 抢占频繁：优化优先级配置
