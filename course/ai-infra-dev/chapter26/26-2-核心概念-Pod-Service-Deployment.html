📦 Pod：最小部署单元

什么是Pod？

Pod是Kubernetes中最小的可部署单元，包含一个或多个共享网络和存储的容器。 Pod中的容器总是协同工作，作为一个整体被调度和管理。

图：Pod包含共享网络和存储的容器
💡
Pod特性
  • • 共享网络：所有容器共享同一个IP和端口空间
  • • 共享存储：通过Volume共享数据
  • • 临时性：Pod是短暂的，随时可能被重建
  • • 原子性：Pod内的容器要么全部启动，要么全部失败

🔄 Pod生命周期

Pending → Running → Succeeded/Failed ↓ Unknown
阶段 说明
Pending Pod已创建，但容器还未启动（调度中/拉取镜像）
Running 至少有一个容器正在运行
Succeeded 所有容器成功终止（一次性任务）
Failed 至少有一个容器异常终止
Unknown 无法获取Pod状态（通信故障）

🌐 Service：服务发现与负载均衡

Service的作用

Service定义了一组Pod的访问策略，提供稳定的网络端点，实现服务发现和负载均衡。

Service类型

ClusterIP

集群内部访问，默认类型

type: ClusterIP

NodePort

通过节点端口访问外部

type: NodePort

LoadBalancer

云厂商负载均衡器

type: LoadBalancer

ExternalName

映射到外部DNS名称

type: ExternalName

🚀 Deployment：声明式应用管理

Deployment功能

  • 管理Pod的副本数量
  • 滚动更新和回滚
  • 应用版本管理
  • 扩缩容控制

Deployment示例

apiVersion: apps/v1 kind: Deployment metadata: name: nginx-deployment spec: replicas: 3 selector: matchLabels: app: nginx template: metadata: labels: app: nginx spec: containers: - name: nginx image: nginx:1.21 ports: - containerPort: 80 --- apiVersion: v1 kind: Service metadata: name: nginx-service spec: selector: app: nginx ports: - port: 80 targetPort: 80 type: ClusterIP

✅
滚动更新优势
  • • 零停机时间
  • • 可控制更新速度和策略
  • • 更新失败可自动回滚
  • • 保留历史版本，方便回溯

📊 核心对象对比

对象 作用 生命周期 IP
Pod 运行容器 临时 动态变化
Deployment 管理Pod 持久 无
Service 暴露Pod 持久 固定
⚠️
最佳实践
  • • 不要直接创建Pod，始终使用Deployment等控制器
  • • 为每个应用创建对应的Service
  • • 使用标签（Labels）组织资源
  • • 定义资源请求和限制（requests/limits）

📝 本节小结

💡
  • • Pod是Kubernetes最小部署单元
  • • Service提供稳定的服务发现和负载均衡
  • Deployment用于管理无状态应用
  • • 三个对象协同工作：Deployment管理Pod，Service暴露Pod
