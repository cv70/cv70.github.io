突破序列长度限制的技术

什么是序列并行？

序列并行（Sequence Parallelism）是一种将序列维度 切分到多个GPU上的并行策略。与传统的张量并行不同，序列并行将输入序列 按长度方向切分，使得每个GPU只处理序列的一部分。这样可以支持更长的序列， 同时减少显存占用。Megatron-LM的序列并行基于Ring Self Attention， 通过环形通信计算全局注意力。

📊 序列长度与显存

传统方法的限制

标准Self Attention的显存占用： 输入：X ∈ ℝ^(B×S×H) 其中：B=batch size, S=sequence length, H=hidden size 注意力计算： Q, K, V = Linear(X) # 3 × B×S×H Attention Matrix = Q × K^T # B×S×S 显存计算： 1. Q, K, V： 3 × B × S × H × sizeof(float16) 2. Attention Matrix： B × S × S × sizeof(float16) 3. Output： B × S × H × sizeof(float16) 总显存（仅Attention部分）： = 3BSH + BS² + BSH = BS² + 4BSH 示例： • B = 4, S = 2048, H = 4096, FP16 • 显存 = 4×2048²×2 + 4×4×2048×4096×2 = 33.6 MB + 268.4 MB ≈ 302 MB 如果S = 8192： • 显存 = 4×8192²×2 + 4×4×8192×4096×2 = 537.6 MB + 1073.7 MB ≈ 1611 MB 问题： • 显存占用随S²增长 • 长序列（S>4096）显存不足 • 限制了长序列任务

⚙️ 序列并行原理

Ring Self Attention

序列并行切分： 假设S = 4096, SP（sequence parallel）= 4 每个GPU处理序列的1/4： ┌─────────────────────────────────────────┐ │ 序列：[token_0, token_1, ..., token_4095] │ ├─────────────────────────────────────────┤ │ GPU0: [token_0, ..., token_1023] │ S/4 │ GPU1: [token_1024, ..., token_2047] │ S/4 │ GPU2: [token_2048, ..., token_3071] │ S/4 │ GPU3: [token_3072, ..., token_4095] │ S/4 └─────────────────────────────────────────┘ Ring Self Attention计算： 每个GPU需要计算其token与所有token的注意力： 1. 本地token与自己token的注意力（本地计算） 2. 本地token与其他GPU token的注意力（通信） Ring通信模式： Step 1: GPU0: 计算与本地token的注意力 GPU1: 计算与本地token的注意力 GPU2: 计算与本地token的注意力 GPU3: 计算与本地token的注意力 Step 2: GPU0 → GPU1: 发送K₀, V₀ GPU1 → GPU2: 发送K₁, V₁ GPU2 → GPU3: 发送K₂, V₂ GPU3 → GPU0: 发送K₃, V₃ Step 3: GPU0: 计算与GPU3 token的注意力 GPU1: 计算与GPU0 token的注意力 GPU2: 计算与GPU1 token的注意力 GPU3: 计算与GPU2 token的注意力 Step 4: GPU0 → GPU1: 发送K₃, V₃ GPU1 → GPU2: 发送K₀, V₀ GPU2 → GPU3: 发送K₁, V₁ GPU3 → GPU0: 发送K₂, V₂ ...（继续环形通信） 经过SP步后，每个GPU获得完整输出

🔧 实现要点

序列并行的关键实现

1. 序列切分 def split_sequence(x, sp_rank, sp_size): """切分序列维度""" B, S, H = x.shape seq_per_rank = S // sp_size start_idx = sp_rank * seq_per_rank end_idx = (sp_rank + 1) * seq_per_rank x_local = x[:, start_idx:end_idx, :] return x_local 2. Ring Attention def ring_attention(q, k, v, sp_rank, sp_size): """环形注意力计算""" B, S_local, H = q.shape S_total = S_local * sp_size # 初始化输出 output = torch.zeros_like(q) # 初始化attention buffer attention_buffer = torch.zeros_like(q) # 环形通信 for step in range(sp_size): # 当前GPU的K, V k_current = k v_current = v # 计算当前注意力 scores = torch.matmul(q, k_current.transpose(-2, -1)) scores = scores / torch.sqrt(torch.tensor(H, dtype=torch.float32)) attention_weights = torch.softmax(scores, dim=-1) attention_output = torch.matmul(attention_weights, v_current) # 累积到buffer attention_buffer += attention_output # 通信：环形发送K, V k_next = ring_send_recv(k, sp_rank, sp_size) v_next = ring_send_recv(v, sp_rank, sp_size) k = k_next v = v_next return attention_buffer 3. 集合输出 def merge_sequence(x_local, sp_rank, sp_size): """合并序列输出""" # AllGather收集完整序列 x_full = torch.distributed.all_gather(x_local) return x_full

🎯 应用场景

序列并行的适用场景

1. 长文本生成 • 生成超过2048 token的长文本 • 需要保持上下文一致性 • 示例：小说生成、代码生成 2. 长文档理解 • 处理整篇文档 • 需要全局注意力 • 示例：文档摘要、问答 3. 视频理解 • 视频作为长序列处理 • 需要跨帧注意力 • 示例：视频分类、动作识别 4. 时间序列 • 处理长时序数据 • 需要长期依赖 • 示例：股票预测、天气预测 5. 基因序列 • 处理超长基因序列 • 需要全局上下文 • 示例：基因分析、蛋白质结构预测
⚠️
注意事项
  • 通信开销：SP增加会带来通信开销
  • 序列长度：序列长度必须能被SP整除
  • 位置编码：需要特殊处理位置编码
  • 性能权衡：需要在显存和速度间权衡
  • 调试困难：分布式系统调试复杂
💡
最佳实践
  • SP大小：通常2、4或8
  • 结合TP：序列并行通常与张量并行结合
  • 监控性能：观察通信时间占比
  • 测试序列长度：逐步增加序列长度
  • 使用NVLink：单机多卡使用NVLink加速
