断点续训概述

大模型训练周期长达数周甚至数月，期间硬件故障、网络中断、软件错误等在所难免。断点续训机制确保训练任务能够从最近的状态恢复，避免数周的训练成果付诸东流。

⚠️ 故障类型分析

硬件故障

  • GPU故障（XID错误）
  • 节点掉电/重启
  • 网络设备故障
  • 存储设备故障

软件故障

  • OOM（内存不足）
  • NCCL通信超时
  • 进程崩溃
  • 容器调度失败

💾 Checkpoint机制

分布式Checkpoint架构

分布式Checkpoint组件：
├── 模型状态：各rank的模型权重、优化器状态
├── 训练状态：全局步数、学习率调度器、随机种子
├── 数据状态：数据加载器状态、当前样本索引
├── 系统状态：进程rank映射、节点拓扑
└── 元数据：Checkpoint时间戳、版本信息

Checkpoint类型：
• 同步Checkpoint：所有rank同步保存，一致性高
• 异步Checkpoint：后台保存，不阻塞训练
• 增量Checkpoint：只保存变化部分
• 分层Checkpoint：快速/完整分层保存

🔧 PyTorch分布式Checkpoint

实现示例

import torch
import torch.distributed as dist
from torch.distributed.checkpoint import save, load

def save_checkpoint(model, optimizer, scheduler, step, path):
    """保存分布式checkpoint"""
    checkpoint = {
        'model': model.state_dict(),
        'optimizer': optimizer.state_dict(),
        'scheduler': scheduler.state_dict(),
        'step': step,
        'rng_state': torch.get_rng_state_all(),
    }

    # 使用分布式Checkpoint API
    state_dict = {
        'model': model,
        'optimizer': optimizer,
        'scheduler': scheduler,
    }

    save(state_dict, checkpoint_id=path)

def load_checkpoint(model, optimizer, scheduler, path):
    """加载分布式checkpoint"""
    state_dict = {
        'model': model,
        'optimizer': optimizer,
        'scheduler': scheduler,
    }

    # 自动加载到正确的rank
    load(state_dict, checkpoint_id=path)
    return checkpoint['step']

💡
分层Checkpoint策略

建议采用三层Checkpoint策略：每100步保存快速checkpoint（仅模型权重），每1000步保存完整checkpoint，每10000步保存归档checkpoint。这样平衡了恢复速度和存储成本。

🚀 异步Checkpoint优化

减少Checkpoint对训练的影响

异步Checkpoint实现：
import threading
import queue

class AsyncCheckpointManager:
    def __init__(self, max_queue_size=2):
        self.queue = queue.Queue(maxsize=max_queue_size)
        self.thread = threading.Thread(
            target=self._save_worker,
            daemon=True
        )
        self.thread.start()

    def async_save(self, state_dict, path):
        """异步保存checkpoint"""
        if self.queue.full():
            self.queue.get()  # 丢弃最旧的
        self.queue.put((state_dict.copy(), path))

    def _save_worker(self):
        """后台保存线程"""
        while True:
            state_dict, path = self.queue.get()
            torch.save(state_dict, path)

# 使用方式
checkpoint_mgr = AsyncCheckpointManager()
if step % 100 == 0:
    checkpoint_mgr.async_save(
        {'model': model.state_dict()},
        f'checkpoint/step_{step}.pt'
    )

🔍 Checkpoint恢复流程

完整恢复流程

恢复流程步骤：
1. 检测最新Checkpoint
   ├── 查找最近的完整checkpoint
   └── 验证checkpoint完整性

2. 节点重新分配
   ├── 如果节点数不变，直接恢复
   └── 如果节点数变化，重新分配rank

3. 模型状态恢复
   ├── 加载模型权重
   ├── 加载优化器状态
   └── 恢复学习率调度器

4. 数据状态恢复
   ├── 恢复数据加载器状态
   └── 定位到正确的样本位置

5. 训练参数恢复
   ├── 恢复全局步数
   ├── 恢复随机种子
   └── 恢复其他训练状态

6. 继续训练
   └── 从中断点继续训练

⚠️
注意事项

Checkpoint恢复时要确保超参数一致性、软件版本一致、硬件拓扑一致。如果这些条件不满足，可能导致恢复失败或训练异常。建议在Checkpoint中记录所有相关元信息。
