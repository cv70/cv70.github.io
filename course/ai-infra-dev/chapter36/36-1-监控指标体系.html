可观测性的三大支柱

可观测性是监控体系的进阶概念，包含三个核心维度：

📊 三大支柱详解

📈

指标（Metrics）

数值化的时间序列数据，反映系统状态变化

📝

日志（Logs）

离散的事件记录，包含上下文信息

🔗

追踪（Traces）

分布式请求的完整路径，记录调用链

🖥️ 硬件监控指标

类别 指标名称 描述 告警阈值

gpu_memory_used 显存使用量 >95% 总显存
gpu_temperature GPU温度 >85°C

cpu_load_avg 平均负载 >核心数
cpu_temperature CPU温度 >80°C
内存 memory_usage_percent 内存使用率 >95%
swap_usage_percent Swap使用率 >50%
存储 disk_usage_percent 磁盘使用率 >90%
disk_io_wait I/O等待时间 >20%
网络 network_bandwidth_usage 网络带宽使用率 >80%
network_latency 网络延迟 >10ms（局域网）

🚀 推理服务指标

性能指标

  • 请求延迟 - p50/p90/p99延迟
  • 吞吐量 - QPS/TPS
  • 队列长度 - 等待处理的请求数
  • 批大小 - 动态批处理大小

业务指标

  • 错误率 - 请求失败比例
  • 成功率 - 成功请求占比
  • 超时率 - 超时请求比例
  • 用户满意度 - 自定义业务指标

📏 指标类型

类型 描述 适用场景 示例
Counter 只增不减的计数器 累计统计 请求总数、错误总数
Gauge 可增可减的瞬时值 当前状态 CPU使用率、内存使用量
Histogram 数值分布直方图 延迟分布 请求延迟分布
Summary 分位数统计 性能分析 p90/p95/p99延迟

🏷️ 指标命名规范

💡
Prometheus命名规范

遵循最佳实践确保指标的一致性和可读性：

metric_name{label_name="label_value"} value
  • 使用snake_case命名（如 gpu_memory_used_bytes）
  • 添加单位后缀（如 _bytes、_seconds）
  • 使用标签区分维度（如 device="gpu:0"）
  • 避免基数爆炸（高基数标签值）

⚙️ 指标采集配置示例

# Prometheus采集配置示例 global: scrape_interval: 15s evaluation_interval: 15s scrape_configs: # GPU监控 - job_name: 'dcgm-exporter' static_configs: - targets: ['localhost:9400'] scrape_interval: 5s # 节点监控 - job_name: 'node-exporter' static_configs: - targets: ['localhost:9100'] # 自定义训练任务指标 - job_name: 'training-metrics' static_configs: - targets: ['training-server:8000'] relabel_configs: - source_labels: [__address__] target_label: instance - source_labels: [job] target_label: task_type
⚠️
注意事项
  • • 避免采集过多指标导致存储压力
  • • 高频指标需要配置适当的降采样
  • • 标签基数过高会影响查询性能
  • • 定期清理无用指标
