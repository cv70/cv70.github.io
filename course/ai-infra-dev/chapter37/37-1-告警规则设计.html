告警规则设计原则

好的告警规则应该及时、准确、可操作，避免告警疲劳。

📋 告警设计原则

⏱️

及时性

快速发现和通知问题

🎯

准确性

减少误报和漏报

🔧

可操作性

明确告警的应对措施

🔔 告警分级标准

级别 颜色 定义 响应时间 处理方式
P0 🔴 红色 严重故障，服务不可用 5分钟 立即处理，电话通知
P1 🟠 橙色 重要故障，功能受损 15分钟 快速处理，短信通知
P2 🟡 黄色 一般问题，性能下降 1小时 及时处理，邮件通知
P3 🔵 蓝色 轻微问题，潜在风险 4小时 工作时间处理
P4 ⚪ 白色 信息提示，无需立即处理 不通知 记录观察

🤖 AI基础设施告警分类

硬件告警

  • GPU温度过高、XID错误
  • CPU负载过高
  • 磁盘空间不足
  • 网络异常

训练告警

  • 训练任务失败
  • 显存溢出（OOM）
  • 训练Loss不收敛
  • 训练速度异常

推理告警

  • 推理延迟过高
  • 错误率突增
  • 服务不可用
  • 吞吐量下降

数据告警

  • 数据加载失败
  • 数据量异常
  • 存储空间告警
  • 数据质量异常

📊 阈值设定方法

💡
阈值设定策略

科学的阈值设定需要基于历史数据分析：

固定阈值法

基于经验设定固定值，简单易实现

  • GPU利用率 > 90%
  • 内存使用 > 95%
  • 磁盘空间 < 10%

动态阈值法

基于历史数据动态调整，适应性强

  • P95 + 2σ（标准差）
  • 同比/环比异常检测
  • 机器学习异常检测

⏱️ 告警持续时间设定

# for参数的设定原则 # 严重故障：短持续时间 - alert: ServiceDown expr: up == 0 for: 1m # 服务挂了1分钟就告警 # 性能问题：中等持续时间 - alert: HighLatency expr: latency > 1.0 for: 5m # 持续5分钟才告警 # 资源压力：较长持续时间 - alert: HighCPUUsage expr: cpu_usage > 90 for: 15m # 避免瞬时峰值误报 # 趋势预警：超长持续时间 - alert: DiskSpaceTrend expr: predict_linear(disk_usage[1h], 24h) > 100 for: 10m # 预测24小时后磁盘满

🚫 避免告警疲劳

告警疲劳的应对策略

  • 抑制规则 - 合并重复告警
  • 静默规则 - 维护期间暂停告警
  • 告警聚合 - 同类告警合并通知
  • 告警衰减 - 高频告警自动降低通知频率
  • 智能路由 - 按优先级和团队分发
  • 告警确认 - 处理人员确认后才关闭

📝 告警文档规范

# 告警规则文档模板 ## 告警名称: GPUTemperatureCritical ### 描述 GPU温度严重过高，可能导致硬件损坏 ### 触发条件 - 指标: nvidia_gpu_temperature_gpu - 阈值: > 90°C - 持续时间: 2分钟 ### 影响范围 - 可能导致GPU降频 - 影响训练/推理任务 - 严重时损坏硬件 ### 处理步骤 1. 检查风扇运行状态 2. 检查散热系统 3. 降低GPU任务负载 4. 必要时重启节点 ### 相关责任人 - 主要: infra-team - 备选: oncall ### 升级策略 - 10分钟未处理 -> 升级到oncall - 30分钟未处理 -> 升级到技术负责人
