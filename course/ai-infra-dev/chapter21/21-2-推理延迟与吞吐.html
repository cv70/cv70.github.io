21.2 推理延迟与吞吐

理解并优化推理性能的核心指标

🎯 学习目标

  • 理解延迟和吞吐的概念
  • 掌握两者的权衡关系
  • 学习性能优化策略
  • 了解性能基准测试方法

⏱️ 推理延迟详解

推理延迟（Latency）是指从接收请求到返回结果的时间，是实时应用的关键指标。

延迟的组成

网络延迟
请求传输时间
预处理延迟
数据准备时间
模型延迟
神经网络计算时间
后处理延迟
结果处理时间

📊 吞吐量详解

吞吐量（Throughput）是指在单位时间内处理的请求数量或数据量，衡量系统的整体处理能力。

吞吐量类型

  • QPS（Queries Per Second）：每秒查询数
  • RPS（Requests Per Second）：每秒请求数
  • TPS（Transactions Per Second）：每秒事务数
  • Samples/Sec：每秒处理的样本数

影响吞吐量因素

  • 计算资源利用率
  • 批处理大小
  • 并发请求处理能力
  • I/O等待时间

⚖️ 延迟 vs 吞吐的权衡

场景 优化目标 典型配置 示例应用
低延迟优先 最小化延迟 小批量，高并发 在线广告、实时对话
高吞吐优先 最大化吞吐 大批量，顺序处理 视频分析、批处理
平衡模式 两者兼顾 中等批量，动态调整 推荐系统、API服务

🚀 延迟优化策略

关键优化技术

模型压缩
量化、剪枝减少计算量
算子融合
减少内存访问
缓存机制
复用计算结果
异步处理
重叠计算与I/O
硬件加速
GPU/TPU专用计算
模型蒸馏
使用小模型推理

📈 吞吐量优化策略

批处理技术

  • 静态批处理：固定批次大小
  • 动态批处理：根据到达时间聚合
  • 连续批处理：不等所有请求到达

资源利用

  • GPU多实例（MIG）
  • 模型并行加载
  • 负载均衡策略
  • 自动扩缩容
💡
性能优化建议
  • 先测量再优化：使用性能分析工具找出瓶颈
  • 关注P99延迟：而非平均值
  • 端到端优化：不局限于模型计算
  • 持续监控：性能会随负载变化

🧪 性能测试示例

# 使用Locust进行压力测试
from locust import HttpUser, task, between

class ModelInferenceUser(HttpUser):
    wait_time = between(0.1, 0.5)  # 请求间隔

    @task
    def predict(self):
        payload = {
            "inputs": [[0.1, 0.2, 0.3, 0.4]]
        }
        response = self.client.post("/predict", json=payload)
        # 验证响应
        if response.status_code != 200:
            print(f"Error: {response.status_code}")

# 运行测试
# locust -f test_locust.py --host=http://localhost:8000

📝 本节小结

✅
  • • 延迟是单个请求的响应时间，吞吐是单位时间的处理量
  • • 延迟和吞吐往往需要权衡，不能同时最优
  • • 优化策略包括模型压缩、算子融合、批处理等
  • • 性能优化需要持续监控和调优
